## 1. 校验目的与范围

### 1.1 目的

对丰麟云枢平台及其 8 大业务域产品（合计 9 个产品）的全套交付文档进行**可实施性、一致性、完整性**三项校验，确认文档集是否达到"可直接用于开发、测试、上线及后续运维"的交付标准。

### 1.2 校验对象

按需求指定的产品顺序：丰麟云销 → 丰麟云协 → 丰麟云才 → 丰麟云财 → 丰麟云研 → 丰麟云服 → 丰麟云法 → 丰麟云智 → 丰麟云枢。

每个产品应交付 **12 类**文档：① 项目需求规格说明书 ② 架构设计文档 ③ 数据库设计文档 ④ 模块详细功能与工作流设计 ⑤ 接口文档 ⑥ UI/UX 设计规范 ⑦ 测试用例文档 ⑧ 性能测试报告 ⑨ 安全评估报告 ⑩ 部署运维手册 ⑪ 用户操作手册 ⑫ 系统管理员手册。

### 1.3 校验方法

| 维度 | 方法 |
|---|---|
| 完整性 | 文件枚举 + 行数统计 + 26 模块关键词覆盖扫描 + 章节模板抽样 |
| 一致性 | 命名体系/域名/API 前缀/表前缀/错误码域 全文正则比对 + 术语统计 + 跨目录污染扫描 |
| 可实施性 | 技术栈成熟度核对 + 接口契约完整性 + Flyway 迁移规范 + 部署方案 + 等保三级映射 + 性能基线 |

### 3.2 英文产品名一致性

`Fenglin Cloud CRM / Collaborate / Talent / Finance / DevOps / Service / Legal / Intelligence / Hub` 均在对应文档集中出现。源清单中域F的 `**Fenglin Cloud Service` 星号为排版符号，全套文档统一使用正确写法 `Fenglin Cloud Service`（仅基线规范第 2.1 节保留一处对该排版符号的澄清说明）。

### 3.3 管理端/用户端分离（双端术语）

全文统计"管理端/用户端"术语使用量，9 个产品均同时具备两端的完整表述，符合基线 1.3 节双端分离要求：

| 产品 | 管理端 | 用户端 | 产品 | 管理端 | 用户端 |
|---|---|---|---|---|---|
| 丰麟云枢 | 175 | 93 | 丰麟云服 | 165 | 169 |
| 丰麟云销 | 150 | 198 | 丰麟云法 | 131 | 118 |
| 丰麟云协 | 121 | 103 | 丰麟云智 | 83 | 68 |
| 丰麟云才 | 180 | 106 | 丰麟云研 | 128 | 184 |
| 丰麟云财 | 146 | 85 | — | — | — |

路由前缀亦双端分离（`/app/{域}` 面向用户端、`/admin/{域}` 面向管理端），且 11/12 号手册分别面向用户端与管理端。

### 3.4 技术栈一致性

所有产品文档均遵循基线第 3 章统一技术栈（Java 17 / Spring Boot 3.2 / Spring Cloud Alibaba / Nacos / Gateway / Sentinel / MyBatis-Plus / PostgreSQL 15 / Flyway / Redis / Kafka / Elasticsearch / MinIO / Flowable / Vue 3 + TS + Vite），未出现异构框架选型。

### 3.5 云智双模式一致性

丰麟云智全套文档贯穿 `standalone`（独立产品模式）与 `embedded`（能力嵌入模式）：需求含双模式需求；架构含双模式部署视图；接口含 `/internal/**` 能力契约；部署手册含 `intelligence.mode` 配置；用户/管理员手册说明双模式能力差异。其余 7 款产品在集成章节以能力调用方式引用云智中台能力，口径一致。

## 6. 遗留与建议

1. **契约机器化校验**：建议引入 OpenAPI lint 与文档-契约比对流水线，避免接口文档与代码契约漂移。
2. **错误码集中治理**：建议建立平台级错误码字典（单一数据源），各产品文档从字典生成，避免跨文档口径不一。
3. **实测数据回填**：性能测试报告与安全评估报告在投产前完成真实压测与等保三级测评，回填实测数据。
4. **截图与原型**：将各手册"截图位"替换为真实系统截图或高保真原型。
5. **模块级文档细化**：当前模块详细设计按产品聚合呈现；开发阶段可进一步拆分为每模块独立文档以适配敏捷迭代。
6. **跨产品一致性复核**：本次已完成自动化命名/术语/模块覆盖校验；建议在文档变更后重跑该校验脚本作为准入门禁。
