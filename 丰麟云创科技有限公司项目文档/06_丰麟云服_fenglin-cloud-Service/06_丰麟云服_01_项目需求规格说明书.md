## 1 引言

### 1.1 目的

本文档定义**丰麟云服（Fenglin Cloud Service）**的产品需求基线，是丰麟云创科技有限公司面向中大型企业客户交付"员工服务与自动化运营平台"的需求依据。本文档用于：

1. 明确 F1–F3 三大业务模块的功能与非功能需求边界；
2. 作为架构设计、数据库设计、接口设计、UI/UX 设计、测试与验收的上游输入；
3. 作为与客户、平台架构组（FL-HUB-STD-001 归口）之间需求确认与变更控制的基线文件。

品牌口号：**服务员工，自动化流程，释放运营效率**。

## 2 产品概述

### 2.1 产品定位

丰麟云服是丰麟云枢平台域F的核心产品，面向中大型企业的 IT/行政/共享服务中心与运营团队，构建"**员工自助 → 服务受理 → SLA 保障 → 知识沉淀 → 低代码快速交付 → 自动化/RPA 替代重复劳动**"的端到端闭环，实现"服务员工、自动化流程、释放运营效率"。

核心价值主张：

1. **服务可及**：F1 提供统一服务台、服务目录与自助服务，员工一次提单、全程可视；
2. **时效可控**：SLA 策略 + 计时 + 违约预警，服务时效量化为可考核指标；
3. **应用可造**：F2 以低代码/零代码让业务人员自助搭建表单、流程与页面，降低交付周期；
4. **流程可挖**：F3 以流程挖掘发现瓶颈、以 RPA 消除重复操作，形成"发现—优化—自动化"闭环；
5. **能力复用**：低代码引擎由中台 `fenglin-lowcode-service` 统一提供，云服通过能力契约调用，避免重复建设。

### 2.2 用户角色

角色基线继承 FL-HUB-STD-001 第 7.3 节，并结合本品业务细化：

|---|---|---|---|

| 平台运维 | 管理端 | `platform:ops:*` | 租户/套餐/监控/灰度 |
| 租户管理员 | 管理端 | `tenant:*` | 本租户配置、组织、角色、权限 |
| 服务运营管理员 | 管理端 | `tenant:service:*` | 服务目录、SLA 策略、知识库、机器人、低代码治理配置 |
| 服务台受理员 | 用户端 | `service:ticket:accept`、`service:ticket:assign` | 工单受理、分派、升级 |

### 2.3 双端分离

严格遵循 FL-HUB-STD-001 第 1.3 节：

| 维度 | 管理端（`/admin/service`） | 用户端（`/app/service`） |
|---|---|---|
| 使用主体 | 平台运维、租户管理员、服务运营管理员、应用审批人 | 员工、服务台受理员、工程师、知识库编辑、应用搭建者、RPA 开发 |
| 归口能力 | 配置、授权、审核、报表定义、租户治理、SLA/目录/机器人策略配置、应用发布审批、监控审计 | 日常业务操作：自助提单、受理处理、知识撰写、应用搭建、机器人运维、挖掘分析 |
| 前端工程 | `fenglin-hub-admin-ui`（`/admin/service`） | `fenglin-hub-portal-ui`（`/app/service`） |
| 组件库 | Element Plus | 自研 Portal 组件（同 Token 体系） |
| 默认首页 | 运营概览/待办/审批/监控 | 我的工作台/待办/消息/快捷入口 |
| 端别声明 | `X-Client-Type: ADMIN` | `X-Client-Type: PORTAL` |

> 说明：**低代码应用设计器**（表单/流程/页面/数据模型设计）与 **RPA 编排** 属于"日常业务操作与生产"，归**用户端**；**应用发布审批、租户级策略（SLA/目录/机器人配额/脚本沙箱策略）配置**归**管理端**。

## 3 业务需求（模块级功能需求）

> 编号规则：`{模块码}-FR-{3位序号}`。优先级：P0（必须）、P1（重要）、P2（一般）。

### 3.1 F1 员工服务与 IT 支持

模块定位：覆盖工单受理、服务目录、SLA、知识库、自助服务台等 ITSM 全流程（参考标杆：EasyVista）。

| 编号 | 需求名称 | 优先级 | 需求描述 | 端别 | 关键权限码 |
|---|---|---|---|---|---|
| F1-FR-001 | 多渠道提单 | P0 | 支持用户端自助提单、服务目录申请、邮件转工单、服务台代客提单、开放 API 提单、RPA/自动化触发提单；统一生成工单编号 `SVC{yyyyMM}{6位}`。 | 用户端 | `service:ticket:create` |
| F1-FR-002 | 服务目录与目录项 | P0 | 管理端维护多级服务目录与目录项（名称、分类、图标、申请表单、默认处理组、默认 SLA、审批要求、可见范围）；目录项可绑定低代码表单（F2 能力契约）。 | 管理端 + 用户端 | `tenant:service:catalog:config`、`service:catalog:apply` |
| F1-FR-003 | 工单分类与自动分派 | P0 | 基于服务目录项、工单类型（事件/请求/问题/变更）、影响范围、来源渠道路由到处理组/工程师；支持轮询、负载、技能组、指定、值班表五种分派策略；AI 智能分类推荐（`fenglin-ai-service`）。 | 用户端 | `service:ticket:assign` |
| F1-FR-004 | 工单流转与协同 | P0 | 工单支持分派、转派、协办、挂起（等待用户/等待第三方）、恢复、升级、解决、关闭、重开；全过程写流转日志（前后状态、操作人、时间、原因）。 | 用户端 | `service:ticket:handle` |
| F1-FR-005 | SLA 策略与计时 | P0 | 管理端定义 SLA 策略（适用目录项/优先级/服务时间日历），配置响应时限与解决时限；工单创建后启动 SLA 计时（区分工作时段/自然时段），暂停/恢复规则与挂起状态联动；临期预警与违约判定。 | 管理端 + 系统 | `tenant:service:sla:config` |
| F1-FR-006 | SLA 违约与升级 | P0 | 响应/解决违约自动触发升级（通知上级、变更优先级、转派）；记录违约原因与责任；输出 SLA 达成率报表。 | 系统 + 用户端 | `service:sla:view` |
| F1-FR-007 | 知识库与知识沉淀 | P0 | 知识文章分类、版本、审核、发布、可见范围；工单解决时一键沉淀为知识或关联知识；支持全文检索（`fenglin-search-service` + IK）；文章浏览/有用性反馈统计。 | 用户端 | `service:kb:edit`、`service:kb:view` |
| F1-FR-008 | 自助服务台 | P0 | 员工查看我的工单、进度、历史；按目录申请服务；检索知识库自助解决（推荐 Top 知识，命中率达标则不建单）；满意度评价。 | 用户端 | `biz:service:self:view` |
| F1-FR-009 | 满意度评价（CSAT） | P0 | 工单关闭后自动发放满意度评价（1–5 星 + 标签 + 留言），回收率与均分统计；低分自动触发回访任务。 | 用户端 + 系统 | `service:csat:submit`、`service:csat:view` |
| F1-FR-010 | 问题与变更管理 | P1 | 支持将重复工单聚合为"问题"，问题根因分析与已知错误库；变更请求（上线/配置变更）走审批流（Flowable）与回滚预案登记。 | 用户端 | `service:problem:manage`、`service:change:manage` |
| F1-FR-011 | IT 资产关联 | P1 | 工单可关联资产（设备/软件/账号），支持资产借用、领用、归还与到期提醒；资产信息复用（与云财 D3 资产能力对接，接口方式）。 | 用户端 | `service:asset:view` |
| F1-FR-012 | 服务报表与看板 | P1 | 工单量趋势、SLA 达成率、工程师工作量、满意度、目录项热度、知识命中率多维看板。 | 用户端 + 管理端 | `service:report:view` |
| F1-FR-013 | 服务台与 SLA 配置 | P1 | 管理端配置工单类型、优先级字典、处理组、值班表、SLA 策略、自动分派规则、升级矩阵、满意度问卷模板。 | 管理端 | `tenant:service:desk:config` |

**F1 验收要点**：多渠道提单 100% 生成可追溯工单；SLA 计时准确（含工作时段计算与暂停恢复）；自动分派规则按配置命中；SLA 达成率口径可解释；知识库检索命中与满意度可统计。

### 3.2 F2 低代码/零代码

模块定位：让业务人员通过可视化配置快速构建表单、流程、数据模型与页面并发布应用（参考标杆：轻流）。**引擎复用中台 `fenglin-lowcode-service`，本品通过能力契约调用。**

| 编号 | 需求名称 | 优先级 | 需求描述 | 端别 | 关键权限码 |
|---|---|---|---|---|---|
| F2-FR-001 | 应用定义与生命周期 | P0 | 创建/复制/归档低代码应用，设置名称、图标、描述、负责人、可见范围、运行环境（草稿/预发/生产）；应用清单支持分组与检索。 | 用户端 | `service:lowcode:app:create` |
| F2-FR-002 | 表单设计器 | P0 | 可视化拖拽设计表单：布局组件、基础字段（文本/数字/日期/下拉/单选多选/附件/人员/部门/关联数据）、校验规则、联动显隐、计算公式、默认值、权限（字段级可编辑/只读/隐藏）；支持表单版本与模板。 | 用户端 | `service:lowcode:form:design` |
| F2-FR-003 | 流程设计器 | P0 | 可视化设计 BPMN 流程：开始/结束、审批节点（会签/或签/依次）、条件网关、并行网关、抄送、服务任务（调用 API/Webhook/脚本）、定时边界事件、超时提醒；节点配置处理人（发起人/角色/部门/指定人/表单人员字段）。 | 用户端 | `service:lowcode:flow:design` |
| F2-FR-004 | 数据模型设计 | P0 | 可视化定义数据模型（实体、字段、类型、约束、索引、关联关系 1:1/1:N/N:N）；模型与表单字段映射；支持内置字段与计算字段；模型变更走"差异预览 + 兼容性校验"。 | 用户端 | `service:lowcode:model:design` |

### 5.2 数据需求要点

1. **多租户**：所有业务表含 `tenant_id` 并启用 RLS；跨租户访问仅平台运营端并强制审计。
2. **公共字段**：`id/tenant_id/created_by/created_at/updated_by/updated_at/deleted/version` 强制存在。
3. **敏感数据**：员工手机号、机器人凭据等采用 AES-256-GCM 加密，配套 `{field}_hash`（SHA-256+租户盐）用于唯一性与检索，禁止明文列唯一索引。
4. **编码规则**：工单编号 `SVC{yyyyMM}{6位}`（如 `SVC202610000123`）；应用编码 `{租户码}-APP-{4位}`；机器人任务号 `RT{yyyyMMdd}{6位}`。
5. **迁移**：全部 DDL/DML 通过 Flyway 脚本（`V1_0_x__*.sql`）提交，禁止手工改库。
6. **大表**：`svc_mining_event_log`、`svc_robot_task_log`、`svc_ticket_flow_log` 按 `tenant_id` + 时间做声明式分区，ES 承担检索分流。

## 6 接口需求

1. 全部接口遵循 `/api/service/v1` 前缀、RESTful 风格、统一响应体（`code/message/data/requestId/timestamp`）。
2. 统一请求头：`Authorization`、`X-Tenant-Id`、`X-Client-Type`（ADMIN/PORTAL）、`X-Request-Id`、`Idempotency-Key`（写操作）。
3. 错误码域前缀 `60`，结构 `{域2}{模块2}{序号3}`：
   - 通用/校验：`6000001`–`6000999`
   - F1 工单/服务台：`6001xxx`；F1 SLA/目录：`6002xxx`；F1 知识库/满意度：`6003xxx`
   - F2 应用/表单：`6004xxx`；F2 流程/数据模型：`6005xxx`
   - F3 流程挖掘：`6006xxx`；F3 机器人调度：`6007xxx`；自动化编排：`6008xxx`
   - 开放 API/集成：`6009xxx`
4. 分页：`page`（从 1 起）、`size`（默认 20，最大 200）。
5. **低代码引擎能力契约**：本品调用中台 `fenglin-lowcode-service` 的能力接口（应用/表单/流程/数据模型/页面/运行时），契约章节在《接口文档》第 5 章，内部走 mTLS。
6. **RPA 调度回调**：机器人执行端通过回调接口回报任务状态（开始/进度/成功/失败/取消），支持幂等与重放保护。
7. 需提供 OpenAPI 3.1 契约与开放 API（前缀 `/openapi/service/v1`）与事件 Webhook（工单、流程、任务、SLA 事件）。
8. 核心接口清单详见 FL-SVC-API-005《接口文档》。

## 7 约束与假设

### 7.1 约束

1. 必须遵循 FL-HUB-STD-001 的命名体系、技术栈、接口/数据/权限/安全/UI 规范；
2. 必须严格实现管理端（`/admin/service`）与用户端（`/app/service`）分离；
3. 低代码/零代码引擎**必须**复用中台 `fenglin-lowcode-service`，不得在云服内重复建设引擎内核；
4. 工作流引擎复用 `fenglin-workflow-service`（Flowable 7.x）；AI 分类/推荐复用 `fenglin-ai-service`；
5. 后端统一技术栈：Java 17 / Spring Boot 3.2.x / Spring Cloud 2023.0.x / MyBatis-Plus 3.5.x / PostgreSQL 15 / Redis 7 / Kafka 3.6 / Flowable 7；
6. 前端统一 Vue 3.4 + TypeScript + Vite 5；管理端 Element Plus，用户端自研 Portal 组件；
7. 不得引入异构框架，确需引入须报平台架构组评审。

### 7.2 假设

1. 丰麟云枢中台（IAM/租户/消息/文件/审计/搜索/AI/报表/低代码/工作流）可用并按契约提供能力；
2. 低代码引擎提供稳定的表单渲染、流程执行、数据模型存储、页面运行时能力，并支持版本快照与回滚；
3. RPA 机器人执行端由本产品提供客户端（Windows）或在容器化环境中运行，受调度服务统一管控；
4. 事件日志来源系统（工单/低代码/外部系统）可提供符合规范的日志字段；
5. 员工具备必要的浏览器与网络环境，机器人执行端具备相应系统访问权限。
