### 1.4 业务规则

1. **优先级矩阵**：`priority = f(impact, urgency)`。影响=高且紧急=高 → P1；一般组合依次落到 P2/P3/P4，可在管理端调整矩阵。
2. **自动分派优先级**：指定处理人 > 目录项默认处理组 > 技能组匹配（按工单分类/标签）> 值班表（当前值班）> 负载均衡（进行中工单最少）> 轮询；全部不命中则落入兜底组并告警。
3. **SLA 计时规则**：计时按 `calendar_id` 指定的服务时间日历进行（仅计入服务工作时段）；工单进入 `PENDING`（挂起）时暂停计时，`RESUME` 后继续；计时状态与 `svc_sla_timer` 一致。
4. **SLA 临期预警**：已用时长达到时限 `warning_threshold`（默认 80%）触发临期预警；达到 100% 判定违约。
5. **SLA 违约升级**：违约后按 `escalation_matrix` 依层级升级（通知上级 → 变更优先级 → 转派主管），记录 `svc_sla_breach.escalated_level`。
6. **知识自助先导**：提交工单前按标题/描述检索知识库，命中高相关内容时提示"先自助解决"，用户仍可继续提单；命中率纳入知识统计（不强制阻断）。
7. **关单与评价**：工单 `RESOLVED` 后 24 小时无异议自动 `CLOSED`；关单后自动发放满意度评价；评分为 1–2 星自动生成回访任务。
8. **重开规则**：`CLOSED` 后 7 天内用户可重开（`reopen_count` +1，重新计入 SLA 或按配置新建关联工单）；超期重开视为新工单。
9. **目录项审批**：目录项 `need_approval=true` 时，提单后先生成审批（`approval_flow_key` 对应 workflow），审批通过才进入分派。
10. **变更与问题联动**：重复工单可一键聚合为问题；变更完成后自动回写关联工单并通知提单人。

### 1.5 状态机

**工单状态机（核心）**

```
[NEW] --自动分派/受理--▶ [ASSIGNED]
[ASSIGNED] --开始处理--▶ [IN_PROGRESS]
[IN_PROGRESS] --等待用户/第三方(挂起)--▶ [PENDING]
[PENDING] --恢复--▶ [IN_PROGRESS]
[IN_PROGRESS/ASSIGNED] --SLA违约升级--▶ [ESCALATED]
[ESCALATED] --处理完成--▶ [RESOLVED]
[IN_PROGRESS] --处理完成--▶ [RESOLVED]
[RESOLVED] --用户确认/24h自动--▶ [CLOSED]（终态）
[RESOLVED] --用户不通过--▶ [IN_PROGRESS]
[CLOSED] --7天内重开--▶ [REOPENED] --受理--▶ [IN_PROGRESS]
[NEW/ASSIGNED/PENDING] --用户撤销--▶ [CANCELLED]（终态）
```

**SLA 计时状态机**

```
[RUNNING] --命中暂停状态(PENDING)--▶ [PAUSED]
[PAUSED] --恢复--▶ [RUNNING]
[RUNNING] --在时限内完成--▶ [MET]（终态）
[RUNNING] --超过时限--▶ [BREACHED]（终态，生成 svc_sla_breach）
```

**服务目录项状态机**

```
[DRAFT] --启用--▶ [ACTIVE] --停用--▶ [DISABLED] --启用--▶ [ACTIVE]
```

### 1.6 工作流（BPMN 说明）

**工单派单与升级流程 `svcTicketDispatchEscalation`**

- 起点（Start Event）→ 服务任务 `autoClassify`（AI 分类/优先级计算）；
- 服务任务 `createTicket`（生成工单号、写库、创建 SLA 计时）→ 服务任务 `dispatch`（分派策略引擎）；
- 排他网关 `gwDispatch`：
  - 命中处理人 → 服务任务 `notifyAssignee` → 用户任务 `handleTicket`；
  - 全部未命中 → 服务任务 `assignFallbackGroup` + 告警 → 用户任务 `handleTicket`；
- 边界定时事件 `slaTimer`（非中断）监听 `svc_sla_timer`：达到 80% → 服务任务 `warn`；达到 100% → 触发中断边界事件 `escalate`；
- `escalate` → 服务任务 `applyEscalationMatrix`（升级矩阵）→ 若层级 < 上限，回到 `handleTicket`；否则 → 服务任务 `alertManager`；
- `handleTicket` 完成 → 服务任务 `resolveTicket` → 用户任务 `userConfirm`（用户确认）；
- `userConfirm` 通过 → 服务任务 `closeTicket` + `sendCsat` → 结束；不通过 → 回 `handleTicket`。

**BPMN 关键元素**：`StartEvent / EndEvent / ServiceTask(svcDelegate) / UserTask / ExclusiveGateway / BoundaryTimerEvent(interrupting) / BoundaryTimerEvent(non-interrupting)`；服务任务通过 `JavaDelegate` 调用领域服务。

**目录项审批流程 `svcCatalogItemApproval`（目录项 need_approval=true）**

- 起点 → 用户任务 `managerApprove`（目录项配置的审批人/角色）→ 排他网关：
  - 通过 → 服务任务 `createTicket` → 进入派单；
  - 驳回 → 服务任务 `notifyRequester` → 结束（工单状态 `CANCELLED`）。

### 1.7 异常与边界

| 场景 | 处理 |
|---|---|
| 提单时处理组无人在岗 | 落兜底组 + 告警服务运营管理员；不影响提单成功 |
| SLA 计时服务不可用 | 计时以"上次 tick + 增量"补偿重算；重算日志留痕，不丢计时 |
| 工单并发修改（多人同时操作） | `version` 乐观锁，冲突返回 `6001005`（状态冲突），前端提示刷新 |
| 邮件转单解析失败 | 落"待受理"队列并标注解析异常，人工补全后转正式工单 |
| 关闭后评价重复提交 | 唯一约束 `uk_csat_ticket` 拦截，返回 `6003002`（重复评价） |
| 资产关联对象已退役 | 允许关联但标记"已退役"，不阻断关闭 |
| 值班表跨时区 | 统一 UTC 存储，按租户时区展示与计算值班 |

### 1.8 验收标准

1. 五类来源提单均可生成唯一年工单且可追溯；
2. 分派规则命中率 ≥ 99%，未命中 100% 落兜底并告警；
3. SLA 计时（工作时段/暂停恢复）与人工核算误差 ≤ 1 分钟；
4. 违约 100% 触发升级且升级层级正确；
5. 知识检索 Top 知识相关率 ≥ 85%；满意度回收率 ≥ 40%。

### 2.4 业务规则

1. **引擎复用**：所有表单/流程/模型/页面的**渲染与执行**由中台 `fenglin-lowcode-service` 提供；本品仅存定义元数据（`schema_json`、`engine_ref`）与治理信息，通过能力契约调用。
2. **版本机制**：表单/流程/模型/页面各自带 `version_no`；应用发布生成 `svc_app_release.snapshot_json`（记录各定义版本），快照不可变。
3. **兼容性校验**：数据模型变更（改字段类型/删除字段）前做"差异预览 + 兼容性校验"，破坏性变更（如删除已用字段）需确认并影响面提示；发布前校验表单/流程/模型/页面引用完整性。
4. **发布审批**：`DRAFT → PRE` 由应用负责人执行（无需审批）；`PRE → PROD` 需管理端审批人审批（合规与脚本风险校验）；审批拒绝返回 `6004002`。
5. **灰度与回滚**：生产发布支持按用户/部门灰度；回滚即把运行环境切回上一 `release` 快照，回滚成功率要求 100%。
6. **脚本沙箱**：脚本（服务任务、计算字段）在独立沙箱执行——禁网络/文件系统，超时 3s，内存上限 64MB，仅允许白名单 API；脚本提交时做静态扫描（危险函数、外链），风险等级 `HIGH` 阻断发布。
7. **权限模型**：应用级（谁可进入）、页面级（谁可见页面）、字段级（可编辑/只读/隐藏）、数据级（本人/本部门/本部门及下级/自定义/全部）；运行时权限由本品注入上下文后交引擎执行。
8. **表单联动与计算**：支持字段联动显隐（条件表达式）与计算公式（受限表达式引擎，非任意脚本）；计算字段在保存时重算。
9. **流程处理人**：节点处理人支持发起人、角色、部门（含上级）、指定人、表单人员字段、表达式；会签/或签/依次审批可配。
10. **运行时数据归属**：低代码运行数据（表单记录、流程实例数据）由中台引擎存储，本品通过 `business_key` 关联业务（如把表单记录关联到工单 `svc_ticket.engine_ref`）。

### 2.6 工作流（BPMN 说明）

**低代码应用发布审批流程 `svcLowcodeAppReleaseApproval`**

- 起点（Start Event）→ 服务任务 `validateBundle`（引用完整性 + 兼容性校验 + 脚本扫描）；
- 排他网关 `gwRisk`：
  - 脚本风险 `LOW` 且无破坏性变更 → 用户任务 `autoApprove`（应用负责人确认）→ `deployProd`；
  - 脚本风险 `MEDIUM/HIGH` 或含破坏性变更 → 用户任务 `adminApprove`（管理端审批人）；
- `adminApprove` → 排他网关 `gwApprove`：通过 → 服务任务 `snapshotAndDeploy`（调 lowcode 发布生产 + 写 `svc_app_release`）；拒绝 → 服务任务 `notifyReject` → 结束；
- `deployProd` → 服务任务 `enableGray`（可选灰度）→ 服务任务 `notifyUsers` → 结束。

**运行时低代码流程（示例：设备申请）**：由中台 `fenglin-workflow-service` 承载发布后的 BPMN；本品负责发起时注入租户/权限上下文，并在关键节点回写业务（如完成后自动关闭关联工单）。

### 2.7 异常与边界

| 场景 | 处理 |
|---|---|
| 引擎能力契约调用超时 | 重试 2 次（幂等），仍失败返回 `6004001`（引擎不可用）并降级为"设计态可保存、运行时暂不可用" |
| 发布时删除被流程引用的字段 | 兼容性校验拦截，返回 `6004003`（破坏性变更），提示影响面 |
| 脚本尝试网络/文件访问 | 沙箱拦截 → 记录安全事件 → 发布阻断（`6004004`） |
| 灰度期间回滚 | 立即切回上一快照并通知灰度用户 |
| 运行时并发提交 | `engine` 幂等键 + `version` 校验，冲突返回 `6005002` |
| 应用被冻结后运行时请求 | 返回 `6004005`（应用已冻结），前端提示联系管理员 |

### 2.8 验收标准

1. 四类设计器均可完成定义、保存版本、预览；
2. 生产发布 100% 走审批，快照可回滚且回滚成功率 100%；
3. 脚本沙箱对网络/文件/超时越权 100% 拦截并告警；
4. 运行时权限（应用/页面/字段/数据）按配置生效，越权 100% 拒绝；
5. 数据模型破坏性变更 100% 被兼容性校验拦截。

### 3.4 业务规则

1. **事件日志规范**：每条日志含 `case_id/activity/event_time/resource/source_system`；来源 `TICKET/FLOW/EXTERNAL/RPA`；实时接入经 Kafka `topic: svc.process.event`（幂等去重键 = `case_id+activity+event_time+resource`）。
2. **模型发现算法**：默认 α-algorithm 变体生成 DFG 与 Petri 网；≥ 2 个用例的活动为强边，< 阈值标注噪声；路径频次与耗时（平均/中位/P95）在图上着色。
3. **一致性率**：`一致性率 = 完全符合设计路径的用例数 / 总用例数`；偏差分类：跳步（Skip）、返工（Rework）、绕过审批（Bypass）、额外活动（Extra）。
4. **瓶颈判定**：活动 P95 耗时或平均等待时间超过全局分位阈值（默认 P90）判为瓶颈；同时输出资源负荷（活动分布到资源）。
5. **自动化候选**：规则 = 高重复度（频次前 20%）∧ 规则性强（分支数少）∧ 人工耗时高；候选可一键生成 `svc_automation_flow` 草稿（`source_candidate_id`）。
6. **调度分配**：按 `robot_selector` 选择满足能力标签、`status=ONLINE`、未达 `max_concurrency` 的机器人；同优先级按创建时间 FIFO；分配失败进入 `QUEUED` 等待并告警。
7. **重试策略**：默认最大 3 次、指数退避 `2^n × 30s`（30s/60s/120s）；超过阈值置 `MANUAL_REQUIRED` 并告警；业务类不可重试错误（如数据校验失败）直接 `FAILED`。
8. **凭据使用**：机器人执行前以任务一次性令牌换取凭据明文（TTL ≤ 60s），使用后立即从内存清除；换取与使用全审计，日志脱敏。
9. **越权防护**：每个自动化编排声明 `target_whitelist`（可访问系统/操作）；调度与执行前校验白名单，越界拒绝返回 `6008002` 并告警。
10. **任务幂等**：`idempotency_key` 保证同一业务不重复执行（如"同一工单同一动作"）；重试遵循幂等，避免重复副作用。

### 3.6 工作流（BPMN 说明）

**RPA 任务编排与执行编排 `svcRpaTaskOrchestration`**

> 说明：RPA 任务编排是**可执行的分支流程**（由引擎 BPMN + 执行端协同），而非审批流；下列给出 BPMN 结构说明。

- 起点（Start Event）→ 服务任务 `resolveTrigger`（定时/事件/手动/队列）→ 服务任务 `buildTask`（生成 `svc_robot_task`、写幂等键）；
- 服务任务 `selectRobot` → 排他网关 `gwRobot`：
  - 有可用机器人 → 服务任务 `dispatchTask`（状态 `DISPATCHED`，发 Kafka）→ 边界定时事件 `execTimeout` 监听执行端；
  - 无可用机器人 → 服务任务 `enqueueAndAlert` → 定时重试 `selectRobot`；
- 收到执行端回调 `POST /rpa/tasks/{id}/callback`：
  - `SUCCEEDED` → 服务任务 `persistOutput` → 服务任务 `emitEvent`（回流事件日志）→ 结束；
  - `FAILED` → 排他网关 `gwRetry`：可重试 → 服务任务 `scheduleRetry`（指数退避，置 `RETRYING`）→ 回到 `selectRobot`；不可重试/超上限 → 服务任务 `manualRequired` + 告警 → 结束；
- 边界定时事件 `execTimeout` 触发 → 与 `FAILED` 同路径处理。

**BPMN 关键元素**：`StartEvent / ServiceTask / ExclusiveGateway / BoundaryTimerEvent(execTimeout) / IntermediateCatchEvent(callback) / EndEvent`；执行端为外部任务（External Task/回调模式）。

**挖掘—自动化闭环流程 `svcMiningToAutomation`（编排级）**

- 起点 → 服务任务 `runMining`（批处理/手动）→ 服务任务 `detectCandidates` → 用户任务 `analystReview`（分析师确认候选）→ 服务任务 `generateFlowDraft`（生成 `svc_automation_flow` 草稿）→ 用户任务 `rpaDevDesign`（RPA 开发完善）→ 服务任务 `publishFlow`（治理审批后发布）→ 结束；发布后执行产生的新事件回流 `svc_mining_event_log`，形成闭环。

### 3.7 异常与边界

| 场景 | 处理 |
|---|---|
| 机器人执行中超时 | 触发 `execTimeout`，按失败路径重试或转人工，截图与日志保留 |
| 执行端崩溃/断连 | 心跳超时置 `OFFLINE`；`RUNNING` 任务由调度在 `N` 分钟后按幂等重投 |
| 回调重复/乱序 | 回调幂等（按 `task_id+attempt+status` 去重），旧状态不覆盖新状态 |
| 事件日志字段缺失 | 丢弃并计入 `ingest_error` 指标，不阻断其他日志；周期性告警 |
| 凭据换取失败/过期 | 任务置 `FAILED`（不可重试），告警 RPA 运维；凭据轮换提示 |
| 白名单外系统访问 | 拒绝执行，任务 `FAILED`，安全告警 `6008002` |
| 大规模批调度 | 分批下发（每批 ≤ 500），限流避免打爆执行端与目标系统 |
| 挖掘事件量过大 | 增量计算 + 采样；超阈值仅统计聚合不渲染全图 |

### 3.8 验收标准

1. 事件日志导入后模型发现与活动耗时统计与人工核算一致（误差 ≤ 1%）；
2. 一致性率与偏差分类可复算，偏差可定位到具体 `case_id`；
3. 失败任务 100% 按策略重试且可追溯，超阈值 100% 转人工并告警；
4. 凭据全程密文存储与传输，日志 0 明文，换取操作 100% 审计；
5. 白名单外访问 100% 被拒并告警；单批 500 任务下发 ≤ 10s。

### 3.9 与标杆产品（来也科技 UiBot）差异点

| 维度 | 标杆 | 本品差异 |
|---|---|---|
| 挖掘与 RPA | 组合但偏工具 | **挖掘—候选—编排—执行—回流**原生闭环，与 F1/F2 数据直接打通 |
| 业务上下文 | 通用自动化 | 与 **ITSM 工单、低代码流程**同源事件日志，无需额外埋点 |
| 安全合规 | 凭据管理 | **KMS 密文 + 一次性临时令牌 + 白名单 + 越权告警**，对齐等保三级 |

| 调度 | 集中调度 | **K8s 执行端弹性 + 心跳 + 幂等重投**，适配 3400 人规模峰值 |
