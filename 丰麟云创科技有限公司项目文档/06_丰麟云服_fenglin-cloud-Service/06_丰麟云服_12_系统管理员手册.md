## 1 管理端总览

### 1.1 管理端定位

管理端（`/admin/service`，`fenglin-hub-admin-ui` + Element Plus）承载 **配置、授权、审核、治理、报表定义、租户治理** 能力，与用户端（`/app/service`）严格分离。管理端接口位于 `/api/service/v1/admin/**`，仅 `ADMIN` 端别令牌可访问。

### 1.2 功能地图

```
运营概览（首页：工单/SLA/满意度/自动化核心指标）
├─ 服务台配置：工单类型与优先级 / 处理组 / 值班表 / 自动分派规则 / 服务目录 / SLA 策略与日历 / 满意度问卷
├─ 资产配置：资产到期提醒
├─ 低代码治理：应用治理清单 / 发布审批 / 数据权限配置 / 沙箱与脚本策略
├─ RPA 治理：凭据保管 / 机器人与配额 / 重试策略模板
├─ 报表中心：报表定义（工单/SLA/满意度/工作量/自动化效能）
└─ 系统设置：参数与字典 / 权限与数据权限 / 审计日志
```

### 1.3 登录与安全基线

| 项 | 说明 |
|---|---|
| 登录 | 管理端账号 + MFA；支持 SSO；连续 5 次失败锁定 15 分钟 |
| 会话 | 空闲 30 分钟超时；高风险操作（凭据配置、发布审批、跨租户查看、批量导出）二次验证 |
| 端别 | 管理端令牌 `client_type=ADMIN`，与用户端令牌不可混用 |
| 审计 | 管理端全部配置与授权变更强制审计（哈希链 + WORM，留存 12 个月） |

### 1.4 角色职责

| 角色 | 职责 | 权限域示例 |
|---|---|---|
| 平台超级管理员 | 平台级最高权限（运维专用、强审计） | `platform:*` |
| 平台运维 | 租户/套餐/监控/灰度 | `platform:ops:*` |
| 租户管理员 | 本租户配置、组织、角色、权限、RPA 凭据与配额 | `tenant:*`、`tenant:service:rpa:credential:config` |
| 服务运营管理员 | 服务台/SLA/目录/满意度配置、报表定义 | `tenant:service:*` |
| 应用审批人 | 低代码应用发布审批、治理、数据权限 | `tenant:service:app:approve`、`tenant:service:app:govern` |

## 2 租户/组织/用户/角色

### 2.1 租户管理（平台侧）

1. 进入平台租户管理，可新建/停用租户、配置套餐与配额（机器人数量、应用数量、事件日志量）；
2. 新建租户后系统初始化：默认工单类型与优先级、兜底处理组、SLA 模板、满意度问卷模板、脚本沙箱策略、默认重试策略；
3. 租户隔离：业务数据通过 `tenant_id` + RLS 隔离，跨租户访问默认拒绝；平台运营跨租户查看需二次确认并记审计。

【截图位：租户列表与租户初始化】

### 2.2 组织与用户（租户侧）

1. **组织架构**：维护多层级部门（编码层级点分，如 `1.2.3`），支持部门负责人设置；
2. **用户管理**：由统一 IAM 提供，支持按组织/岗位查询、停用/启用、离职联动账号回收；
3. **岗位**：定义岗位与默认角色映射，新员工入职自动赋权；
4. 组织或人员变更后，数据权限（DEPT/DEPT_AND_CHILD）与工单分派（值班表/技能组）自动按最新组织树生效。

### 2.3 角色管理

1. 角色 = 功能权限码集合 + 数据权限范围 + 字段权限；支持继承与复制；
2. 云服预置角色：服务台受理员、IT 支持工程师、知识库编辑、应用搭建者、应用审批人、RPA 开发/运维、流程分析师、员工、只读；
3. 角色变更后对在线用户即时生效（令牌权限码以服务端实时校验为准）；
4. 关键角色遵循职责分离：申请人 ≠ 审批人；发布设计者 ≠ 发布审批人；编排设计者 ≠ 自动化治理责任人。

## 3 权限与数据权限配置

### 3.1 功能权限（节选）

| 权限码示例 | 说明 |
|---|---|
| `service:ticket:create/view/accept/assign/handle/escalate/close` | 工单全流程 |
| `service:catalog:apply/view`、`biz:service:self:view` | 目录与自助 |
| `service:sla:view/manage` | SLA |
| `service:kb:view/edit/publish/suggest`、`service:csat:submit/view` | 知识与满意度 |
| `service:problem:manage`、`service:change:manage`、`service:asset:view/manage` | 问题/变更/资产 |
| `service:lowcode:app:create`、`form:design`、`flow:design`、`model:design`、`page:design`、`script:edit`、`app:publish`、`app:perm:config`、`runtime:use`、`template:use` | 低代码 |
| `service:mining:log:ingest`、`view`、`model:create`、`conformance:view`、`analyze`、`to:automation` | 流程挖掘 |
| `service:rpa:robot:manage`、`task:dispatch`、`task:manage`、`report:view`、`service:automation:flow:design` | RPA/自动化 |
| `service:report:view` | 报表 |
| `tenant:service:desk:config` / `sla:config` / `catalog:config` / `csat:config` / `app:approve` / `app:govern` / `rpa:config` / `rpa:credential:config` | 管理端配置类 |

### 3.2 数据权限

| 枚举 | 含义 | 典型角色 |
|---|---|---|
| SELF | 本人数据 | 员工、知识库编辑（本人草稿） |
| DEPT | 本部门数据 | 服务台受理员 |
| DEPT_AND_CHILD | 本部门及下级 | 主管、运营管理员 |
| CUSTOM | 指定部门/用户 | 跨团队协作场景 |
| ALL | 本租户全部 | 运营管理员、租户管理员 |

配置路径：系统设置 → 权限与数据权限 → 选择角色 → 设置数据权限范围。规则：数据权限与功能权限取交集；工单、应用、任务均按此范围过滤；越权返回 `6001004`/`0000002`。

### 3.3 字段权限与应用权限

1. 路径：「服务台配置 → 字段与权限配置」可对工单/资产的敏感字段（联系人手机号等）按角色配置为**可见 / 脱敏 / 隐藏**；
2. 查看明文需相应 PII 权限且每次查看记录审计；
3. 低代码应用支持应用级、页面级、字段级权限（用户端配置）+ 数据级权限（管理端「低代码治理 → 数据权限配置」）。

## 5 流程与审批配置

### 5.1 审批流程清单

| 流程 Key | 名称 | 节点/分支 |
|---|---|---|
| `svcCatalogItemApproval` | 目录项申请审批 | 按目录项配置审批人；通过后生成工单并分派；驳回通知申请人 |
| `svcChangeApproval` | 变更请求审批 | 按变更类型（常规/紧急/标准）与风险等级路由；通过后执行变更并回写关联工单 |
| `svcLowcodeAppReleaseApproval` | 低代码应用发布审批 | 生产发布必审；校验脚本风险/破坏性变更；通过后引擎快照发布 |
| `svcAutomationPublishApproval` | 自动化编排发布审批 | 校验白名单/参数/节点可达性；通过后编排可调度 |

### 5.2 流程配置要点

1. 流程由 `fenglin-workflow-service`（Flowable 7）统一托管，支持节点审批人配置（角色/指定人/上级）；
2. 每个用户任务配置**驳回**边界事件与**超时升级**定时边界事件（默认 48h）；
3. 回调采用幂等回调，更新业务状态并发布事件（如 `service.lowcode.app.published`、`service.rpa.task.dispatched`）；
4. 审批记录不可删改；审批人不得与申请人直接利害相关（职责分离）；
5. 关键流程变更需评审并留痕，变更前在 staging 完整回归（回归组 R4/R5/R7）。

## 6 集成与开放平台

### 6.1 中台能力集成

| 能力 | 服务 | 云服用法 |
|---|---|---|
| 身份与权限 | `fenglin-iam-service` | 账号、角色、组织、数据权限 |
| 工作流 | `fenglin-workflow-service` | 目录项/变更/应用发布/编排发布审批 |
| 低代码引擎 | `fenglin-lowcode-service` | 表单/流程/数据模型/页面/脚本（能力契约） |
| 消息 | `fenglin-message-service` | 站内信/邮件/短信/企微飞书钉钉/WebSocket/Webhook |
| 文件 | `fenglin-file-service` | 附件、截图、导入报告、导出文件 |
| 审计 | `fenglin-audit-service` | 全链路审计、哈希链、WORM |
| 搜索 | `fenglin-search-service` | 知识/工单/日志检索（ES+IK） |
| AI | `fenglin-ai-service` | 工单智能分类/知识推荐 |
| 报表 | `fenglin-report-service` | 指标中心与看板 |
| 密钥 | KMS | PII 密钥、RPA 凭据密钥 |
| 开放平台 | `fenglin-openapi-service` | 应用与密钥、配额、沙箱、Webhook 订阅 |

### 6.2 开放 API

1. 前缀 `/openapi/service/v1`，由 `fenglin-openapi-service` 统一网关承载；
2. 应用注册 → 分配 AppKey/AppSecret（HMAC-SHA256 签名）→ 申请 Scope → 配额与限流（超限返回 `6009002`，签名失败返回 `6009001`）；
3. 在线调试沙箱与 SDK（Java/JS/Python）；密钥由 KMS 托管并支持轮换；
4. 对外开放资源：创建/查询工单、查询服务目录、推送事件日志、查询/触发机器人任务；
5. 开放事件：见 6.3。

### 6.3 Webhook 订阅

1. 订阅事件 → 配置回调地址 → 验签（HMAC `eventId.timestamp.body`）+ 时间戳防重放（±300s）→ 按 `eventId` 幂等处理；
2. 失败重试策略：指数退避 10s/30s/2m/10m/1h/6h，最多 6 次；连续失败告警并暂停订阅；
3. 事件类型：`service.ticket.created`、`service.ticket.status_changed`、`service.ticket.escalated`、`service.sla.warning`、`service.sla.breached`、`service.csat.submitted`、`service.kb.published`、`service.lowcode.app.published`、`service.lowcode.app.frozen`、`service.flow.task.timeout`、`service.mining.model.ready`、`service.mining.candidate.detected`、`service.rpa.task.dispatched`、`service.rpa.task.succeeded`、`service.rpa.task.failed`、`service.rpa.task.manual_required`；
4. 回调日志可查，支持手动补发。

【截图位：开放平台应用与事件订阅】

### 6.4 RPA 凭据与执行端治理（管理端重点）

1. 「RPA 治理 → 凭据保管」：新增/编辑凭据，选择类型（密码/API Key/证书），密钥由 KMS 加密保管，界面与接口均不回显明文；配置轮换周期（≤90 天）与绑定机器人；
2. 「RPA 治理 → 机器人与配额」：配置机器人配额、单机并发上限、**目标系统白名单**（系统/域名/动作）、默认重试策略、任务日志留存；
3. 「RPA 治理 → 重试策略模板」：配置最大重试次数、退避表达式、超限动作（转人工）与**不可重试错误集**；
4. 处置要求：凭据变更、白名单变更、配额调整均需二次验证并强制审计。

## 7 监控与审计

### 7.1 运营与系统监控

| 视图 | 内容 |
|---|---|
| 运营概览 | 工单量/SLA 达成率/满意度/自动化效能核心指标与趋势 |
| 系统监控 | 服务健康、QPS、P95/P99、错误率、依赖健康（Prometheus+Grafana） |
| 任务监控 | SLA 计时/升级、自动分派、机器人调度、挖掘发现、知识索引的成功率与耗时 |

### 7.2 审计日志

1. 路径：「系统设置 → 审计日志」；审计记录不可删改（哈希链 + WORM）；
2. 审计范围：登录、权限与角色变更、配置变更（SLA/目录/分派/问卷/字段/沙箱/白名单/凭据/重试策略）、业务关键操作（分派、升级、关闭、发布审批、编排发布、凭据换取、导出）、跨租户访问；
3. 查询与导出：按操作人、操作类型、时间、对象筛选；导出需权限并留痕；
4. 留存：操作审计 12 个月，安全日志 ≥6 个月，任务日志默认 365 天。

## 8 备份与安全运维

### 8.1 备份

| 对象 | 策略 | 保留 |
|---|---|---|
| PostgreSQL | 每日全备 + 15min WAL（PITR） | 全备 30 天、WAL 7 天 |
| 对象存储 | 版本控制 + 每日增量（含截图、导入报告） | 90 天（截图 30 天） |
| ES | 每日快照 | 30 天 |
| Redis | AOF + 每日 RDB | 7 天 |
| 配置（Nacos） | 每日导出 + Git | 永久 |

异地容灾：同城双活 + 异地备份，RPO ≤5min、RTO ≤30min（演练实测 RPO 2.4min / RTO 18min）。恢复演练每季度一次。

### 8.2 安全运维

| 项 | 要求 |
|---|---|
| PII 加密 | 联系人手机号等 AES-256-GCM 存储 + `phone_hash`（SHA-256 + 租户盐）检索；禁止明文唯一索引 |
| 密钥管理 | PII 密钥与 RPA 凭据密钥由 KMS 托管，轮换 ≤90 天 |
| 脚本沙箱 | 无网络/文件系统、超时限制、API 白名单；高风险脚本阻断发布 |
| 自动化白名单 | 双重校验（调度+执行）；越界拒绝并告警 |
| 权限复核 | 每季度复核角色与数据权限、应用权限、机器人配额，回收冗余权限 |
| 漏洞管理 | 定期扫描 + 高危即修；发布前 SAST/SCA/镜像扫描阻断高危 |
| 三员分立 | 系统管理员、安全管理员、审计管理员职责分离 |
| 数据清理 | 逻辑删除 + 定时物理清理；截图/日志按保留策略清理；介质销毁流程 |

### 8.3 日常巡检（管理端视角）

| 频率 | 项目 |
|---|---|
| 每日 | SLA 任务与 RPA 调度成功、任务与告警清零、审计异常、备份完成 |
| 每周 | 限流统计、SLA 计时准确性抽检、任务失败 TOP、白名单拦截记录、权限变更记录 |
| 每月 | 容量趋势、密钥与凭据轮换状态、权限复核抽检、沙箱策略复核 |
| 每季度 | 容灾与恢复演练、权限全量复核、安全复评、压测基准回归 |

## 9 故障处理

| 故障 | 常见原因 | 处理步骤 |
|---|---|---|
| 用户无法登录 | 账号锁定/口令过期/MFA 未绑定 | 核对账号状态 → 解锁或重置口令 → 引导绑定 MFA |
| 提示无权限 `0000002` | 功能权限缺失/数据权限范围不足/端别不符 | 核对角色权限码与数据权限范围 → 调整并留痕 |
| 提示工单越权 `6001004` | 数据范围外或非本人/本部门 | 确认为正常拦截；如为业务需要，调整角色数据权限而非放宽校验 |
| 提示状态不允许 `6001002` | 工单/任务状态与操作不匹配 | 查看当前状态与可用操作；必要时按流程推进状态 |
| 提示并发冲突 `6001005` | 多人同时修改同一工单 | 刷新后重试；冲突为正常保护 |
| 提示 SLA 配置非法 `6002002` | 时限/日历缺失 | 补全 SLA 策略与工作日历后保存 |
| 无法提交凭据 `6007004` | KMS 异常或凭据过期 | 检查 KMS 与凭据状态 → 轮换凭据 → 失败任务转人工 |
| 提示脚本风险 `6004004` | 脚本含高风险（网络/文件） | 按扫描详情修改脚本；必要时评审 API 白名单 |
| 提示应用冻结 `6004005` | 应用被治理冻结 | 核实原因；解除冻结需权限并留痕 |
| 提示白名单越界 `6008002` | 目标系统不在白名单 | 核实为业务需要后维护白名单（二次验证 + 审计） |
| 提示发布审批拒绝 `6004002` | 合规/安全校验未通过 | 查看审批意见 → 修正后重新提交 |
| 提示限流 `0000006`/`6009002` | 超出租户+接口或开放 API 配额 | 降频重试；必要时申请调整配额 |
| SLA 升级未触发 | tick 任务异常/日历配置错误 | 检查调度任务状态与日历 → 重算（幂等）→ 恢复 |
| 机器人大面积离线 | 执行端网络/凭证失效 | 检查执行端与凭证 → 重新下发准入凭证 → 任务按幂等重投 |
| RPA 任务堆积 | 并发不足/目标系统不可达 | 扩容执行端或并发；检查目标系统可达性；暂停非核心调度 |
| 挖掘任务失败 | 数据源异常/耗时超限 | 分片重试（幂等）→ 保留上次结果 → 定位慢数据源 |
| 审批任务堆积 | 节点路由异常/实例不足 | 检查工作流实例与路由 → 扩容 → 人工兜底推进 |
| 导出任务失败 | 数据量大/超时 | 重试或缩小范围 → 检查对象存储 → 完成后补发下载 |
| 数据异常（误删/错乱） | 人为或程序缺陷 | 隔离影响 → PITR 恢复至故障前 → 校验 → 回归核心链路 → 复盘 |

故障响应与升级：一线运维（7×24）→ 二线研发值班 → 三线架构/安全；P0 事件 15 分钟内成立应急小组，30 分钟内通报进展，事后 3 个工作日内提交复盘报告；处理过程全程留痕审计。
