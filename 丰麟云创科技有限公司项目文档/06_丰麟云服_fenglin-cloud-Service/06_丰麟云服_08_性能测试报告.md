## 1 目标与指标

### 1.1 性能基线（继承 FL-HUB-STD-001 第 11 章）

| 指标 | 目标值 |
|---|---|
| 服务可用性 | ≥ 99.99%（年不可用 ≤ 52.6 分钟） |
| 并发用户 | 3400 人在线；核心接口峰值 ≥ 1200 QPS |
| 核心接口响应 | P95 ≤ 300ms；P99 ≤ 800ms |
| 页面首屏 | 内网 ≤ 1s；4G ≤ 2s |
| 单接口错误率 | ≤ 0.1% |
| 容灾 | 同城双活，RPO ≤ 5min、RTO ≤ 30min |

### 1.2 本品重点压测目标（SRS NFR）

| 编号 | 指标 | 目标 |
|---|---|---|
| P1 | 工单并发创建 | ≥ 300 TPS，P95 ≤ 300ms，无重复/丢单 |
| P2 | 流程实例高并发流转 | ≥ 200 TPS，实例状态一致、无死锁 |
| P3 | RPA 批量调度 | 单批 ≥500 任务下发 ≤ 10s |
| P4 | 列表/详情混合 | P95 ≤ 300ms、P99 ≤ 800ms |
| P5 | 报表/看板查询 | P95 ≤ 800ms，超时熔断有效 |
| P6 | 挖掘批处理 | 12 万事件日志模型发现 ≤ 30min，不影响在线 |

## 5 瓶颈分析

| 编号 | 现象 | 定位 | 根因 |
|---|---|---|---|
| B-01 | S1 初期 TPS 上不去（<200） | 提单链路 | 工单编号生成（序列）与 SLA 计时初始化串行；连接池偏小 |
| B-02 | S3 P99 抖动至 900ms+ | 流程流转 | 引擎回调与本地事务同库；同步写流转日志 + 事件发布 |
| B-03 | S4 第 3 批耗时接近上限 | 批量调度 | 单次批量选择机器人按能力逐条查询，未批量预取 |
| B-04 | S6 报表偶发超时 | 报表 | SLA 达成率聚合未走物化视图，全表扫描 |
| B-05 | S8 CPU 峰值 68%（单副本） | 应用 | 详情聚合接口多次串行远程调用（引擎/文件/知识） |
| B-06 | S7 前期发现耗时偏长 | 挖掘 | DFG 发现单线程，未分片 |

## 6 调优措施

| 编号 | 对应瓶颈 | 措施 | 效果 |
|---|---|---|---|
| O-01 | B-01 | 工单编号改用**号段缓存**（Leaf-segment）+ SLA 计时异步初始化；Hikari `maximum-pool-size` 40→60 | S1 TPS 从 198→346，P95 从 420ms→268ms |
| O-02 | B-02 | 流转日志与事件改为**异步 + 独立线程池**；引擎回调轻量化；关键事务缩短锁持有 | S3 P99 从 980ms→668ms |
| O-03 | B-03 | 批量调度改为**一次预取候选机器人 + 内存分配**；分批（100/批）并行下发 | S4 稳定 6.7–6.9s/500 |
| O-04 | B-04 | SLA 达成率建立**物化视图**（每 5min 刷新），报表查询走视图 | S6 P95 从 1200ms→486ms |
| O-05 | B-05 | 详情聚合改**并行调用 + 结果缓存（Redis，TTL 30s）**；N+1 查询合并 | S8 单副本 CPU 峰值 68%→52% |
| O-06 | B-06 | 模型发现**分片并行**（按 case_id 分 8 片）+ 中间结果落盘 | S7 从 27min→18.6min |
| O-07 | 通用 | 网关层限流规则按租户+接口；`HPA` 目标 CPU 65%；慢查询治理 | 峰值弹性扩容及时 |
| O-08 | 通用 | ES 索引优化（`search_after`、冷热分层）；Kafka 分区数按峰值 2 倍冗余 | 检索 P95 132ms |

## 7 结论与容量建议

### 7.1 结论

1. **全部重点场景达标**：工单并发创建 346 TPS（目标 300）、流程流转 238 TPS（目标 200）、RPA 批量调度 6.84s/500（目标 ≤10s）、混合峰值 1428 QPS（目标 ≥1200）；
2. **响应指标达标**：核心接口 P95 ≤ 300ms、P99 ≤ 800ms；报表 P95 486ms；错误率 ≤ 0.05%（目标 ≤0.1%）；
3. **稳定性达标**：8h 运行无内存泄漏、无错误累积、Full GC 0 次；
4. **容灾指标**：同城双活 RPO ≤5min / RTO ≤30min（演练实测 RPO 2.4min / RTO 18min，见 FL-SVC-DEPLOY-010）；
5. 支撑 **3400 人在线、峰值 ≥1200 QPS** 的规模目标。

### 7.2 生产资源配置建议

| 组件 | 建议规格/数量 |
|---|---|
| service api | 8C16G × 8（HPA 至 12），限 6C12G |
| service worker | 8C16G × 4 |
| PostgreSQL | 16C64G + SSD，1 主 2 从 |
| Redis | 8C16G × 3 主 3 从 |
| Kafka | 8C16G × 3 Broker |
| Elasticsearch | 8C32G × 3 |
| Flowable/lowcode（中台） | 各 4C8G × 2 |

### 7.3 容量增长与告警阈值

| 指标 | 建议扩容阈值 | 说明 |
|---|---|---|
| 应用 CPU | 持续 >65% 触发 HPA | 目标 ≤65% |
| 数据库连接 | >600/800 | 优先加只读副本 |
| 工单表行数 | >5000 万 | 触发分区归档（见 FL-SVC-DB-003） |
| Kafka Lag | >10 万 | 扩容消费者 |
| ES 查询 P95 | >200ms | 索引/分片优化 |

### 7.4 遗留与后续

1. B-02 的引擎回调 P99 在极端并发下仍偏高，后续引入**事件溯源 + 独立事件库**进一步解耦；
2. RPA 机器人数量 >50 时，调度选择算法需引入**加权轮询 + 健康度**；
3. 挖掘批处理超 50 万事件日志时建议引入**Spark/Flink**离线链路（预留，不在本期）。
