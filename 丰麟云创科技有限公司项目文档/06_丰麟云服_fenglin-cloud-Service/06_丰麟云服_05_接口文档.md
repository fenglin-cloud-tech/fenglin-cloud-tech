## 1 通用约定

（完整约定引用 FL-HUB-STD-001 第 5 章，本品补充如下。）

- 协议 HTTPS（TLS 1.2+，推荐 1.3）；数据格式 `application/json; charset=UTF-8`；文件上传 `multipart/form-data`。
- 时间：ISO-8601（`yyyy-MM-dd'T'HH:mm:ss.SSSXXX`），存储 UTC，按租户时区展示。
- 分页：`page`（从 1 开始）、`size`（默认 20，最大 200）；响应 `data = { records, total, page, size }`。
- 统一响应体：

```json
{
  "code": "0",
  "message": "success",
  "data": {},
  "requestId": "b1f2c3d4-5e6f-7a8b-9c0d-1e2f3a4b5c6d",
  "timestamp": "2026-10-19T08:00:00.000+08:00"
}
```

- 请求头：`Authorization`、`X-Tenant-Id`、`X-Client-Type`（ADMIN/PORTAL）、`X-Request-Id`、`Idempotency-Key`、`Accept-Language`。
- 错误码结构 `{域2}{模块2}{序号3}`，域前缀 `60`：

## 2 鉴权与端别

| 项 | 说明 |
|---|---|
| 鉴权 | OAuth2.1/OIDC，JWT（RS256）；`Authorization: Bearer {access_token}` |
| 端别 | `X-Client-Type`：`ADMIN`（管理端）/`PORTAL`（用户端）；须与令牌 `client_type` 一致，否则 `0000002` |
| 租户 | `X-Tenant-Id` 必填，须与令牌 `tenant_id` 一致 |
| 权限 | 功能权限码校验（如 `service:ticket:create`）；数据权限（SELF/DEPT/DEPT_AND_CHILD/CUSTOM/ALL）行级过滤 |
| 幂等 | 写操作支持 `Idempotency-Key`（24h 有效）；提单/审批/任务调度/凭据换取类强制 |
| 追踪 | `X-Request-Id`（贯穿全链路）、`X-Trace-Id`（SkyWalking） |

**端别归属原则**：

- `/api/service/v1/admin/**` 仅 `ADMIN` 可访问（配置、授权、审核、治理、报表定义）；
- 其余 `/api/service/v1/**` 仅 `PORTAL` 可访问（提单、受理、知识、低代码搭建、挖掘、RPA 运维）；
- 内部接口 `/api/service/v1/internal/**` 仅服务间 mTLS 调用（引擎回调、执行端回调、事件接入）；
- 双端术语与功能归属遵循 FL-HUB-STD-001 第 1.3 节。

**权限码总表**：

| 域 | 权限码 |
|---|---|
| 工单 | `service:ticket:create`、`service:ticket:view`、`service:ticket:accept`、`service:ticket:assign`、`service:ticket:handle`、`service:ticket:escalate`、`service:ticket:close` |

## 4 逐接口定义

> 说明：所有接口均须携带第 2 章请求头；`data` 为统一响应体中的数据体。员工手机号等 PII 默认脱敏返回（`138****8888`），查看明文需相应权限并记审计。

### SVC-API-001 创建工单

- **方法/路径**：`POST /api/service/v1/tickets`；**端别**：PORTAL；**鉴权**：`service:ticket:create`；**幂等**：强制（`Idempotency-Key`，`tenant_id` 维度）。
- **请求体**：

| 参数 | 类型 | 必填 | 约束 | 说明 |
|---|---|---|---|---|
| `title` | string | 是 | 1–200 | 工单标题 |
| `description` | string | 否 | ≤5000 | 问题描述（富文本） |
| `ticketType` | string | 是 | 枚举 INCIDENT/REQUEST/PROBLEM/CHANGE | 工单类型 |
| `catalogItemId` | long | 否 | — | 来源目录项（目录申请时必填） |
| `priority` | string | 否 | 枚举 P1/P2/P3/P4 | 为空则按影响/紧急度矩阵计算 |
| `impact` | string | 否 | 枚举 HIGH/MEDIUM/LOW | 影响范围 |
| `urgency` | string | 否 | 枚举 HIGH/MEDIUM/LOW | 紧急程度 |
| `source` | string | 是 | 枚举 SELF/CATALOG/EMAIL/DESK/API/RPA | 来源渠道 |
| `requesterId` | long | 是 | — | 提单人（代客提单时可为他人） |
| `contactPhone` | string | 否 | 11 位手机号 | 联系方式（加密存储） |
| `assigneeId` | long | 否 | — | 指定处理人（为空走分派规则） |
| `assetIds` | long[] | 否 | — | 关联资产 |
| `attachments` | long[] | 否 | — | 附件 ID 列表（文件服务） |
| `dynamicFields` | object | 否 | — | 目录项绑定的低代码表单字段（F2 能力契约） |

- **响应示例**：

```json
{
  "code": "0",
  "message": "success",
  "data": {
    "id": 1789012345678901234,
    "ticketNo": "SVC202610000123",
    "status": "NEW",
    "priority": "P2",
    "assigneeId": 10086,
    "slaTimerId": 665001,
    "responseDeadline": "2026-10-19T10:00:00.000+08:00",
    "resolveDeadline": "2026-10-20T08:00:00.000+08:00",
    "createdAt": "2026-10-19T08:00:00.000+08:00"
  },
  "requestId": "b1f2c3d4-...",
  "timestamp": "2026-10-19T08:00:00.000+08:00"
}
```

- **错误码**：`6000001`（参数）、`6001001`（幂等键重复）、`6002001`（目录项不可申请）、`6000002`（无权限）。
- **副作用**：生成工单编号 `SVC{yyyyMM}{6位}`；创建 `svc_sla_timer` 计时；发布事件 `service.ticket.created`；若目录项需审批则先生成审批。

- **请求体**：`{ "messageId":"<...>", "from":"a@x.com", "subject":"...", "body":"...", "receivedAt":"2026-10-19T08:00:00.000+08:00", "attachments":[{"name":"a.pdf","fileId":"..."}] }`

### SVC-API-004 工单详情

- **方法/路径**：`GET /api/service/v1/tickets/{id}`；**端别**：PORTAL；**鉴权**：`service:ticket:view`。

### SVC-API-006 分派工单

- **方法/路径**：`POST /api/service/v1/tickets/{id}/assign`；**端别**：PORTAL；**鉴权**：`service:ticket:assign`；**幂等**：支持。
- **请求体**：`{ "assigneeId": 10086, "groupId": 2001, "strategy": "MANUAL|ROUND_ROBIN|LOAD_BALANCE|SKILL|DUTY", "reason": "技能匹配" }`
- **规则**：`assigneeId` 为空时按 `strategy` 执行；目标为离职账号则回退部门池；工单 `NEW/ASSIGNED` 状态才可分派。
- **错误码**：`6001002`（状态不允许）、`6001005`（并发冲突）。

### SVC-API-007 工单状态流转

- **方法/路径**：`POST /api/service/v1/tickets/{id}/transition`；**端别**：PORTAL；**鉴权**：`service:ticket:handle`；**幂等**：支持。
- **请求体**：`{ "action": "START|SUSPEND|RESUME|ESCALATE|RESOLVE|CLOSE|REOPEN|CANCEL", "reason": "...", "resolution": "...", "toAssigneeId": 10090 }`
- **状态机**：`NEW→ASSIGNED→IN_PROGRESS→PENDING→ESCALATED→RESOLVED→CLOSED/REOPENED/CANCELLED`（详见 FL-SVC-MOD-004 第 1.5 节）。
- **副作用**：写 `svc_ticket_flow_log`（前后状态、操作人、时间、原因）；挂起触发 SLA 暂停；解决后 24h 自动关闭并发放 CSAT；发布 `service.ticket.status_changed`。
- **错误码**：`6001002`（非法迁移）、`6001006`（已关闭/撤销）。

## 5 低代码引擎能力契约

> 本品**不实现**低代码引擎内核，全部表单/流程/模型/页面**渲染与执行**由中台 `fenglin-lowcode-service` 提供。以下为能力契约（内部 mTLS 调用，Base 路径 `/lowcode-engine/v1`），是本品《接口文档》与引擎之间的稳定约定。

| 契约编号 | 能力 | 方法/路径 | 说明 |
|---|---|---|---|
| SVC-CAP-001 | 表单渲染描述 | `POST /lowcode-engine/v1/forms/render` | 入参 `formSchemaRef` + `fieldPermContext`，返回运行时渲染描述 |
| SVC-CAP-002 | 表单数据保存 | `POST /lowcode-engine/v1/forms/{formId}/submit` | 入参 `data` + `businessKey` + `idempotencyKey`，引擎落库并返回 `recordId` |
| SVC-CAP-003 | 流程定义部署 | `POST /lowcode-engine/v1/flows/deploy` | 入参 `bpmnXml` + `flowKey`，部署到引擎 |
| SVC-CAP-004 | 流程实例发起/办理 | `POST /lowcode-engine/v1/flows/{flowKey}/start`、`/tasks/{taskId}/complete` | 运行时发起与办理 |
| SVC-CAP-005 | 数据模型存储 | `POST /lowcode-engine/v1/models/{modelId}/records` | 记录读写与查询（分页/过滤） |
| SVC-CAP-006 | 页面运行时 | `POST /lowcode-engine/v1/pages/{pageKey}/runtime` | 返回页面运行时描述与数据源解析结果 |
| SVC-CAP-007 | 版本快照与回滚 | `POST /lowcode-engine/v1/releases/snapshot`、`/releases/rollback` | 生成不可变快照 / 回滚到指定快照 |
| SVC-CAP-008 | 脚本沙箱执行 | `POST /lowcode-engine/v1/sandbox/execute` | 沙箱执行脚本（无网络/无文件/超时 3s/白名单 API） |

**契约约定**：

1. 全部调用经 mTLS，携带服务间令牌与 `X-Tenant-Id`；
2. 契约调用超时默认 3s，重试 2 次（幂等），仍失败返回 `6004001`（引擎不可用），本品降级为"设计态可保存、运行时暂不可用"；
3. 资源标识：本品的 `form_definition.id`/`flow_definition.id`/`data_model.id`/`page_schema.id` 与引擎的 `engine_ref` 一一映射，存于各定义的 `engine_ref` 字段；
4. 引擎版本快照与本品 `svc_app_release.snapshot_json` 保持一致；
5. 契约变更须经平台架构组评审（FL-HUB-STD-001 第 5 章约束）。

## 6 RPA 调度与回调

### 6.1 调度交互序列

```
调度端(worker)                         执行端(rpa-agent)
     │  selectRobot(能力/在线/并发)          │
     │──── POST /internal/rpa/tasks/{id}/dispatch ───▶│（领取任务）
     │      （Kafka: svc.rpa.task.dispatched）        │
     │                                       │ 换取凭据临时令牌
     │◀─── POST /internal/rpa/credentials/token ──────│
     │──── tempToken(ttl≤60s) ──────────────▶│  执行
     │◀─── POST /internal/rpa/tasks/{id}/callback ────│（RUNNING/进度）
     │◀─── POST /internal/rpa/tasks/{id}/callback ────│（SUCCEEDED/FAILED）
     │  SUCCEEDED → 回流事件日志 / FAILED → 重试策略   │
```

### 6.2 回调契约

| 契约编号 | 名称 | 方法/路径 | 幂等键 | 说明 |
|---|---|---|---|---|
| SVC-CB-001 | 任务开始 | `POST /internal/rpa/tasks/{id}/callback` `status=RUNNING` | `task_id+attempt+RUNNING` | 置 `RUNNING`，记录开始时间 |
| SVC-CB-002 | 进度上报 | 同上 `status=RUNNING` `progress` | 每次进度 upsert | 前端进度条 |
| SVC-CB-003 | 成功 | 同上 `status=SUCCEEDED` | `task_id+attempt+SUCCEEDED` | 持久化输出、回流事件 |
| SVC-CB-004 | 失败 | 同上 `status=FAILED` | `task_id+attempt+FAILED` | 触发重试或转人工 |

**回调约定**：

1. 回调必须携带 `idempotency key`（`task_id+attempt+status`）；重复/乱序回调返回 `6007003` 并按幂等忽略，旧状态不覆盖新状态；
2. 执行端崩溃/断连：心跳超时（90s）置机器人 `OFFLINE`；`RUNNING` 任务由调度在 `N` 分钟后按幂等重投；
3. 凭据临时令牌 TTL ≤ 60s，使用后立即从内存清除；换取与使用全审计、日志脱敏；
4. 白名单校验在调度与执行前双重执行，越界返回 `6008002` 并安全告警。

## 9 版本与兼容

1. 版本以 URL 段体现（`/v1`）；重大不兼容变更升 `/v2`，旧版本保留 ≥ 12 个月。
2. 兼容性策略：新增字段为向后兼容；字段语义变更或删除视为不兼容。
3. 废弃流程：先标记 `Deprecated`（OpenAPI `deprecated: true`）并在变更公告中通知，≥ 6 个月后下线。
4. 新增枚举值消费方需容错；错误码只增不改语义。
5. 能力契约（第 5 章）与回调契约（第 6 章）变更须同步更新版本并通知 `fenglin-lowcode-service` 与执行端。
6. OpenAPI 3.1 契约（`openapi.yaml`）随服务发布，作为接口契约唯一来源。
