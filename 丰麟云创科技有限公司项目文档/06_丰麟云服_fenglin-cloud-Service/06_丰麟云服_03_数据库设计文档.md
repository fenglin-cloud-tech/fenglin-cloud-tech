## 1 设计原则

1. **多租户**：所有业务表含 `tenant_id`，启用 PostgreSQL RLS 行级安全，跨租户访问默认拒绝。
2. **公共字段强制**：每表含 `id / tenant_id / created_by / created_at / updated_by / updated_at / deleted / version`。
3. **主键**：高并发写使用雪花 ID（`bigint`）；对外暴露资源标识同时以 `uuid` 列保证不可枚举。
4. **命名**：表名小写下划线、模块前缀 `svc_`；字段小写下划线。
5. **敏感字段加密**：员工手机号、机器人凭据等 AES-256-GCM，配套 `{field}_hash`（SHA-256+租户盐）用于唯一性与检索，禁止明文列唯一索引。
6. **逻辑删除**：`deleted`（0 正常/1 删除），唯一约束以"未删除"为条件（部分索引）。
7. **乐观锁**：`version` 由 MyBatis-Plus `@Version` 维护。
8. **迁移**：所有 DDL/DML 通过 Flyway 脚本 `V1_0_x__*.sql` 提交，禁止手工改库。
9. **金额**：统一 `numeric(18,2)`；时长 `numeric(12,2)`（秒/分钟按列注释）；时间 `timestamptz`（UTC）。
10. **大表分区**：`svc_mining_event_log`、`svc_robot_task_log`、`svc_ticket_flow_log` 按 `tenant_id` + 月做声明式分区，ES 承担检索分流。
11. **Schema 与元数据**：低代码应用/表单/流程/页面的**运行数据**由中台 `fenglin-lowcode-service` 托管，本库仅存**定义元数据与引用**（`engine_ref`）。

## 2 逻辑模型（ER）

```
F1 员工服务与 IT 支持
┌──────────────┐  1:N  ┌──────────────────┐   N:1  ┌──────────────────┐
│ svc_catalog  │──────▶│svc_catalog_item  │───────▶│  svc_sla_policy  │
└──────────────┘       └────────┬─────────┘        └────────┬─────────┘
                                │ 申请                       │ 1:N
                                ▼                            ▼
┌──────────────┐  N:1  ┌──────────────────┐        ┌──────────────────┐
│svc_it_asset  │◀──────│   svc_ticket     │───────▶│  svc_sla_timer   │
└──────────────┘       └───┬───┬───┬───┬──┘        └────────┬─────────┘
       ▲ sponsored         │   │   │   │                    │ 1:N
       │                   │   │   │   └──▶svc_csat_survey  ▼
┌──────────────┐  1:N      │   │   │            └────▶ svc_sla_breach
│ svc_problem  │◀──────────┘   │   └──▶svc_ticket_comment
└──────────────┘  problem      │
┌──────────────┐  change       └──▶svc_ticket_flow_log (状态流转)
│svc_change_req│◀──────────────┘
└──────────────┘
┌──────────────┐  1:N  ┌──────────────────┐  1:N  ┌──────────────────┐
│svc_kb_category│─────▶│  svc_kb_article  │─────▶ │  svc_kb_feedback │
└──────────────┘      └──────────────────┘       └──────────────────┘

F2 低代码/零代码（元数据；运行数据在中台 lowcode 引擎）
┌──────────────────┐ 1:N ┌──────────────────┐ 1:N ┌──────────────────┐
│ svc_app_definition│────▶│ svc_form_definition│─▶│  svc_form_field  │
└───┬────────┬─────┘     └──────────────────┘    └──────────────────┘
    │1:N     │1:N
    ▼        ▼
┌──────────────┐ 1:N ┌──────────────────┐      ┌──────────────────┐
│svc_flow_definition│▶│ svc_flow_instance│──1:N▶│  svc_flow_task   │
└──────────────┘     └──────────────────┘      └──────────────────┘
┌──────────────────┐ 1:N ┌──────────────────┐  ┌──────────────────┐
│ svc_data_model   │────▶│svc_data_model_field│ │ svc_page_schema  │
└──────────────────┘     └──────────────────┘  └──────────────────┘
┌──────────────────┐
│  svc_app_release │ (应用版本快照/发布记录)
└──────────────────┘

F3 自动化流程挖掘与机器人
┌──────────────────┐ 聚合→ ┌──────────────────┐
│svc_mining_event_log│────▶│ svc_mining_result│
└──────────────────┘      └──────────────────┘
┌──────────────┐ 1:N ┌──────────────────┐  1:N  ┌──────────────────┐
│  svc_robot   │────▶│ svc_robot_task   │──────▶│ svc_robot_task_log│
└──────┬───────┘     └────────┬─────────┘       └──────────────────┘
       │ 1:N                  │ N:1
       ▼                      ▼
┌──────────────────┐  ┌──────────────────┐  ┌──────────────────┐
│svc_robot_schedule│  │svc_automation_flow│ │svc_robot_credential│
└──────────────────┘  └──────────────────┘  └──────────────────┘

通用：svc_tag ─1:N─ svc_tag_relation（多态）；svc_attachment（多态）
```

关系说明：

- `svc_catalog_item` 1:N → `svc_ticket`（目录项申请）；`svc_sla_policy` 1:N → `svc_sla_timer`；
- `svc_ticket` 1:N → 流转日志/评论/满意度/子工单；M:N → 资产、问题、变更（通过关联表或外键）；
- `svc_app_definition` 1:N → 表单/流程/数据模型/页面/发布记录；`svc_flow_definition` 1:N → 实例 → 任务；
- `svc_mining_event_log` 聚合 → `svc_mining_result`；`svc_mining_result` 可生成 `svc_automation_flow` 草稿；
- `svc_automation_flow` 1:N → `svc_robot_task`；`svc_robot` 1:N → 任务/调度/凭据。

## 6 约束与 RLS

### 6.1 通用 RLS 策略

对每张业务表统一创建：

```sql
ALTER TABLE svc_ticket ENABLE ROW LEVEL SECURITY;

CREATE POLICY p_svc_ticket_tenant ON svc_ticket
  USING (tenant_id = current_setting('app.tenant_id')::bigint)
  WITH CHECK (tenant_id = current_setting('app.tenant_id')::bigint);
```

- 应用连接建立后由 `TenantContext` 通过 `SET LOCAL app.tenant_id = ?` 注入；
- 平台运营端跨租户访问需以 `platform:*` 权限并经审计通道，RLS 在审计通道使用独立角色 `svc_platform_reader`；
- 数据权限（本人/本部门/本部门及下级/指定部门/全部）在应用层追加 `owner_id/dept_id/assignee_id` 谓词。

### 6.2 关键约束清单

| 表 | 约束 | 说明 |
|---|---|---|
| `svc_ticket` | `uk_ticket_no` | 工单号唯一 |

## 7 敏感字段加密

### 7.1 加密范围

| 表.字段 | 明文语义 | 密文列 | 哈希列 | 展示 |
|---|---|---|---|---|
| `svc_ticket.contact` | 提单人联系方式 | `contact_enc` | `contact_hash` | `138****8888` |
| `svc_csat_survey` 关联联系方式 | 评价人电话（可选） | 复用 `svc_ticket.contact_enc` | — | 脱敏 |
| `svc_robot_credential.secret` | 机器人/API 凭据 | `secret_enc` | — | 永不展示，仅执行时解密 |

### 7.2 加密方案

- **算法**：AES-256-GCM；
- **密钥**：由平台 KMS 管理，密钥版本随密文存储（`{keyVersion}:{iv}:{ciphertext}:{tag}` 的 Base64 封装），支持轮换（≤ 90 天）；
- **实现**：自定义 MyBatis-Plus `TypeHandler`（`EncryptedFieldTypeHandler`）透明加解密；对 `svc_robot_credential.secret_enc` 使用**专用加密器** `CredentialCipher`，仅在 RPA 执行代理请求时通过一次性令牌解密，且**不经过常规查询映射**（专用 Repository，禁止 `SELECT *`）；
- **哈希**：`{field}_hash = SHA256(明文 + 租户盐)`，租户盐由 KMS 下发并按租户隔离。

### 7.3 凭据保管专项要求（RPA）

1. 凭据仅以 KMS 引用 + 密文存储，**明文不落库、不落日志、不进 MQ 消息**；
2. 机器人执行时由执行代理携带任务一次性令牌向 `POST /api/service/v1/rpa/credentials/{id}/fetch` 换取短时明文（TTL ≤ 60s），换取行为全审计；
3. 凭据按 `rotate_due_at` 强制轮换，轮换期间双版本并存；
4. 越权访问（非授权机器人/非授权自动化流程）返回 `6007003` 并告警。

### 7.4 字段权限

| 角色 | 联系方式 | 机器人凭据 |
|---|---|---|
| 服务台受理员 | 脱敏，需 `service:ticket:pii:view` 方可见完整（强审计） | 不可见 |
| 工程师 | 脱敏 | 不可见 |
| RPA 运维 | 不涉及 | 仅可管理引用，不可见明文 |
| 服务运营管理员 | 依配置，默认脱敏 | 可配置不可见明文 |
| 平台运维 | 不可见（需授权并经审计） | 不可见 |
