## 1 架构概览

丰麟云服采用"**中台能力复用 + 业务域服务 + 双端分离 + 开放生态**"的架构。核心设计原则：

1. **复用不重建**：低代码引擎复用中台 `fenglin-lowcode-service`，工作流复用 `fenglin-workflow-service`，AI 复用 `fenglin-ai-service`，本品以**能力契约**方式调用；
2. **域内自治**：`fenglin-service-service` 承载 F1/F2/F3 三模块业务逻辑与数据，独立库 `fenglin_service`、独立命名空间 `fenglin-service`；
3. **双端分离**：管理端（`/admin/service`）与用户端（`/app/service`）共用后端与令牌体系，通过 `X-Client-Type` 声明端别，网关执行路由与鉴权；
4. **异步解耦**：工单事件、SLA 计时、流程实例流转、RPA 调度采用 Kafka 事件驱动，重智能/重计算（挖掘、模型发现）采用 XXL-Job 批处理；
5. **可观测与可审计**：全链路 SkyWalking 追踪、结构化日志、审计哈希链。

### 2.1 逻辑分层

| 层次 | 组件 | 职责 |
|---|---|---|

└───────────────────────────────────────────────────────────┘
        ▲
        │ mTLS

**部署分解**：

| 工作负载 | 副本 | 说明 |
|---|---|---|
| `service-api` | 3–N（HPA CPU 60%） | 承接 HTTP，无状态 |
| `service-worker` | 2–M | Kafka 消费（工单事件、SLA 计时、任务回调），无状态 |
| `service-scheduler` | 1 主 1 备 | XXL-Job 执行器：SLA 扫描、到期提醒、调研重算、挖掘批处理 |
| `rpa-agent` | 按机器人数量弹性 | 独立部署，落客户侧或独立安全域 |

## 4 关键流程时序

### 4.1 工单创建与自动分派（F1）

```
员工(用户端) → Gateway → service-api
  service-api: 校验权限 → 生成工单号 SVC{yyyyMM}{6位} → 落库 svc_ticket
  service-api → 中台 workflow(可选审批) / catalog 取默认处理组与 SLA
  service-api → 分派策略引擎：匹配 目录项→技能组→值班→负载
  service-api: 写 svc_ticket_flow_log、创建 svc_sla_timer、发 Kafka(ticket.created)
  service-worker: 消费事件 → 通知处理人(message-service) → ES 索引工单
  service-scheduler: 定时扫描 svc_sla_timer 临期/违约 → 升级与告警
```

### 4.2 低代码应用发布（F2）

```
应用搭建者 → service-api: 提交发布(POST /lowcode/apps/{id}/publish)
  service-api → 一致性校验(表单/流程/模型/页面完整性) → 生成 draft version
  service-api → 中台 lowcode: 校验 Schema、创建版本快照(pre) 
  管理端审批人(ADMIN): 审批(approve) → service-api 调 lowcode: 发布生产(prod)
  service-api: 写 svc_app_release、发 Kafka(lowcode.app.released)
  运行时: 用户端发起 → service-api 注入权限上下文 → lowcode runtime 渲染/执行
  (回滚: POST /lowcode/apps/{id}/rollback → lowcode 切换到指定版本)
```

### 4.3 RPA 任务调度与重试（F3）

```
触发(定时/事件/手动/队列) → service-scheduler/服务端 → 生成 svc_robot_task(QUEUED)
  调度: 选机器人(能力标签+并发+优先级) → 状态 DISPATCHED → 发 Kafka(rpa.task.dispatch)
  rpa-agent: 拉取任务 → 取临时凭据(KMS, 一次性令牌) → 执行
  rpa-agent: 回调 /rpa/tasks/{id}/callback(状态/日志/截图) → service-api(幂等)
  失败: 按重试策略(指数退避, max N)重新入队; 超阈值 → MANUAL_REQUIRED + 告警
  成功: 回写结果 → 发 Kafka(rpa.task.completed) → 事件日志回流(挖掘)
```

## 5 数据架构

### 5.1 数据存储分工

| 存储 | 内容 | 说明 |
|---|---|---|
| PostgreSQL `fenglin_service` | 全部业务主数据（工单、SLA、知识、应用定义、流程、机器人、任务、事件日志） | RLS 多租户，分区大表 |
| Redis | 会话/令牌缓存、SLA 计时快照、工单锁、任务队列、幂等键 | 7 天 TTL（按需） |
| Elasticsearch | 工单检索、知识检索、事件日志检索、挖掘索引 | IK 分词 |
| Kafka | 领域事件（ticket.*、sla.*、flow.*、rpa.*、lowcode.*） | 事件总线 + Webhook 分发 |
| MinIO | 附件、机器人执行截图、导入文件、导出报表 | 预签名 URL |
| 中台 lowcode 存储 | 低代码运行时数据（表单数据、流程实例数据） | 由引擎托管，本品存引用与元数据 |

### 5.2 多租户与分区

- 所有业务表含 `tenant_id` + RLS；跨租户仅平台运营端。
- 大表分区：`svc_mining_event_log`、`svc_robot_task_log`、`svc_ticket_flow_log`、`svc_csat_survey` 按 `tenant_id` 哈希 + 月分区（声明式）。
- 归档：事件日志、任务日志留存 12 个月，超期归档至 MinIO 冷存。

### 5.3 数据流（挖掘闭环）

```
业务系统(F1工单/F2流程/外部) --事件--> Kafka(topic: svc.process.event) 
   --> service-worker 落 svc_mining_event_log --> ES 建索引
   --> XXL-Job 批处理: 模型发现/一致性/瓶颈 --> svc_mining_result
   --> 用户端可视化(ECharts DFG/时长热力) --> 候选自动化点 --> F3 任务编排草稿
   --> 自动化执行完成 --> 回写事件日志 --> 再挖掘
```

## 6 集成与开放

### 6.1 集成清单

| 对象 | 方向 | 方式 |
|---|---|---|
| 中台 lowcode | 出 | 能力契约（REST/mTLS），表单/流程/模型/页面/运行时 |
| 中台 workflow | 出 | 能力契约，审批流部署与办理 |
| 中台 ai | 出 | 能力契约，工单分类、知识推荐 |
| 中台 message | 出 | 能力契约，多通道通知 |
| 云财 D3 IT 资产 | 双向 | 开放 API（资产查询/领用回写） |
| 云协（协作办公） | 入 | 事件订阅，会议室/审批联动（可选） |
| 外部系统（ERP/HR/OA） | 双向 | 开放 API + Kafka 事件（事件日志采集与提单） |
| 邮件系统 | 双向 | IMAP 拉取转工单、SMTP 通知 |

### 6.2 开放 API（前缀 `/openapi/service/v1`）

- 应用注册 + AppKey/AppSecret（HMAC-SHA256 签名）+ OAuth2.1 授权码模式；
- 配额与限流按应用/接口维度；超限返回 `0000006`；
- 事件订阅：Kafka → Webhook 回调（重试 + 签名验签 + 幂等）；
- 开发者门户：应用管理、API 目录、在线调试沙箱、SDK（Java/JS/Python）。

对外可开放资源（摘要）：工单创建/查询/状态回调、服务目录查询、知识检索、应用运行时（表单提交/流程发起）、机器人任务下发/状态。

## 7 双端分离架构

| 维度 | 管理端 | 用户端 |
|---|---|---|
| 前端工程 | `fenglin-hub-admin-ui` + `/admin/service` | `fenglin-hub-portal-ui` + `/app/service` |
| 路由命名空间 | `/admin/service/**` | `/app/service/**` |
| 权限域 | `platform:*`、`tenant:*` | `biz:*`、`service:*`（业务操作类） |
| 端别声明 | `X-Client-Type: ADMIN` | `X-Client-Type: PORTAL` |
| 导航骨架 | 左侧菜单 + 面包屑 + 信息密集表格 | 顶部导航 + 卡片工作台 |
| 首页 | 运营概览/待办/审批/监控 | 我的工作台/待办/消息/快捷入口 |
| 组件库 | Element Plus | 自研 Portal 组件（同 Token） |
| 审计粒度 | 配置类操作强审计（变更前后值） | 业务操作审计 |

**路由与鉴权策略**：`/api/service/v1/admin/**` 仅 `ADMIN`；其余 `/api/service/v1/**` 仅 `PORTAL`；`/api/service/v1/internal/**` 仅服务间 mTLS；`/api/service/v1/rpa/agent/**` 仅机器人代理（专用客户端凭据）。端别与令牌 `client_type` 不一致返回 `6000002`。

## 8 高可用与容灾

| 维度 | 措施 |
|---|---|
| 服务高可用 | 无状态多副本 + HPA；网关与服务均 ≥ 3 副本；Pod 反亲和 |
| 数据库 | PostgreSQL 主从流复制 + 只读副本；Patroni 自动故障转移 |
| 缓存 | Redis 哨兵/集群，持久化 AOF |
| 消息 | Kafka 3 broker + 分区副本 ≥ 2，min.insync.replicas=2 |
| 检索 | ES 3 节点，索引副本 ≥ 1 |
| 对象存储 | MinIO 4 节点纠删码 |
| 同城双活 | 双可用区部署，GSLB 流量调度 |
| 容灾指标 | RPO ≤ 5min、RTO ≤ 30min；季度演练 |
| 可用性目标 | ≥ 99.99%/年（年不可用 ≤ 52.6 分钟） |
| 降级策略 | 中台 AI 不可用→规则分派兜底；ES 不可用→PG 直查；lowcode 运行时不可用→只读提示 |
| 限流熔断 | Sentinel 按资源/接口限流，熔断降级返回缓存或友好提示 |

## 9 安全架构

1. **边界安全**：WAF + IPS，TLS1.3；网关统一鉴权与限流。
2. **身份与访问**：OAuth2.1/OIDC + JWT(RS256)；MFA；RBAC+ABAC+数据权限；三员分立。
3. **数据传输/存储加密**：客户端↔网关 TLS1.3；服务间 mTLS；PII/凭据 AES-256-GCM；PG TDE；KMS 密钥轮换 ≤ 90 天。
4. **脚本沙箱（重点）**：F2 脚本在独立沙箱进程/V8 isolate 执行——禁网络、禁文件系统、超时 3s、内存上限、API 白名单、包扫描（SCA）、内容审计留档。
5. **RPA 凭据保管（重点）**：凭据密文存 `svc_robot_credential`（仅存 KMS 引用 + 密文），执行时经 KMS 签发一次性临时令牌解密，不写日志、不进内存快照，解密操作全审计。
6. **自动化越权防护（重点）**：机器人/自动化任务继承"服务账号 + 最小权限"模型；每个自动化流程声明所需系统/操作白名单；调度校验白名单，越界拒绝并告警；RPA 执行端网络微隔离。
7. **审计**：全链路审计（哈希链 + WORM），留存 ≥ 6 个月（建议 12 个月）。
8. **恶意代码防范**：镜像扫描、依赖 SCA、主机 HIDS。

> 详见 FL-SVC-SEC-009《安全评估报告》逐项对照等保三级控制矩阵。

| 编号 | 风险 | 等级 | 应对 |
|---|---|---|---|
| R-01 | 低代码引擎能力契约变更导致 F2 不稳定 | 中 | 契约版本化 + 适配层 + 契约兼容性测试；订阅变更公告 |
| R-02 | 流程实例高并发（3400 人）下引擎压力 | 高 | 引擎独立部署+连接池调优；异步化；压测达 200 TPS 流转 |
| R-03 | RPA 执行端环境差异导致任务失败 | 高 | 执行端标准镜像+健康检查；失败重试+人工兜底；灰度发布 |
| R-04 | 脚本沙箱逃逸导致越权 | 高 | 独立隔离执行、白名单、双人复核、静态扫描、渗透测试 |
| R-05 | 机器人凭据泄漏 | 高 | KMS 保管、临时令牌、最小权限、全程审计、定期轮换 |
| R-06 | 事件日志量大导致挖掘性能下降 | 中 | 分区分表+ES 索引+批处理增量计算+冷热分离 |
| R-07 | 跨域强一致（工单↔审批↔资产）一致性 | 中 | Seata AT + 补偿+对账 |
| R-08 | 开放 API 被滥用 | 中 | 配额/限流/签名/审计；异常调用风控 |
