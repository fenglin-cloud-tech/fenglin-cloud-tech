## 1 设计原则

1. **双端分离**：管理端（`/admin/service`，`fenglin-hub-admin-ui` + Element Plus，信息密集）承载配置/授权/审核/治理/报表定义；用户端（`/app/service`，`fenglin-hub-portal-ui` + 自研 Portal 组件，任务导向）承载提单/受理/知识/低代码搭建/挖掘/RPA 运维。
2. **服务可及**：员工一次提单、全程可视；服务目录分类清晰、图标化；提单表单按目录项动态渲染（F2 能力契约）。
3. **时效可视**：SLA 计时以进度条 + 倒计时 + 颜色分级（正常蓝 / 临期黄 / 违约红）贯穿列表与详情。
4. **搭建友好**：低代码设计器遵循"拖拽即所得、右侧属性、底部预览"三段式；保存即校验，错误就地提示。
5. **自动化可信**：RPA 任务状态、重试、截图、失败原因全程可查；凭据明文永不回显。
6. **一致复用**：共用同一套设计令牌；用户端与管理端仅导航骨架、信息密度、默认首页不同。

## 6 交互流程

### 6.1 提单与自助闭环

```
员工进入「自助提单」
 → 选择/搜索服务目录项（SvcCatalogPicker）
 → 标题失焦触发知识推荐（SvcKbSuggest）→ 命中则提示"先自助解决"（不阻断）
 → 选择目录项后表单区替换为对应低代码表单（LowcodeRuntimeHost）
 → 提交（SVC-API-001，带 Idempotency-Key）→ 生成工单号 → 跳转工单详情
 → 工单关闭后收到满意度问卷 → 提交评价（SVC-API-066，防重复）
```

### 6.2 受理与分派闭环

```
受理员进入「服务台工作台」→ 待受理页签
 → 认领（SVC-API-006 分派给自己）或按规则自动分派
 → 处理（START→IN_PROGRESS）；需要用户反馈则「挂起」（SLA 暂停）
 → 解决（RESOLVE，填解决方案；可「沉淀为知识」）
 → 自动关闭（24h）→ 发放满意度
```

### 6.3 低代码搭建到发布闭环

```
搭建者「创建应用」（SVC-API-100）
 → 表单设计（110）→ 流程设计（120）→ 数据模型（130）→ 页面搭建（140）→ 权限配置（172）
 → 发布到预发（150，免审批）→ 验证
 → 发布到生产（150，触发管理端审批 151）→ 通过后引擎快照发布（SVC-CAP-007）
 → 运行时使用（160/161/163）；管理端可冻结（153）
```

### 6.4 挖掘到自动化闭环

```
分析师导入事件日志（SVC-API-200）→ 模型发现（210）
 → 一致性检查（212）→ 瓶颈分析（213）→ 自动化候选（215）
 → 生成编排草稿（216）→ 编排设计（240）→ 白名单（242）→ 发布（241）
 → 调度计划（250）→ 任务执行（251/252）→ 回调（262）→ 效能看板（270）
```

### 6.5 关键交互细节

| 场景 | 交互 |
|---|---|
| 长列表 | 滚动加载 + 筛选条件 URL 同步（可分享） |
| 保存冲突 | 乐观锁冲突提示"内容已被他人修改"，提供刷新/对比 |
| 幂等提交 | 提交按钮 loading 锁定至响应返回；重复点击不重复提交 |
| 危险操作 | 关闭/撤销/冻结/删除二次确认，输入原因 |
| 引擎不可用 | 设计态可保存，运行时提示"暂不可用"（`6004001`） |
| 表单离开守卫 | 存在未保存修改时拦截路由并提示 |
| 移动端 | 复杂设计器提示"建议桌面端操作"，仅提供只读浏览 |

## 7 响应式规则

断点：`≥1440 / 1200 / 992 / 768 / <768`（继承 FL-HUB-STD-001 第 9.3 节）。

| 断点 | 用户端 | 管理端 |
|---|---|---|
| ≥1440 | 三栏（导航+内容+侧栏） | 左侧菜单展开 + 多列卡片 |
| 1200–1439 | 三栏收窄，表格列自适应 | 左侧菜单展开 |
| 992–1199 | 侧栏折叠为抽屉 | 左侧菜单收起为图标 |
| 768–991 | 单栏；列表转卡片；设计器转只读提示 | 简化表格，隐藏次要列 |
| <768 | 单栏 + 底部 Tab；最小点击区 44×44px | 提示使用桌面端 |

要点：

1. 低代码设计器（表单/流程/页面）在 <992 断点下切换为**只读预览 + 提示**，避免误操作；
2. SLA 计时条、状态标签在窄屏下保留颜色语义、隐藏冗余文字；
3. 挖掘画布在移动端转为**节点列表 + 瓶颈榜**（放弃力导向图交互）；
4. 表格在移动端提供横向滚动 + 冻结首列。

## 8 状态规范

| 状态 | 呈现 | 组件 |
|---|---|---|
| 加载 | 骨架屏（列表/卡片/表格）≤1s 内出现，禁止白屏 | `FlStateBlock` type=loading |
| 空态 | 插画 + 说明 + 主操作按钮（如"新建工单"） | `FlStateBlock` type=empty |
| 错误 | 错误码 + 人话说明 + 重试按钮；不暴露堆栈 | `FlStateBlock` type=error |
| 无权限 | 锁形插画 + "无权限（6000002）" + 申请入口 | `FlStateBlock` type=forbidden |
| 限流 | Toast"请求过于频繁，请稍后重试（0000006）" | Toast |
| 成功反馈 | Toast（轻）/ 结果页（重，如"发布成功"含快照号） | Toast/Result |
| 部分成功 | 批量导入/调度返回成功+失败数，提供错误清单下载 | Result |
| 乐观锁冲突 | 弹窗"内容已被修改"，提供刷新/对比 | Modal |

| `6009001` | 开放 API 签名校验失败 | 检查 AppSecret/时间戳 |

## 9 可访问性

1. **对比度**：文本与背景对比度 ≥ 4.5:1；状态色不作唯一信息载体（辅以图标/文字）。
2. **键盘导航**：全部交互可键盘完成；焦点样式清晰（`outline: 2px var(--fl-color-primary)`）；模态框焦点陷阱与 `Esc` 关闭。
3. **语义化**：表格 `th`、按钮 `aria-label`；状态标签提供 `aria-live` 播报（如任务完成）。
4. **点击区**：移动端最小 44×44px；图标按钮带 tooltip 与可访问名称。
5. **动效**：遵循 `prefers-reduced-motion`，可关闭非必要动效。
6. **国际化**：文案外置 i18n，默认 `zh-CN`，预留 `en-US`；数字/时间本地化。
7. **表单**：必填项标注 `*` 且 `aria-required`；错误信息与字段 `aria-describedby` 关联。
8. **颜色盲友好**：SLA/优先级/任务状态同时使用形状或文字差异。
