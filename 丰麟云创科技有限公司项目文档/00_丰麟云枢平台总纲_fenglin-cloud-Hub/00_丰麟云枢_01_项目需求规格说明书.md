## 1 引言

### 1.1 目的

本文件定义丰麟云枢（Fenglin Cloud Hub）平台总纲产品的能力需求、非功能需求、数据与接口需求及验收标准，作为平台 13 个中台服务、8 大业务域产品矩阵集成、开放 API 生态建设与验收的唯一需求依据。

本文件面向：平台产品经理、架构师、中台研发团队、8 大业务域产品组、测试与验收人员、安全与运维团队。

### 1.2 范围

**纳入范围**：

- 丰麟云枢平台中台层 13 个服务（`fenglin-gateway`、`fenglin-auth-service`、`fenglin-iam-service`、`fenglin-tenant-service`、`fenglin-workflow-service`、`fenglin-message-service`、`fenglin-file-service`、`fenglin-audit-service`、`fenglin-search-service`、`fenglin-openapi-service`、`fenglin-report-service`、`fenglin-lowcode-service`、`fenglin-ai-service`）；
- 统一门户与单点登录、租户治理与计费、统一身份与权限中心（IAM/4A）、工作流引擎、消息中心、文件中心、审计中心、搜索中心、开放平台、报表/指标中心、低代码引擎、AI 中台十二大能力域；
- 8 大业务域产品矩阵（云销/云协/云才/云财/云研/云服/云法/云智）与平台的集成关系、26 个业务模块清单、云智双模式、多租户隔离策略；
- 管理端（`/admin/**`）与用户端（`/app/**`）分离的平台级页面与权限域。

**不纳入范围**：

- 8 大业务域的域内业务功能（由各产品《需求规格说明书》定义）；
- 客户侧业务系统改造、第三方软件采购；
- 客户个性化定制功能的实现细节（以配置化/低代码承载）。

### 1.3 术语与缩写

| 术语 | 说明 |

## 3 业务需求

### 3.1 统一门户与单点登录

| 编号 | 需求名称 | 需求描述 | 优先级 |
|---|---|---|---|
| FR-HUB-PORTAL-001 | 统一门户入口 | 提供 `hub.fenglincloud.com` 统一门户，聚合 8 大产品入口，按用户权限动态渲染应用磁贴与菜单 | 高 |
| FR-HUB-PORTAL-002 | 单点登录 SSO | 支持 OIDC/SAML2/企微/飞书/钉钉协议单点登录，一次登录贯通 8 大产品，无需重复认证 | 高 |
| FR-HUB-PORTAL-003 | 单点登出 | 支持全局登出（SLO），登出后各产品会话失效；支持令牌撤销列表（黑名单） | 高 |
| FR-HUB-PORTAL-004 | 双端工作台 | 管理端首页呈现运营概览/待办/审批/监控；用户端首页呈现我的工作台/待办/消息/快捷入口 | 高 |
| FR-HUB-PORTAL-005 | 统一待办中心 | 聚合各域审批/任务待办，支持按域/类型/紧急度筛选与一键跳转处理 | 高 |
| FR-HUB-PORTAL-006 | 应用订阅与权限可见 | 门户仅展示租户已订阅且用户有权限的产品入口；未订阅产品引导至开通页 | 中 |
| FR-HUB-PORTAL-007 | 多语言与主题 | 支持 `zh-CN`/`en-US` 切换与租户级主题（Logo/色板）配置 | 中 |
| FR-HUB-PORTAL-008 | 会话安全策略 | 会话超时 30min、空闲自动锁定、异地登录检测与提醒、并发会话上限控制 | 高 |

## 5 数据需求

### 5.1 数据模型需求

| 编号 | 需求 |
|---|---|
| DR-001 | 平台库 `fenglin_hub`，全部平台业务表前缀 `hub_`，含 `id`、`tenant_id`、审计四字段（`created_by/created_at/updated_by/updated_at`）、`deleted`、`version` |
| DR-002 | 平台表数量 ≥ 30，覆盖租户/套餐/订阅/计量/用户/账号/角色/权限/组织/岗位/数据权限/菜单/字典/参数/会话/SSO 配置/工作流/消息/文件/审计/开放应用/AppKey/配额/报表/指标/低代码/AI 授权等 |
| DR-003 | 主键策略：高并发写用雪花 ID（bigint），对外暴露用 uuid |
| DR-004 | 敏感字段（PII、密钥、AppSecret）AES-256-GCM 加密，另存 `{field}_hash` |
| DR-005 | 大表（审计日志、消息、API 调用日志）按月/年分区，支持归档 |

### 5.2 多租户数据隔离

| 部署形态 | 隔离策略 |
|---|---|
| SaaS 多租户 | 共享库共享模式 + `tenant_id` 逻辑隔离 + PostgreSQL RLS |
| 私有化单租户 | 独立库（database per tenant） |
| 混合部署 | 核心数据私有库 + 智能中台 SaaS 化 |

平台全局配置表（如套餐定义、字典类型）可不含 `tenant_id`，其余一律强制。

### 5.3 数据编码与主数据

| 对象 | 规则 | 示例 |
|---|---|---|
| 租户 | `T{6位}` | `T000001` |
| 员工工号 | `{公司码}{4位序号}` | `FL0001` |
| 组织编码 | 层级点分 | `1.2.3` |
| 应用（开放） | `APP{yyyy}{6位}` | `APP2026000001` |
| 报表/指标编码 | `{域码}{类型}{序号}` | `RPT0001`、`MET0001` |

### 5.4 数据生命周期

- 在线数据：租户业务数据在线 ≥ 3 年，历史归档可查；
- 审计数据：操作审计 ≥ 6 个月（建议 12 个月），WORM 存储；
- 消息数据：站内信 ≥ 12 个月，短信/邮件回执 ≥ 6 个月；
- 注销租户：数据保留 30 天后经审批物理擦除（剩余信息保护）。

## 6 接口需求

### 6.1 接口规范需求

| 编号 | 需求 |
|---|---|
| IR-001 | 全部平台接口遵循 FL-HUB-STD-001 第 5 章：HTTPS、RESTful、`/api/hub/v1`、统一响应体、统一错误码 |
| IR-002 | 请求头强制 `Authorization`、`X-Tenant-Id`、`X-Client-Type`（ADMIN/PORTAL） |
| IR-003 | 写操作支持 `Idempotency-Key`；金额/审批/计量类强制幂等 |
| IR-004 | 分页 `page`(从 1)/`size`(默认 20，最大 200)；时间 ISO-8601，存储 UTC |
| IR-005 | 提供 OpenAPI 3.1 契约文件 `openapi.yaml` |

### 6.2 接口分类需求

| 分类 | 前缀 | 端别 | 说明 |
|---|---|---|---|
| 管理端接口 | `/api/hub/v1/admin/**` | ADMIN | 租户/用户/角色/参数/流程/开放平台治理 |
| 用户端接口 | `/api/hub/v1/**` | PORTAL | 待办/消息/文件/搜索/报表/AI |
| 能力嵌入契约 | `/internal/v1/**` | 服务间（mTLS） | 供 8 大产品与云智 embedded 调用 |
| 开放 API | `/openapi/{domain}/v1` | 第三方 | 经 `fenglin-openapi-service` |
| SSO/OIDC | `/api/hub/v1/sso/**`、`/.well-known/**` | 混合 | 标准 OIDC 发现与授权端点 |

### 6.3 接口数量与覆盖需求

- 平台核心接口 ≥ 50 个，覆盖 SSO/OIDC、租户、用户、角色权限、工作流、消息、文件、审计、搜索、开放平台、报表、低代码、AI 能力；
- 每个接口须定义：方法/路径/端别/权限码/请求参数/响应示例/错误码/幂等/限流；
- 对外/跨域接口须完整登记并纳入版本兼容管理。

## 7 约束与假设

### 7.1 约束

1. 技术栈、命名体系、域名/前缀/命名空间严格遵循 FL-HUB-STD-001，不得引入异构框架；
2. 部署于 Kubernetes（1.28+），中间件为 Nacos/PostgreSQL 15/Redis 7/Kafka 3.6/RocketMQ 5.x/ES 8/MinIO；
3. 8 大产品必须通过标准能力契约调用中台，不得自建重复能力；
4. 管理端/用户端分离，配置类归管理端、操作类归用户端，端别不匹配拒绝；
5. 等保三级为验收前置条件。

### 7.2 假设

1. 客户侧网络满足 HTTPS/WSS 访问；
2. 3400 人规模基于丰麟云创集团实际组织结构；
3. 公有云大模型服务在网络可达且具备合规资质；
4. 私有化客户的独立数据库具备主备能力。
