## 2 部署拓扑（K8s）

```
                        ┌────────────────────────────┐
      Internet ────────▶│ SLB + WAF（多可用区）        │
                        └──────────────┬─────────────┘
                                       ▼
                        ┌────────────────────────────┐
                        │ Nginx Ingress Controller    │
                        └──────────────┬─────────────┘
                                       ▼
        ┌──────────────────────────────┴─────────────────────────────┐
        ▼                                                             ▼
┌───────────────────────────────┐                    ┌───────────────────────────┐
│ ns: fenglin-hub               │                    │ ns: fenglin-hub           │
│ fenglin-gateway (3, HPA 3-10) │                    │ openapi-service (2)       │
│ auth/iam/tenant (3/4/3)       │                    │ 8 业务域服务 (各 2-4)     │
│ workflow/message/file (4/3/3) │                    └───────────────────────────┘
│ audit/search/report (3/4/3)   │
│ lowcode/ai (3/4)              │
└───────────────┬───────────────┘
                ▼
┌──────────────────────────────────────────────────────────────────────────────┐
│ ns: fenglin-middleware                                                        │
│ Nacos(3) · PostgreSQL(主备+只读) · Redis(3) · ES(3) · Kafka(3) · MinIO(4)       │
│ XXL-Job(2) · SkyWalking OAP(2) · Prometheus · Grafana · Loki                   │
└──────────────────────────────────────────────────────────────────────────────┘
```

**关键配置**：
- 每个 Deployment 配置 `readinessProbe`/`livenessProbe`/`startupProbe` + `preStop` 优雅停机（sleep 15s）+ `PodDisruptionBudget`（minAvailable 50%）；
- 资源 `requests/limits` 按服务画像设置（如 gateway 1C2G/2C4G）；
- 拓扑分布约束 `topologySpreadConstraints` 跨可用区均衡；
- 配置与密钥经 Nacos / K8s Secret / KMS，禁止硬编码。

## 3 中台服务编排

### 3.1 服务清单与副本

| 服务 | Deployment | 副本 | HPA 触发 | 依赖 |
|---|---|---|---|---|
| fenglin-gateway | `hub-gateway` | 3 | CPU ≥70% | auth(JWKS)、Redis |
| fenglin-auth-service | `hub-auth` | 3 | CPU ≥70% | PostgreSQL、Redis、iam |
| fenglin-iam-service | `hub-iam` | 4 | CPU ≥65% | PostgreSQL、Redis |
| fenglin-tenant-service | `hub-tenant` | 3 | CPU ≥70% | PostgreSQL、workflow |
| fenglin-workflow-service | `hub-workflow` | 4 | CPU ≥65% | PostgreSQL、Flowable、message |
| fenglin-message-service | `hub-message` | 3 | CPU ≥70% | Kafka、Redis、通道 |
| fenglin-file-service | `hub-file` | 3 | CPU ≥70% | MinIO |
| fenglin-audit-service | `hub-audit` | 3 | CPU ≥70% | Kafka、PostgreSQL |
| fenglin-search-service | `hub-search` | 4 | CPU ≥65% | ES、Kafka |
| fenglin-openapi-service | `hub-openapi` | 2 | CPU ≥70% | Redis、PostgreSQL |
| fenglin-report-service | `hub-report` | 3 | CPU ≥70% | PostgreSQL、Redis |
| fenglin-lowcode-service | `hub-lowcode` | 3 | CPU ≥70% | PostgreSQL |
| fenglin-ai-service | `hub-ai` | 4 | CPU ≥65% | 向量库、模型服务、search |

### 3.2 启动顺序（依赖编排）

```
① 中间件（Nacos → PostgreSQL → Redis → Kafka → ES → MinIO）
② 基础中台：auth-service → iam-service → tenant-service
③ 能力中台：workflow → message → file → audit → search → report → lowcode → ai
④ 网关：gateway、openapi-service
⑤ 业务域：8 个 fenglin-{domain}-service
⑥ 前端：admin-ui、portal-ui、开发者门户
```

- 依赖就绪探测：服务启动执行 `/actuator/health` + 自检（DB/Redis/依赖服务连通）；
- 数据库迁移在发布前置 Job 执行（Flyway `migrate`），失败阻断发布。

### 3.3 部署命令（示例）

```bash
# 1) 数据库迁移（前置 Job）
kubectl apply -f k8s/jobs/hub-flyway-migrate.yaml -n fenglin-hub

# 2) 部署中台服务
kubectl apply -f k8s/hub-iam/ -n fenglin-hub

# 3) 校验滚动状态
kubectl rollout status deploy/hub-iam -n fenglin-hub

# 4) 部署网关（最后）
kubectl apply -f k8s/hub-gateway/ -n fenglin-hub
```

> 生产统一经 ArgoCD 声明式发布（GitOps），禁止手工 `kubectl edit`。

## 4 中间件部署

### 4.1 Nacos 2.3.x

- 3 节点集群，MySQL（或内嵌 Derby 仅测试）持久化；命名空间 `fenglin-hub-{env}`；
- 服务注册发现 + 配置中心；开启鉴权，账号最小权限。

### 4.2 PostgreSQL 15

- Patroni 主备 + etcd 仲裁；同步复制（`synchronous_commit=remote_apply`）；
- 只读副本分流查询；PgBouncer 连接池；
- 关键参数：`shared_buffers=16GB`、`work_mem=64MB`、`max_connections=500`（配合 PgBouncer）、`archive_mode=on`（WAL 归档）；
- Flyway 迁移由专用 Job 执行，账号仅 DDL 权限，应用账号仅 DML。

### 4.3 Redis 7

- 主从 + 哨兵（3 哨兵）；开启 ACL 与 `requirepass`；持久化 AOF（everysec）+ RDB；
- 用途：会话、令牌黑名单、限流、幂等键、缓存。

### 4.4 Kafka 3.6

- 3 Broker；`default.replication.factor=3`、`min.insync.replicas=2`；
- Topic 规划：`hub.tenant.*`、`hub.user.*`、`hub.workflow.*`、`hub.message.*`、`hub.audit.*`、`hub.metering.*`、`hub.ai.*`；分区 ≥ 6。

### 4.5 Elasticsearch 8

- 3 节点，分片副本 ≥ 1；开启安全认证（内网亦启用）；
- 平台索引 `hub_*` + 8 域索引；IK 分词插件；生命周期 ILM 冷热分层。

### 4.6 MinIO

- 4 节点纠删码；桶：`hub-files`、`hub-reports`、`hub-archive`、`hub-backup`；
- 禁用公开桶，访问走签名 URL；开启版本控制与服务端加密。

### 4.7 其他

- **XXL-Job**：2 执行器，承载计量归集、审计归档、索引重建、超时催办、分区预建；
- **SkyWalking OAP**：2 节点，接收链路追踪；
- **Prometheus/Grafana/Loki**：指标/可视化/日志。

## 5 灰度发布与回滚

### 5.1 发布策略

| 策略 | 适用 | 说明 |
|---|---|---|
| 滚动发布 | 常规变更 | 分批替换，`maxUnavailable=25%` |
| 蓝绿发布 | 网关/核心中台 | 双环境，流量切换 |
| 灰度发布 | 高风险变更 | 按租户/用户/比例路由 |

### 5.2 灰度发布流程

```
① 部署新版本（不导流量，Standby）
② 配置灰度规则（租户白名单 → 用户白名单 → 百分比）
③ 观察期（≥30min）：错误率、P95、告警
④ 全量发布（逐步放量 5%→20%→50%→100%）
⑤ 观察稳定后收敛
```

- 灰度规则由网关承载（`platform:gw:gray:manage`），支持粘滞（同一用户稳定命中）；
- 前端发布：静态资源 CDN 版本化 + 特性开关（Feature Flag）。

### 5.3 回滚

| 场景 | 动作 | 目标时限 |
|---|---|---|
| 应用异常 | 回滚镜像版本（ArgoCD `rollback`） | ≤ 5min |
| 数据库迁移 | 前向兼容脚本（避免破坏性 DDL）；必要时反向脚本 | ≤ 30min |
| 网关路由 | 切回旧版本路由 | ≤ 1min |
| 配置错误 | Nacos 配置回滚 + 推送 | ≤ 1min |

**原则**：数据库变更必须向前兼容（新增列可空/默认值），禁止在发布中执行破坏性 DDL；灰度回滚演练目标 ≤ 5min（实测 128s）。

### 5.4 令牌与签名密钥（PLAT-10）

| 项 | 当前行为 | 重启/发布影响 | 生产要求 |
|---|---|---|---|
| RSA 签名密钥 | auth 启动时在内存生成（dev） | 换钥后全部已签发 access token 验签失败（401）；实现 401→refresh 的端可用 refresh token 无感恢复，脚本、第三方直连、导出链路会中断 | 必须改为 KMS 或固定密钥文件（K8s Secret 挂载），**多副本共享同一密钥**，否则副本间验签随机失败 |
| access token | 864B，TTL 2h，claims 只含 `roles`+`pv` | 无影响 | 兼容期旧令牌（含 `permissions` claim）继续可用，自然过期后收敛 |
| 权限解析缓存 | 网关 L1 60s + Redis L2 10min，键 `tenant:user:pv` | 网关重启 L1 清空、L2 命中，无感 | 权限变更 ≤60s 生效；Redis 故障降级 L1 10s；auth 故障 fail-close 503 `FL-COMMON-0503` |
| 发布顺序 | — | 先滚动 auth（保持同一密钥）再滚动网关 | 禁止多副本 auth 各自生成密钥；未完成密钥持久化前，重启 auth 视为"全员重登"事件，需避开业务高峰 |

> 结论：**未落地密钥持久化之前，不允许把 auth 重启当作普通滚动发布**。对应缺口见总账 PLAT-15（阻塞）。

## 6 监控告警

### 6.1 监控体系

| 维度 | 工具 | 内容 |
|---|---|---|
| 指标 | Prometheus + Grafana | JVM、QPS、RT、错误率、连接池、中间件指标 |
| 日志 | Loki（采集）+ 结构化 JSON | 全服务日志，`X-Request-Id` 检索 |
| 链路 | SkyWalking | 全链路追踪（`X-Trace-Id`） |
| 业务 | 自研业务看板 | 租户用量、配额、SLA、待办积压、审计告警 |

### 6.2 核心指标与阈值

| 指标 | 阈值 | 告警级别 |
|---|---|---|
| 网关 P95 响应 | > 300ms 持续 5min | P2 |
| 接口错误率 | > 1% 持续 5min | P1 |
| JVM GC 停顿 | P99 > 300ms | P2 |
| CPU 使用率 | > 80% 持续 10min | P2 |
| DB 连接池使用率 | > 85% | P2 |
| 磁盘使用率 | > 80% | P2 |
| 可用性（黑盒探测） | < 99.99%（滚动） | P1 |
| 审计链校验失败 | 任意一次 | P0 |
| 跨租户访问尝试 | 任意一次 | P0 |
| 配额使用率 | ≥ 80% / 100% | P3 / P2 |
| 工作流超时任务 | > 阈值 | P3 |

### 6.3 告警通道

- P0/P1：电话 + 短信 + 企微/飞书群；
- P2：企微/飞书群 + 邮件；
- P3：站内信/邮件；
- 告警收敛（同源聚合）、抑制（维护窗口）、升级（15min 未响应升级）。

## 7 备份与恢复

### 7.1 备份策略

| 对象 | 方式 | 频率 | 保留 |
|---|---|---|---|
| PostgreSQL | pg_basebackup 全备 + WAL 归档 | 每日全备 + 持续增量 | 30 天（异地 90 天） |
| Redis | RDB + AOF | 每小时 RDB | 7 天 |
| Elasticsearch | 快照（snapshot） | 每日 | 14 天 |
| MinIO | 跨集群复制 | 实时/每小时 | 30 天 |
| Kafka | 副本（非备份） | — | Topic 保留策略 |
| 配置 | Nacos 配置导出 + Git | 每次变更 | 永久（Git） |

### 7.2 恢复演练

| 场景 | RTO 目标 | 实测 |
|---|---|---|
| 单 Pod 故障 | 自动重调度 ≤ 1min | 35s |
| 数据库主备切换 | ≤ 30min | 42s |
| 整机房故障（双活切换） | ≤ 30min | 8min |
| 数据误删恢复（PITR） | ≤ 30min | 18min |

**备份校验**：每月抽样恢复验证；季度完整演练并记录；备份加密（AES-256）。

## 8 巡检与应急预案

### 8.1 日常巡检清单

| 频率 | 项目 |
|---|---|
| 每日 | 服务健康、SLA、错误率、告警、慢查询、磁盘/连接池、备份成功 |
| 每周 | 证书有效期、配额使用、日志异常、安全告警复核 |
| 每月 | 依赖漏洞扫描、备份恢复抽样、容量趋势分析、索引健康 |
| 每季度 | 容灾演练、账号复核、权限审计、密钥轮换核查 |

### 8.2 应急预案

| 场景 | 应急措施 |
|---|---|
| 网关不可用 | 摘除故障 Pod + 扩容 + 切换备用入口；必要时降级非核心路由 |
| 认证服务异常 | JWKS 本地缓存兜底；缩短令牌有效期；修复后恢复 |
| 数据库故障 | Patroni 自动切换；只读副本提升；应用重连重试 |
| Redis 故障 | 降级本地缓存；限流放宽（风险窗口）；修复后恢复 |
| Kafka 积压 | 扩容消费者 + 增加分区；必要时降级非关键事件 |
| ES 故障 | 搜索降级数据库检索；重建索引 |
| AI 模型不可用 | 多模型路由 → 降级检索 → 提示用户 |
| 突发大流量 | 限流 + HPA 扩容 + CDN 缓存；必要时临时封禁异常来源 |
| 数据安全事件 | 立即隔离 + 冻结账号会话 + 取证（审计）+ 上报 |

**应急流程**：发现 → 定级 → 通知（值班/升级）→ 处置 → 恢复验证 → 复盘（RCA）→ 改进。

## 9 SaaS 与私有化部署方案

### 9.1 SaaS 多租户方案

| 项 | 方案 |
|---|---|
| 隔离 | 共享库 + `tenant_id` + RLS |
| 部署 | 多云/多可用区 K8s，共享中间件（逻辑隔离+配额） |
| 网络 | 公网 HTTPS（WAF），多租户共享入口 |
| 升级 | 平台统一灰度升级 |
| 计量 | 多租户计量归集与出账 |
| 适用 | 中小客户、快速开通 |

### 9.2 私有化单租户方案

| 项 | 方案 |
|---|---|
| 隔离 | 独立库（database per tenant），物理隔离 |
| 部署 | 客户内网/专有云 K8s，独立中间件 |
| 网络 | 内网部署，可选 VPN/专线回连 SaaS 智能中台 |
| 许可 | License 文件（含产品/席位/有效期） |
| 升级 | 版本包 + 升级脚本 + 回滚预案；支持离线镜像 |
| 适用 | 大型客户、强合规要求 |

### 9.3 混合方案

- 核心业务数据私有化部署（独立库），智能中台（search/ai/report）SaaS 化；
- 经 `/internal/**` mTLS 打通，数据脱敏后出域；
- 计量与计费统一归集至平台。

### 9.4 私有化部署检查清单

1. 环境预检（K8s 版本、节点资源、网络策略、存储类）；
2. 中间件部署与连通性验证；
3. 平台镜像加载与签名校验；
4. 数据库迁移与内置数据初始化；
5. License 导入与校验；
6. SSO 对接（客户 IdP）验证；
7. 冒烟测试 + 性能抽测；
8. 监控接入与告警配置；
9. 备份策略配置与首次备份；
10. 交付文档与运维交接。
