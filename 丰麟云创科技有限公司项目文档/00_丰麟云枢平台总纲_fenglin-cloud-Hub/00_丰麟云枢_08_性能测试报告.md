## 1 目标与指标

### 1.1 测试目标

验证丰麟云枢平台在 **3400 人在线并发**、核心接口 **峰值 ≥ 1200 QPS** 条件下满足 **可用性 99.99%**、**P95 ≤ 300ms / P99 ≤ 800ms**、**错误率 ≤ 0.1%** 的性能目标，并给出容量规划建议。

### 1.2 验收指标（对齐基线第 11 章）

| 指标 | 目标值 | 判定 |
|---|---|---|
| 并发用户 | 3400 在线 | 通过 |
| 峰值吞吐 | ≥ 1200 QPS（核心接口） | 通过 |
| P95 响应 | ≤ 300ms | 通过 |
| P99 响应 | ≤ 800ms | 通过 |
| 错误率 | ≤ 0.1% | 通过 |
| 可用性 | ≥ 99.99% | 通过（演练） |
| 首屏 | 4G ≤ 2s / 内网 ≤ 1s | 通过 |

## 3 场景设计

| 场景 | 编号 | 描述 | 目标 QPS/并发 | 权重 |
|---|---|---|---|---|

| 用户/组织列表 | P-04 | 用户列表分页查询（含数据权限） | 400 QPS | 10% |
| 工作流待办/审批 | P-05 | 我的待办列表 + 审批提交 | 300 QPS | 15% |
| 统一搜索 | P-06 | 混合检索（全文+向量） | 200 QPS | 10% |
| 审计写入 | P-07 | 异步审计埋点写入（含哈希链） | 1200 QPS | 10% |
| 消息推送 | P-08 | 站内信生成 + WS 推送 | 300 QPS | 5% |

## 4 结果与图表

### 4.1 混合场景总体结果（稳态 30min）

| 指标 | 结果 | 目标 | 判定 |
|---|---|---|---|
| 总请求数 | 2,160,000 | — | — |
| 峰值 QPS | **1,286** | ≥ 1200 | ✔ |
| 平均响应时间 | 96ms | — | ✔ |
| P95 响应 | **212ms** | ≤ 300ms | ✔ |
| P99 响应 | **523ms** | ≤ 800ms | ✔ |
| 错误率 | **0.04%** | ≤ 0.1% | ✔ |
| 网关本机 CPU | 62% | ≤ 80% | ✔ |
| DB 主库 CPU | 58% | ≤ 80% | ✔ |

### 4.2 分场景结果

| 场景 | QPS | 平均 RT | P95 | P99 | 错误率 | 判定 |
|---|---|---|---|---|---|---|

| P-03 鉴权决策 | 1,520 | 12ms | 31ms | 68ms | 0.00% | ✔ |
| P-04 用户列表 | 405 | 88ms | 224ms | 486ms | 0.03% | ✔ |
| P-05 工作流待办/审批 | 308 | 104ms | 268ms | 612ms | 0.05% | ✔ |
| P-06 统一搜索 | 206 | 132ms | 288ms | 742ms | 0.06% | ✔ |

\* AI 场景为流式生成，RT 指整段完成时间；关键指标为首 Token 延迟（TTFT）P95 = 986ms（≤ 1.2s 达标）。

### 4.3 阶梯加压曲线（关键节点）

| 阶梯 QPS | 平均 RT | P95 | 错误率 | 备注 |
|---|---|---|---|---|
| 300 | 62ms | 138ms | 0.00% | 平稳 |
| 600 | 78ms | 176ms | 0.01% | 平稳 |
| 900 | 92ms | 204ms | 0.03% | HPA 扩容触发 |
| 1200 | 108ms | 214ms | 0.04% | 达标 |
| 1500 | 186ms | 512ms | 0.42% | 出现排队，限流介入 |

**结论**：峰值 1200 QPS 时延余量充足；1500 QPS 为容量拐点，限流按配置生效（错误率上升但服务未崩溃，可用性保持）。

### 4.4 稳定性与可用性

- 稳态 30min 内无节点重启、无 OOM；错误率稳定 0.04%；
- 双活切换演练：主库切换 42s，RPO = 1.8min（≤ 5min）、RTO = 8min（≤ 30min），达标；
- 灰度回滚演练：回滚耗时 128s（≤ 5min），达标；
- 可用性推算：以演练与稳态数据推算年度可用性 ≥ 99.99%。

## 5 瓶颈分析

| 编号 | 瓶颈 | 现象 | 根因 | 影响 |
|---|---|---|---|---|
| B-01 | 鉴权决策数据库查询 | P-03 在 1500 QPS 时 DB 读放大 | 权限/数据范围每次查库 | P99 上升 |
| B-02 | 工作流待办列表慢查询 | P-05 P99 612ms | `hub_wf_task` 多条件组合未命中复合索引 | 待办延迟 |
| B-03 | 搜索深分页 | P-06 深分页（from>5000）RT 上升 | `from+size` 深分页开销 | 检索变慢 |
| B-04 | 审计哈希链串行写入 | P-07 高峰写放大 | 链式哈希需前序哈希 | 写入吞吐受限 |
| B-05 | 报表聚合查询 | P-09 冷查询 P99 688ms | 首次无缓存直查大表 | 首屏慢 |
| B-06 | DB 连接池 | 高并发下连接等待 | HikariCP 池偏小 | RT 抖动 |
| B-07 | 向量检索 | P-10 检索阶段占 TTFT 40% | 向量库并发参数保守 | 首 Token 延迟 |

## 6 调优措施

| 编号 | 措施 | 实施 | 效果 |
|---|---|---|---|
| O-01 | 鉴权决策结果缓存（用户维度 TTL 5min + 变更广播失效） | Redis + Caffeine 二级缓存 | P-03 P99 由 96ms→68ms，DB 读降 85% |
| O-02 | `hub_wf_task` 建复合索引 `(tenant_id,assignee_id,status,created_at)` | Flyway V1_0_15 | 待办 P95 由 380ms→268ms |
| O-03 | 搜索深分页改 `search_after` + 限制最大页深 | search-service | P-06 稳定 ≤ 300ms |
| O-04 | 审计分片哈希链（按租户分片并行）+ 批量提交 | audit-service | 写入吞吐提升 2.3× |
| O-05 | 看板预聚合 + 结果缓存（TTL 5min） | report-service + Redis | 冷查询 P95 由 620ms→296ms |
| O-06 | HikariCP 池调整（max 50→80）+ PgBouncer | DB 侧 | 连接等待消除 |
| O-07 | 向量库并发参数调优 + 检索结果缓存 | ai-service | TTFT P95 由 1.18s→0.99s |
| O-08 | 网关 JWKS 本地缓存 + 令牌黑名单本地缓存 | gateway | P-01 P99 ≤ 96ms |

**PostgreSQL 关键参数调优**：`shared_buffers=16GB`、`work_mem=64MB`、`effective_cache_size=48GB`、`max_connections` 配合 PgBouncer、`random_page_cost=1.1`（SSD）。

**JVM 调优**：`-Xms8g -Xmx8g -XX:+UseG1GC -XX:MaxGCPauseMillis=200 -XX:ActiveProcessorCount=4`；GC 停顿 P99 ≤ 180ms。

## 7 结论与容量建议

### 7.1 结论

1. 平台在 **1200 QPS / 3400 并发** 下 **P95 = 212ms、P99 = 523ms、错误率 0.04%**，**全部指标达标**；
2. 鉴权决策、工作流待办、统一搜索、报表看板为高耗资源场景，经调优后均满足目标；
3. 审计写入采用异步+分片哈希链，满足全链路审计与防篡改的性能要求；
4. AI 问答首 Token P95 = 986ms，满足 ≤ 1.2s 目标；依赖外部模型时延，建议配置降级与多模型路由；
5. 可用性通过双活切换与灰度回滚演练验证，满足 99.99% 与 RPO/RTO 目标。

### 7.2 容量建议

| 维度 | 当前配置 | 建议容量 | 说明 |
|---|---|---|---|
| 网关副本 | 3 | 3–10（HPA） | CPU ≥ 70% 扩容 |
| 鉴权决策 | 缓存命中率 ≥ 95% | Redis 集群 3 节点 | 变更广播保证一致性 |
| 数据库 | 16C64G 主备 | 32C128G + 2 只读副本 | 数据量 > 5000 万行时扩容 |
| Elasticsearch | 3 节点 | 每 1000 万文档增 1 节点 | 分片副本 ≥ 1 |
| Kafka | 3 副本 | 按事件量扩分区（≥ 6） | `min.insync.replicas=2` |
| 审计存储 | 热 12 个月 | 冷归档 MinIO + WORM | 日均 500 万行 |
| 扩容拐点 | 1200 QPS 达标 | 1500 QPS 触发限流 | 提前扩容至 2× 冗余 |

### 7.3 后续优化项

- 引入读写分离路由（@ReadOnly）进一步分流查询；
- 审计/消息写入进一步异步化与批量合并；
- 向量库水平扩展与索引量化（降低内存）；
- 报表层引入列式存储（ClickHouse 可选）承载大宽表分析。
