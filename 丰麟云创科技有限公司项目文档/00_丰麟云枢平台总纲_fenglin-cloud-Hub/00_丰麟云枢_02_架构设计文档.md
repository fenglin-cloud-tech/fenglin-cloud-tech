## 1 架构概览

### 1.1 架构定位

丰麟云枢（Fenglin Cloud Hub）是丰麟云创企业综合管理操作系统，采用「**微服务中台 + 8 大业务域产品矩阵 + 开放 API 生态**」架构，是 8 大业务域产品（云销/云协/云才/云财/云研/云服/云法/云智）的总纲与底座。核心设计取向：

- **一个中枢贯通八大业务域**：13 个中台服务统一提供身份、租户、权限、流程、消息、文件、审计、搜索、开放、报表、低代码、AI 能力，8 大产品零重复建设、按标准契约调用；
- **能力即服务（Capability as a Service）**：中台能力以 OpenAPI 3.1 契约对外发布，8 大产品与云智双模式统一复用；
- **双端分离**：管理端（`/admin/**`）与用户端（`/app/**`）分离，网关按 `X-Client-Type` 执行差异化鉴权与路由；
- **多形态交付**：SaaS 多租户（共享库 + RLS）、私有化单租户（独立库）、混合部署（核心私有 + 智能 SaaS 化）三种隔离策略由同一套代码承载，由配置驱动。

### 1.2 架构原则

| 原则 | 说明 |
|---|---|
| 中台唯一 | 通用能力仅在中台实现一次，禁止业务域重复建设 |
| 契约优先 | 能力先定 OpenAPI 3.1 契约，再实现，跨域调用一律走契约 |
| 能力可嵌入 | 中台能力可被 8 大产品以 embedded 模式内嵌使用，计费计量归集到宿主产品 |
| 多租户强隔离 | `tenant_id` + RLS，跨租户默认拒绝，跨租户仅平台运营端且强审计 |
| 端别清晰 | 术语统一为"管理端/用户端"，配置类归管理端、操作类归用户端 |
| 灰度与降级 | 一切依赖可降级、可熔断、可灰度、可回滚 |
| 可观测优先 | `X-Request-Id`/`X-Trace-Id` 贯穿全链路，指标/日志/追踪三位一体 |
| 安全内建 | 传输/存储加密、KMS、最小权限、三员分立、全链路审计 |

## 2 分层与部署图

### 2.1 逻辑分层

| 层 | 组件 | 职责 |
|---|---|---|
| 接入层 | 管理端 UI、用户端 UI、移动端 PWA、开放 API 调用方 | 交互与请求发起 |
| 网关层 | `fenglin-gateway`、`fenglin-openapi-service` | 统一鉴权、端别识别、限流熔断（Sentinel）、路由、灰度、审计埋点 |
| 中台层 | 13 个 `fenglin-hub-*` 服务 | 身份/租户/权限/流程/消息/文件/审计/搜索/报表/低代码/AI/开放 |
| 业务域层 | 8 个 `fenglin-{domain}-service` | 8 大产品领域逻辑与聚合根 |
| 数据层 | PostgreSQL/Redis/ES/Kafka/RocketMQ/MinIO/向量库/XXL-Job | 持久化、缓存、检索、消息、对象存储、任务调度 |

### 2.2 应用内部分层（以 `fenglin-iam-service` 为例）


**部署形态**：
- **SaaS**：多租户共享库共享模式 + `tenant_id` + RLS；
- **私有化**：独立库（database per tenant）、独立中间件，可选单机房主备或双活；
- **混合**：核心业务数据私有化部署，智能中台（search/ai/bi）以 SaaS 方式嵌入，经 `/internal/**` mTLS 打通。

## 4 关键流程时序

### 4.1 SSO 统一登录（OIDC 授权码 + PKCE）

```
用户         管理端/用户端 UI    gateway      auth-service     iam-service    session/Redis
 │  访问受保护资源  │              │              │                │              │
 ├───────────────▶│  302 /sso/authorize         │                │              │
 │                ├─────────────▶│ 路由校验(白名单)│                │              │
 │                │              ├─────────────▶│ 1 校验 client_id/redirect_uri │
 │                │              │              │ 2 生成 code（PKCE challenge 绑定）
 │                │              │              ├───────────────▶│ 3 用户认证（口令/MFA/SSO 联邦）
 │                │              │              │                │ 4 加载用户+租户+角色+权限
 │                │              │              │◀───────────────┤ 5 写 session（Redis）
 │                │  302 callback?code=xxx      │                │
 │                │◀─────────────┤              │                │
 │                ├────────────────────────────▶│ 6 换 token（code+verifier）
 │                │◀────────────────────────────┤ 7 签发 access_token(JWT RS256)/refresh/id
 │  8 携带 Bearer 调用业务接口                    │                │
 ├───────────────▶│  Authorization: Bearer ...   │                │
 │                ├─────────────▶│ 9 本地验签(JWKS)+黑名单校验+client_type 校验
 │                │              ├─────────────────────────────▶（后续请求 O(1) 验签，不落库）
 │◀───────────────┴──────────────┤ 10 注入 X-User-Id/X-Tenant-Id/X-Client-Type 转发业务服务
```

**要点**：JWKS 公钥本地缓存（TTL 5min），令牌撤销走 Redis 黑名单；`client_type` = `ADMIN`/`PORTAL` 决定端别路由。

### 4.2 跨域工单流转（云服工单 → 云财成本 / 跨域事件）

```
用户        云服 service      workflow      事件总线(Kafka)   云财 service    消息中心
 │ 提交跨域工单 │                │                │                │              │
 ├────────────▶│ 1 建单（含关联域/业务键）        │                │              │
 │             ├───────────────▶│ 2 部署/发起跨域流程实例（businessKey=工单号）
 │             │                │ 3 节点审批（按域动态路由审批人）│              │
 │             │                ├───────────────▶│ 4 事件 svc.ticket.approved
 │             │                │                ├───────────────▶│ 5 触发成本归集（幂等）
 │             │                │                │◀───────────────┤ 6 回写结果 finance.cost.booked
 │             │◀───────────────┤ 7 流程结束回调（幂等）            │
 │             ├────────────────────────────────────────────────────────────────▶│ 8 多通道通知
 │◀────────────┘                │                │                │              │
```

跨域一致性：金额/结算类采用 Seata AT（强一致）；其余采用 Kafka 事件 + 本地消息表（最终一致）+ 幂等消费。

### 4.3 统一审批（Flowable）

```
发起人 → 提交单据 → workflow-service 解析流程定义（条件分支：金额/部门/等级）
      → 生成任务（候选人/候选组）→ message-service 通知审批人
      → 审批人处理（同意/驳回/加签/转办）→ 条件网关判定下一节点
      → 全部通过：流程结束 → 回调业务系统（幂等）→ 状态更新 + 事件发布
      → 任一驳回：返回发起人 → 记录意见 → 可重新提交（新实例，幂等键隔离）
超时：XXL-Job 扫描超时任务 → 催办 → 升级至上级（可配置）
Idempotency-Key：审批提交、回调均强制幂等
```

### 4.4 开放 API 调用（签名 + 配额）

```
第三方应用        openapi-service       gateway        目标中台/业务服务
   │ POST /openapi/crm/v1/leads            │                  │
   │ Header: X-App-Key, X-Timestamp, X-Nonce, X-Signature     │
   ├───────────────▶│ 1 校验应用状态与授权范围                 │
   │                │ 2 验签 HMAC-SHA256(AppSecret, method+path+ts+nonce+bodyHash)
   │                │ 3 防重放（nonce+ts ≤5min，Redis 去重）   │
   │                │ 4 配额/限流校验（应用+接口维度），超限 0000006
   │                │ 5 转换为内部令牌（服务身份 + 授权租户） │
   │                ├────────────────────────────────────────▶│ 6 执行
   │◀───────────────┤ 7 统一响应体 + 调用日志落库（审计/计量）│
```

### 4.5 能力嵌入调用（云智 embedded）

```
业务产品(crm)                       fenglin-ai-service           计量/审计
   │ POST /internal/v1/copilot/rag  (mTLS)  │                       │
   │ Header: X-Caller-Product=crm, X-Tenant-Id, X-On-Behalf-Of=用户 │
   ├───────────────────────────────────────▶│ 1 校验 ai_capability_grant
   │                                         │ 2 以 X-On-Behalf-Of 解析用户数据权限
   │                                         │ 3 执行检索+生成（护栏）
   │◀───────────────────────────────────────┤ 4 返回答案+引用
   │                                         ├──────────────────────▶│ 5 计量上报（Token）
```

## 5 数据架构

### 5.1 数据存储分布

| 存储 | 用途 | 关键设计 |
|---|---|---|
| PostgreSQL 15（`fenglin_hub`） | 平台主数据 | 表前缀 `hub_`；`tenant_id` + RLS；大表分区 |
| PostgreSQL 15（各域库） | 业务域数据 | `fenglin_crm`/`fenglin_collab`/… |
| Redis 7 | 缓存/分布式锁/会话/限流/幂等 | 令牌黑名单、幂等键、热点配置、登录会话 |
| Elasticsearch 8 | 统一全文检索 | 平台索引 `hub_*`，8 域索引，IK 分词 |
| 向量库（pgvector/Milvus） | 语义检索/RAG | 云智知识库向量集合 |
| Kafka 3.6 | 事件总线 | Topic 命名 `{domain}.{entity}.{action}` |
| RocketMQ 5.x | 事务消息 | 计量计费、跨域强一致（配 Seata） |
| MinIO | 对象存储 | 文件、导入导出、报表产物、备份 |
| XXL-Job | 任务调度 | 计量归集、审计归档、索引重建、超时催办 |

### 5.2 多租户隔离设计

| 部署形态 | 隔离策略 | 实现 |
|---|---|---|
| SaaS 多租户 | 共享库共享模式 + `tenant_id` 逻辑隔离 + RLS | 所有表含 `tenant_id`，RLS 策略 `USING (tenant_id = current_setting('app.tenant_id')::bigint)` |
| 私有化单租户 | 独立库（database per tenant） | 每租户独立 schema/库，物理隔离 |
| 混合部署 | 核心数据私有库 + 智能中台 SaaS 化 | 私有库 + `/internal/**` mTLS 打通 |

- 平台全局配置表（套餐、字典类型）可不含 `tenant_id`，其余强制；
- 跨租户查询仅平台运营端（`platform:*`）可执行，且强制落审计并告警。

### 5.3 数据一致性与缓存

- 域内强一致：本地事务（`@Transactional`）；
- 跨域强一致（计量扣费、额度扣减、结算）：Seata AT 模式；
- 跨域最终一致：Kafka 事件 + 本地消息表/事务消息 + 幂等消费；
- 缓存：本地 Caffeine + Redis 二级缓存（配置类，变更失效）；分布式锁 Redisson；幂等键 `idem:{tenant}:{key}` 24h。

### 5.4 数据流与治理

```
业务写入 → PostgreSQL（RLS）→ 事务消息/事件 → Kafka → 消费方（search 建索引/audit 落审计/report 更新指标/AI 训练语料）
定时任务（XXL-Job）→ 计量归集（tenant-service）→ 出账（report-service）→ 账单核对
```

## 8 高可用与容灾

### 8.1 高可用设计

| 层次 | 措施 |
|---|---|
| 接入 | SLB + WAF + 多可用区 Ingress；DNS 智能解析 |
| 应用 | Pod 多副本 + HPA + 就绪/存活探针 + 优雅停机；无状态化，会话外置 |
| 网关 | 多副本 + Sentinel 熔断降级 + 灰度路由 |
| 认证 | auth 多副本 + JWKS 多节点缓存 + 令牌黑名单多级 |
| 数据库 | Patroni 主备自动切换 + 只读副本分流 + 连接池（HikariCP） |
| 缓存 | Redis 哨兵/集群 + 持久化（AOF+RDB） |
| 消息 | Kafka 3 副本 + `min.insync.replicas=2`；RocketMQ 主从 |
| 搜索 | ES 3 节点 + 分片副本 ≥ 1 |
| 存储 | MinIO 纠删码多节点 |

### 8.2 容灾目标

| 指标 | 目标 |
|---|---|
| 可用性 | ≥ 99.99%（年不可用 ≤ 52.6 分钟） |
| RPO | ≤ 5 分钟 |
| RTO | ≤ 30 分钟 |
| 架构 | 同城双活（双机房），核心库跨机房流复制 |
| 备份 | 每日全备 + 增量（WAL 归档），异地备份，季度演练 |

### 8.3 降级策略

| 依赖不可用 | 降级 |
|---|---|
| ai-service | RAG 降级为纯检索结果；文本能力返回模板；提示 degraded |
| search-service | 回退数据库 LIKE 检索（限流） |
| report-service | 回退缓存快照（标注数据时间） |
| message-service | 消息进入本地重试表，恢复后补发 |
| workflow-service | 审批暂存队列，恢复后继续（保证幂等） |
| file-service | 预览降级为下载；禁用在线转换 |
| 向量库 | 降级为全文检索（RRF 权重置 0） |

## 9 安全架构

### 9.1 分层防护

| 层 | 措施 |
|---|---|
| 网络 | WAF、IDS/IPS、网络分区、微服务间 mTLS、最小开放端口 |
| 应用 | OAuth2.1/OIDC、JWT(RS256)、MFA、RBAC+ABAC、数据/字段权限、CSRF/XSS 防护 |
| 数据 | AES-256-GCM（PII/密钥）、TDE、KMS、`*_hash` 检索、备份加密 |
| 审计 | 全链路审计、哈希链 + WORM、留存 ≥ 6 个月 |
| 运维 | 三员分立（系统管理员/安全管理员/审计管理员）、堡垒机、镜像扫描、依赖 SCA |

### 9.2 身份与权限体系

- **4A**：认证（IAM+OAuth2.1/OIDC+SSO+MFA）、授权（RBAC+ABAC+数据权限）、账号（生命周期+复核）、审计（全链路）；
- **权限粒度**：功能（菜单/按钮/接口，`{域}:{模块}:{操作}`）、数据（五档 `data_scope`）、字段（隐藏/脱敏）、租户边界（默认拒绝）；
- **三员分立**：系统管理员负责系统配置与运行维护，安全管理员负责密钥与安全策略，审计管理员负责审计复核，相互制约。

### 9.3 密钥与加密

| 项 | 措施 |
|---|---|
| KMS | 统一密钥管理服务，密钥分层（根密钥/数据密钥） |
| 轮换 | 数据密钥 ≤ 90 天轮换，支持重加密 |
| 字段加密 | PII/AppSecret/AI apiKey AES-256-GCM + `*_hash` |
| 传输 | 客户端↔网关 TLS1.3，服务间 mTLS |
| 剩余信息 | 存储/内存清理、介质销毁 |

### 9.4 安全控制要点

1. 越权：跨租户默认拒绝，数据权限行/列级 SQL 拦截；
2. 口令：复杂度 + 5 次失败锁定 + 90 天轮换 + 会话 30min 超时；
3. 审计：登录/鉴权/数据变更/配置变更/导出/密钥变更全量审计，防篡改；
4. 三员分立与最小权限、堡垒机运维；
5. 供应链：镜像扫描、依赖 SCA、SBOM 管理。

详见 FL-HUB-SEC-009《安全评估报告》。

## 10 技术风险

| 编号 | 风险 | 影响 | 概率 | 应对 |
|---|---|---|---|---|
| R-01 | 中台能力成为全局单点（gateway/auth/iam 故障致平台不可用） | 平台级不可用 | 中 | 多副本+多可用区+无状态+降级预案；JWKS 本地缓存 |
| R-02 | 多租户 RLS 策略遗漏导致数据越权 | 数据泄露 | 低 | RLS 强制模板化 + 自动化越权测试 + 上线前扫描 |
| R-03 | 开放 API 被滥用/配额击穿 | 资源争抢 | 中 | 应用+接口双重限流、配额预警、异常调用风控 |
| R-04 | 审计日志量激增（3400 人全链路） | 存储与查询压力 | 中 | 分区 + 冷热分层 + WORM 归档 + 采样（非核心） |
| R-05 | AI 能力依赖外部大模型不可用 | 智能能力降级 | 中 | 多模型路由 + 降级为检索 + 私有化模型兜底 |
| R-06 | 计量误差导致计费争议 | 商务风险 | 低 | 幂等计量 + 日对账 + 误差阈值告警 |
| R-07 | 跨域强一致场景（额度扣减）失败 | 数据不一致 | 低 | Seata AT + 幂等 + 补偿任务 |
| R-08 | 峰值流量（月初/季末集中开票与报表） | 响应劣化 | 中 | HPA + 限流 + 缓存 + 压测容量规划 + 异步化 |
| R-09 | 私有化部署环境差异（中间件版本/网络） | 交付延期 | 中 | 交付基线镜像 + 部署自检脚本 + 预检清单 |
| R-10 | 云智双模式配置不一致 | 能力越界暴露 | 低 | 模式一致性校验接口 + 启动自检 + 审计 |
