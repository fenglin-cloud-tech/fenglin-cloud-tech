### 1.3 管理端与用户端分离架构（强制）

平台所有产品**必须**采用「管理端 / 用户端」双端分离架构，分离维度包括：前端工程、路由命名空间、权限域、导航结构、首页形态、审计粒度。术语统一如下：

| 端 | 中文表述 | 使用主体 | 前端工程命名 | 路由前缀 | 权限域 |
|---|---|---|---|---|---|
| 管理端 | 平台运营端 / 租户管理端 | 平台运营人员、租户管理员、系统管理员 | `fenglin-hub-admin-ui` | `/admin/**` | `platform:*`、`tenant:*` |
| 用户端 | 业务用户端 / 员工工作台 | 企业员工、业务使用者 | `fenglin-hub-portal-ui` | `/app/**` | `biz:*` |

约定：
1. 涉及"配置、授权、审核、报表定义、租户治理"的能力归**管理端**；涉及"日常业务操作、协同、查询、填报"的能力归**用户端**。
2. 两端共用同一套设计令牌（Design Token，见第 9 章），但导航骨架、信息密度、默认首页不同。
3. 后端通过统一令牌中的 `client_type`（`ADMIN`/`PORTAL`）声明端别，网关据此执行路由与鉴权策略。
4. 本规范全部文档中，"管理端/用户端分离"一律以上表术语表述，避免出现"后台/前台""admin 端/用户端"等混用。

## 5. 接口规范（强制）

### 5.1 基本约定

- 协议：HTTPS（TLS 1.2+，推荐 1.3）；内部服务间 mTLS。
- 风格：RESTful + 资源化；动作型复杂接口允许 `POST /{resource}/{action}`。
- 版本：URL 版本段（`/v1`），重大不兼容变更升 `v2`，不删除旧版本至少 12 个月。
- 数据格式：`application/json; charset=UTF-8`；文件上传 `multipart/form-data`。
- 时间格式：ISO-8601（`yyyy-MM-dd'T'HH:mm:ss.SSSXXX`），存储统一 UTC。
- 分页：`page`（从 1 开始）、`size`（默认 20，最大 200）。
- 幂等：写操作支持 `Idempotency-Key` 请求头；金额、库存、审批类操作强制幂等。
- 追踪：请求头 `X-Request-Id`（网关生成贯穿全链路）、`X-Trace-Id`（SkyWalking）。

### 5.2 请求头约定

| 名称 | 必填 | 说明 |
|---|---|---|
| `Authorization` | 是 | `Bearer {access_token}`（JWT RS256） |
| `X-Tenant-Id` | 是 | 租户标识（网关校验与令牌一致性） |
| `X-Client-Type` | 是 | `ADMIN` / `PORTAL`，声明端别 |
| `X-Request-Id` | 否 | 幂等与追踪；网关缺失时自动生成 |
| `Accept-Language` | 否 | `zh-CN` / `en-US` |
| `Idempotency-Key` | 否 | 写操作幂等键（24h 内有效） |

### 5.3 统一响应体

```json
{
  "code": "0",
  "message": "success",
  "data": {},
  "requestId": "b1f2c3d4-...",
  "timestamp": "2026-10-19T08:00:00.000+08:00"
}
```

- `code`：`"0"` 表示成功；非 `0` 为标准错误码（见 5.4）。字符串类型，避免前端大整数精度问题。
- 分页响应 `data` 结构：`{ "records": [], "total": 0, "page": 1, "size": 20 }`。
- 错误响应 HTTP 状态码与业务码并行：鉴权失败 `401`、越权 `403`、资源不存在 `404`、参数错误 `400`、限流 `429`、服务端错误 `500`。

### 5.4 错误码规范

错误码结构：`{域(2位)}{模块(2位)}{序号(3位)}`，字符串。

| 域 | 前缀 | 域 | 前缀 |
|---|---|---|---|
| 平台通用 | `00` | 云研 | `50` |
| 云销 | `10` | 云服 | `60` |
| 云协 | `20` | 云法 | `70` |
| 云才 | `30` | 云智 | `80` |
| 云财 | `40` | — | — |

通用错误码（各域复用）：

| 错误码 | HTTP | 含义 |
|---|---|---|
| `0000001` | 401 | 未认证或令牌失效 |
| `0000002` | 403 | 无权限（功能或数据） |
| `0000003` | 400 | 参数校验失败 |
| `0000004` | 404 | 资源不存在 |
| `0000005` | 409 | 状态冲突（并发/重复提交） |
| `0000006` | 429 | 触发限流 |
| `0000007` | 500 | 系统内部错误 |
| `0000008` | 503 | 依赖服务不可用 |
| `0000101` | 403 | 租户配额不足 |
| `0000102` | 403 | 许可（License）过期 |

### 5.5 接口文档要求

- 每个产品必须提供 OpenAPI 3.1 契约（`openapi.yaml`）与《接口文档》Markdown。
- 每个接口必须包含：接口名、方法、路径、鉴权要求、请求头、路径/查询/请求体参数（类型、必填、约束）、响应示例、错误码、幂等说明、限流阈值、端别（ADMIN/PORTAL）。
- 对外/跨域接口必须遵守 5.1–5.4；域内私有接口可精简但需登记。

## 6. 数据模型规范（强制）

### 6.1 多租户模型

| 部署形态 | 隔离策略 | 说明 |
|---|---|---|
| SaaS 多租户 | 共享库共享模式 + `tenant_id` 逻辑隔离 + PostgreSQL RLS 行级安全 | 默认形态 |
| 私有化单租户 | 独立库（database per tenant） | 高合规客户 |
| 混合部署 | 核心数据私有库 + 智能中台 SaaS 化 | 云智能力嵌入场景 |

- 所有业务表**必须**包含 `tenant_id`（除平台全局配置表），并建立 RLS 策略。
- 跨租户查询仅限平台运营端（`platform:*` 权限）并强制审计。

### 6.2 主键与公共字段（强制）

所有业务表必须包含：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | `bigint` / `uuid` | 主键；高并发写用雪花 ID（bigint），对外暴露用 uuid |
| `tenant_id` | `bigint` | 租户 ID |
| `created_by` | `bigint` | 创建人 |
| `created_at` | `timestamptz` | 创建时间（UTC） |
| `updated_by` | `bigint` | 更新人 |
| `updated_at` | `timestamptz` | 更新时间（UTC） |
| `deleted` | `smallint` | 逻辑删除：0 正常 / 1 删除 |
| `version` | `int` | 乐观锁 |

### 6.3 敏感数据与加密（强制）

- PII 字段（员工手机号、线索/客户手机号、身份证号、银行卡号等）**必须**使用 **AES-256-GCM** 加密存储，密钥由 KMS 管理、支持轮换。
- 加密字段**必须**同时保存 `{field}_hash`（SHA-256 + 租户盐）用于唯一性约束与检索，**禁止**在明文列上建唯一索引。
- 展示层必须脱敏（手机号 `138****8888`、身份证 `110***********1234`）。
- 加密/解密通过自定义 MyBatis `TypeHandler` 透明实现，业务代码不感知。

### 6.4 数据库迁移（强制）

- 所有 DDL/DML 变更**必须**通过 Flyway 脚本提交，命名：`V{版本}__{描述}.sql`（如 `V1_0_3__add_crm_lead_hash.sql`）。
- 禁止手工改库；生产环境迁移纳入发布流水线并留痕审计。
- 每个产品交付《数据库设计文档》需包含：ER 图、表清单、字段字典、索引设计、RLS 策略、Flyway 脚本清单。

### 6.5 数据字典与编码

统一编码规则（跨域共享）：

| 对象 | 编码规则 | 示例 |
|---|---|---|
| 租户 | `T{6位}` | `T000001` |

## 7. 统一身份与权限模型（强制）

### 7.1 4A 体系

| 能力 | 实现 |
|---|---|
| 认证 Authentication | 统一 IAM + OAuth2.1/OIDC + SSO（SAML2/企微/飞书/钉钉）+ MFA |
| 授权 Authorization | RBAC（角色）+ ABAC（属性）+ 数据权限（行/列级） |
| 账号 Account | 生命周期管理、离职联动、定期复核 |
| 审计 Audit | 全链路操作审计、不可篡改存储、留存 ≥ 6 个月（等保要求） |

### 7.2 权限粒度

- **功能权限**：菜单/按钮/接口三级，权限码 `{域}:{模块}:{操作}`，如 `crm:lead:export`。
- **数据权限（规划，当前未实现）**：本人 / 本部门 / 本部门及下级 / 指定部门 / 全部。`hub_role.data_scope` 为保留字段，当前不参与鉴权；实际范围由权限码区分——租户级码对应「全部」，`*:self:*` 码对应「本人」并由 `/my` 接口在服务端强制收敛。
- **字段权限**：敏感字段按角色隐藏或脱敏。
- **租户边界**：任何跨租户访问默认拒绝。

### 7.3 角色基线（各产品继承）

| 角色 | 端 | 说明 |
|---|---|---|
| 平台超级管理员 | 管理端 | 平台级最高权限（运维专用、强审计） |
| 平台运维 | 管理端 | 租户/套餐/监控/灰度 |
| 租户管理员 | 管理端 | 本租户配置、组织、角色、权限 |
| 业务管理员 | 管理端 | 本域配置、审批、报表 |
| 业务用户 | 用户端 | 日常业务操作 |
| 只读/访客 | 用户端 | 受限查看 |

## 8. 安全与等保三级控制矩阵（强制）

平台整体**必须**通过网络安全等级保护三级测评。控制矩阵（摘取核心项，各产品《安全评估报告》须逐项对照）：

| 控制类别 | 控制项 | 平台措施 |
|---|---|---|
| 身份鉴别 | 双因子/强口令/登录失败锁定 | MFA、口令复杂度、5 次锁定、会话超时 30min |
| 访问控制 | 最小权限、职责分离 | RBAC+ABAC+数据权限、三员分立 |
| 安全审计 | 全量审计、防篡改 | 全链路审计日志、哈希链、WORM、留存 ≥6 个月 |
| 入侵防范 | 边界防护、攻击检测 | WAF、IDS/IPS、Sentinel 流控、漏洞扫描 |
| 恶意代码防范 | 主机/应用防护 | 主机 HIDS、镜像扫描、依赖 SCA |
| 数据完整性 | 传输/存储完整性 | TLS1.3、HMAC、数据库校验 |
| 数据保密性 | 传输/存储加密 | TLS、AES-256-GCM、密钥 KMS 管理 |
| 数据备份恢复 | 本地+异地备份、演练 | 每日全备+增量、异地容灾、季度演练 |
| 剩余信息保护 | 数据擦除 | 存储/内存剩余信息清理、介质销毁 |
| 个人信息保护 | 最小必要、脱敏、同意 | PII 加密、脱敏、授权访问、审计 |
| 安全管理 | 制度、机构、人员、建设、运维 | 安全管理制度体系、三员分立、应急预案 |

补充要求：
- 全链路加密：客户端↔网关 TLS1.3，微服务间 mTLS。
- 存储加密：PII 字段 AES-256-GCM；数据库透明加密（TDE）。
- 密钥管理：KMS + 定期轮换（≤ 90 天）。
- 日志留存：操作审计 ≥ 6 个月（建议 12 个月），安全日志 ≥ 6 个月。

## 13. 丰麟云智双模式规范（强制）

| 模式 | 说明 | 交付形态 | 控制方式 |
|---|---|---|---|
| 模式① 独立产品模式 | 作为独立 SaaS 产品对外售卖，提供完整知识检索、AI Copilot、BI 洞察 | 独立租户、独立门户、独立计费 | 部署配置 `intelligence.mode=standalone` |
| 模式② 能力嵌入模式 | 以智能中台服务形式，为其余 7 款业务产品输出 AI、检索、BI 能力 | 各业务产品按需启用智能能力，统一由 `fenglin-ai-service`/`fenglin-search-service` 提供 | 部署配置 `intelligence.mode=embedded` |

约定：
- 两模式由**部署配置**控制，同一套代码；`standalone` 额外暴露面向前台用户的知识搜索/Copilot/BI 门户，`embedded` 仅暴露内部能力接口（`/api/intelligence/v1/**` 内部化 + `/internal/**`）。
- 嵌入模式下，业务产品通过标准能力契约调用智能能力（见云智《接口文档》能力契约章节）。
- 计费与计量：`standalone` 按席位/调用量计费；`embedded` 按能力调用计量计入宿主产品。
