## 1 设计原则

1. **统一公共字段**：所有平台业务表含 `id`、`tenant_id`、`created_by`、`created_at`、`updated_by`、`updated_at`、`deleted`、`version`（审计四字段见基线 6.2）。
2. **多租户强制**：除平台全局配置表（`hub_package`、`hub_dict_type`、`hub_metric`、`hub_permission`、`hub_menu` 等）外，一律含 `tenant_id` 并启用 RLS。
3. **主键策略**：高并发写表（日志/计量/消息/审计）用雪花 ID（`bigint`）；主数据表同时提供 `uuid`（对外暴露）。
4. **逻辑删除**：`deleted` 0/1，配合 `version` 乐观锁；查询默认过滤 `deleted=0`。
5. **时间统一 UTC**：`timestamptz`，展示层按租户时区转换。
6. **敏感字段加密**：PII、AppSecret、AI apiKey 使用 AES-256-GCM 加密列 + `{field}_hash` 检索列（SHA-256 + 租户盐）。
7. **索引规范**：所有 `tenant_id` 列建索引；高频组合查询建复合索引；逻辑删除表建部分索引（`WHERE deleted=0`）。
8. **大表分区**：`hub_audit_log`、`hub_message`、`hub_api_call_log`、`hub_metering` 按月/年分区。
9. **变更管控**：DDL/DML 全部经 Flyway，命名 `V{版本}__{描述}.sql`，禁止手工改库。

```
 hub_tenant ──1:N── hub_subscription ──N:1── hub_package ──1:N── hub_package_item
     │                  │                                              │
     │                  └──1:N── hub_metering ──1:N── hub_usage_daily │
     │                  └──1:N── hub_bill ──1:N── hub_bill_item       │

     │           ├──N:1── hub_org ──1:N── hub_position

     ├──1:N── hub_wf_definition ──1:N── hub_wf_instance ──1:N── hub_wf_task
     │                                          └──1:N── hub_wf_form_data
     ├──1:N── hub_message ──N:1── hub_message_template
     │           └──1:N── hub_message_receipt
     ├──1:N── hub_file ──1:N── hub_file_version
     ├──1:N── hub_audit_log ──1:N── hub_audit_chain
     ├──1:N── hub_open_app ──1:N── hub_app_key ──1:N── hub_api_quota
     │           └──1:N── hub_api_call_log
     ├──1:N── hub_report_def / hub_metric
     ├──1:N── hub_lowcode_app
     └──1:N── hub_ai_capability_grant ──1:N── hub_ai_metering
```

| `hub_file` | `idx_file_md5(tenant_id,md5)`、`idx_file_biz(tenant_id,biz_type,biz_id)` | 普通 | 秒传/业务关联 |
| `hub_metering` | `uk_meter_source(tenant_id,metric_code,source_id)` | 唯一 | 幂等去重 |

**分区策略**：`hub_audit_log`、`hub_message`、`hub_api_call_log`、`hub_metering`、`hub_ai_metering` 按 `occurred_at`/`created_at`/`called_at`/`stat_date` 的月做 RANGE 分区，保留 12 个月热数据，冷数据归档至对象存储。

## 6 约束与 RLS

### 6.1 关键约束

| 表 | 约束 |
|---|---|
| `hub_tenant` | `code` 唯一；`status` 枚举；`iso_strategy` 枚举 |
| `hub_user` | `(tenant_id, employee_no)` 唯一、`(tenant_id, username)` 唯一 |
| `hub_role` | `(tenant_id, code)` 唯一 |
| `hub_open_app` | `code` 唯一 |
| `hub_app_key` | `app_key` 唯一 |
| `hub_metric` | `(tenant_id, code)` 唯一 |
| 全表 | 外键采用逻辑关联（不建物理外键，保证分库扩展性），由应用层保证 |

### 6.2 RLS 策略（SaaS 共享库）

```sql
-- 平台库通用 RLS 模板（以 hub_user 为例）
ALTER TABLE hub_user ENABLE ROW LEVEL SECURITY;

CREATE POLICY p_hub_user_tenant ON hub_user
  USING (tenant_id = current_setting('app.tenant_id', true)::bigint)
  WITH CHECK (tenant_id = current_setting('app.tenant_id', true)::bigint);

-- 平台运营端跨租户访客（显式声明）
CREATE POLICY p_hub_user_platform ON hub_user
  FOR SELECT
  TO fl_platform_role
  USING (current_setting('app.cross_tenant', true) = 'on');
```

- 应用连接池初始化时执行 `SET app.tenant_id = {tenantId}`（由网关传入 `X-Tenant-Id` 经上下文注入）；
- 平台运营端跨租户操作须显式置 `app.cross_tenant = 'on'` 且落审计与告警；
- 全局配置表（`hub_package`、`hub_permission`、`hub_menu`、`hub_dict_type`）不启用 RLS。

### 6.3 无租户表的例外

`hub_package`、`hub_package_item`、`hub_permission`、`hub_menu`、`hub_dict_type` 为平台全局定义表（`tenant_id=0`），不启用 RLS；租户对字典的定制写入 `hub_dict_item`（含 `tenant_id`）。

## 7 敏感字段加密

| 表.字段 | 类型 | 加密算法 | 哈希列 | 展示脱敏 |
|---|---|---|---|---|
| `hub_user.mobile_enc` | PII | AES-256-GCM | `mobile_hash` | `138****8888` |
| `hub_user.email_enc` | PII | AES-256-GCM | `email_hash` | `a***@fl.com` |
| `hub_tenant.contact_mobile_enc` | PII | AES-256-GCM | `contact_mobile_hash` | `138****8888` |
| `hub_account.password_enc` | 凭据 | BCrypt(成本12) | — | 不可展示 |
| `hub_account.mfa_secret_enc` | 凭据 | AES-256-GCM | — | 不可展示 |
| `hub_sso_config.client_secret_enc` | 凭据 | AES-256-GCM | — | 指纹回显 |
| `hub_app_key.app_secret_enc` | 凭据 | AES-256-GCM | — | 指纹回显 |
| `hub_license.content_enc` | 凭据 | AES-256-GCM | — | 不可展示 |
| `hub_login_session.ip_enc` / `hub_audit_log.ip_enc` | PII | AES-256-GCM | — | `10.*.*.*` |

**实现约定**：
- 加密/解密通过自定义 MyBatis `TypeHandler`（`EncryptedTypeHandler`）透明实现，业务代码不感知；
- 密钥由 KMS 管理，数据密钥 ≤ 90 天轮换，支持重加密；
- 哈希列 = `SHA-256(明文 + tenant_salt)`，用于唯一性约束与检索，禁止在明文列建唯一索引；
- 加密列不参与 `LIKE` 模糊查询，模糊检索经 `search-service` 索引完成。

## 9 数据量估算与归档

### 9.1 容量估算（3400 人规模基线）

| 表 | 单租户年增量估算 | 5 年规模 | 归档策略 |
|---|---|---|---|

| `hub_org`/`hub_position` | 1 千 | 6 千 | 在线保留 |
| `hub_wf_instance` | 50 万 | 250 万 | 3 年后归档 |
| `hub_wf_task` | 200 万 | 1000 万 | 3 年后归档 |
| `hub_message` | 2000 万 | 1 亿 | 12 个月热，冷归档 |
| `hub_audit_log` | 5000 万 | 2.5 亿 | 12 个月热，WORM 归档 |
| `hub_api_call_log` | 3000 万 | 1.5 亿 | 6 个月热，冷归档 |
| `hub_metering` | 100 万 | 500 万 | 24 个月热 |
| `hub_ai_metering` | 365 万 | 1800 万 | 12 个月热 |

### 9.2 归档与生命周期

- 分区表按 `RANGE` 自动创建滚动分区（XXL-Job 提前 1 个月建分区）；
- 到期分区 `DETACH` 后导出至 MinIO（Parquet），元数据登记 `hub_param` 归档索引；
- 审计数据满足等保留存 ≥ 6 个月（建议 12 个月）后归档至 WORM 存储，保留 5 年；
- 租户注销：数据保留 30 天经审批后物理擦除（剩余信息保护），擦除行为审计。
