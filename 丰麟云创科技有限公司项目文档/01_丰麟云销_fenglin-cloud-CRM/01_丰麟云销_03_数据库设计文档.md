## 1 设计原则

1. **多租户**：所有业务表含 `tenant_id`，启用 PostgreSQL RLS 行级安全，跨租户访问默认拒绝。
2. **公共字段强制**：每表含 `id / tenant_id / created_by / created_at / updated_by / updated_at / deleted / version`。
3. **主键**：高并发写使用雪花 ID（`bigint`）；对外暴露资源标识同时以 `uuid` 列保证不可枚举。
4. **命名**：表名小写下划线、模块前缀 `crm_`；字段小写下划线。
5. **敏感字段加密**：PII（线索/客户/联系人/伙伴手机号）AES-256-GCM，配套 `{field}_hash`（SHA-256+租户盐）用于唯一性与检索，禁止明文列唯一索引。
6. **逻辑删除**：`deleted`（0 正常/1 删除），唯一约束以"未删除"为条件（部分索引）。
7. **乐观锁**：`version` 由 MyBatis-Plus `@Version` 维护。
8. **迁移**：所有 DDL/DML 通过 Flyway 脚本 `V1_0_x__*.sql` 提交，禁止手工改库。
9. **金额**：统一 `numeric(18,2)`；比例 `numeric(8,4)`；时间 `timestamptz`（UTC）。
10. **大表**：按 `tenant_id` + 时间做分区（声明式分区），ES 承担检索分流。

## 2 逻辑模型（ER）

```
                                  ┌──────────────┐
                                  │ crm_customer │◀─────┐
                                  └──────┬───────┘      │
        ┌──────────┐  转换   ┌───────────┴──────────┐   │
        │ crm_lead │────────▶│ crm_contact (1:N)     │   │
        └────┬─────┘         │ crm_opportunity (1:N) │   │
             │               │ crm_activity (1:N)    │   │
             │ 报备(伙伴)     │ crm_quotation (1:N)   │   │
             ▼               │ crm_success_plan (1:1)│   │
   ┌────────────────────┐    │ crm_health_score (1:N)│   │
   │ crm_partner_deal_reg│──▶│ crm_renewal_order(1:N)│   │
   └─────────┬──────────┘    │ crm_service_contract  │   │
             │               │ crm_nps_response (1:N)│   │
   ┌─────────▼─────────┐     │ crm_sentiment_record  │   │
   │   crm_partner     │     │ crm_voice (1:N)       │   │
   │  1:N 协议/报备/佣金 │     └───────────┬───────────┘   │
   └───────────────────┘                 │               │
                                          │ 舆情命中        │
   ┌───────────────┐   ┌──────────────────▼────────┐      │
   │ crm_competitor│   │ crm_opinion_item ──▶ crm_alert_record
   └──────┬────────┘   └───────────────────────────┘      │
          │ 1:N                                            │
   ┌──────▼───────────┐        ┌──────────────┐            │
   │crm_competitor_intel│      │ crm_alert_rule│           │
   └──────────────────┘        └──────────────┘            │
                                                            │
   ┌──────────┐  ┌────────────────┐  ┌────────────┐        │
   │ crm_tag  │─▶│crm_tag_relation│  │crm_attachment│◀──────┘
   └──────────┘  └────────────────┘  └────────────┘
```

关系说明：

- `crm_lead` 1:1~1:N → `crm_customer`（转化）；
- `crm_customer` 1:N → 联系人/商机/活动/报价/成功计划/健康度/续费单/服务合同/NPS/情绪/客户之声；
- `crm_partner` 1:N → 协议/报备/佣金/认证；`crm_partner_deal_reg` 1:1 → `crm_opportunity`；
- `crm_opinion_item` 命中 `crm_customer` 时建立关联，并可生成 `crm_alert_record`；
- `crm_tag_relation` 多态关联业务对象；`crm_attachment` 多态关联业务对象。

## 6 约束与 RLS

### 6.1 通用 RLS 策略

对每张业务表统一创建：

```sql
ALTER TABLE crm_lead ENABLE ROW LEVEL SECURITY;

CREATE POLICY p_crm_lead_tenant ON crm_lead
  USING (tenant_id = current_setting('app.tenant_id')::bigint)
  WITH CHECK (tenant_id = current_setting('app.tenant_id')::bigint);
```

- 应用连接建立后由 `TenantContext` 通过 `SET LOCAL app.tenant_id = ?` 注入；
- 平台运营端跨租户访问需以 `platform:*` 权限并经审计通道（明文审计 event），RLS 在审计通道使用独立角色 `crm_platform_reader`；
- 数据权限（本人/本部门/本部门及下级/指定部门/全部）在应用层追加 `owner_id/dept_id` 谓词。

### 6.3 状态字段枚举校验

关键状态字段使用 `CHECK` 约束（示例）：


## 7 敏感字段加密

### 7.1 加密范围

| 表.字段 | 明文语义 | 密文列 | 哈希列 | 展示 |
|---|---|---|---|---|
| `crm_lead.mobile` | 线索手机号 | `mobile_enc` | `mobile_hash` | `138****8888` |
| `crm_customer.mobile` | 客户联系电话 | `mobile_enc` | `mobile_hash` | 脱敏 |
| `crm_contact.mobile` | 联系人手机号 | `mobile_enc` | `mobile_hash` | 脱敏 |
| `crm_partner.mobile` | 伙伴联系电话 | `mobile_enc` | `mobile_hash` | 脱敏 |

### 7.2 加密方案

- **算法**：AES-256-GCM；
- **密钥**：由 KMS 管理，密钥版本随密文存储（`{keyVersion}:{iv}:{ciphertext}:{tag}` 的 Base64 封装），支持轮换（≤ 90 天）；
- **实现**：自定义 MyBatis-Plus `TypeHandler`（`EncryptedFieldTypeHandler`）透明加解密，业务代码无感知；
- **哈希**：`{field}_hash = SHA256(明文 + 租户盐)`，租户盐由 KMS 下发并按租户隔离，用于唯一约束与精确检索（如查重）。

### 7.3 检索与查询

- **精确检索**：入参手机号先计算哈希再比对 `mobile_hash`；
- **模糊检索**：使用 `mobile_tail`（后 4 位）辅助，或仅在管理端授权下解密后模糊匹配（强审计）；
- **禁止**：在明文列建唯一索引；在日志、异常、消息中输出明文 PII。

### 7.4 字段权限

| 角色 | 手机号 |
|---|---|
| 销售代表 | 脱敏展示，需 `crm:lead:pii:view` 方可查看完整（强审计） |
| 销售经理 | 脱敏展示 |
| CSM | 脱敏展示 |
| 租户管理员 | 依配置，默认脱敏 |
| 平台运维 | 不可见（需授权并经审计） |

### 9.2 归档策略

| 数据 | 在线保留 | 归档 | 说明 |
|---|---|---|---|
| 活动 `crm_activity` | 24 个月 | MinIO 冷存 + 分区 detach | 24 个月后转冷 |
| 情绪记录 | 12 个月 | 冷存 | 保留聚合指标 |

- `crm_activity`、`crm_sentiment_record`、`crm_opinion_item`、`crm_health_score` 按 `RANGE` 分区（月分区），主键为 `(id, 分区键)`；
