## 1 管理端总览

### 1.1 管理端定位

管理端（`/admin/crm`，`fenglin-hub-admin-ui` + Element Plus）承载 **配置、授权、审核、报表定义、租户治理** 能力，与用户端（`/app/crm`）严格分离。管理端接口位于 `/api/crm/v1/admin/**`，仅 `ADMIN` 端别令牌可访问。

### 1.2 功能地图

```
运营概览（首页：销售/续费/NPS/伙伴/舆情指标）
├─ 销售配置：阶段配置 / 字段与权限配置 / 公海规则配置 / 销售目标
├─ 客户成功配置：健康度模型 / 分层与分派规则
├─ 体验配置：问卷模板 / 触点与频次 / 情绪与预警规则
├─ 渠道配置：伙伴等级与权益 / 招募审核 / 佣金结算审核 / 冲突裁决
├─ 舆情配置：舆情源与关键词 / 预警规则 / 舆情监控总览
├─ 报表中心：销售 / 续费 / NPS / 伙伴绩效
└─ 系统设置：参数与字典 / 权限与数据权限 / 审计日志
```

### 1.3 登录与安全基线

| 项 | 说明 |
|---|---|
| 登录 | 管理端账号 + MFA；支持 SSO；连续 5 次失败锁定 15 分钟 |
| 会话 | 空闲 30 分钟超时；高风险操作（跨租户查看、佣金支付、批量导出）二次验证 |
| 端别 | 管理端令牌 `client_type=ADMIN`，与用户端令牌不可混用 |
| 审计 | 管理端全部配置与授权变更强制审计（哈希链 + WORM，留存 12 个月） |

### 1.4 角色职责

| 角色 | 职责 | 权限域示例 |
|---|---|---|
| 平台超级管理员 | 平台级最高权限（运维专用、强审计） | `platform:*` |
| 平台运维 | 租户/套餐/监控/灰度 | `platform:ops:*` |
| 租户管理员 | 本租户配置、组织、角色、权限 | `tenant:*` |
| CRM 业务管理员 | 本域配置、流程、字段、报表、字典 | `tenant:crm:*` |

## 2 租户/组织/用户/角色

### 2.1 租户管理（平台侧）

1. 进入平台租户管理，可新建/停用租户、配置套餐与配额；
2. 新建租户后系统初始化：默认组织、默认角色、CRM 默认配置（阶段、健康度权重、触点、舆情源模板）；
3. 租户隔离：业务数据通过 `tenant_id` + RLS 隔离，跨租户访问默认拒绝；平台运营跨租户查看需二次确认并记审计。

【截图位：租户列表与租户初始化】

### 2.2 组织与用户（租户侧）

1. **组织架构**：维护多层级部门（编码层级点分，如 `1.2.3`），支持部门负责人设置；
2. **用户管理**：由统一 IAM 提供，支持按组织/岗位查询、停用/启用、离职联动账号回收；
3. **岗位**：定义岗位与默认角色映射，新员工入职自动赋权；
4. 组织或人员变更后，数据权限（DEPT/DEPT_AND_CHILD）自动按最新组织树生效。

### 2.3 角色管理

1. 角色 = 功能权限码集合 + 数据权限范围 + 字段权限；支持继承与复制；
2. CRM 预置角色：销售代表、销售经理、销售总监、CSM、客户成功主管、渠道经理、渠道总监、客户成功专员、市场分析专员、伙伴用户、只读；
3. 角色变更后对在线用户即时生效（令牌权限码以服务端实时校验为准）；
4. 关键角色（审批、财务、伙伴）遵循职责分离：申请人 ≠ 审批人。

## 3 权限与数据权限配置

### 3.1 功能权限

| 权限码示例 | 说明 |
|---|---|
| `crm:lead:create` / `crm:lead:assign` / `crm:lead:merge` | 线索相关 |
| `crm:opportunity:manage` / `crm:quotation:approve` | 商机与报价 |
| `crm:renewal:manage` / `crm:renewal:approve` | 续费 |
| `crm:nps:survey:manage` / `crm:sentiment:alert` / `crm:voice:manage` | 体验 |
| `crm:partner:deal:approve` / `crm:partner:commission:manage` | 渠道 |
| `crm:opinion:report` / `crm:competitor:manage` | 舆情竞品 |
| `tenant:crm:stage:config` / `tenant:crm:field:config` / `tenant:crm:health:config` / `tenant:crm:partner:config` | 管理端配置类 |

### 3.2 数据权限

| 枚举 | 含义 | 典型角色 |
|---|---|---|
| SELF | 本人数据 | 销售代表、CSM、伙伴用户 |
| DEPT | 本部门数据 | 渠道经理、财务 |
| DEPT_AND_CHILD | 本部门及下级 | 销售经理、客户成功主管 |
| CUSTOM | 指定部门/用户 | 跨团队协作场景 |
| ALL | 本租户全部 | 销售总监、渠道总监、CRM 业务管理员 |

配置路径：系统设置 → 权限与数据权限 → 选择角色 → 设置数据权限范围。规则：数据权限与功能权限取交集；伙伴用户额外受 `partner_id` 强隔离。

### 3.3 字段权限

1. 路径：「销售配置 → 字段与权限配置」，可对客户/线索的敏感字段（手机号、邮箱）按角色配置为**可见 / 脱敏 / 隐藏**；
2. 查看明文需 `crm:lead:pii:view` 权限，且每次查看记录审计；
3. 配置为隐藏时，列表与详情均不展示该列；导出默认脱敏。

2. 字典变更影响前端下拉选项与新数据录入，历史数据按值存储不受影响；
3. 字典项支持启用/停用与排序；停用项不再出现在新建表单。

## 5 流程与审批配置

### 5.1 审批流程清单

| 流程 Key | 名称 | 节点/分支 |
|---|---|---|
| `crmQuotationApproval` | 报价折扣审批 | ≤20% 自动通过；20–35% 销售经理；>35% 销售经理→财务复核→总经理；金额>100 万追加总经理；驳回回 REJECTED |
| `crmRenewalApproval` | 续费审批 | ≤20% 且 ≤50 万自动通过；否则主管→财务；S 级追加总监；驳回回 QUOTING |
| `crmPartnerDealRegApproval` | 伙伴报备审批 | 无冲突自动/经理审批；有冲突渠道经理裁决；通过生成关联商机并通知伙伴 |
| `crmPartnerCommissionSettlement` | 佣金结算 | 计算（幂等）→ 渠道总监审批 → 财务对账 → 标记已支付 |

### 5.2 流程配置要点

1. 流程由 `fenglin-workflow-service`（Flowable 7）统一托管，支持节点审批人配置（角色/指定人/上级）；
2. 每个用户任务配置**驳回**边界事件与**超时（48h）升级**定时边界事件；
3. 回调采用幂等回调，更新业务状态并发布事件（如 `crm.quotation.approved`、`crm.renewal.signed`）；
4. 审批记录不可删改；审批人不得为申请人的直接利害相关人（职责分离）；
5. 关键流程变更需评审并留痕，变更前在 staging 完整回归（回归组 R1/R2/R4）。

## 6 集成与开放平台

### 6.1 中台能力集成

| 能力 | 服务 | 云销用法 |
|---|---|---|
| 身份与权限 | `fenglin-iam-service` | 账号、角色、组织、数据权限 |
| 工作流 | `fenglin-workflow-service` | 报价/续费/报备/佣金审批 |
| 消息 | `fenglin-message-service` | 站内信/邮件/短信/企微飞书钉钉/WebSocket/Webhook |
| 文件 | `fenglin-file-service` | 附件上传下载、预览、水印 |
| 审计 | `fenglin-audit-service` | 全链路审计、哈希链、WORM |
| 搜索 | `fenglin-search-service` | 舆情与全局检索（ES+IK） |
| AI | `fenglin-ai-service` | 情绪极性/标签识别、词云与摘要 |
| 报表 | `fenglin-report-service` | 指标中心与看板 |

### 6.2 开放 API

1. 前缀 `/openapi/crm/v1`，由 `fenglin-openapi-service` 统一网关承载；
2. 应用注册 → 分配 AppKey/AppSecret（HMAC-SHA256 签名）→ 申请 Scope → 配额与限流（超限返回 `0000006`）；
3. 在线调试沙箱与 SDK（Java/JS/Python）；密钥由 KMS 托管并支持轮换；
4. 对外开放资源（节选）：线索创建、商机查询、续费台账、伙伴报备状态；开放事件（节选）：`crm.lead.converted`、`crm.opportunity.won`、`crm.renewal.signed`、`crm.partner.deal_approved`、`crm.sentiment.negative_detected`、`crm.opinion.alert`。

### 6.3 Webhook 订阅

1. 订阅事件 → 配置回调地址 → 验签（HMAC）+ 时间戳防重放 → 幂等处理；
2. 失败重试策略：指数退避，最多 5 次；连续失败告警并暂停订阅；
3. 回调日志可查，支持手动补发。

## 8 备份与安全运维

### 8.1 备份

| 对象 | 策略 | 保留 |
|---|---|---|
| PostgreSQL | 每日全备 + 15min WAL（PITR） | 全备 30 天、WAL 7 天 |
| 对象存储 | 版本控制 + 每日增量 | 90 天 |
| ES | 每日快照 | 30 天 |
| Redis | AOF + 每日 RDB | 7 天 |
| 配置（Nacos） | 每日导出 + Git | 永久 |

异地容灾：同城双活 + 异地备份，RPO ≤5min、RTO ≤30min（演练实测 RPO 2.4min / RTO 18min）。恢复演练每季度一次。

### 8.2 安全运维

| 项 | 要求 |
|---|---|
| PII 加密 | 手机号 AES-256-GCM 存储 + `mobile_hash`（SHA-256+租户盐）检索；禁止明文唯一索引 |
| 密钥管理 | KMS 托管，轮换 ≤90 天 |
| 权限复核 | 每季度复核角色与数据权限，回收冗余权限 |
| 漏洞管理 | 定期扫描 + 高危即修；发布前 SAST/SCA/镜像扫描阻断高危 |
| 三员分立 | 系统管理员、安全管理员、审计管理员职责分离 |
| 数据清理 | 逻辑删除 + 定时物理清理；介质销毁流程 |

### 8.3 日常巡检（管理端视角）

| 频率 | 项目 |
|---|---|
| 每日 | 任务成功、告警清零、审计异常、备份完成 |
| 每周 | 限流统计、预警触达时延、权限变更记录 |
| 每月 | 容量趋势、密钥轮换状态、权限复核抽检 |
| 每季度 | 容灾与恢复演练、权限全量复核、安全复评 |

## 9 故障处理

| 故障 | 常见原因 | 处理步骤 |
|---|---|---|
| 用户无法登录 | 账号锁定/口令过期/MFA 未绑定 | 核对账号状态 → 解锁或重置口令 → 引导绑定 MFA |
| 提示无权限 `0000002` | 功能权限缺失/数据权限范围不足/端别不符 | 核对角色权限码与数据权限范围 → 调整并留痕 |
| 提示「伙伴数据越权」`1007002` | 伙伴用户访问非本伙伴数据 | 确认为正常拦截；如为业务需要，调整伙伴归属而非放宽隔离 |
| 提示「线索重复」`1001001` | 手机号命中已有线索 | 在重复提示中跳转或合并处理 |
| 提示「阶段准入不满足」`1002001` | 商机阶段必填项缺失 | 按弹窗补全预计金额/成交日/关键决策人或有报价单 |
| 提示「报价折扣超限」`1003001` | 折扣超阈值未审批 | 提交审批流程 |
| 提示「续费单重复」`1004001` | 依据 `contract_id + term_start` 已存在续费单 | 复用既有续费单继续推进 |
| 提示「健康度权重非 100%」`1005001` | 权重配置合计不为 100% | 调整权重合计为 100% 后保存 |
| 提示「NPS 问卷重复投放」`1006001` | 频次控制命中 | 按频次策略调整投放时间或名单 |
| 提示「报备冲突」`1007003` | 存在有效报备或直营商机 | 进入冲突裁决台按保护期与优先级裁决 |
| 提示「佣金重复结算」`1008001` | 幂等键重复 | 使用既有结算单，无需重复操作 |
| 提示「触发限流」`0000006` | 超出租户+接口 QPS | 降频重试；必要时申请调整配额 |
| 健康度重算失败 | 因子数据源异常/任务超时 | 分片重试（幂等）→ 保留上次结果 → 定位数据源 |
| 舆情采集失败 | 采集源不可达/规则异常 | 重试 3 次 → 标记源异常 → 修复后补采 |
| 审批任务堆积 | 节点路由异常/实例不足 | 检查工作流实例与路由 → 扩容 → 人工兜底推进 |
| 导出任务失败 | 数据量大/超时 | 重试或缩小范围 → 检查对象存储 → 完成后补发下载 |
| 数据异常（误删/错乱） | 人为或程序缺陷 | 隔离影响 → PITR 恢复至故障前 → 校验 → 回归核心链路 → 复盘 |

故障响应与升级：一线运维（7×24）→ 二线研发值班 → 三线架构/安全；P0 事件 15 分钟内成立应急小组，30 分钟内通报进展，事后 3 个工作日内提交复盘报告；处理过程全程留痕审计。
