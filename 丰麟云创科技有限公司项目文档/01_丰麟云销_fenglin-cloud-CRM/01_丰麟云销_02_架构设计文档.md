## 1 架构概览

### 1.1 架构定位

丰麟云销（Fenglin Cloud CRM）是丰麟云枢平台域A业务产品，采用"**中台复用 + 域内领域服务 + 双端分离 + 开放生态**"架构：

- **中台复用**：统一身份（IAM）、租户、工作流、消息、文件、审计、搜索、AI、报表、开放平台均由丰麟云枢提供，云销按标准契约调用，不重复建设；
- **域内领域服务**：`fenglin-crm-service` 承载 A1–A5 五大模块的领域逻辑，按模块划分 Domain 包（`com.fenglin.crm.lead/customer/opportunity/success/nps/partner/opinion/...`）；
- **双端分离**：管理端（`/admin/crm`）与用户端（`/app/crm`）分离，后端以 `X-Client-Type` 区分端别并执行差异化鉴权与路由；
- **开放生态**：通过 `fenglin-openapi-service` 暴露开放 API（`/openapi/crm/v1`）与 Kafka 事件 Webhook。

### 1.2 架构原则

| 原则 | 说明 |
|---|---|
| 单一职责 | 每个领域包只负责本模块聚合根与用例 |
| 契约优先 | 对外接口先定 OpenAPI 3.1 契约，再实现 |
| 中台复用 | 通用能力一律调用中台，不重复造轮子 |
| 多租户隔离 | 所有业务表 `tenant_id` + RLS，跨租户默认拒绝 |
| 端别清晰 | 术语统一为"管理端/用户端"，配置类归管理端、操作类归用户端 |
| 可观测优先 | 全链路 `X-Request-Id`/`X-Trace-Id` 贯穿 |
| 幂等与最终一致 | 金额/审批/结算类操作幂等；跨域事件最终一致 |

## 4 关键流程时序

### 4.1 线索转化为商机（A1）

```
销售代表        网关          crm-service      workflow      message/AI
   │  POST /leads/{id}/convert │                  │              │
   ├─────────────▶│ 鉴权+X-Client-Type=PORTAL      │              │
   │              ├────────────▶│ 1 校验权限 crm:lead:transfer
   │              │             │ 2 查重（mobile_hash/企业名）
   │              │             │ 3 创建 Customer/Contact/Opportunity
   │              │             │ 4 更新 Lead 状态=CONVERTED
   │              │             │ 5 写审计（audit-service）
   │              │             │ 6 发事件 crm.lead.converted（Kafka）
   │              │             ├───────────────▶│ 分配任务/通知
   │              │             ├──────────────────────────────▶│ 线索打分
   │◀─────────────┴─────────────┤ 统一响应体（code/data/requestId）
```

### 4.2 报价折扣审批（A1，Flowable）

```
销售代表 → 提交报价（折扣 22% < 阈值 20%）→ 触发 workflow：销售经理 → 财务 → 总经理（金额分段）
→ 审批通过后报价单状态 APPROVED，可转合同；任一节点驳回则返回 DRAFT 并记录意见
→ 金额/审批类操作用 Idempotency-Key 保证幂等
```

### 4.3 健康度重算（A2，XXL-Job + AI）

```
XXL-Job（每日 02:00）→ crm-service 拉取在服客户清单
→ 并行聚合：产品使用活跃度(埋点) / 工单 / 情绪分(A3) / NPS(A3) / 回款 / 关键人变动
→ 归一化 + 加权（权重来自管理端配置）→ 写 crm_health_score
→ 与上次比较，若跨等级（如 健康→风险）则发事件 crm.health.level_changed → 触发续费/赢回任务
```

### 4.4 负面情绪实时预警（A3）

```
数据源（工单/会话/评价/社媒）→ Kafka topic crm.sentiment.raw
→ crm-service 消费 → 调 ai-service 情感分析（极性+置信度）→ 写 crm_sentiment_record
→ 规则引擎匹配（负面 & 置信度>0.8 & 客户等级 S/A）→ 生成 crm_alert_record
→ message-service 推送（站内信/邮件/Webhook）→ 指派责任人跟踪
```

### 4.5 伙伴商机报备（A4）

```
伙伴用户 → POST /partner/deals（客户、金额、预计成交）
→ 查重（同客户是否已有报备/直营商机）→ 保护期规则校验
→ 无冲突：自动/人工审批通过 → 生成 DealRegistration(APPROVED) + 关联 Opportunity(A1)
→ 有冲突：进入裁决队列 → 渠道经理裁决 → 记录裁决结果（可申诉）
→ 佣金计算：成交后按等级返点生成 crm_partner_commission（幂等）
```

## 5 数据架构

### 5.1 数据存储分布

| 存储 | 用途 | 关键设计 |
|---|---|---|
| PostgreSQL 15（`fenglin_crm`） | 业务主数据 | 表前缀 `crm_`；`tenant_id` + RLS；分区（大表按月/年） |
| Redis 7 | 缓存/分布式锁/会话 | 线索查重缓存、字典缓存、幂等键、热点看板 |
| Elasticsearch 8 | 全文检索/语义 | 线索/客户/舆情条目索引，IK 分词 |
| Kafka 3.6 | 事件总线 | 领域事件 `crm.*`，供中台与开放订阅 |
| RocketMQ 5.x | 事务消息 | 佣金结算、跨域强一致（配 Seata） |
| MinIO | 附件/导入导出文件 | 报价单、导入模板、报告 |
| XXL-Job | 定时任务 | 健康度重算、续费提醒、舆情采集、公海回收 |

### 5.2 多租户与隔离

- SaaS：共享库共享模式 + `tenant_id` 逻辑隔离 + PostgreSQL RLS；
- 私有化：独立库（database per tenant）；
- 混合：核心数据私有库 + 智能中台 SaaS 化。

### 5.3 数据一致性

- 域内强一致：本地事务（`@Transactional`）；
- 跨域强一致（佣金结算、额度扣减）：Seata AT 模式；
- 跨域最终一致：Kafka 事件 + 本地消息表/事务消息 + 幂等消费。

### 5.4 缓存策略

| 场景 | 策略 |
|---|---|
| 字典/配置 | 本地 Caffeine + Redis 二级缓存，变更发布失效 |
| 线索查重 | Redis Bloom/Set（`mobile_hash` 前缀索引） |
| 热点看板 | Redis 5 分钟 TTL + 定时刷新 |
| 幂等键 | Redis `idem:{tenant}:{key}` 24h |
| 分布式锁 | Redisson，锁续期，超时释放 |

## 6 集成与开放

### 6.1 与中台集成

| 集成点 | 协议 | 说明 |
|---|---|---|
| 认证鉴权 | OAuth2.1/OIDC | 令牌校验、`client_type` 端别 |
| 权限 | IAM OpenAPI | 功能/数据/字段权限下发 |
| 审批 | workflow-service | Flowable 流程部署与任务回调 |
| 消息 | message-service | 多通道通知 |
| 文件 | file-service | 附件上传下载 |
| AI | ai-service | 情感识别、摘要、推荐 |
| 检索 | search-service | ES 索引与查询 |
| 报表 | report-service | 指标与看板 |
| 审计 | audit-service | 操作审计埋点 |

### 6.2 开放 API

- 前缀 `/openapi/crm/v1`，经 `fenglin-openapi-service`；
- 鉴权：OAuth2.1 授权码 + AppKey/AppSecret（HMAC-SHA256 签名）；
- 配额：按应用/接口维度 QPS，超限返回 `0000006`；
- 沙箱：在线调试，与生产隔离。

### 6.3 事件与 Webhook

| 事件 | 触发 | 载荷要点 |
|---|---|---|
| `crm.lead.created` | 线索创建 | leadId、source、owner |
| `crm.lead.converted` | 线索转化 | leadId、customerId、opportunityId |
| `crm.opportunity.stage_changed` | 商机阶段变更 | opportunityId、from、to |
| `crm.health.level_changed` | 健康度等级变更 | customerId、from、to、score |
| `crm.nps.submitted` | NPS 提交 | surveyId、score、category |
| `crm.sentiment.negative_detected` | 负面情绪识别 | customerId、polarity、confidence |
| `crm.partner.deal_approved` | 报备通过 | dealId、partnerId、customerId |
| `crm.commission.settled` | 佣金结算 | commissionId、amount、status |
| `crm.opinion.alert` | 舆情预警 | itemId、heat、sentiment |

Webhook 投递：签名验签 + 重试（指数退避，最多 6 次）+ 幂等（事件 ID 去重）。

## 7 双端分离架构

### 7.1 前端工程

| 端 | 工程 | 路由 | 组件库 |
|---|---|---|---|
| 管理端 | `fenglin-hub-admin-ui` | `/admin/crm/**` | Element Plus |
| 用户端 | `fenglin-hub-portal-ui` | `/app/crm/**` | 自研 Portal 组件 |

### 7.2 后端端别路由

- 网关依据令牌 `client_type` 与请求头 `X-Client-Type` 校验一致性；
- 后端接口按端别分目录：`api/admin`（`/api/crm/v1/admin/**`）、`api/portal`（`/api/crm/v1/**`）；
- 管理端权限域 `tenant:crm:*`，用户端权限域 `crm:*`；端别不匹配返回 `0000002`（403）。

### 7.3 能力归属

| 能力 | 管理端 | 用户端 |
|---|---|---|
| 阶段/字段/字典配置 | ✔ | ✘ |
| 健康度权重配置 | ✔ | ✘ |
| 问卷模板/触点配置 | ✔ | ✘ |
| 伙伴等级/权益配置 | ✔ | ✘ |
| 舆情源/预警规则配置 | ✔ | ✘ |
| 日常销售/续费/渠道操作 | ✘ | ✔ |

## 8 高可用与容灾

### 8.1 高可用设计

| 层次 | 措施 |
|---|---|
| 接入 | SLB + WAF + 多可用区 Ingress |
| 应用 | Pod 多副本 + HPA + 就绪/存活探针 + 优雅停机 |
| 网关 | 多副本 + Sentinel 熔断降级 |
| 数据库 | Patroni 主备自动切换 + 只读副本分流 |
| 缓存 | Redis 哨兵/集群 |
| 消息 | Kafka 3 副本 + min.insync.replicas=2 |
| 存储 | MinIO 纠删码多节点 |
| 服务 | 无状态化，会话外置（Redis），支持滚动/蓝绿/灰度 |

### 8.2 容灾目标

| 指标 | 目标 |
|---|---|
| 可用性 | ≥ 99.99%（年不可用 ≤ 52.6 分钟） |
| RPO | ≤ 5 分钟 |
| RTO | ≤ 30 分钟 |
| 备份 | 每日全备 + 增量（WAL 归档），异地容灾，季度演练 |

### 8.3 降级策略

| 依赖不可用 | 降级 |
|---|---|
| ai-service | 情感识别降级为规则关键词匹配；NPS 词云延后 |
| search-service | 回退数据库 LIKE 检索（限流） |
| report-service | 回退缓存快照 |
| message-service | 消息进入本地重试表，恢复后补发 |

## 9 安全架构

### 9.1 分层防护

| 层 | 措施 |
|---|---|
| 网络 | WAF、IDS/IPS、网络分区、微服务间 mTLS |
| 应用 | OAuth2.1/OIDC、JWT(RS256)、MFA、RBAC+ABAC、数据权限、字段脱敏 |
| 数据 | AES-256-GCM（PII）、TDE、KMS、`*_hash` 检索、备份加密 |
| 审计 | 全链路审计、哈希链 + WORM、留存 ≥ 6 个月 |
| 运维 | 三员分立、最小权限、堡垒机、镜像扫描、依赖 SCA |

### 9.2 关键安全控制

1. 传输：客户端↔网关 TLS1.3，内部 mTLS；
2. 存储：PII 加密、数据库 TDE；
3. 密钥：KMS 管理，轮换 ≤ 90 天；
4. 口令：复杂度 + 5 次失败锁定 + 会话 30min 超时；
5. 越权：跨租户默认拒绝，数据权限行/列级拦截。

详见 FL-CRM-SEC-009《安全评估报告》。
