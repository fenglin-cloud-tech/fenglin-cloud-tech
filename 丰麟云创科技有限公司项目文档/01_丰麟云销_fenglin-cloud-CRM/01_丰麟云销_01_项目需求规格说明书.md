## 1 引言

### 1.1 目的

本文档定义**丰麟云销（Fenglin Cloud CRM）**的产品需求基线，是丰麟云创科技有限公司面向中大型企业客户交付"客户增长与渠道生态平台"的需求依据。本文档用于：

1. 明确 A1–A5 五大业务模块的功能与非功能需求边界；
2. 作为架构设计、数据库设计、接口设计、UI/UX 设计、测试与验收的上游输入；
3. 作为与客户、平台架构组（FL-HUB-STD-001 归口）之间需求确认与变更控制的基线文件。

品牌口号：**让每一条客户线索都走向续费与增长**。

## 2 产品概述

### 2.1 产品定位

丰麟云销是丰麟云枢平台域A的核心产品，面向中大型企业的销售、客户成功与渠道生态团队，构建"**线索获取 → 商机转化 → 成交交付 → 客户成功 → 续费增购 → 渠道协同**"的端到端闭环，并以舆情与竞品监测能力为营销与竞争决策提供支撑。

核心价值主张：

1. **增长闭环**：A1 销售管理与 A2 客户成功打通，线索到续费全生命周期可视；
2. **体验驱动**：A3 情绪与 NPS 实时监测，将客户体验量化并驱动续费动作；
3. **生态放大**：A4 PRM 激活渠道伙伴，形成直销+渠道双引擎；
4. **环境感知**：A5 舆情与竞品监测，形成外部市场感知的"雷达"。

### 2.2 用户角色

角色基线继承 FL-HUB-STD-001 第 7.3 节，并结合本品业务细化：

| 角色 | 端 | 权限域示例 | 说明 |
|---|---|---|---|
| 平台超级管理员 | 管理端 | `platform:*` | 平台级最高权限，运维专用，强审计 |
| 平台运维 | 管理端 | `platform:ops:*` | 租户/套餐/监控/灰度 |
| 租户管理员 | 管理端 | `tenant:*` | 本租户配置、组织、角色、权限 |

| 销售代表 | 用户端 | `crm:lead:*`、`crm:opportunity:*` | 客户开发与商机推进 |

## 3 业务需求（模块级功能需求）

> 编号规则：`{模块码}-FR-{3位序号}`。优先级：P0（必须）、P1（重要）、P2（一般）。

### 3.1 A1 销售管理

模块定位：覆盖线索、客户、联系人、商机、活动、报价、目标与预测的销售全流程管理（参考标杆：销售易）。

| 编号 | 需求名称 | 优先级 | 需求描述 | 端别 | 关键权限码 |
|---|---|---|---|---|---|
| A1-FR-001 | 线索采集与分配 | P0 | 支持手工录入、批量导入（Excel/CSV）、Web 表单、开放 API、渠道报备等多来源线索入库；支持按组织架构、区域、行业、产品线配置分配规则（轮询/负载/指定），分配后触发消息通知。 | 用户端 | `crm:lead:create`、`crm:lead:assign` |
| A1-FR-002 | 线索查重与合并 | P0 | 入库时基于手机号（`mobile_hash`）、企业名称、邮箱进行查重，命中疑似重复则提示；支持线索合并（保留主记录、关联从记录）并保留合并审计。 | 用户端 | `crm:lead:merge` |
| A1-FR-003 | 线索跟进与转化 | P0 | 记录跟进活动（电话/邮件/拜访/微信），支持线索状态流转（新建→跟进中→已转化/无效/培育），转化时一键生成客户+联系人+商机，保留来源链路。 | 用户端 | `crm:lead:transfer` |
| A1-FR-004 | 客户 360 视图与分级 | P0 | 客户主档（工商信息、标签、分级 A/B/C/D、行业、区域、归属销售）；提供客户 360 视图聚合商机、合同、活动、服务、情绪、NPS、舆情。 | 用户端 | `crm:customer:view` |
| A1-FR-005 | 联系人管理 | P1 | 维护客户下多联系人（决策人/影响人/使用人角色），记录联系方式（手机号加密）、职务、影响力，支持关系图谱展示。 | 用户端 | `crm:contact:manage` |
| A1-FR-006 | 商机阶段与预测 | P0 | 商机按可配置销售阶段（S1 初步接触→S2 需求确认→S3 方案报价→S4 商务谈判→S5 赢单/输单）推进；每阶段设必填项与准入/退出准则；支持加权预测（金额×赢率×阶段系数）与销售预测汇总。 | 用户端 | `crm:opportunity:manage` |
| A1-FR-007 | 报价与折扣审批 | P0 | 生成报价单（多产品行、数量、单价、折扣、税率），折扣低于阈值触发审批流（Flowable）；报价单可版本化并转合同。 | 用户端 | `crm:quotation:manage`、`crm:quotation:approve` |
| A1-FR-008 | 销售活动与日历 | P1 | 记录并统计销售活动量（有效拜访/通话时长/邮件数），与日程打通，形成活动效率分析。 | 用户端 | `crm:activity:manage` |
| A1-FR-009 | 公海池与回收规则 | P0 | 未跟进超期线索/客户自动回收至公海池；支持领取、分配、回收规则配置（N 天无活动/无商机）；操作全程审计。 | 用户端 | `crm:pool:manage` |
| A1-FR-010 | 销售目标与业绩看板 | P1 | 按周期（年/季/月）、组织、个人设定销售目标（签约额/回款额/商机数）；实时业绩看板展示完成率、排名、漏斗。 | 用户端 + 管理端 | `crm:target:manage`、`crm:report:sales` |
| A1-FR-011 | 销售流程与阶段配置 | P1 | 管理端可配置销售阶段名称、顺序、必填字段、赢率、自动化动作（如进入 S3 自动创建任务）。 | 管理端 | `tenant:crm:stage:config` |
| A1-FR-012 | 线索/客户字段权限 | P0 | 管理端配置敏感字段（手机号）按角色脱敏或隐藏，配置客户/线索的列表列与必填项。 | 管理端 | `tenant:crm:field:config` |

**A1 验收要点**：线索转化率、商机阶段流转数据完整可追溯；折扣审批 100% 走流程；公海回收规则按配置准确执行。

### 3.2 A2 客户成功与续费管理

模块定位：以健康度驱动续费与增购，降低流失（参考标杆：探马）。

| 编号 | 需求名称 | 优先级 | 需求描述 | 端别 | 关键权限码 |
|---|---|---|---|---|---|
| A2-FR-001 | 客户成功计划 | P0 | 为新成交客户自动/手动创建成功计划，定义里程碑（上线、首值、月活、扩展），跟踪达成情况与责任人。 | 用户端 | `crm:success:plan:manage` |
| A2-FR-002 | 健康度模型与评分 | P0 | 基于多因子（产品使用活跃度、工单、情绪、NPS、回款、关键人变动、使用深度）计算客户健康度分数（0–100）与等级（健康/关注/风险/危急），支持权重配置与定时重算。 | 用户端 + 管理端 | `crm:health:view`、`tenant:crm:health:config` |
| A2-FR-003 | 续费提醒与台账 | P0 | 按合同到期提前 T-90/60/30/15/7 天分级提醒；维护续费台账（到期客户、金额、状态、责任人、进展）。 | 用户端 | `crm:renewal:manage` |
| A2-FR-004 | 续费流程与审批 | P0 | 续费单从"待跟进→报价→审批→签约→完成/流失"流转，支持折扣/账期审批，与 A1 报价能力复用。 | 用户端 | `crm:renewal:manage`、`crm:renewal:approve` |
| A2-FR-005 | 流失预警与赢回 | P0 | 健康度低于阈值或连续负向事件触发流失预警，自动创建赢回任务；记录流失原因分类与赢回结果。 | 用户端 | `crm:churn:manage` |
| A2-FR-006 | 增购/交叉销售推荐 | P1 | 基于使用缺口、产品关联规则、客户画像给出增购建议清单，支持一键转商机（联动 A1）。 | 用户端 | `crm:upsell:view` |
| A2-FR-007 | 客户成功任务与 SOP | P1 | 按客户分层配置 CSM 触点 SOP（季度业务回顾 QBR、健康巡检、关键人维护），系统生成任务并跟踪闭环。 | 用户端 | `crm:success:task:manage` |
| A2-FR-008 | 服务合同与 SLA | P1 | 维护服务合同、SLA 等级、服务包，关联工单时效与续费权益。 | 用户端 | `crm:contract:manage` |
| A2-FR-009 | 客户分层与分派 | P0 | 按 ARR、行业、战略级别分层（S/A/B/C），自动分派 CSM，支持管理端调整规则与负载。 | 用户端 + 管理端 | `crm:success:segment:config` |
| A2-FR-010 | 续费业绩与预测 | P1 | 续费率（金额/客户数）、流失率、NRR/GRR 指标看板与预测。 | 用户端 + 管理端 | `crm:report:renewal` |

**A2 验收要点**：健康度评分每日定时重算且可解释（因子明细可查）；续费提醒按时触达；流失预警闭环率可统计。

### 3.3 A3 客户情绪与 NPS 实时监测

模块定位：实时采集、量化并响应客户情绪与忠诚度（参考标杆：企客云）。

| 编号 | 需求名称 | 优先级 | 需求描述 | 端别 | 关键权限码 |
|---|---|---|---|---|---|
| A3-FR-001 | NPS 问卷设计 | P0 | 可视化设计 NPS/CSAT/CES 问卷（题目类型、逻辑跳转、品牌皮肤），支持分渠道（邮件/短信/站内/企微/飞书）投放。 | 用户端 + 管理端 | `crm:nps:survey:manage` |
| A3-FR-002 | NPS 投放与回收 | P0 | 按客户分层/触点事件触发投放（如续费前、QBR 后、工单关闭后），回收答案并计算 NPS（推荐者-贬损者比例）。 | 用户端 | `crm:nps:survey:send` |
| A3-FR-003 | NPS 实时看板 | P0 | 按客户/客户群/产品线/CSM 维度实时展示 NPS 趋势、分布、开放题词云（IK 分词）。 | 用户端 | `crm:nps:report` |
| A3-FR-004 | 情绪采集与识别 | P0 | 从工单、会话、评价、邮件、社交媒体等多渠道采集文本，通过 `fenglin-ai-service` 做情感极性（正/中/负）与情绪标签（愤怒/失望/满意/惊喜）识别，输出置信度。 | 用户端 + 系统 | `crm:sentiment:view` |
| A3-FR-005 | 情绪实时监测与预警 | P0 | 负面情绪突增或关键客户负面事件触发实时预警（站内信/邮件/Webhook），指派责任人并跟踪处置。 | 用户端 | `crm:sentiment:alert` |
| A3-FR-006 | 客户之声（VoC）闭环 | P0 | 汇集 NPS 开放题、情绪记录、投诉形成客户之声条目，分类归档并驱动改进项（关联工单/需求池），跟踪闭环。 | 用户端 | `crm:voice:manage` |
| A3-FR-007 | 情绪与健康度联动 | P1 | 情绪分作为 A2 健康度模型的因子输入，权重可在管理端配置。 | 系统 | `tenant:crm:health:config` |
| A3-FR-008 | 触点与问卷模板库 | P1 | 管理端维护触点库、问卷模板、投放频次控制（避免打扰），支持黑白名单。 | 管理端 | `tenant:crm:nps:config` |

**A3 验收要点**：NPS 计算准确；负面情绪预警 5 分钟内触达；VoC 闭环率可统计。

### 3.4 A4 合作伙伴/渠道生态管理（PRM）

### 5.2 数据需求要点

1. **多租户**：所有业务表含 `tenant_id` 并启用 RLS；跨租户访问仅平台运营端并强制审计。

5. **迁移**：全部 DDL/DML 通过 Flyway 脚本（`V1_0_x__*.sql`）提交。

## 6 接口需求

1. 全部接口遵循 `/api/crm/v1` 前缀、RESTful 风格、统一响应体（`code/message/data/requestId/timestamp`）。
2. 统一请求头：`Authorization`、`X-Tenant-Id`、`X-Client-Type`（ADMIN/PORTAL）、`X-Request-Id`、`Idempotency-Key`（写操作）。
3. 错误码域前缀 `10`，结构 `{域2}{模块2}{序号3}`：
   - 通用/校验：`1000001`–`1000999`
   - A1：`1001xxx`；A2：`1002xxx`；A3：`1003xxx`；A4：`1004xxx`；A5：`1005xxx`
4. 分页：`page`（从 1 起）、`size`（默认 20，最大 200）。
5. 需提供 OpenAPI 3.1 契约与开放 API（前缀 `/openapi/crm/v1`）与事件 Webhook。
6. 核心接口清单详见 FL-CRM-API-005《接口文档》。

## 7 约束与假设

### 7.1 约束

1. 必须遵循 FL-HUB-STD-001 的命名体系、技术栈、接口/数据/权限/安全/UI 规范；
2. 必须严格实现管理端（`/admin/crm`）与用户端（`/app/crm`）分离；
3. 后端统一技术栈：Java 17 / Spring Boot 3.2.x / Spring Cloud 2023.0.x / MyBatis-Plus 3.5.x / PostgreSQL 15 / Redis 7 / Kafka 3.6 / Flowable 7；
4. 前端统一 Vue 3.4 + TypeScript + Vite 5；管理端 Element Plus，用户端自研 Portal 组件；
5. 不得引入异构框架，确需引入须报平台架构组评审。

### 7.2 假设

1. 丰麟云枢中台（IAM/租户/消息/文件/审计/搜索/AI/报表）可用并按契约提供能力；
2. AI 情感识别与文本分析由 `fenglin-ai-service` 提供，本品不重复建设模型；
3. 舆情外部数据源通过合规采集渠道获取，遵守相关法律法规与 robots 协议；
4. 客户具备必要的浏览器与网络环境。
