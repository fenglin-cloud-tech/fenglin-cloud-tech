### 1.4 业务规则

1. **线索查重**：入库时以 `mobile_hash` 精确匹配；命中未删除线索则返回 `1001001`（线索重复）并给出重复记录；企业名+邮箱模糊命中给出疑似列表（不阻断）。
2. **分配规则优先级**：指定 > 区域/行业匹配 > 负载均衡 > 轮询；分配后 5 秒内推送通知。
3. **公海回收**：默认 N=30 天无活动且无关联商机的线索/客户回收至公海；领取上限默认每人 50 条/天。规则可配置。
4. **阶段准入准则**：进入 S3 必须填写"预计金额、预计成交日期、关键决策人"；进入 S4 必须存在已审批或待审批报价单；不满足则拒绝迁移并返回 `1002001`（阶段准入不满足）。
5. **加权预测**：`weighted_amount = amount × win_rate × stage_factor`；阶段系数默认 S1=0.2、S2=0.4、S3=0.6、S4=0.8、WON=1.0。
6. **折扣审批阈值**：综合折扣 > 20% 触发审批；> 35% 增审总经理节点；金额 > 100 万加重审。
7. **字段脱敏**：手机号默认脱敏；查看明文需 `crm:lead:pii:view` 且记录审计。

### 1.5 状态机

**线索状态机**

```
[NEW] --开始跟进--> [FOLLOWING] --转化--> [CONVERTED]（终态）
[NEW] --判定无效--> [INVALID]（终态）
[NEW/FOLLOWING] --进入培育--> [NURTURING] --重新激活--> [FOLLOWING]
[FOLLOWING] --超期无活动(公海规则)--> [NEW]（回收至公海，owner 清空）
```

**商机状态机**

```
[OPEN/S1] --> [OPEN/S2] --> [OPEN/S3] --> [OPEN/S4] --> [WON]（终态）
任意 OPEN 阶段 --> [LOST]（需填输单原因，终态）
[WON] --合同作废--> [OPEN/S4]（管理端授权，强审计）
```

**报价单状态机**

```
[DRAFT] --提交--> [PENDING] --通过--> [APPROVED] --转合同--> [CONVERTED]（终态）
[PENDING] --驳回--> [REJECTED] --修改--> [DRAFT]
[APPROVED] --过期(valid_until)--> [DRAFT]（版本+1）
```

### 1.6 工作流（BPMN 说明）

**报价折扣审批流程 `crmQuotationApproval`**

- 起点（Start Event）→ 排他网关 `gwDiscount`；
- 分支判定：`discount_rate ≤ 20%` → 直接 `End（自动通过）`；
- `20% < discount_rate ≤ 35%` → 用户任务 `销售经理审批`；
- `discount_rate > 35%` → 用户任务 `销售经理审批` → `财务复核` → `总经理审批`；
- `amount > 1,000,000` → 在链路末端追加 `总经理审批`（与折扣分支合并去重）；
- 每个用户任务配置 `Reject` 边界事件 → 回到 `REJECTED` 并记录意见；
- 超时升级：节点超 48h 未处理，升级至上级（定时边界事件）；
- 结束（End Event）→ 回调 `crm-service` 更新报价单状态并发布事件 `crm.quotation.approved`。

BPMN 关键元素：`StartEvent`、`ExclusiveGateway`、`UserTask`、`BoundaryEvent(Error/Timer)`、`ServiceTask(回调)`、`EndEvent`。

### 1.7 异常与边界

| 场景 | 处理 |
|---|---|
| 并发转化同一线索 | 乐观锁 `version` 冲突返回 `0000005`（状态冲突） |
| 导入文件含重复手机号 | 行级校验，重复行跳过并输出错误报告 |
| 分配时目标销售已离职 | 规则引擎跳过离职账号，回退至部门池 |
| 报价审批中报价单被并发修改 | 审批版本校验，版本不一致拒绝并提示重新提交 |
| 商机输单无原因 | 拒绝并返回 `1001003`（必填缺失） |

### 1.8 验收标准

1. 线索→客户→商机→报价→（转合同）全链路数据可追溯，来源链路完整；
2. 折扣审批 100% 走流程，流程记录可审计；
3. 公海回收规则按配置准确执行，回收操作有审计；
4. 阶段准入准则生效，非法迁移 100% 被拦截。

### 1.9 与标杆（销售易）差异点

| 维度 | 标杆（销售易） | 丰麟云销 A1 |
|---|---|---|
| 与客户成功打通 | 侧重销售过程 | 线索/商机原生关联 A2 续费与健康度，成交即进入成功计划 |
| 情绪/舆情联动 | 无 | 客户详情聚合 A3 情绪、NPS 与 A5 舆情 |
| 多租户与双端 | 侧重单租户 | 强制管理端/用户端分离 + 租户 RLS |
| 渠道报备 | 独立 PRM | A1 与 A4 报备商机双向打通，保护期联动 |
| 预测口径 | 阶段赢率 | 阶段赢率×阶段系数，系数可配置且口径可解释 |

### 2.4 业务规则

1. **健康度因子与权重（默认）**：产品使用活跃度 30%、工单 15%、情绪分（A3）20%、NPS（A3）15%、回款 10%、关键人变动 5%、使用深度 5%；权重可在管理端调整，总和须为 100%。
2. **健康度等级阈值**：`≥80 健康`、`60–79 关注`、`40–59 风险`、`<40 危急`。
3. **续费提醒节点**：T-90/60/30/15/7 天分级提醒；到期未续且无进展 → 流失预警。
4. **续费折扣审批**：复用 A1 报价审批（同一 Flowable 定义，业务类型区分）。
5. **分层规则**：`ARR ≥ 500 万 或 战略客户 → S`；`200–500 万 → A`；`50–200 万 → B`；`< 50 万 → C`。
6. **CSM 分派**：分层 S/A 客户由资深 CSM 承接，单 CSM 在服客户上限默认 80（可配置）。
7. **增购推荐**：基于"未使用模块 + 产品关联规则 + 相似客户已购"生成，覆盖率与点击率可统计。

### 2.5 状态机

**健康度等级状态机**

```
[HEALTHY] --评分下降--> [WATCH] --继续下降--> [RISK] --低于40--> [CRITICAL]
任意等级 --评分回升--> 上一等级（逐级回升，避免抖动：连续 2 日同向变化才升级/降级）
```

**续费单状态机**

```
[PENDING] --开始跟进--> [QUOTING] --提交审批--> [APPROVING] --通过--> [SIGNED] --完成--> [COMPLETED]（终态）
[APPROVING] --驳回--> [QUOTING]
[PENDING/QUOTING/APPROVING] --客户明确不续--> [CHURNED]（终态，需填流失原因）
```

**成功计划状态机**

```
[ACTIVE] --全部里程碑完成--> [COMPLETED]（终态）
[ACTIVE] --暂停--> [PAUSED] --恢复--> [ACTIVE]
```

### 2.6 工作流（BPMN 说明）

**续费审批流程 `crmRenewalApproval`**

- `StartEvent` → 读取续费单折扣与金额 → `ExclusiveGateway`；
- `discount ≤ 20%` 且 `amount ≤ 50万` → 自动通过（ServiceTask 回调）；
- 否则 → `UserTask 客户成功主管审批` → `UserTask 财务审核`；
- 客户为 S 级战略客户 → 追加 `UserTask 销售总监审批`；
- 边界：`Timer` 48h 升级；`Error` 驳回回退 `QUOTING`；
- `EndEvent` → 回调更新续费单 → 发布 `crm.renewal.signed` → 触发 A1 合同与服务合同更新。

**健康度重算任务编排（XXL-Job）**

- 任务 `crmHealthRecalcJob`（每日 02:00）：拉取在服客户 → 并行聚合因子 → 归一化加权 → 写 `crm_health_score` → 等级变化发事件 → 触发续费/赢回任务。

### 2.7 异常与边界

| 场景 | 处理 |
|---|---|
| 因子数据缺失（埋点未接入） | 该项按中间分（50）计入并标记 `missing=true`，明细可见 |
| 权重配置总和 ≠ 100% | 管理端保存时校验拒绝，返回 `1005001` |
| 同一客户重复生成续费单 | 依据 `contract_id + term_start` 幂等，重复返回既有单 |
| 流失预警重复派单 | 同客户同规则 24h 内去重 |
| 健康度重算超时 | 分片并行，单租户超时熔断并告警，保留上次结果 |

### 2.8 验收标准

1. 健康度每日重算成功率 ≥ 99.9%，因子明细可查、可解释；
2. 续费提醒按 T-90/60/30/15/7 准确触达，台账状态与实际一致；
3. 流失预警闭环可统计（预警→处置→关闭）；
4. 续费率、流失率、NRR/GRR 指标口径可解释并与明细对账一致。

### 2.9 与标杆（探马）差异点

| 维度 | 标杆（探马） | 丰麟云销 A2 |
|---|---|---|
| 健康度数据源 | 以产品埋点为主 | 融合 A3 情绪分与 NPS 原生因子 |
| 舆情输入 | 无 | A5 舆情命中自动提示 CSM |
| 与销售打通 | 侧重服务 | 续费/增购一键转 A1 商机，闭环销售 |
| 预测口径 | 续费率 | 续费率 + NRR/GRR + 加权预测，支持分层 |
| 多租户 | 单租户为主 | 租户 RLS + 双端配置分离 |

### 3.4 业务规则

1. **NPS 计算**：`NPS = (推荐者占比 - 贬损者占比) × 100`；评分 9–10 推荐者、7–8 被动者、0–6 贬损者。
2. **投放频次控制**：同一客户 30 天内同类问卷最多 1 次（可配置）；黑名单客户不投放。
3. **情绪识别阈值**：AI 置信度 < 0.6 的结果标记"待人工复核"，不触发预警。
4. **负面预警条件**：`polarity=NEGATIVE 且 confidence ≥ 0.8 且（客户分层 ∈ {S,A} 或 emotion_tag=ANGRY）` → 生成 P0/P1 预警。
5. **情绪分**：`sentiment_score = Σ(情绪极性权重 × 置信度)` 归一至 -100~100，作为健康度因子。
6. **VoC 闭环时限**：P0 24h、P1 72h、P2 7 天、P3 30 天；超时升级。
7. **NPS 与 VoC 联动**：贬损者（0–6）自动生成 VoC 条目并指派 CSM 回访。

### 4.4 业务规则

1. **入驻审核**：提交资质（营业执照、法人、联系人）→ 渠道经理审核 → 通过后开通伙伴账号与等级；驳回需填原因。
2. **报备保护期**：默认 90 天（可配置）；保护期内同一客户仅承认首个通过报备的伙伴。
3. **报备查重**：命中已有有效报备或存在直营商机（owner 为本厂销售）→ 标记冲突 `conflict_flag=true`，进入裁决。
4. **返点计算**：`佣金 = 成交金额 × 等级返点率 × 行业系数`；金牌 15%、银牌 10%、认证 6%、注册 3%（可配置）。
5. **佣金幂等**：以 `idempotency_key` 保证同一成交只结算一次；重复结算请求返回既有单。
6. **结算链路**：生成结算单 → 渠道总监审批 → 财务对账 → 标记已支付；状态回写伙伴门户。
7. **数据隔离**：伙伴用户仅可见 `partner_id = 自身` 的报备、佣金、协议数据；越权返回 `1007002`。
8. **保护期过期**：到期未成交自动释放，报备状态转 `EXPIRED`，客户可被重新报备。

### 4.5 状态机

**伙伴状态机**

```

```

```

```


### 4.6 工作流（BPMN 说明）

**伙伴报备审批流程 `crmPartnerDealRegApproval`**

- `StartEvent（伙伴提交报备）` → `ServiceTask 查重与保护期校验` → `ExclusiveGateway`；
- 无冲突 → `ServiceTask 自动通过`（配置自动审批）或 `UserTask 渠道经理审批`；
- 有冲突 → `UserTask 渠道经理裁决` → `ExclusiveGateway（通过/驳回）`；
- 通过 → `ServiceTask 生成关联商机（A1）` → `ServiceTask 通知伙伴` → `EndEvent`；
- 驳回 → `UserTask 通知伙伴并记录原因` → `EndEvent`。

**佣金结算流程 `crmPartnerCommissionSettlement`**

- `StartEvent（成交确认，来自 A1 商机 WON 事件）` → `ServiceTask 计算佣金（幂等校验）` → `UserTask 渠道总监审批` → `UserTask 财务对账` → `ServiceTask 标记已支付 + 回调伙伴门户` → `EndEvent`；
- 边界：对账不一致 → `Error` 回退复核。

### 4.7 异常与边界

| 场景 | 处理 |
|---|---|
| 同一客户多伙伴报备 | 按保护期与提交时间裁决，记录裁决过程 |
| 报备金额与成交金额差异大 | 佣金以成交金额为准并提示差异比率 |
| 伙伴账号停用后提交 | 拒绝，返回 `1007001`（伙伴未激活） |

| 伙伴查看非本伙伴数据 | 数据权限拦截，返回 `1007002` 并记审计 |

### 4.8 验收标准

1. 报备查重与保护期规则 100% 准确，裁决过程可追溯；
2. 佣金计算可复算（结果 = 成交额 × 返点 × 系数），结算可对账；
3. 伙伴数据隔离 100% 生效，越权 100% 被拒并审计；
4. 保护期过期自动释放准确。

## 6 模块间协同总览

```
        A1 销售管理 ──成交(WON)──▶ A2 客户成功与续费
             ▲  │                      │
             │  │ 报备转商机            │ 续费/增购转商机
             │  ▼                      ▼
        A4 PRM ◀──伙伴贡献── A2 续费率/健康度
             ▲                      ▲
             │ 舆情命中伙伴相关        │ 情绪/NPS 因子
        A5 舆情竞品 ──命中客户──▶ A3 情绪与NPS ──情绪分──▶ A2 健康度
             └──────────关联提醒──────────▶ A1 客户/商机
```

关键事件流：

| 事件 | 生产者 | 消费者 | 动作 |
|---|---|---|---|
| `crm.lead.converted` | A1 | A2/A5 | 创建成功计划、关联舆情监测 |
| `crm.opportunity.won` | A1 | A2/A4 | 生成服务合同、触发佣金计算 |
| `crm.health.level_changed` | A2 | A1/A3 | 提示跟进、触发情绪回访 |
| `crm.sentiment.negative_detected` | A3 | A2/A5 | 健康度因子、舆情关联 |
| `crm.partner.deal_approved` | A4 | A1 | 生成关联商机 |
| `crm.opinion.alert` | A5 | A1/A2 | 关联客户提醒 |
