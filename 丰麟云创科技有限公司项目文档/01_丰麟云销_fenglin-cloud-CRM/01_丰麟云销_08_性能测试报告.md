## 1 目标与指标

### 1.1 性能目标（对齐平台基线）

| 指标 | 目标值 | 来源 |
|---|---|---|
| 支持并发用户 | 3400 人在线 | NFR-002 |
| 核心接口峰值吞吐 | ≥ 1200 QPS | NFR-002 |
| 核心接口响应 | P95 ≤ 300ms，P99 ≤ 800ms | NFR-001 |
| 页面首屏 | 内网 ≤ 1s，4G ≤ 2s | NFR-003 |
| 单接口错误率 | ≤ 0.1% | NFR-001 |
| 服务可用性 | ≥ 99.99%/年 | NFR-004 |
| 容灾 | RPO ≤ 5min，RTO ≤ 30min | NFR-005 |
| 数据规模基线 | 单租户 ≤ 10 亿行；核心表年增按 FL-CRM-DB-003 预估 | NFR-017 |

### 1.2 通过准则

全部核心场景满足：错误率 ≤ 0.1% 且 P95 ≤ 300ms（P99 ≤ 800ms）；峰值场景稳定运行 30 分钟无资源泄漏；容灾演练 RPO/RTO 达标。

## 5 瓶颈分析

| 序号 | 现象 | 定位 | 根因 | 影响 |
|---|---|---|---|---|
| B-01 | 商机漏斗在 1500 并发时 P95 升至 640ms | SkyWalking + EXPLAIN | 漏斗聚合按阶段全表扫描，缺复合索引 | 报表场景 P95 超线 |
| B-02 | 客户 360° 视图首屏 RT 达 1.8s | 链路追踪 | 聚合 6 个子域接口串行调用 | 首屏超 1s |
| B-03 | 线索导入批量写入放大 | pgBadger | 逐行 INSERT，单事务过大 | 导入窗口 CPU 抖动 |
| B-04 | 舆情全文检索 GB 级结果集排序耗时 | ES profile | 深分页 + 无 `search_after` | 检索 P99 升高 |
| B-05 | 健康度重算单租户耗时 82min（首轮） | XXL-Job 日志 | 全量串行、无分片并行 | 超出 60min 目标 |
| B-06 | 峰值下消息服务偶发超时 | 链路追踪 | 预警推送同步调用 message-service | 情绪预警链路 P99 波动 |

## 6 调优措施

| 对应瓶颈 | 措施 | 实施内容 | 效果 |
|---|---|---|---|
| B-01 | 索引与预聚合 | 对 `crm_opportunity(tenant_id, stage, deleted)` 建复合索引；漏斗按物化视图/定时预聚合 | 漏斗 P95 640ms → 248ms |
| B-02 | 并行聚合与缓存 | 客户 360° 子域调用改并行（CompletableFuture）+ 结果缓存 60s | 首屏 1.8s → 0.86s |
| B-03 | 批量写入 | 导入改 `COPY`/批量 `INSERT`，分批提交（5000 行/批） | 导入吞吐 +3.2 倍，CPU 平稳 |
| B-04 | 检索优化 | 采用 `search_after` 深分页；热度字段加 `doc_values`；限制返回字段 | 检索 P99 ↓38% |
| B-05 | 分片并行 | 健康度重算按租户/客户分片并行（线程池 + 分片键），单租户超时熔断保留上次结果 | 82min → 42min |
| B-06 | 异步与削峰 | 预警推送改异步（Kafka + 重试 + 幂等），消息服务独立线程池 | P99 波动消除，链路稳定 |
| 通用 | 缓存与限流 | 热点字典/配置本地缓存 + Redis 二级；Sentinel 按租户+接口限流 | 数据库 QPS ↓42% |
| 通用 | SQL 与连接 | 消除 N+1，MyBatis-Plus 分页优化；连接池按节点调优（最大 40） | 慢查询清零 |

## 7 结论与容量建议

### 7.1 结论

1. 在 3400 并发在线、峰值 1268 QPS 的压力下，全部核心场景满足 **P95 ≤ 300ms、P99 ≤ 800ms、错误率 ≤ 0.1%**；
2. 页面首屏内网 0.86s、4G 1.72s，满足 ≤1s / ≤2s 目标；
3. 24 小时长跑无内存泄漏与错误率攀升，服务可用性达标（≥99.99%）；
4. 容灾演练 RPO 2.4min、RTO 18min，满足 ≤5min / ≤30min；
5. 性能测试用例 TC-PERF-001~006 全部通过。

### 7.2 容量建议

| 项 | 当前 | 建议（按 12 个月增长） |
|---|---|---|
| 应用副本 | 8 | 基准 8，峰值弹性至 12（HPA：CPU>65% 扩容） |
| 数据库 | 1 主 2 从 | 保持读写分离；商机/活动表按租户+时间分区；预留只读扩容 |
| Redis | 3 主 3 从 | 命中率 <90% 时扩容至 6 主 6 从 |
| Kafka | 3 Broker | 分区数按峰值 2 倍冗余；监控消费滞后 |
| ES | 3 节点 | 索引按 30 天滚动，冷热分层，容量 ≥ 12 个月舆情数据 |
| 定时任务 | 分片并行 | 健康度重算窗口预留 2 小时；超时熔断告警 |
| 容量水位 | CPU ≤70%、DB CPU ≤75% | 任一持续超阈值触发扩容评审 |

### 7.3 复测结论

调优措施全部落地后，对 B-01~B-06 涉及场景复测，指标达成且无回归；复测数据见上表。后续每季度执行一次基准回归（回归组 R8）。
