## 1 引言

### 1.1 目的

本文档定义**丰麟云法（Fenglin Cloud Legal）**的产品需求基线，是丰麟云创科技有限公司面向中大型企业客户交付"合同法务与信息风控平台"的需求依据。本文档用于：

1. 明确 G1 合同与电子签章、G2 内部信息防泄漏（DLP）两大业务模块的功能与非功能需求边界；
2. 作为架构设计、数据库设计、接口设计、UI/UX 设计、测试与验收的上游输入；
3. 作为与客户、平台架构组（FL-HUB-STD-001 归口）之间需求确认与变更控制的基线文件。

品牌口号：**合同全生命周期可控，核心信息不泄漏**。

## 2 产品概述

### 2.1 产品定位

丰麟云法是丰麟云枢平台域G的核心产品，面向中大型企业的法务、合同、信息安全管理团队，构建"**合同全生命周期可控 + 核心信息不泄漏**"的双引擎风控平台：

1. **G1 合同与电子签章（参考标杆：法大大）**：覆盖合同模板、起草、审批、用印、电子签章、存证、履约跟踪、到期提醒的端到端闭环，确保合同文本与签章证据**防篡改、可追溯、可举证**；
2. **G2 内部信息防泄漏 DLP（参考标杆：亿赛通）**：覆盖敏感数据识别、外发管控、水印、审计追溯，并对终端/网盘/邮件等外发通道实施管控与实时拦截。

核心价值主张：

1. **合规可控**：电子签章符合《电子签名法》，签署证据链完整可追溯；
2. **防篡改**：合同正文与签章证据、DLP 审计日志采用哈希链 + WORM 固化；
3. **全生命周期**：合同从模板到归档全程线上化、可审计；
4. **风险前置**：DLP 实时拦截 + 水印溯源，核心信息"带不走、看不清、赖不掉"。

## 3 业务需求（模块级功能需求）

> 编号规则：`{模块码}-FR-{3位序号}`。优先级：P0（必须）、P1（重要）、P2（一般）。

### 3.1 G1 合同与电子签章

模块定位：覆盖合同模板、起草、审批、用印、电子签章、存证、履约跟踪、到期提醒的合同全生命周期管理（参考标杆：法大大）。

| 编号 | 需求名称 | 优先级 | 需求描述 | 端别 | 关键权限码 |
|---|---|---|---|---|---|
| G1-FR-001 | 合同模板管理 | P0 | 支持分类（采购/销售/劳务/保密/租赁）维护合同模板，模板含版本与状态（草稿/已发布/停用）；模板正文支持富文本与附件；模板可设定适用组织与可见范围。 | 用户端 + 管理端 | `legal:template:manage`、`tenant:legal:template:config` |
| G1-FR-002 | 模板版本与变量 | P0 | 模板支持多版本（发布后不可改，新版本 +1）；模板内定义变量占位符（如 `${partyA}`、`${amount}`、`${signDate}`），变量可设类型、必填、默认值与取值来源；起草时按变量填充。 | 用户端 + 管理端 | `legal:template:version`、`tenant:legal:template:variable` |
| G1-FR-003 | 合同起草 | P0 | 基于模板或空白起草合同，录入合同名称、类型、相对方、金额、币种、起止日期、归属组织与负责人；自动生成合同编号 `CT{yyyy}{6位}`；支持从 A1（商机/报价）等外部来源带入信息。 | 用户端 | `legal:contract:create` |
| G1-FR-004 | 合同版本与条款管理 | P0 | 合同正文支持多版本（每次修改生成新版本并留痕）；条款结构化维护（条款编号、标题、正文、是否必留）；正文与条款变更记录变更人、时间、差异摘要。 | 用户端 | `legal:contract:edit` |
| G1-FR-005 | 合同审批 | P0 | 合同提交审批，按金额区间、合同类型、所属组织、相对方风险等级路由至多级审批流（Flowable）；支持会签、或签、加签、转办、驳回；审批通过后合同进入用印阶段。 | 用户端 | `legal:contract:submit`、`legal:contract:approve` |
| G1-FR-006 | 用印申请与审批 | P0 | 用印前须提交用印申请（合同、印章、份数、用途、用印类型：电子章/实物章），经用印审批流审批；审批通过方可执行用印。 | 用户端 | `legal:seal:apply`、`legal:seal:approve` |
| G1-FR-007 | 用印执行与用印记录 | P0 | 用印管理员依据审批执行用印（电子盖章或实物章登记），生成用印记录（印章、次数、位置、操作人、时间）；用印记录不可删除。 | 用户端 | `legal:seal:execute`、`legal:seal:view` |
| G1-FR-008 | 电子签章与签署方管理 | P0 | 对接第三方 CA/电子签章服务（法大大/e签宝/CFCA 等），管理签约印章与数字证书；维护签署方（内部/外部、签署顺序、签署方式：手写签名/企业章/时间戳）；支持顺序签与并行签。 | 用户端 | `legal:sign:initiate`、`legal:signatory:manage` |
| G1-FR-009 | 签署证据链与存证 | P0 | 签署过程产生完整证据链（实名认证记录、意愿确认、签署时间戳、合同哈希、CA 证书信息、IP/设备）；签署完成后对合同正文与证据固化存证，生成存证编号 `EVD{yyyy}{6位}`，支持一键核验与出证。 | 用户端 | `legal:evidence:manage`、`legal:evidence:verify` |
| G1-FR-010 | 合同与签章证据防篡改 | P0 | 合同正文、条款、签署证据、用印记录采用哈希链（`prev_hash` 串联 + 块哈希）与 WORM 存储固化；任何篡改可被检测；提供完整性核验接口。 | 系统 | `legal:contract:integrity` |
| G1-FR-011 | 履约跟踪 | P0 | 依据合同条款维护履约节点（交付、验收、付款、开票、质保），设定节点责任人、计划时间、金额；节点到期提醒、逾期预警，跟踪履约状态与完成凭证。 | 用户端 | `legal:performance:manage` |
| G1-FR-012 | 到期提醒 | P0 | 按合同到期（终止日/续签日）提前 T-90/60/30/15/7 天分级提醒；支持续签、终止、归档处理；提醒渠道站内信 + 邮件。 | 用户端 + 管理端 | `legal:contract:remind`、`tenant:legal:reminder:config` |
| G1-FR-013 | 合同检索与台账 | P0 | 提供合同台账（按类型、状态、组织、相对方、金额、时间筛选）与全文检索（ES + IK，含条款正文）；支持导出（脱敏）。 | 用户端 | `legal:contract:view`、`legal:contract:export` |
| G1-FR-014 | 相对方管理 | P1 | 维护相对方档案（名称、统一社会信用代码、联系人、联系方式加密、风险等级、历史合同）；相对方变更留痕；高风险相对方触发加审。 | 用户端 | `legal:party:manage` |
| G1-FR-015 | 印章与证书管理 | P0 | 管理端维护电子印章与数字证书（印章图片、证书序列号、有效期、绑定主体、状态：启用/停用/吊销）；证书到期预警；用印水印叠加。 | 管理端 | `tenant:legal:seal:config` |
| G1-FR-016 | 合同归档与防篡改校验 | P0 | 合同完成后归档（只读），归档快照固化哈希；提供完整性校验（比对归档哈希）与篡改告警。 | 用户端 | `legal:contract:archive` |

**G1 验收要点**：合同全生命周期状态可追溯；电子签章符合《电子签名法》要件；签署证据链完整可核验；合同正文与证据哈希校验 100% 通过；用印记录不可删除。

### 3.2 G2 内部信息防泄漏（DLP）

模块定位：识别、分级并管控企业敏感数据，阻断核心信息经终端/网盘/邮件等通道泄漏，实现"识别—管控—拦截—审计—溯源"闭环（参考标杆：亿赛通）。

| 编号 | 需求名称 | 优先级 | 需求描述 | 端别 | 关键权限码 |
|---|---|---|---|---|---|
| G2-FR-001 | 敏感数据识别规则 | P0 | 管理端定义敏感识别规则：关键字/正则（身份证、银行卡、手机号）、文件指纹（文档指纹/相似度）、数据分类分级标签、机器学习模型（经 `fenglin-ai-service`）；规则可组合、可优先级排序、可设命中阈值。 | 管理端 | `tenant:legal:dlp:rule:config` |
| G2-FR-002 | 敏感数据识别与分级 | P0 | 对文档内容、文件名、元数据进行识别与分类分级（公开/内部/秘密/机密），输出命中的规则、敏感片段位置与置信度；识别结果写入敏感标签。 | 系统 | `legal:dlp:detect` |
| G2-FR-003 | DLP 策略管理 | P0 | 按组织/角色/数据级别/通道组合定义策略动作（告警/审计/拦截/审批放行/加密/加水印）；策略支持生效时间、优先级与例外；策略变更留痕与版本。 | 管理端 | `tenant:legal:dlp:policy:config` |

### 5.2 数据需求要点

1. **多租户**：所有业务表含 `tenant_id` 并启用 RLS；跨租户访问仅平台运营端并强制审计。

6. **迁移**：全部 DDL/DML 通过 Flyway 脚本（`V1_0_x__*.sql`）提交。
7. **证据留存**：签署证据链与存证数据长期留存（≥ 合同到期后 5 年），DLP 审计日志留存 12 个月。

## 6 接口需求

1. 全部接口遵循 `/api/legal/v1` 前缀、RESTful 风格、统一响应体（`code/message/data/requestId/timestamp`）。
2. 统一请求头：`Authorization`、`X-Tenant-Id`、`X-Client-Type`（ADMIN/PORTAL）、`X-Request-Id`、`Idempotency-Key`（写操作）。
3. 错误码域前缀 `70`，结构 `{域2}{模块2}{序号3}`：
   - 通用/校验：`7000001`–`7000999`
   - G1 合同与签章：`7001xxx`
   - G2 DLP：`7002xxx`
4. 分页：`page`（从 1 起）、`size`（默认 20，最大 200）。
5. **第三方 CA/签章服务对接**：通过适配层对接 CA/电子签章服务商（法大大/e签宝/CFCA/自建 CA），统一定义"实名认证、证书申领、签署任务发起、签署回调、时间戳、存证出证"六类能力契约；服务商配置化管理端可切换；回调采用 HMAC-SHA256 验签 + 幂等。
6. **DLP 事件上报**：终端 Agent 通过内部接口 `POST /api/legal/v1/dlp/events/report`（单条）与 `/dlp/events/batch-report`（批量）上报外发事件；实时拦截决策接口 `POST /api/legal/v1/internal/dlp/decide` 供终端/网关毫秒级调用。
7. 需提供 OpenAPI 3.1 契约与开放 API（前缀 `/openapi/legal/v1`）与事件 Webhook。
8. 核心接口清单详见 FL-LEGAL-API-005《接口文档》。

## 7 约束与假设

### 7.1 约束

1. 必须遵循 FL-HUB-STD-001 的命名体系、技术栈、接口/数据/权限/安全/UI 规范；
2. 必须严格实现管理端（`/admin/legal`）与用户端（`/app/legal`）分离；
3. 后端统一技术栈：Java 17 / Spring Boot 3.2.x / Spring Cloud 2023.0.x / MyBatis-Plus 3.5.x / PostgreSQL 15 / Redis 7 / Kafka 3.6 / Flowable 7；
4. 前端统一 Vue 3.4 + TypeScript + Vite 5；管理端 Element Plus，用户端自研 Portal 组件；
5. 电子签章必须符合《电子签名法》与 GM/T 0031，签署证据链完整可追溯，采用国密 SM2/SM3 或国际 RSA/SHA-256 算法（按 CA 支持）；
6. 合同正文、签章证据、DLP 审计日志必须防篡改（哈希链 + WORM）；
7. 不得引入异构框架，确需引入须报平台架构组评审。

### 7.2 假设

1. 丰麟云枢中台（IAM/租户/消息/文件/审计/搜索/AI/报表/工作流/开放平台）可用并按契约提供能力；
2. 第三方 CA/电子签章服务商可提供标准 API（事实以适配层为准），其证书具备法律效力；
3. 敏感数据识别中的语义/模型能力由 `fenglin-ai-service` 提供，本品负责规则编排与策略执行；
4. DLP 终端 Agent 部署于受管终端，具备本地扫描与策略执行能力；
5. 文件服务（`fenglin-file-service`）提供水印与防泄漏钩子能力供本品复用。
