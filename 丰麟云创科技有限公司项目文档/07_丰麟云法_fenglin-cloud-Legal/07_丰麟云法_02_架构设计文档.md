## 1 架构概览

### 1.1 架构定位

丰麟云法（`fenglin-legal-service`）是丰麟云枢平台域G的业务域微服务，遵循"中台复用 + 业务域自治 + 开放生态"的总体架构，交付"合同全生命周期可控 + 核心信息不泄漏"的双引擎能力。

| 项 | 内容 |
|---|---|
| 微服务名 | `fenglin-legal-service` |
| 命名空间 | `fenglin-legal` |
| API 前缀 | `/api/legal/v1` |
| 数据库 | `fenglin_legal`（PostgreSQL 15） |
| 覆盖模块 | G1 合同与电子签章、G2 内部信息防泄漏（DLP） |
| 关键外部集成 | 第三方 CA/电子签章服务商、DLP 终端 Agent、中台服务 |

### 1.2 架构原则

1. **合规优先**：电子签章、存证、审计满足《电子签名法》与等保三级要求；
2. **防篡改为纲**：合同正文/签章证据/用印记录/DLP 审计日志一律哈希链 + WORM；
3. **中台复用**：身份、租户、工作流、消息、文件、审计、搜索、AI 全部复用中台能力，本品不重复建设；
4. **双端分离**：管理端与用户端在路由、权限域、前端工程、审计粒度上强制分离；
5. **实时决策**：DLP 拦截决策走低延迟链路（缓存规则 + 内存匹配），不依赖同步外呼重服务；
6. **适配隔离**：第三方 CA/签章服务通过适配层抽象，多服务商可切换、可降级；
7. **多租户安全**：全表 `tenant_id` + RLS，跨租户默认拒绝。

## 4 关键流程时序

### 4.1 合同起草与审批（G1）

```
用户端        网关        legal-service      workflow-service     消息/文件
  │  起草合同    │              │                   │                │
  ├─────────────▶│──────────────▶│  校验模板/变量       │                │
  │              │              ├── 生成 CT 编号 ──────│                │
  │              │              ├── 保存正文版本/条款 ─┼──▶ 存储(MinIO)  │
  │              │◀─────────────┤ 返回合同草稿         │                │
  │  提交审批     │              │                   │                │
  ├─────────────▶│──────────────▶│ 校验必填/条款完整性   │                │
  │              │              ├── 启动流程实例 ─────▶│                │
  │              │              │   (金额/类型/组织/风险路由)             │
  │              │              │◀── 待办生成 ────────┤                │
  │              │◀─────────────┤ 通知审批人 ─────────┼──▶ 消息服务     │
  │  审批通过     │              │                   │                │
  ├─────────────▶│──────────────▶│ 流程结束回调 ───────▶│                │
  │              │              ├── 合同置 SIGNING_READY                │
  │              │              ├── 发布 legal.contract.approved ──▶ Kafka
```

### 4.2 用印与电子签署（G1，含 CA 适配）

```
用印管理员   legal-service   workflow-service   CA 适配层   第三方 CA     EVENCE/WORM
   │  用印申请    │                │               │          │            │
   ├────────────▶│  校验合同已审批  │               │          │            │
   │             ├── 启动用印审批 ─▶│               │          │            │
   │  审批通过    │◀───────────────┤               │          │            │
   ├────────────▶│  发起签署流程    │               │          │            │
   │             ├─ 生成签署方/任务(SIGN)           │          │            │
   │             ├─ 实名认证+意愿确认 ─────────────▶│─────────▶│            │
   │             ├─ 申请证书/签章 ─────────────────▶│─────────▶│            │
   │             ├─ 文档哈希+时间戳 ───────────────▶│─────────▶│            │
   │             │◀─ 签署回调(HMAC 验签+幂等) ──────┤◀─────────┤            │
   │             ├─ 生成签署证据链 ─────────────────┼──────────┼──▶ 固化     │
   │             ├─ 合同置 SIGNED                   │          │            │
   │             ├─ 哈希链写入 + WORM ──────────────┼──────────┼──▶ 存证 EVD │
   │◀─ 签署完成   │                                │          │            │
```

### 4.3 用印执行（G1）

1. 用印申请审批通过 → `legal-service` 校验合同版本哈希与申请一致；
2. 用印管理员执行：电子章由 CA 服务加盖，实物章登记用印信息（图片、份数、位置）；
3. 生成 `legal_seal_record`（不可删除）→ 写哈希链 → 更新合同状态；
4. 发布事件 `legal.seal.executed`。

### 4.4 合同到期提醒（G1，XXL-Job）

```
XXL-Job `legalExpiryReminderJob`（每日 08:00）
  → 扫描 legal_contract（end_date 在 T-90/60/30/15/7 窗口且 status=SIGNED/EFFECTIVE）
  → 生成/更新 legal_expiry_reminder（去重键：contract_id + offset_days）
  → 经 message-service 触达负责人/合同管理员（站内信+邮件）
  → 记录触达结果与审计
```

### 4.5 DLP 事件上报与实时拦截（G2）

```
DLP Agent        网关/终端钩子      legal-service 决策引擎      Kafka        审计/处置
   │  文件外发动作    │                  │                   │             │
   ├───────────────▶│  实时决策请求      │                   │             │
   │                ├─────────────────▶│ 加载策略(本地缓存)   │             │
   │                │                  ├─ 规则匹配/分级       │             │
   │                │◀─ 决策(ALLOW/WARN/BLOCK/APPROVE) ───────┤             │
   │  (拦截) 阻止外发  │                  │                   │             │
   │                ├─────────────────▶│ 事件上报             │             │
   │                │                  ├─ 落库 legal_dlp_event│             │
   │                │                  ├─ 写审计(哈希链+WORM) ─┼─────────▶ 审计
   │                │                  ├─ 发布 legal.dlp.event.raised ──▶ Kafka
   │                │                  │                   │  ▶ 处置工作流
```

### 4.6 水印溯源（G2）

1. 疑似泄漏文档提交溯源 → 提取暗水印（嵌入的 `wm_id + 用户 + 时间` 编码）；
2. 反查 `legal_watermark_record` 得到施加水印的用户/终端/IP/文档/时间；
3. 关联 `legal_dlp_event` 形成泄漏链路 → 输出溯源报告 → 归档至 WORM。

## 5 数据架构

### 5.1 数据存储分布

| 存储 | 承载数据 | 说明 |
|---|---|---|
| PostgreSQL `fenglin_legal` | 全部业务表（27 张） | RLS 隔离、TDE 透明加密 |
| Redis 7 | 合同草稿缓存、DLP 策略缓存、决策规则、分布式锁、限流计数 | 策略缓存保障实时决策低延迟 |
| Kafka 3.6 | 领域事件（合同/签章/DLP 事件） | 事件驱动与异步解耦 |
| RocketMQ 5 | 用印/签署/放行强一致事务消息 | 补偿与对账 |
| Elasticsearch 8 | 合同与条款全文索引、DLP 事件检索 | IK 分词、30 天滚动 |
| MinIO | 合同文件、签署文档、证据附件、水印文档 | 版本控制、生命周期 |
| WORM 存储 | 合同正文/条款快照、签署证据、用印记录、DLP 审计日志 | 一次写入不可改 |

### 5.2 多租户与隔离

- SaaS：共享库共享模式 + `tenant_id` 逻辑隔离 + PostgreSQL RLS（默认策略 `USING (tenant_id = current_setting('app.tenant_id')::bigint)`）；
- 私有化：独立库（database per tenant）；
- 跨租户访问仅平台运营端（`platform:*`）并强制审计；
- 组织级数据权限通过 `data_scope` + 部门维度列过滤（合同/事件按所属组织隔离）。

### 5.3 数据一致性

| 场景 | 方案 |
|---|---|
| 用印审批通过 → 合同状态变更 | RocketMQ 事务消息 + 幂等消费 |
| 签署回调 → 证据链固化 | 幂等（`sign_task_id` + 唯一约束）+ 重试 |
| 合同状态与索引一致性 | 事件驱动异步更新 ES，失败重试 + 对账任务 |
| 用印记录/审计日志写入 | 哈希链顺序写入（分布式锁/串行化），失败阻断并告警 |

### 5.4 缓存策略

| 缓存对象 | 键 | TTL | 失效 |
|---|---|---|---|
| DLP 策略与规则 | `legal:dlp:policy:{tenant}:{org}` | 300s | 策略变更发布事件失效 |
| 合同草稿 | `legal:contract:draft:{id}` | 1800s | 保存后刷新 |
| 印章/证书状态 | `legal:seal:{id}` | 600s | 印章变更失效 |
| 字典/配置 | `legal:dict:{type}` | 3600s | 配置变更失效 |
| 幂等键 | `legal:idem:{tenant}:{key}` | 24h | 过期自动清理 |

## 6 集成与开放

### 6.1 与中台集成

| 中台能力 | 集成方式 |
|---|---|
| 认证/SSO/MFA | OAuth2.1/OIDC，签署前二次认证（`/auth/step-up`） |
| 权限 | 功能权限码 + 数据权限注解；网关 + 服务双层校验 |
| 工作流 | Flowable BPMN 流程定义（合同/用印/放行/处置），回调更新业务状态 |
| 消息 | 模板化通知（提醒/邀请/告警），多渠道 + Webhook |
| 文件 | 上传/下载/预览/版本/水印钩子（`X-Watermark`） |
| 审计 | 关键操作写 `fenglin-audit-service`（哈希链 + WORM） |
| 搜索 | 合同/条款/事件索引与检索 |
| AI | 敏感语义识别、合同要素抽取（辅助，不阻断主流程） |
| 报表 | 合同统计、DLP 风险看板 |
| 开放平台 | 应用注册、AppKey/Secret、配额、沙箱 |

### 6.2 开放 API

- 前缀 `/openapi/legal/v1`；AppKey/AppSecret（HMAC-SHA256 签名）+ OAuth2.1；
- 对外开放资源：合同台账查询、合同状态查询、签署任务发起、DLP 事件查询（只读）、敏感识别（受配额限制）；
- 配额与限流按应用/接口维度配置，超限返回 `0000006`。

### 6.3 第三方 CA/签章服务对接（适配层）

```
com.fenglin.legal.domain.signature.spi.CaProviderPort（端口）
   ├── RealNameVerifyPort      实名认证（企业四要素/个人三要素）
   ├── CertIssuePort           证书申领/查询/吊销
   ├── SignTaskPort            签署任务发起/查询/撤销
   ├── CallbackPort            签署回调验签与解析
   ├── TimestampPort           可信时间戳
   └── EvidencePort            存证固化与出证
适配实现：FaDaDaAdapter / EsignAdapter / CfcaAdapter / SelfBuiltCaAdapter
```

统一能力契约要点：

| 能力 | 请求要素 | 响应要素 | 幂等 |
|---|---|---|---|
| 实名认证 | 主体类型、名称、证件号（加密）、法人信息 | 认证结果、认证流水、证据引用 | 支持 |
| 证书申领 | 主体、用途、算法（SM2/RSA） | 证书序列号、有效期、公钥 | 支持 |
| 签署任务 | 文档哈希、签署方、签署顺序、签署方式 | 任务 ID、签署链接/二维码 | 强制 |
| 签署回调 | 任务 ID、签署人、时间戳、签章数据 | 验签结果、证据文件 | 强制 |
| 时间戳 | 文档哈希 | TSA 时间戳、可信时间 | 支持 |
| 存证出证 | 存证编号、哈希 | 存证凭证/出证报告 | 支持 |

降级策略：CA 服务不可用时不阻断起草与审批；签署任务排队重试（指数退避，最多 5 次），超限告警并置"待人工处理"。

### 7.2 后端端别路由

- `/api/legal/v1/admin/**` 仅 `ADMIN`（`X-Client-Type: ADMIN`）可访问（印章管理、DLP 策略/规则/通道/白名单/终端、报表、配置）；

- 端别与令牌 `client_type` 不一致返回 `0000002`。

## 8 高可用与容灾

### 8.1 高可用设计

| 组件 | 高可用措施 |
|---|---|
| 应用 | 6~12 副本（HPA：CPU>65%），无状态，滚动发布 |
| 网关 | 2 副本双活 |
| PostgreSQL | 1 主 2 从，流复制 + 读写分离 + 自动故障转移 |
| Redis | Cluster 3 主 3 从 |
| Kafka | 3 Broker，`min.insync.replicas=2` |
| ES | 3 节点，分片副本 |
| MinIO/WORM | 4 节点纠删码 |
| 调度 | XXL-Job 2 实例，任务分片 |

### 8.2 容灾目标

| 项 | 目标 |
|---|---|
| 可用性 | ≥ 99.99%/年 |
| RPO | ≤ 5min（WAL 归档 + 异地同步） |
| RTO | ≤ 30min（同城双活切换） |
| 存证/审计数据 | 异地冗余，不可丢失 |

### 8.3 降级策略

| 依赖故障 | 降级 |
|---|---|
| CA/签章服务不可用 | 起草/审批不受影响；签署任务排队重试并告警 |
| AI 识别不可用 | 敏感识别退化为规则匹配（正则/指纹），标注"AI 未参与" |
| 搜索不可用 | 合同检索退化为数据库精确/模糊查询 |
| 消息服务不可用 | 提醒延迟重试，落库待补发 |
| ES 不可用 | 事件列表退化为数据库分页查询 |

## 9 安全架构

### 9.1 分层防护

| 层 | 措施 |
|---|---|
| 网络 | WAF、K8s NetworkPolicy、内部接口仅 mTLS |
| 传输 | 客户端↔网关 TLS1.3，微服务间 mTLS |
| 应用 | 鉴权、端别校验、幂等、限流（Sentinel）、参数校验、越权防护 |
| 数据 | PII AES-256-GCM、TDE、RLS、字段脱敏 |
| 完整性 | 哈希链 + WORM、完整性定期校验 |
| 审计 | 全链路审计、不可篡改、留存 12 个月 |
| 合规 | 电子签名四要件、证据链完整 |

### 9.2 关键安全控制（本品特异性）

| 控制 | 实现 |
|---|---|
| 电子签名有效性 | 实名认证 + 意愿确认（二次认证/短信验证码）+ 数字证书 + 可信时间戳 + 签名后文档哈希固化 |
| 防抵赖 | 签署行为绑定唯一身份与证书，证据链留痕（IP/设备/时间/USER_AGENT） |
| 合同防篡改 | 每次状态变更写入哈希链；归档快照固化；完整性校验可自动执行 |
| 用印管控 | 用印须审批；用印记录不可删除；用印与合同版本哈希绑定 |
| DLP 防泄漏 | 识别→策略→实时拦截→审批放行→水印→审计完整闭环 |
| DLP 审计防篡改 | 审计日志哈希链 + WORM，应用侧无删除接口 |
| 密钥管理 | KMS 托管证书私钥与加密密钥，轮换 ≤ 90 天 |

## 10 技术风险

| 编号 | 风险 | 影响 | 概率 | 应对 |
|---|---|---|---|---|
| R-01 | 第三方 CA 服务不稳定/接口变更 | 签署链路中断 | 中 | 适配层隔离 + 多服务商可切换 + 队列重试 + 契约测试 |
| R-02 | 哈希链高并发写入串行化形成瓶颈 | 用印/审计写入延迟 | 中 | 按聚合分链（合同/审计分链）+ 批量提交 + 异步固化 |
| R-03 | DLP 实时决策依赖策略缓存一致性 | 策略变更后短暂误判 | 中 | 策略版本号 + 事件失效 + 短 TTL 双保险 |
| R-04 | 敏感识别误报率偏高影响体验 | 用户绕过或投诉 | 中 | 规则分级 + 白名单 + 人工复核 + 模型持续调优 |
| R-05 | WORM 存储成本增长 | 成本压力 | 低 | 分级留存（证据长期、审计 12 月）+ 冷热分层 |
| R-06 | ES 与数据库一致性延迟 | 检索结果滞后 | 低 | 事件驱动 + 定时对账 + 关键查询回源 |
| R-07 | 终端 Agent 覆盖面不足 | 泄漏通道遗漏 | 中 | 通道分级管控 + 未注册终端阻断策略 + 覆盖率看板 |
| R-08 | 国密算法与部分 CA 兼容性 | 签章失败 | 低 | 算法协商与降级（SM 优先，RSA 兼容） |
