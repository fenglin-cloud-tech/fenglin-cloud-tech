### 1.4 业务规则

1. **编号生成**：合同编号 `CT{yyyy}{6位}`（租户内唯一、全局自增序列）；模板 `TPL{yyyy}{6位}`；用印申请 `SEAL{yyyy}{6位}`；签署任务 `SIGN{yyyy}{6位}`；存证 `EVD{yyyy}{6位}`。
2. **变量校验**：合同提交审批前，所有 `required=true` 的模板变量必须已填充；缺失则拒绝提交并返回 `7001004`（模板变量未填充）。
3. **条款完整性**：`is_mandatory=true` 的条款不得删除；缺失则拒绝提交并返回 `7001003`。
4. **审批路由**：按 `amount`（金额区间）、`category`（合同类型）、`org_id`（组织）、`risk_level`（相对方风险）组合路由；高风险相对方自动加审法务总监节点。
5. **审签一致**：用印版本必须与审批终态版本一致（`seal_application.contract_version_id == approval.contract_version_id`），否则拒绝用印并返回 `7001007`（版本不一致）。
6. **用印前置**：合同状态必须为 `APPROVED` 才允许提交用印申请；用印执行前须用印审批通过。
7. **用印不可删**：`legal_seal_record` 应用侧无删除/修改接口；每次用印写哈希链并同步 WORM。
8. **签署顺序**：顺序签（`SEQ`）需前一签署方完成后方可通知下一位；并行签（`PARALLEL`）同时发起；任一签署方拒签则合同置回 `SIGNING` 待处理（可重新发起或终止）。
9. **电子签名合规**：签署前必须完成实名认证（企业四要素/个人三要素）与意愿确认（短信验证码或人脸或 CA 证书 + 二次认证）；签署后文档与证据哈希固化，任何修改可检出。
10. **证据链完整**：一次签署必须包含实名认证记录、意愿确认记录、可信时间戳、文档哈希、证书信息、签署 IP/设备；缺任一项不得置 `SIGNED`。
11. **防篡改**：合同状态每次变更写入 `legal_contract_version`（快照 + 哈希）；归档时固化 `archive_hash`；完整性校验任务每日执行，不一致则告警 `legal.integrity.alert`。
12. **到期提醒**：`legalExpiryReminderJob` 每日扫描 `end_date` 处于 T-90/60/30/15/7 的合同，生成提醒并触达；提醒去重键 `contract_id + offset_days`。
13. **字段脱敏**：签署人身份证/手机号默认脱敏；查看明文需 `legal:sign:pii:view` 并记录审计。
14. **相对方查重**：按 `uscc_hash` 精确查重；命中则提示并可关联已有相对方。

### 1.5 状态机

**合同状态机（`legal_contract.status`）**

```
[DRAFT] --提交审批--> [APPROVING] --审批通过--> [APPROVED]
[APPROVING] --驳回--> [DRAFT]
[APPROVED] --提交/审批用印--> [SEALING] --用印完成--> [APPROVED(seal_status=SEALED)]
[APPROVED] --发起签署--> [SIGNING] --全部签署完成--> [SIGNED] --生效--> [EFFECTIVE]
[SIGNING] --拒签/超时--> [SIGNING]（待重新发起）
[SIGNED/EFFECTIVE] --终止/解除--> [TERMINATED]（终态）
[EFFECTIVE] --到期--> [EXPIRED] --归档--> [ARCHIVED]（终态）
[TERMINATED] --归档--> [ARCHIVED]（终态）
任意状态（未归档） --管理端授权撤销--> 上一状态（强审计）
```

**签署状态机（`legal_sign_record.status`，按签署方粒度）**

```
[PENDING] --查看合同--> [VIEWED] --实名认证+意愿确认--> [SIGNED]（该签署方终态）
[PENDING/VIEWED] --拒签--> [REJECTED]（签署方终态）
[PENDING/VIEWED] --超时未签(截止时间)--> [EXPIRED]（终止，可重新发起）
[SIGNED] --CA 证书吊销/司法撤销--> [REVOKED]（管理端授权，强审计）
```

**用印申请状态机（`legal_seal_application.status`）**

```
[PENDING] --审批通过--> [APPROVED] --用印执行--> [EXECUTED]（终态）
[PENDING] --驳回--> [REJECTED] --修改--> [PENDING]
[PENDING/APPROVED] --撤回--> [CANCELED]（终态）
[APPROVED] --超期未用印--> [CANCELED]（过期失效）
```

**履约节点状态机（`legal_performance_node.status`）**

```
[PENDING] --开始--> [IN_PROGRESS] --完成--> [DONE]（终态）
[PENDING/IN_PROGRESS] --超过 plan_date--> [OVERDUE] --完成--> [DONE]
[PENDING] --取消--> [CANCELED]（终态）
```

### 1.6 工作流（BPMN 说明）

#### 1.6.1 合同审批流程 `legalContractApproval`

```
StartEvent
  → ServiceTask[校验提交前置：变量完整 + 必留条款存在 + 相对方信息]
  → ExclusiveGateway{违约？}
       ├─ 是 → EndEvent(驳回: 7001003/7001004)
       └─ 否 ↓
  → ExclusiveGateway{gwRouteByAmount}
       ├─ amount ≤ 50万 → UserTask[部门负责人审批]
       ├─ 50万 < amount ≤ 200万 → UserTask[部门负责人 → 法务专员]
       └─ amount > 200万 → UserTask[部门负责人 → 法务专员 → 财务复核 → 法务总监]
  → ExclusiveGateway{risk_level}
       ├─ HIGH → 追加 UserTask[法务总监会签]（与上链合并去重）
       └─ 其他 → 跳过
  → 若存在条款风险标签"免责/无限责任" → 追加 UserTask[法务总监复核]
  → ServiceTask[回调 legal-service：置 APPROVED + 记录审批版本]
  → EndEvent(发布 legal.contract.approved)
```

- BPMN 元素：`StartEvent`、`ServiceTask`（校验/回调）、`ExclusiveGateway`（路由/风险）、`UserTask`（审批节点，支持会签 `multiInstance` 与加签）、`BoundaryEvent(Timer/Error)`、`EndEvent`。
- 每个 `UserTask` 支持：通过 / 驳回 / 加签 / 转办；驳回走错误边界事件回 `DRAFT`。
- 超时升级：节点超 48h 未处理，定时边界事件升级至上级；法务专员节点超 24h 升级法务总监。
- 会签：法务总监会签采用 `completionCondition = nrOfCompletedInstances/nrOfInstances >= 1`（全部同意）或按配置比例。

#### 1.6.2 用印申请流程 `legalSealApproval`

```
StartEvent
  → ServiceTask[校验：合同状态=APPROVED、用印版本=审批版本]
  → UserTask[用印审批：法务/用印管理员]
  → ExclusiveGateway{seal_type}
       ├─ ELECTRONIC → 追加 UserTask[印章管理员确认]
       └─ PHYSICAL  → 追加 UserTask[用印管理员登记确认]
  → ServiceTask[回调 legal-service：置 APPROVED]
  → EndEvent(发布 legal.seal.application.approved)
```

#### 1.6.3 签署流程 `legalContractSign`

```
StartEvent
  → ServiceTask[生成签署方与签署任务(顺序签展开为 N 个串行 UserTask)]
  → 循环 UserTask[签署人签署]
       ├─ 前置：实名认证(RealNameVerifyPort)
       ├─ 前置：意愿确认(SMS/FACE/CA_CERT + 二次认证)
       ├─ 执行：请求 CA 签章(SignTaskPort) + 可信时间戳(TimestampPort)
       ├─ 回调：CallbackPort 验签(HMAC-SHA256) + 幂等(provider_task_id)
       └─ 产出：签署证据(写入 legal_sign_record)
  → 排他网关{全部签署完成？}
       ├─ 否（有拒签/超时）→ 回退至签署发起节点并通知发起人
       └─ 是 ↓
  → ServiceTask[固化证据链 → 写 legal_evidence + 哈希链 + WORM]
  → ServiceTask[回调 legal-service：置 SIGNED → 触发生效判定]
  → EndEvent(发布 legal.sign.completed、legal.evidence.preserved)
```

- 顺序签：`UserTask` 串行，前序完成事件驱动激活下一任务。
- 并行签：使用 `ParallelGateway` 分叉，全部签署方完成后汇聚。
- 拒签：`BoundaryEvent(Error)` 捕获，流程转人工处理。
- 超时：签署截止时间到达触发 `BoundaryEvent(Timer)` 置 `EXPIRED`。

### 1.7 异常与边界

| 场景 | 处理 |
|---|---|
| 提交审批时变量缺失 | 拒绝提交，返回 `7001004`，定位缺失变量 |
| 必留条款被删除 | 拒绝保存/提交，返回 `7001003` |
| 用印版本与审批版本不一致 | 拒绝用印，返回 `7001007` |
| 印章已停用/吊销/过期 | 拒绝用印，返回 `7001006` |
| CA/签章服务不可用 | 签署任务排队重试（指数退避，最多 5 次），超限告警转人工；起草/审批不受影响 |
| 签署回调重复到达 | 幂等（`provider_task_id` 唯一约束）返回既有结果 |
| 签署回调验签失败 | 拒绝处理并告警 `legal.integrity.alert` |
| 契约证据缺失（时间戳/认证记录） | 不得置 `SIGNED`，返回 `7001009`（证据链校验失败） |
| 归档后修改合同 | 拒绝，返回 `7001011`（已归档不可修改） |
| 哈希校验失败 | 告警并冻结该合同进一步操作，人工介入 |
| 到期提醒发送失败 | 记录 `FAILED`，重试补偿（最多 3 次） |

### 1.8 验收标准

1. 合同模板→起草→审批→用印→签署→存证→履约→归档全链路可跑通，状态可追溯；
2. 审批路由按金额/类型/组织/风险 100% 正确，审批记录完整且记录审批版本（防"审 A 签 B"）；
3. 未经审批不得用印，用印记录不可删除、不可修改，用印版本与审批版本一致；
4. 电子签署完成实名认证 + 意愿确认 + 时间戳 + 证书信息，符合《电子签名法》要件；
5. 签署证据链完整可核验，存证核验与出证可用；
6. 合同正文/条款/签署证据/用印记录哈希链校验 100% 通过，篡改可检出并告警；
7. 履约节点状态准确，逾期预警与到期 T-90/60/30/15/7 提醒按时触达。

### 1.9 与标杆（法大大）差异点

| 维度 | 标杆（法大大） | 丰麟云法 G1 |
|---|---|---|
| 定位 | 电子签名 SaaS 服务 | 合同全生命周期管理平台（模板→履约→到期），签章为其一节 |
| CA 服务 | 自建 CA 为主 | 适配层多 CA 可切换（法大大/e签宝/CFCA/自建），不与单一厂商绑定 |
| 用印管理 | 侧重电子签 | 电子章 + 实物章统一管控，用印须审批且记录不可删 |
| 防篡改 | 签署证据存证 | 合同正文/条款/证据/用印记录全量哈希链 + WORM，归档快照核验 |
| 履约跟踪 | 弱 | 履约节点、逾期预警、到期续签一体化 |
| 双端与多租户 | 单租户为主 | 强制管理端/用户端分离 + 多租户 RLS |
| 与业务域联动 | 独立 | 与 A1 商机/报价、D1 财务付款等可经开放 API 联动 |

## 2 G2 内部信息防泄漏（DLP）

模块定位：识别、分级并管控企业敏感数据，阻断核心信息经终端/网盘/邮件等通道泄漏，实现"识别—管控—拦截—审计—溯源"闭环（参考标杆：亿赛通）。

### 2.4 业务规则

1. **规则优先级**：识别按 `priority` 升序匹配，命中高优先级规则即定级；多规则命中取最高数据级别。
2. **识别方式**：关键字/正则（内容匹配）、文件指纹（文档相似度，阈值可配）、模型（经 `fenglin-ai-service` 语义识别，置信度阈值可配）、分类分级标签。
3. **策略执行**：实时决策按 `优先级` 从小到大匹配首条命中策略；动作优先级 BLOCK > APPROVE > ENCRYPT > WATERMARK > WARN > AUDIT > ALLOW。
4. **实时决策**：终端外发动作调用 `/internal/dlp/decide`，决策引擎基于本地缓存策略（TTL 300s + 版本失效）在毫秒级返回；P95 ≤ 300ms。
5. **拦截与放行**：`BLOCK` 即时阻断并提示；`APPROVE` 转入放行审批流，审批通过后在有效期内放行同内容外发；放行过期自动失效。
6. **白名单**：命中白名单不拦截但不放行审计；白名单须经审批（记录 `approval_record_id`），设有效期，过期自动失效并通知复核。
7. **水印**：按数据级别与角色施加明/暗水印；暗水印编码包含 `user_id + terminal_id + timestamp + doc_id`，写入 `legal_watermark_record` 的 `embed_code`。
8. **溯源**：对疑似泄漏文档提取暗水印 → 匹配 `embed_code` → 反查用户/终端/IP/时间 → 关联事件输出溯源报告。
9. **审计防篡改**：所有 DLP 审计动作写 `legal_dlp_audit_log`，哈希链（`chain_id` + `seq_no` + `prev_hash` + `block_hash`）+ WORM；应用侧无删除/修改接口。
10. **事件去重**：同一 `user_id + channel_code + file_fingerprint + 5 分钟窗口` 的重复外发合并为一条事件（`hit_count` 累加），避免事件风暴。
11. **SLA**：事件处置 SLA 按风险分（P0 4h / P1 24h / P2 72h / P3 7d），超时自动升级并通知上级。
12. **误报处理**：审计员可标记 `FALSE_POSITIVE` 并填写原因，误报率纳入规则质量报表，驱动规则优化。
13. **脱敏**：事件列表对文件内容片段、用户终端信息脱敏展示；查看明文需 `legal:dlp:pii:view` 并审计。

### 2.5 状态机

**DLP 事件处置状态机（`legal_dlp_event.status`）**

```
[NEW] --研判(分派)--> [TRIAGING] --确认需要调查--> [INVESTIGATING]
[NEW/TRIAGING] --判定误报--> [FALSE_POSITIVE]（终态）
[TRIAGING/INVESTIGATING] --确认泄漏--> [HANDLED]（终态，须填结论与整改项）
[TRIAGING/INVESTIGATING] --升级--> [ESCALATED] --继续处置--> [INVESTIGATING]
[ESCALATED] --闭环--> [HANDLED]（终态）
[NEW/TRIAGING/INVESTIGATING] --超 SLA--> 自动升级 ESCALATED（定时边界事件）
```

**放行申请状态机（外发放行）**

```
[DRAFT] --提交--> [PENDING] --信息安全管理员通过--> [APPROVED] --有效期届满--> [EXPIRED]（终态）
[PENDING] --驳回--> [REJECTED]（终态）
[PENDING/APPROVED] --撤回--> [CANCELED]（终态）
```

**终端状态机（`legal_dlp_terminal.status`）**

```
[UNREGISTERED] --注册--> [ONLINE] --失去心跳(>5min)--> [OFFLINE] --恢复--> [ONLINE]
[ONLINE/OFFLINE] --违规/失联策略--> [BLOCKED]（终态，人工解封）
```

### 2.6 工作流（BPMN 说明）

#### 2.6.1 DLP 事件处置流程 `legalDlpEventHandle`

```
StartEvent(事件产生 legal.dlp.event.raised)
  → ServiceTask[去重合并 + 风险评分 + 定级(P0-P3)]
  → UserTask[研判分派：DLP 审计员/部门安全接口人]
  → ExclusiveGateway{判定}
       ├─ 误报 → UserTask[标记误报 + 原因] → EndEvent(FALSE_POSITIVE)
       ├─ 需调查 → UserTask[调查取证 + 上传证据]
       │            → ExclusiveGateway{是否泄漏}
       │                 ├─ 是 → UserTask[确认泄漏 + 整改项] → ServiceTask[关闭事件 HANDLED]
       │                 └─ 需升级 → UserTask[升级至安全负责人] → 回调查
       └─ 需放行 → 关联放行审批子流程
  → ServiceTask[回调 legal-service 更新事件状态 + 写审计(哈希链)]
  → EndEvent(发布 legal.dlp.event.closed)
```

- 边界事件：`BoundaryEvent(Timer)` 按 SLA 计时触发升级；`BoundaryEvent(Error)` 捕获依赖失败。
- 会签/加签：重大泄漏事件支持安全负责人与法务会签。

#### 2.6.2 敏感外发放行流程 `legalDlpReleaseApproval`

```
StartEvent
  → ServiceTask[校验：命中 APPROVE 策略、内容指纹、外发对象]
  → UserTask[信息安全管理员审批]
  → ExclusiveGateway{批准？}
       ├─ 驳回 → EndEvent(REJECTED)
       └─ 批准 → ServiceTask[生成放行凭证 + 有效期]
                  → EndEvent(发布 legal.dlp.release.approved)
```

### 2.7 异常与边界

| 场景 | 处理 |
|---|---|
| 决策引擎策略缓存过期/不一致 | 以版本号校验；缓存未命中回源数据库；双保险短 TTL |
| 事件高频上报（风暴） | 去重合并 + 批量落库 + Kafka 削峰；超出配额返回 `7002009` |
| 文件指纹计算超时 | 快速失败，降级为规则匹配并标注"指纹未参与" |
| 终端离线/未注册发起敏感外发 | 按策略阻断（默认阻断敏感级别），返回 `7002008` |
| 白名单过期未复核 | 自动失效并通知信息安全管理员；失效期间恢复默认策略 |
| 水印提取失败（文档损坏/截图） | 返回溯源失败并保留原始文档，人工介入 |
| 审计链写入失败 | 阻断该操作并告警 `legal.integrity.alert`，保证链不断裂 |
| 放行审批通过但内容变更 | 校验内容指纹，不一致则放行失效，重新走审批 |
| AI 识别服务不可用 | 降级为规则匹配（正则/指纹），事件标注"AI 未参与" |

### 2.8 验收标准

1. 敏感数据识别在既定样本集上准确率 ≥ 90%、误报率 ≤ 5%，分类分级正确；
2. 各通道按策略执行告警/拦截/放行，实时决策 P95 ≤ 300ms；
3. 明/暗水印可正常施加，暗水印可反向溯源到人（准确率 ≥ 95%）；
4. DLP 审计日志哈希链 100% 校验通过，删除/修改可检出并告警；
5. 事件按 SLA 处置闭环，超时升级生效；误报可标记且可统计；
6. 白名单须审批且到期自动失效；终端离线/未注册敏感外发被阻断。

### 2.9 与标杆（亿赛通）差异点

| 维度 | 标杆（亿赛通） | 丰麟云法 G2 |
|---|---|---|
| 定位 | 传统终端 DLP + 加密 | 覆盖终端/网盘/邮件/IM 的全通道 DLP，SaaS 多租户友好 |
| 部署形态 | 私有化重部署为主 | SaaS 多租户 + 私有化双形态，Agent 轻量化 |
| 识别能力 | 规则 + 指纹 | 规则 + 指纹 + AI 语义识别（复用 `fenglin-ai-service`），阈值可调 |
| 审计防篡改 | 本地日志 | 哈希链 + WORM，可校验、可举证，与合同域统一防篡改体系 |
| 水印 | 明水印为主 | 明/暗水印结合，暗水印可精准溯源到人 |
| 与法务联动 | 无 | 与 G1 合同域联动（合同文件外发同受管控），敏感事件可触发法务介入 |
| 放行管控 | 审批放行 | 放行绑定内容指纹与有效期，变更即失效 |

## 3 模块间协同总览

| 协同场景 | G1 动作 | G2 动作 | 数据/事件 |
|---|---|---|---|
| 合同文件外发 | 提供合同文件与密级 | 命中策略时拦截/加水印 | `legal.dlp.blocked` / `legal_watermark_record` |
| 合同泄漏溯源 | 提供合同哈希与版本 | 暗水印溯源定位泄漏人 | `legal.dlp.event.raised`（SUSPECTED_LEAK） |
| 敏感合同加审 | 高风险相对方触发加审 | 敏感级别提升触发策略 | 相对方 `risk_level` / 数据级别 |
| 用印控制 | 用印申请审批 | 用印文件按级别加水印 | `legal.seal.executed` |
| 统一审计 | 合同操作审计 | DLP 操作审计 | 同写 `fenglin-audit-service`（哈希链 + WORM） |
| 到期/风险看板 | 合同到期与履约 | DLP 风险与事件 | 报表聚合（`fenglin-report-service`） |

**跨模块约束**：合同域与 DLP 域共享数据分级口径（PUBLIC/INTERNAL/SECRET/CONFIDENTIAL）；合同密级变更触发 DLP 策略重新评估；两域审计统一进 `fenglin-audit-service` 并各自维护哈希链。
