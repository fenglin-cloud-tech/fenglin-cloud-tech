## 1 测试概述

### 1.1 测试范围

覆盖 G1 合同与电子签章（模板、起草、审批、用印、签署、存证、履约、到期、归档）、G2 内部信息防泄漏 DLP（识别、策略、通道、拦截、放行、水印、溯源、审计、终端），以及安全、性能、可靠性、兼容性维度。

### 1.2 测试环境

| 项 | 配置 |
|---|---|
| 应用 | `fenglin-legal-service` 8 副本（4C8G） |
| 数据库 | PostgreSQL 15（16C64G 主 + 2 从） |
| 缓存/消息 | Redis 7 Cluster、Kafka 3.6 (3 Broker) |
| 检索/存储 | Elasticsearch 8、MinIO |
| CA 桩 | CA/电子签章服务 Mock（支持签名、时间戳、回调） |
| 终端 Agent | DLP Agent 桩（模拟外发与决策调用） |
| 测试数据 | 租户 2 个、组织 12 个、用户 3400、相对方 2000、合同 12000、DLP 事件 50 万 |

### 1.3 测试类型与编号规则

| 前缀 | 类型 | 说明 |
|---|---|---|
| TC-G1- | 合同与电子签章功能 | 功能、流程、状态机 |
| TC-G2- | DLP 功能 | 识别、策略、拦截、水印、审计 |
| TC-SEC- | 安全与防篡改 | 证据链、哈希链、越权、加密 |
| TC-CFG- | 配置 | 模板/印章/策略配置 |
| TC-PERF- | 性能 | 响应、并发、吞吐 |
| TC-REL- | 可靠性 | 容灾、降级、重试、幂等 |
| TC-COMPAT- | 兼容性 | 浏览器、响应式、终端 |

优先级：P0（阻断）/P1（重要）/P2（一般）。用例总数 **58 条**。

## 3 详细用例

> 每条包含：前置条件、步骤、预期结果。以下为 P0/关键用例详述，其余按同等格式执行。

### TC-G1-003 模板版本发布与变量配置

- **前置**：已登录用户端，具备 `legal:template:version`、`tenant:legal:template:variable`（配置需管理端）。
- **步骤**：
  1. 新建模板 `TPL202600000123`；
  2. 上传正文并发布版本 V1；
  3. 管理端配置变量 `partyA`（必填，来源 SYSTEM）、`amount`（必填，来源 CONTRACT_FIELD）；
  4. 发布模板。
- **预期**：版本号自增为 1，`content_hash` 生成；模板状态 `PUBLISHED`；重复发布生成 V2 且 V1 不可改；非法变量键→`7000001`。

### TC-G1-004 基于模板起草合同

- **前置**：存在已发布模板 V2，相对方存在。
- **步骤**：起草页选择模板 → 填写名称/相对方/金额/日期/组织 → 填充变量 → 保存。
- **预期**：生成合同编号 `CT{yyyy}{6位}`；状态 `DRAFT`；`currentVersionId` 指向 V1 正文；变量值快照写入 `legal_contract_version.variable_values`；缺失必填变量时保存成功但提交校验拦截 `7001004`。

### TC-G1-006 合同版本保存与差异留痕

- **步骤**：在草稿合同修改正文 → 保存新版本 → 再次修改 → 保存。
- **预期**：版本号 1→2→3；每次生成 `content_hash` 与 `diff_digest`；历史版本不可修改；合同详情可查看版本差异摘要。

### TC-G1-010 提交合同审批（变量校验）

- **步骤**：草稿合同缺失必填变量 `amount`，点击提交审批。
- **预期**：拒绝提交，`code=7001004`，提示缺失变量；合同状态仍为 `DRAFT`；无流程实例产生。

### TC-G1-012 审批路由（金额区间）

- **步骤**：分别以金额 30 万、120 万、500 万提交审批。
- **预期**：30 万→部门负责人 1 级；120 万→部门负责人 + 法务专员 2 级；500 万→部门负责人 + 法务专员 + 财务复核 + 法务总监 4 级；路由结果与配置一致。

### TC-G1-015 审批记录防「审A签B」

- **步骤**：合同 V2 通过审批 → 弃用该方法，尝试用印 V3。
- **预期**：用印申请校验 `contractVersionId != 审批版本`，返回 `7001007`；审批记录中保留审批时版本；无法用非审批版本用印。

### TC-G1-020 用印申请（状态与版本校验）

- **步骤**：对 `DRAFT`/`APPROVING` 状态合同提交用印申请。
- **预期**：`code=7001002`（状态不允许）；仅 `APPROVED` 且版本一致的合同可提交。

### TC-G1-023 用印执行（电子章）

- **前置**：用印申请 `APPROVED`，印章 `ACTIVE`。
- **步骤**：执行用印 → 选择电子章 → 确认。
- **预期**：生成 `legal_seal_record`（`recordNo`），`version_hash` 与审批版本一致；合同 `seal_status=SEALED`；记录写入哈希链（`prev_hash`/`block_hash`）并同步 WORM；返回 `blockHash`。

### TC-G1-024 用印执行（实物章登记）与不可删

- **步骤**：对实物章执行用印登记 → 尝试调用删除接口。
- **预期**：生成实物章用印记录；删除接口不存在（404）且数据库禁止删除（触发器报错）；记录恒在。

### TC-G1-030 签署方维护与加密存储

- **步骤**：添加签署方，`signerIdNo=110101199001011234`、`signerMobile=13900001111`。
- **预期**：库中 `signer_id_no_enc`/`signer_mobile_enc` 为密文；`signer_id_hash`/`signer_mobile_hash` 生成；接口返回脱敏 `139****1111`；无 `legal:sign:pii:view` 时看不到明文。

### TC-G1-031 顺序签流程

- **步骤**：配置 3 名签署方 `SEQ`，依次签署。
- **预期**：仅第 1 位收到签署激活；完成后激活第 2 位；前一位未完成时后一位无法签署（`7001002`）；全部完成合同置 `SIGNED`。

### TC-G1-032 并行签流程

- **步骤**：配置 2 名签署方 `PARALLEL`，同时签署。
- **预期**：两位可同时签署；全部完成后合同置 `SIGNED`；任一人拒签则合同回 `SIGNING` 待处理。

### TC-G1-033 实名认证与意愿确认

- **步骤**：未完成二次认证的令牌直接调用签署执行。
- **预期**：`code=7001010`（需二次认证）；完成短信/人脸核验并获得 `step_up` 令牌后可签署；未勾选意愿确认拒绝签署。

### TC-G1-040 签署证据链完整性（核心）

- **前置**：一名签署方完成签署。
- **步骤**：查看 `legal_sign_record` 与 `legal_evidence`。
- **预期**：证据含实名认证记录、意愿确认、可信时间戳 `tsa_token`、文档哈希 `doc_hash`、证书信息、签署 IP/设备；缺失任一项则合同不得置 `SIGNED`（`7001009`）；证据链完整且可核验；`block_hash` 与前一条 `prev_hash` 串联。

### TC-G1-041 存证生成与核验

- **步骤**：签署完成后查询存证 → 点击核验。
- **预期**：生成 `EVD{yyyy}{6位}`；重算内容哈希与存证哈希、WORM 一致；`valid=true`；篡改存证内容后核验返回 `7001012`。

### TC-G1-043 签署回调幂等

- **步骤**：同一 `provider_task_id` 回调两次。
- **预期**：第二次返回既有结果，不重复生成签署记录与存证；不重复发布事件。

### TC-G1-044 签署回调验签失败处理

- **步骤**：使用错误 `X-Signature` 回调。
- **预期**：拒绝处理，返回失败并告警 `legal.integrity.alert`；不影响既有签署状态。

### TC-G1-051 到期提醒 T-90/60/30/15/7

- **前置**：合同 `end_date` 距今天 90/60/30/15/7 天各一。
- **步骤**：执行 `legalExpiryReminderJob`。
- **预期**：各生成一条 `legal_expiry_reminder`（去重键 `contract_id+offset_days`）；按配置渠道触达；重复执行不重复生成；触达失败置 `FAILED` 并重试。

### TC-G1-053 合同归档与只读

- **步骤**：对 `EFFECTIVE` 合同归档 → 尝试修改。
- **预期**：归档成功，`archive_hash` 生成并写 WORM；后续修改返回 `7001011`；完整性校验通过。

### TC-G2-001 创建敏感识别规则

- **步骤**：管理端创建正则规则 `\d{17}[\dXx]`（身份证），级别 `SECRET`。
- **预期**：创建成功，`ruleNo` 生成；非法正则返回 `7002001`；优先级生效。

### TC-G2-002 规则测试（正则/关键字）

- **步骤**：用样本 `身份证 110101199001011234` 测试规则。
- **预期**：`matched=true`，命中片段脱敏显示，`dataLevel=SECRET`。

### TC-G2-003 敏感数据识别与分级

- **步骤**：对含身份证、银行卡、商业机密的文档识别。
- **预期**：分级取最高级别；命中多条规则时输出全部命中；置信度达标；误报率在样本集 ≤5%。

### TC-G2-005 创建 DLP 策略

- **步骤**：创建 `CONFIDENTIAL + [USB,EMAIL] + BLOCK` 策略。
- **预期**：策略保存，`version=1`；缓存失效并重新加载；实时决策命中该策略。

### TC-G2-007 通道启停与管控

- **步骤**：关闭 `USB` 通道 → 终端 USB 外发敏感文件。
- **预期**：`USB` 关闭后不拦截（按策略）或按默认动作处理；返回 `7002004` 说明通道状态；重新启用后恢复管控。

### TC-G2-010 实时拦截（BLOCK，核心）

- **步骤**：终端对机密文件执行 USB 外发 → 调用 `/internal/dlp/decide`。
- **预期**：决策 `BLOCK`，P95 ≤ 300ms；终端阻断外发；生成事件 `legal_dlp_event`（`action_taken=BLOCK`）；写审计（哈希链 + WORM）；发布 `legal.dlp.blocked`。

### TC-G2-012 放行审批（APPROVE）

- **步骤**：命中 `APPROVE` 策略的外发 → 提交放行申请 → 信息安全管理员通过。
- **预期**：审批通过后返回放行凭证与有效期；有效期内同指纹外发放行；写入审计链。

### TC-G2-013 放行凭证有效期与内容变更失效

- **步骤**：放行通过后 ①有效期内同指纹外发；②有效期后外发；③内容变更后外发。
- **预期**：①放行；②失效重新拦截；③指纹不一致放行失效，重新走审批。

### TC-G2-021 暗水印施加与记录

- **步骤**：对文档施加暗水印。
- **预期**：生成 `WM{yyyyMMdd}{6位}`；`embed_code` 含用户/终端/时间/文档；写入 `legal_watermark_record`。

### TC-G2-022 暗水印溯源到人（核心）

- **步骤**：对疑似泄漏文档提取暗水印。
- **预期**：`trace_status=TRACED`；反查到用户、终端、IP、时间；关联事件；溯源准确率 ≥95%。

### TC-G2-031 事件检索与导出（脱敏）

- **步骤**：按时间/通道/级别检索 DLP 事件 → 导出。
- **预期**：结果正确；导出内容中文件片段、用户终端信息脱敏；导出行为写审计。

### TC-G2-032 事件处置流程闭环

- **步骤**：事件 `NEW` → 研判 → 调查 → 确认泄漏（填结论与整改项）→ 关闭。
- **预期**：状态依次流转 `NEW→TRIAGING→INVESTIGATING→HANDLED`；`CONFIRM` 必填结论；处置记录写入审计链；发布 `legal.dlp.event.closed`。

### TC-G2-033 误报标记与统计

- **步骤**：对误报事件标记 `FALSE_POSITIVE` 并填原因。
- **预期**：状态置 `FALSE_POSITIVE`（终态）；误报计入报表 `falsePositiveRate`；原因可查。

### TC-G2-035 白名单生效与过期失效

- **步骤**：创建白名单（有效期至 +1 天），过期后再次外发。
- **预期**：有效期内不拦截但留审计；过期后自动 `EXPIRED` 并按默认策略拦截；白名单须审批（`approval_record_id` 非空）。

### TC-G2-036 终端注册/心跳/离线阻断

- **步骤**：终端注册 → 停止心跳 >5min → 离线终端外发敏感文件。
- **预期**：注册返回 `terminalNo` 与策略版本；离线置 `OFFLINE`；离线/未注册敏感外发被阻断并返回 `7002008`。
