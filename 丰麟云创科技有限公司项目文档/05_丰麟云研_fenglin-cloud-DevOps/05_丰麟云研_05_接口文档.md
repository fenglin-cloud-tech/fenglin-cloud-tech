## 1. 通用约定

遵循基线规范 §5。要点：

- 协议：HTTPS（TLS 1.2+，推荐 1.3）；内部服务间 mTLS。
- 风格：RESTful + 资源化；动作型接口 `POST /{resource}/{action}`。
- 前缀：`/api/devops/v1`；版本在 URL 段。
- 数据格式：`application/json; charset=UTF-8`；上传 `multipart/form-data`。
- 时间：ISO-8601（`yyyy-MM-dd'T'HH:mm:ss.SSSXXX`），存储 UTC。
- 分页：`page`（从 1 开始）、`size`（默认 20，最大 200）。
- 幂等：写操作支持 `Idempotency-Key`；需求/任务/缺陷/发布/部署/Webhook 入库强制幂等。
- 追踪：`X-Request-Id`（网关生成）、`X-Trace-Id`（SkyWalking）。

### 1.1 请求头

| 名称 | 必填 | 说明 |
|---|---|---|
| `Authorization` | 是 | `Bearer {access_token}`（JWT RS256） |
| `X-Tenant-Id` | 是 | 租户标识 |
| `X-Client-Type` | 是 | `ADMIN` / `PORTAL` |
| `X-Request-Id` | 否 | 追踪与幂等 |
| `Accept-Language` | 否 | `zh-CN` / `en-US` |
| `Idempotency-Key` | 条件 | 写操作幂等键（24h） |

### 1.2 统一响应体

```json
{ "code": "0", "message": "success", "data": {}, "requestId": "b1f2c3d4", "timestamp": "2026-10-19T08:00:00.000+08:00" }
```

分页 `data`：`{ "records": [], "total": 0, "page": 1, "size": 20 }`。

### 1.3 错误码

| 错误码 | HTTP | 含义 |
|---|---|---|
| `5000001` | 401 | 未认证或令牌失效 |
| `5000002` | 403 | 无权限（功能或数据） |
| `5000003` | 400 | 参数校验失败 |
| `5000004` | 404 | 资源不存在 |
| `5000005` | 409 | 状态冲突 |
| `5000006` | 429 | 触发限流 |
| `5000007` | 500 | 系统内部错误 |
| `5000008` | 503 | 依赖服务不可用 |
| `5000201` | 400 | 工作项状态非法流转 |
| `5000202` | 409 | 迭代日期重叠 |
| `5000203` | 400 | 集成令牌无效 |
| `5000204` | 400 | Webhook 验签失败 |
| `5000205` | 409 | 发布审批未通过不可部署 |
| `5000301` | 400 | 度量口径不存在 |

## 2. 鉴权与端别

- 认证：OAuth2.1/OIDC，JWT（RS256）；管理端与生产部署操作强制 MFA。
- 端别：`X-Client-Type` 与令牌 `client_type` 一致，网关校验；管理端接口拒绝 PORTAL 令牌，反之亦然。
- 权限：功能权限码 `{域}:{模块}:{操作}`；数据权限按 `data_scope` 过滤。
- 租户：`X-Tenant-Id` 与令牌一致，RLS 二次保障。

## 4. 逐接口定义

> 以下对核心接口给出完整定义；未单列的同族接口（列表/详情/更新）遵循相同约定。所有响应体为基线规范统一响应体，示例中省略外层 `code/message/requestId/timestamp`，仅展示 `data`。

### API-01 产品列表 `GET /products`

| 项 | 值 |
|---|---|
| 端别 | 用户端 |
| 鉴权 | Bearer（PORTAL） |
| 权限 | `biz:devops:product:view` |
| 幂等 | 只读，无需 |
| 限流 | 30 QPS/租户 |

查询参数：`keyword`(string)、`status`(active/archived)、`page`、`size`。

```json
// 响应 data
{ "records": [ { "id": 10001, "productCode": "FLCLOUD", "name": "丰麟云研平台", "ownerId": 2001, "visibility": "public", "status": "active" } ], "total": 1, "page": 1, "size": 20 }
```

错误码：`5000001`、`5000002`。

### API-02 创建产品 `POST /products`

| 项 | 值 |
|---|---|
| 端别 | 管理端 |
| 权限 | `tenant:devops:product:manage` |
| 幂等 | 强制 `Idempotency-Key` |
| 限流 | 5 QPS/租户 |

请求体：

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `productCode` | string | 是 | `^[A-Z0-9_]{2,64}$`，租户内唯一 |
| `name` | string | 是 | ≤128 |
| `productLine` | string | 否 | ≤64 |
| `ownerId` | long | 是 | 有效用户 |
| `visibility` | string | 否 | private/public，默认 private |
| `sprintCycleDays` | int | 否 | 1–60，默认 14 |

```json
// 响应 data
{ "id": 10002, "productCode": "PAY", "name": "支付中台" }
```

错误码：`5000003`（参数）、`5000005`（编码重复）。

### API-03 产品详情 `GET /products/{id}`

返回产品基础信息 + 成员数 + 迭代数 + 需求统计。错误码 `5000004`。

### API-04 更新产品 `PUT /products/{id}`

可更新 `name/productLine/ownerId/visibility/sprintCycleDays/requirementSchemeId`；`productCode` 不可改。幂等建议携带。错误码 `5000004`、`5000005`。

### API-05 产品成员配置 `POST /products/{id}/members`

请求体：`{ "members": [ { "userId": 2002, "roleCode": "developer", "dataScope": "dept" } ] }`。整体覆盖式更新；`roleCode∈{owner,admin,developer,tester,reporter}`。幂等强制。错误码 `5000003`、`5000004`。

### API-06 产品路线图 `GET /products/{id}/roadmap`

参数：`from`(date)、`to`(date)、`groupBy`(release/quarter)。返回时间轴上的需求与里程碑。错误码 `5000003`。

### API-07 需求列表 `GET /requirements`

参数：`productId`(必填)、`sprintId`、`statusId`、`reqType`、`priority`、`assigneeId`、`keyword`、`page`、`size`。数据权限过滤。限流 50 QPS/租户。

### API-08 创建需求 `POST /requirements`

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `productId` | long | 是 | 有效产品 |
| `title` | string | 是 | ≤256 |
| `reqType` | string | 否 | business/user/tech，默认 user |
| `priority` | string | 否 | P0–P3，默认 P2 |
| `statusId` | long | 否 | 默认"待评审" |
| `parentId` | long | 否 | 同产品 |
| `assigneeId` | long | 否 | — |
| `estimateHours` | number | 否 | ≥0 |
| `acceptanceCriteria` | string | 否 | — |

```json
// 响应 data
{ "id": 30001, "reqNo": "DEV-RQ202610000001", "title": "需求评审流程", "statusId": 9001 }
```

错误码 `5000003`、`5000004`。

### API-09 需求详情 `GET /requirements/{id}`

返回需求全字段 + 关联任务/缺陷/提交数 + 时间线。错误码 `5000004`。

### API-10 更新需求 `PUT /requirements/{id}`

可更新标题/类型/优先级/负责人/预估工时/验收标准/计划时间。冲突返回 `5000005`。幂等建议。

### API-11 删除需求 `DELETE /requirements/{id}`

逻辑删除；存在关联任务/缺陷时返回 `5000005`。

### API-12 需求状态流转 `POST /requirements/{id}/transition`

请求体：`{ "action": "submit_review|approve|reject|into_sprint|deliver|reopen|close", "comment": "...", "sprintId": 5001 }`。状态机校验，非法返回 `5000201`。幂等强制。

### API-13 提交需求评审 `POST /requirements/{id}/review/submit`

请求体：`{ "reviewerIds": [2001,2002], "dueAt": "2026-10-21T10:00:00.000+08:00" }`。触发 BPMN `devops-requirement-review`。返回 `{ "processInstanceId": "..." }`。错误码 `5000003`、`5000201`。

### API-14 需求关联提交 `GET /requirements/{id}/commits`

返回提交 SHA、作者、分支、行数、时间。错误码 `5000004`。

### API-15 需求状态方案 `GET /requirement-statuses`

参数：`productId`。返回状态定义列表（编码/名称/类别/颜色/排序）。管理端。错误码 `5000002`。

### API-16 迭代列表 `GET /sprints`

参数：`productId`(必填)、`status`、`page`、`size`。

### API-17 创建迭代 `POST /sprints`

请求体：`{ "productId": 10001, "name": "Sprint 42", "goal": "...", "startDate": "2026-10-20", "endDate": "2026-11-02", "capacityHours": 320 }`。日期重叠返回 `5000202`。幂等强制。

### API-18 更新迭代 `PUT /sprints/{id}`

可更新名称/目标/容量/状态。启动后容量锁定，变更需原因。错误码 `5000005`、`5000202`。

### API-19 迭代需求调整 `POST /sprints/{id}/requirements`

请求体：`{ "add": [30001], "remove": [30005], "reason": "追加需求" }`。容量超载返回告警字段 `capacityWarning=true` 但成功。

### API-20 燃尽图 `GET /sprints/{id}/burndown`

返回每日剩余工作项点数/工时序列。错误码 `5000004`。

### API-21 看板详情 `GET /boards/{id}`

返回看板列 + 每列工作项（分页）。大迭代支持 `page`/`size`。缓存 60s。

### API-22 创建看板 `POST /boards`

请求体：`{ "productId": 10001, "name": "研发看板", "boardType": "scrum", "sprintId": 5001, "columns": [ { "columnName": "待处理", "statusCodes": ["todo"], "wipLimit": 20 } ] }`。管理端。幂等强制。

### API-23 看板拖拽流转 `POST /boards/{id}/move`

请求体：`{ "bizType": "task", "bizId": 40001, "toColumnId": 7002, "toStatus": "doing", "sortNo": 3 }`。校验状态机与 WIP；非法返回 `5000201`。幂等强制。

### API-24 任务列表 `GET /tasks`

参数：`productId`、`sprintId`、`assigneeId`、`status`、`keyword`、`page`、`size`。

## 5. 开放 API

| 项 | 说明 |
|---|---|
| 前缀 | `/openapi/devops/v1` |
| 认证 | AppKey/AppSecret HMAC-SHA256 签名 + OAuth2.1 授权码 |
| 配额 | 按应用/接口 QPS 限流，超限 `0000006` |
| 沙箱 | 提供在线调试与 Mock |
| 开放资源 | 需求、迭代、缺陷、发布、度量指标（受控读写） |

开放接口（示例）：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/openapi/devops/v1/requirements` | 查询需求（分页/过滤） |
| POST | `/openapi/devops/v1/requirements` | 创建需求 |
| PATCH | `/openapi/devops/v1/requirements/{id}/status` | 更新需求状态 |
| GET | `/openapi/devops/v1/defects` | 查询缺陷 |
| GET | `/openapi/devops/v1/releases` | 查询发布单 |
| GET | `/openapi/devops/v1/metrics` | 查询指标快照 |

签名规则：`sign = HMAC-SHA256(AppSecret, method + "\n" + path + "\n" + timestamp + "\n" + nonce + "\n" + sha256(body))`，请求头携带 `X-FL-AppKey`、`X-FL-Timestamp`、`X-FL-Nonce`、`X-FL-Signature`。

## 6. 事件与 Webhook

### 6.1 对外可订阅事件（Kafka → Webhook 回调）

| 事件 | 触发 | 载荷要点 |
|---|---|---|
| `requirement.created` | 需求创建 | productId, reqNo, title, priority |
| `requirement.status_changed` | 需求状态流转 | reqNo, from, to, operator |
| `defect.created` | 缺陷创建 | defectNo, severity, foundStage, productId |
| `release.deployed` | 生产部署完成 | releaseNo, version, env, deployedAt, isRollback |
| `metric.snapshot_ready` | 快照生成 | metricCode, scopeType, scopeId, periodType, periodKey |

回调投递：HTTP POST + HMAC-SHA256 签名（`X-FL-Signature`），失败指数退避重试 ≤ 5 次，超限入死信并告警；消费方需按事件 ID 幂等。

### 6.2 入站 Webhook 汇总

见 §4 的 API-55~58；全部要求验签、幂等、限流、异步落库、异常入死信。

## 7. 版本与兼容

- 版本：URL 段 `/v1`；不兼容变更升 `/v2`；旧版本至少保留 12 个月。
- 兼容策略：新增可选字段不视为不兼容；字段废弃先标记 `deprecated` 并保留至下个大版本。
- 契约：以 `openapi.yaml` 为准，变更纳入 CI 契约测试与变更公告。
- 限流与配额：网关 + Sentinel 双层；管理端写接口配额低于用户端读接口；Webhook 独立配额。
- 废弃流程：公告 → 双写过渡 → 下线，提前 ≥ 90 天通知。
