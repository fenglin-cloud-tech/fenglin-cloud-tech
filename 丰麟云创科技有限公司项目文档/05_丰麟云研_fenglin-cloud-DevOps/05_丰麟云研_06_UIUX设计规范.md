## 5. 交互流程

| 流程 | 交互要点 |
|---|---|
| 需求创建 → 评审 | 表单校验（验收标准非空）→ 指定评审人 → Toast"已提交评审" |
| 看板拖拽 | 拖拽预览 → 落位校验（状态机/WIP）→ 成功动画 / 非法回退 + 原因提示 |
| 迭代规划 | 需求池拖入/按钮拉入 → 容量条实时更新 → 超载橙色提示 |
| 缺陷修复 → 验证 | 修复完成须选构建 → 验证通过/不通过（不通过弹重开确认） |
| 绑定代码库 | 输入地址 → "测试连接"验证令牌 → 成功后仅一次展示明文 → 列表脱敏 |
| 触发流水线 | 选择分支/参数 → 二次确认 → 跳转运行详情，进度实时刷新 |
| 发布审批 | 提交 → 审批人收到待办 → MFA 确认 → 通过后自动部署 → 结果通知 |
| 大盘下钻 | 图表点击 → 面包屑 + 下钻 → 支持返回；口径版本切换提示对比语义 |
| 报表导出 | 选择范围/周期/格式 → 异步提交 → 完成后站内通知下载 |

## 6. 响应式

| 断点 | 布局 |
|---|---|
| ≥1440 | 看板多列完整展示；表格全列；大盘 4 宫格 |
| 1200 | 看板横向滚动；表格次要列折叠 |
| 992 | 侧栏可收起；大盘 2 列 |
| 768 | 卡片单列；表格转卡片列表 |
| <768 | 移动端：看板只读 + 轻操作（状态更新/评论）；可点击区 ≥44×44px |

- 图表容器自适应，指标卡自动换行。
- 拖拽在触屏下提供"移动到…"下拉替代。

## 7. 状态规范

| 状态 | 规范 |
|---|---|
| 加载 | 骨架屏（列表/卡片/图表）；>300ms 展示，避免闪烁 |
| 空态 | 插画 + 引导文案 + 主操作按钮（如"创建第一个需求"） |
| 错误 | 错误插画 + 原因 + 重试按钮；网络错误单独文案 |
| 无权限 | 锁定插画 + 申请权限入口 |
| 成功 | Toast/Message 提示（构建触发/流转成功） |
| 部分失败 | 列表行内错误标记 + 汇总提示 |
| 数据不足 | 指标显示"—" + "数据不足"徽标 |

## 8. 可访问性

- 对比度 ≥ 4.5:1（文本），交互元素 ≥ 3:1。
- 全键盘可达：Tab 顺序符合视觉流，看板支持键盘"移动到…"操作。
- 焦点样式：`outline: 2px solid var(--fl-color-primary)`，不依赖颜色单独传达信息（状态用图标 + 文字）。
- 图表提供数据表格替代（无障碍模式）与文字摘要。
- 文案外置（i18n），默认 `zh-CN`，预留 `en-US`。
- 图标按钮提供 `aria-label`；进度与结果使用 `aria-live` 播报。
