## 1. 总则

本文档逐模块给出：功能清单、角色与权限、页面与双端归属、业务规则、状态机、工作流（含 BPMN 说明）、异常与边界、验收标准、"与标杆产品差异点"。工作流统一由平台 `fenglin-workflow-service`（Flowable 7，BPMN 2.0）编排；状态机由业务服务在应用层强制校验，非法流转返回 `5000005`（状态冲突）。

## 2. 全局设计约定

| 项 | 约定 |
|---|---|
| 范围 | 本产品不含统一身份/租户治理、消息、工作流引擎（由中台承接，见 FL-DEVOPS-SRS-001 §1.2） |
| 幂等 | 需求/任务/缺陷/发布/部署/Webhook 入库等写操作强制 `Idempotency-Key` |
| 编号 | 需求 `DEV-RQ{yyyyMM}{6位}`、任务 `DEV-TK{yyyyMM}{6位}`、缺陷 `DEV-BG{yyyyMM}{6位}`、迭代 `DEV-SP{yyyyMMdd}{2位}`、用例 `DEV-TC{yyyyMM}{6位}`、发布 `DEV-RL{yyyyMM}{6位}` |
| 审计 | 所有写操作留审计；发布/部署/集成凭据操作写哈希链 + WORM |
| 双端 | 管理端配置/授权/审核/报表定义；用户端业务操作/协同/查询/填报 |
| 状态机 | 各模块显式定义状态；非法流转返回 `5000005` |
| 工作流 | BPMN 统一命名 `devops-{模块}-{场景}` |
| 时区 | 存储 UTC，展示按租户时区 |

### 4.4 需求业务规则

| 编号 | 规则 |
|---|---|
| BR-R-01 | 需求必属一个产品与类型；父需求与子需求必须同产品 |
| BR-R-02 | 需求提交评审须指定 ≥1 名评审人；评审中不可再提交 |
| BR-R-03 | 仅"已评审"的需求可拉入迭代；已交付需求变更须走"重新打开" |
| BR-R-04 | 需求删除为逻辑删除；有关联任务/缺陷的需求禁止删除（返回 `5000005`） |
| BR-R-05 | 需求完成（status_category=done）时写入 `delivered_at`，用于交付效率度量 |
| BR-R-06 | 需求验收标准为空时，进入"已评审"前给出阻断校验 |
| BR-R-07 | 需求优先级变更记录到审计与时间线 |

### 4.5 迭代业务规则

| 编号 | 规则 |
|---|---|
| BR-S-01 | 迭代日期不得重叠（同产品同时间盒唯一） |
| BR-S-02 | 迭代启动（active）后容量锁定；新增需求仅可"追加"并记录原因 |
| BR-S-03 | 迭代结束时未完成需求自动移入"未完成需求池" |
| BR-S-04 | 燃尽图每日 00:30（租户时区）生成快照，支持补算 |
| BR-S-05 | 迭代关闭后不可再编辑；需变更须走迭代变更记录 |

### 4.6 看板业务规则

| 编号 | 规则 |
|---|---|
| BR-B-01 | 看板列映射一个或多个工作项状态；工作项状态与列双向联动 |
| BR-B-02 | WIP 限制触发时列头高亮告警，但不阻断拖拽（可配置为阻断） |
| BR-B-03 | 看板支持泳道（按负责人/优先级/类型分组） |
| BR-B-04 | 拖拽流转触发状态机校验，非法流转回退并提示原因 |
| BR-B-05 | 看板数据走缓存（TTL 60s），拖拽后主动失效 |

### 4.7 任务与工时业务规则

| 编号 | 规则 |
|---|---|
| BR-T-01 | 子任务工时汇总至父任务；父任务 `actual_hours` 为子任务之和 |
| BR-T-02 | 任务完成需填写实际工时或标记"免工时" |
| BR-T-03 | 工时单日单人 ≤ 24 小时，0.5 小时步进 |
| BR-T-04 | 任务可关联需求或缺陷，跨产品关联禁止 |

### 4.8 缺陷业务规则

| 编号 | 规则 |
|---|---|
| BR-D-01 | 严重级（blocker/critical/normal/minor）与优先级（P0–P3）独立，blocker 自动标记迭代阻断项 |
| BR-D-02 | 缺陷关闭须至少一次"验证通过"（verifying→closed） |
| BR-D-03 | "已关闭"缺陷重新处理须走"重新打开"，`reopen_count` 累加 |
| BR-D-04 | 缺陷 `found_stage=prod` 计入逃逸缺陷，用于逃逸率与质量度量 |
| BR-D-05 | 测试执行失败生成缺陷时自动关联用例与构建版本 |
| BR-D-06 | 修复后缺陷须关联修复构建（`fix_build_id`）方可进入验证 |

### 4.9 测试业务规则

| 编号 | 规则 |
|---|---|
| BR-TE-01 | 用例步骤为空不可提交评审 |
| BR-TE-02 | 测试计划关联构建后可执行；被禁用（deprecated）用例不可执行 |
| BR-TE-03 | 执行结果为 fail 时可一键生成缺陷；blocked 需填写阻塞原因 |
| BR-TE-04 | 计划通过率 = pass /（pass+fail+blocked），skip 不计入分母 |

### 4.10 代码集成业务规则

| 编号 | 规则 |
|---|---|
| BR-C-01 | 访问令牌 AES-256-GCM 加密存储，创建时仅明文返回一次 |
| BR-C-02 | 提交关联关键字：`#REQ-xxx`/`#TASK-xxx`/`#BUG-xxx`/`[req:123]` |
| BR-C-03 | 跨租户/跨产品可见范围的关联一律拒绝（返回 `5000002`） |
| BR-C-04 | 合并提交、二进制与生成代码（按路径/扩展名规则）不计入贡献度 |
| BR-C-05 | 提交去重键：`repo_id + commit_sha`；重复事件幂等忽略 |
| BR-C-06 | 平台仅只读拉取代码，状态回写限白名单字段（不写代码内容） |

### 4.11 流水线与构建业务规则

| 编号 | 规则 |
|---|---|
| BR-P-01 | 流水线触发须校验产品成员权限与令牌有效性 |
| BR-P-02 | 构建状态由回调更新；回调验签失败拒绝并记录 |
| BR-P-03 | Sonar 质量门禁 fail 时构建标记 `quality_gate=fail`，禁止进入生产发布审批（可配置） |
| BR-P-04 | 构建与提交、发布单双向关联可追溯 |

### 4.12 发布与部署业务规则

| 编号 | 规则 |
|---|---|
| BR-RL-01 | 生产环境发布必须经审批（BPMN），且审批须双人复核 + MFA |
| BR-RL-02 | 审批通过前执行生产部署一律拒绝（返回 `5000005`） |
| BR-RL-03 | 发布须落在发布窗口内（如工作日晚 20:00–23:00），越窗需管理员豁免 |
| BR-RL-04 | 部署失败须记录原因，支持一键回滚并标记 `is_rollback` |
| BR-RL-05 | 部署完成写入 `deployed_at`，触发 DORA 指标计算事件 |
| BR-RL-06 | 非生产环境（staging）发布审批可配置为免审批 |

### 4.13 异常与边界

| 场景 | 处理 |
|---|---|
| 并发编辑同一需求 | 乐观锁冲突返回 `5000005`，前端提示刷新 |
| 迭代容量超载 | 允许但高亮提示；容量锁定后追加需原因 |
| 集成令牌失效 | 同步任务失败告警，健康检查标记 `sync_status=failed`，通知管理员 |
| Webhook 重复投递 | 事件 ID 幂等去重，忽略重复 |
| Webhook 突发洪峰 | Sentinel 限流，超出部分入 Kafka 缓冲，保护主库 |
| 看板大迭代（>1000 项） | 服务端分页 + 虚拟滚动，超出阈值提示筛选 |
| 提交关联失效关键词 | 忽略并记录到未关联提交列表，供人工关联 |
| 发布审批超时 | 72 小时未处理自动催办，完成后自动关闭 |

### 4.14 验收标准

| 编号 | 验收项 | 判定 |
|---|---|---|
| AC-E1-01 | 需求全生命周期 | 创建→评审→规划→交付→验收可闭环，状态流转合规 |
| AC-E1-02 | 迭代与看板 | 容量、燃尽、看板拖拽与 WIP 正确 |
| AC-E1-03 | 缺陷闭环 | 提交→修复→验证→关闭闭环，重开计数正确 |
| AC-E1-04 | 测试执行 | 结果记录与缺陷生成正确 |
| AC-E1-05 | 代码关联 | 关键字关联准确，时间线可见 |
| AC-E1-06 | 流水线与发布 | 触发/回调同步正确，未审批不可部署，回滚可追溯 |

| 我的效能 | 用户端 | `/app/devops/metric/me` |

### 5.4 度量业务规则

| 编号 | 规则 |
|---|---|
| BR-M-01 | 指标计算以 UTC 为准，统计窗口默认自然日 00:00–24:00（租户时区校准） |
| BR-M-02 | 快照唯一键（租户, 指标, 范围, 周期, 口径版本），重复计算幂等 upsert |
| BR-M-03 | 派生指标须保存分子/分母/样本数，可溯源至源记录 |
| BR-M-04 | 口径变更须新版本，历史快照保留原口径版本标记 |
| BR-M-05 | 数据质量标记：缺失（源数据不足）/异常（超 3σ）/正常 |
| BR-M-06 | 画像评分 = Σ(指标归一化值 × 权重)，权重合计为 1 |

### 5.5 DORA 指标口径

| 指标 | 口径 |
|---|---|
| 部署频率 Deploy Frequency | 生产部署次数 ÷ 统计周期天数（次/天） |
| 变更前置时间 Lead Time for Changes | 变更关联最近提交时间 → 生产部署完成时间的中位数（小时） |
| 变更失败率 Change Failure Rate | 导致回滚/热修复的生产部署数 ÷ 生产部署总数 |
| 故障恢复时间 MTTR | 生产故障从发生到恢复的中位数（小时） |
| 等级评估 | 四指标对照 DORA 分级阈值输出 elite/high/medium/low |

### 5.6 洞察大盘业务规则

| 编号 | 规则 |
|---|---|
| BR-I-01 | 大盘默认读取快照表 + Redis 预聚合缓存，避免实时全表扫描 |
| BR-I-02 | 支持按产品/团队/迭代/时间多维下钻与对比 |
| BR-I-03 | 大盘配置可共享（同租户授权范围内） |
| BR-I-04 | 导出内容与页面一致，含口径版本与生成时间水印 |

### 5.7 异常与边界

| 场景 | 处理 |
|---|---|
| 源数据缺失 | 指标标记 `missing`，大盘展示"—"并提示数据不足 |
| 极端异常值 | 标记 `outlier`，可配置是否剔除 |
| 口径变更追溯 | 历史快照保留口径版本，跨版本对比给出提示 |
| 聚合任务失败 | 告警 + 自动重试 3 次，仍失败降级读上一快照 |
| 越权查看 | 数据权限过滤，越权返回 `5000002` |
| 大范围查询（全租户 3 年） | 建议收敛时间范围，超阈值走异步导出 |

### 5.8 验收标准

| 编号 | 验收项 | 判定 |
|---|---|---|
| AC-E2-01 | 指标计算准确性 | 抽样核对与人工计算一致（误差 0） |
| AC-E2-02 | DORA 口径 | 四项指标口径正确，等级评估合理 |
| AC-E2-03 | 大盘性能 | 近 90 天 10 指标查询 P95 ≤ 800ms |
| AC-E2-04 | 数据可见范围 | 权限过滤正确，越权被拒 |
| AC-E2-05 | 口径版本 | 变更留版本，历史可追溯 |
| AC-E2-06 | 预警 | 越界触发通知并记录 |

## 6. 状态机汇总

### 6.1 需求状态机

```
        创建
         │
         ▼
      [待评审 todo] ──提交评审──▶ [评审中 doing]
         ▲                           │
         │                    ┌──────┴───────┐
         │                  通过           驳回
         │                    │              │
         │                    ▼              ▼
         │              [已评审 todo]   [已驳回 todo]
         │                    │              │
         │                 拉入迭代       修改重提
         │                    ▼              │
         │              [进行中 doing] ◀─────┘
         │                    │
         │                 完成交付
         │                    ▼
         │              [已完成 done] ──产生逃逸缺陷──▶ [重新打开 doing]
         └────────────────────────────────────────────────┘
                            关闭
                              ▼
                        [已关闭 done]
```

| 当前状态 | 允许动作 | 目标状态 | 约束 |
|---|---|---|---|
| 待评审 | 提交评审 | 评审中 | 须指定评审人 |
| 评审中 | 通过 | 已评审 | 评审人 |
| 评审中 | 驳回 | 已驳回 | 附驳回意见 |
| 已驳回 | 修改重提 | 评审中 | 提出人 |
| 已评审 | 拉入迭代 | 进行中 | 迭代容量校验 |
| 进行中 | 完成交付 | 已完成 | 写 `delivered_at` |
| 已完成 | 重新打开 | 进行中 | 记录原因 |
| 已完成 | 关闭 | 已关闭 | PM/管理员 |

### 6.2 缺陷状态机

```
     新建 new ──确认──▶ 已确认 confirmed ──开始修复──▶ 修复中 fixing
        │                     │                          │
        │                  拒绝/无效                    修复完成
        ▼                     ▼                          ▼
    已拒绝 rejected      已关闭 closed ◀──验证通过── 待验证 fixed
                                                        │
                                            验证不通过（重开）
                                                        ▼
                                                  已重新打开 reopened
                                                        │
                                            重新进入修复──▶ 修复中 fixing
```

| 当前状态 | 允许动作 | 目标状态 | 约束 |
|---|---|---|---|
| 新建 | 确认 | 已确认 | 处理人 |
| 新建 | 拒绝 | 已拒绝 | 附原因 |
| 已确认 | 开始修复 | 修复中 | — |
| 修复中 | 修复完成 | 待验证 | 须关联修复构建 |
| 待验证 | 验证通过 | 已关闭 | 验证人 |
| 待验证 | 验证不通过 | 已重新打开 | `reopen_count++` |
| 已重新打开 | 重新修复 | 修复中 | — |
| 已关闭 | 重新打开 | 已重新打开 | 记录原因 |

### 6.3 迭代状态机

```
   规划中 planning ──启动──▶ 进行中 active ──结束──▶ 已完成 completed ──关闭──▶ 已关闭 closed
        │                        │                        │
        └── 取消 ──▶ 已取消 cancelled                    └── 未完成需求移入未完成池
```

| 当前状态 | 允许动作 | 目标状态 | 约束 |
|---|---|---|---|
| 规划中 | 启动 | 进行中 | 日期有效、容量锁定 |
| 规划中 | 取消 | 已取消 | 记录原因 |
| 进行中 | 结束 | 已完成 | 未完成需求移池 |
| 已完成 | 关闭 | 已关闭 | 不可再编辑 |

## 7. 工作流与 BPMN 说明

### 7.1 需求评审工作流 `devops-requirement-review`

| 项 | 说明 |
|---|---|
| 触发 | 需求提交评审 |
| 参与 | 提出人 → 评审人（≥1）→（可选）产品负责人 |
| 网关 | 排他网关：全部评审人通过→通过；任一驳回→驳回 |
| 任务 | UserTask「评审」assignee=指定评审人；多实例（并行） |
| 结束 | 通过→需求置"已评审"；驳回→需求置"已驳回"，回填意见 |
| 通知 | 各节点经 `fenglin-message-service` 推送待办 |
| 超时 | 48h 未处理自动催办，7 天自动驳回 |

BPMN 节点：StartEvent(submitted) → UserTask(review，多实例并行) → ExclusiveGateway(allPassed?) → [yes] ServiceTask(updateStatus=已评审) → EndEvent ；[no] ServiceTask(updateStatus=已驳回) → EndEvent。

### 7.2 缺陷流转工作流 `devops-defect-flow`

| 项 | 说明 |
|---|---|
| 触发 | 缺陷状态流转事件 |
| 参与 | 提交人 → 处理人 → 验证人 |
| 网关 | 排他网关：验证通过/不通过 |
| 任务 | UserTask「修复」assignee=处理人；UserTask「验证」assignee=验证人 |
| 结束 | 验证通过→关闭；不通过→重开并回修复 |
| 约束 | 修复完成须关联 `fix_build_id` 方可流转至验证 |

BPMN 节点：StartEvent(confirmed) → UserTask(fix) → ExclusiveGateway(hasFixBuild?) → [yes] UserTask(verify) → ExclusiveGateway(pass?) → [yes] ServiceTask(close) / [no] ServiceTask(reopen)→ 回 UserTask(fix)。

### 7.3 发布审批工作流 `devops-release-approval`

| 项 | 说明 |
|---|---|
| 触发 | 发布单提交审批（env=prod 强制） |
| 参与 | 提交人 → 研发主管 → 运维负责人（双人复核） |
| 网关 | 排他网关：全部通过→批准；任一驳回→驳回 |
| 任务 | 串行 UserTask×2（双人复核）+ MFA 确认 |
| 服务任务 | 通过后调用部署服务执行部署，写 `devops_deployment` |
| 结束 | 部署完成发 `release.deployed` 事件 → 触发 DORA 计算 |
| 回滚 | 部署失败/异常时启动回滚子流程，`is_rollback=1` |

BPMN 节点：StartEvent(submit) → UserTask(techLeadApprove,MFA) → UserTask(opsApprove,MFA) → ExclusiveGateway(allApproved?) → [yes] ServiceTask(deploy) → ExclusiveGateway(deployOk?) → [yes] ServiceTask(mark deployed) → EndEvent / [no] ServiceTask(rollback) → EndEvent ；[no] ServiceTask(reject) → EndEvent。

### 7.4 Webhook 事件处理流（事件驱动）

```
第三方事件 → 网关（验签/限流）→ Kafka(devops.integration.event)
   → integration-worker 消费 → 幂等校验 → 业务落库 → 领域事件
   → 失败重试（指数退避 ≤5）→ 死信队列(devops.integration.dlq) + 告警
```

## 8. 跨模块协同

| 协同点 | 说明 |
|---|---|
| 需求 ↔ 任务 | 任务关联需求，汇报进度；需求交付依赖任务完成 |
| 需求 ↔ 缺陷 | 缺陷关联需求，逃逸缺陷标记需求 `is_escaped` |
| 缺陷 ↔ 测试 | 测试失败生成缺陷，缺陷回归驱动测试执行 |
| 提交 ↔ 工作项 | 提交关键字关联需求/任务/缺陷，驱动贡献度 |
| 构建 ↔ 发布 ↔ DORA | 构建→发布→部署链路驱动 DORA 与交付效率 |
| Sonar ↔ 质量度量 | 质量门禁与代码复杂度入质量度量与贡献度 |
| E1 ↔ E2 | E1 产生的全量过程数据为 E2 的唯一数据源，E2 回写快照供大盘 |

## 9. 与标杆产品差异点

| 模块 | 标杆（PingCode / 思码逸） | 丰麟云研差异点 |
|---|---|---|
| E1 研发效能 | 以团队/项目为中心，配置分散，与集团中台弱耦合 | 深度融入丰麟云枢中台（统一 IAM/租户/工作流/消息/审计），管理端与用户端强制分离；面向 3400 人多层级组织的数据权限与可见范围模型 |
| E1 集成 | 以单一 GitLab 为主 | 同时支持 GitLab/GitHub/Jenkins/SonarQube，Webhook 事件驱动 + 幂等 + 死信，令牌 AES-256-GCM + KMS 管理，满足等保三级 |
| E1 发布 | 发布流水线偏工程化，审批较弱 | 发布审批纳入中台 BPMN，生产发布强制双人复核 + MFA + 发布窗口，回滚可追溯并直连 DORA |
| E2 度量 | 通用效能指标库，口径固定 | 指标口径可配置、可版本化（口径版本管理），派生指标保存分子/分母可溯源，支持跨版本对比提示 |
| E2 DORA | 提供指标展示 | 与 E1 部署/回滚链路强绑定，自动识别回滚与热修复，等级评估内置 DORA 分级阈值 |
| E2 数据质量 | 弱 | 内置数据质量校验（缺失/异常值）与预警，指标可信度可量化 |
| 双端 | 单一控制台 | 管理端（口径/配置/审计）与用户端（画像/大盘）职责清晰，权限域与首页分离 |
