## 1. 引言

### 1.1 编写目的

本文档定义丰麟云研（Fenglin Cloud DevOps）产品的功能与非功能需求，是架构设计、数据库设计、接口设计、UI/UX 设计、测试与验收的统一依据。读者对象为产品经理、架构师、研发工程师、测试工程师、实施顾问、运维工程师与质量评审人员。

### 1.2 产品范围

丰麟云研是丰麟云枢平台"域E：研发"业务域产品，定位为**研发效能与度量平台**，品牌口号"**让研发过程可管理，让研发效能可度量**"。产品覆盖 2 个核心模块：

| 模块码 | 模块名 | 参考标杆 | 一句话定位 |
|---|---|---|---|
| E1 | 研发效能 | PingCode | 从需求、迭代、任务、缺陷、测试到代码库集成、流水线与发布的一体化研发过程管理 |
| E2 | 研发效能度量 | 思码逸 | 以代码贡献度、需求交付效率、质量度量、DORA 指标为核心的研发效能度量与洞察 |

本产品**不含**以下范围（由其它产品/中台承接）：统一身份与租户治理（丰麟云枢中台 IAM/租户）、审批流引擎（中台 `fenglin-workflow-service`）、消息通知（中台 `fenglin-message-service`）、知识沉淀与培训（丰麟云才 C2）、员工服务工单（丰麟云服 F1）。

| 术语 | 说明 |

## 2. 产品概述

### 2.1 产品定位与价值

丰麟云研以"研发过程可管理、研发效能可度量"双主线，覆盖软件研发全生命周期：

- **过程可管理**：需求 → 迭代 → 任务 → 缺陷 → 测试 → 代码 → 构建 → 发布 全链路在线化、可视化；
- **效能可度量**：以代码贡献度、交付效率、质量、DORA 为核心，量化团队与个人效能；
- **集成开箱**：与 GitHub/GitLab/Jenkins/SonarQube 深度集成，代码与工作项双向关联；
- **决策可支撑**：洞察大盘驱动资源配置、流程改进与效能提升；
- **合规可信**：源代码与凭据保护、审计留痕、等保三级。

### 2.2 目标用户与角色

| 角色 | 端 | 职责 |
|---|---|---|
| 平台超级管理员 | 管理端 | 平台级最高权限（运维专用、强审计） |
| 平台运维 | 管理端 | 租户/套餐/监控/灰度 |
| 租户管理员 | 管理端 | 本租户研发配置、组织、角色、权限 |
| 研发管理员（业务管理员） | 管理端 | 产品/流程/字段/集成/度量口径配置、审批 |
| 产品经理（PM） | 用户端 | 需求收集与规划、需求评审、验收 |
| 研发主管/Team Leader | 用户端 | 迭代规划、任务分配、燃尽跟踪、效能查看 |
| 开发工程师 | 用户端 | 任务执行、提交关联、构建修复、部署 |
| 测试工程师（QA） | 用户端 | 用例编写、测试执行、缺陷提交与回归 |
| 运维/发布工程师 | 用户端 | 流水线、发布、部署、环境管理 |

### 2.4 双端分离约束

严格遵循基线规范 §1.3：后端以令牌 `client_type`（`ADMIN`/`PORTAL`）声明端别，网关据此执行路由与鉴权策略；配置、授权、审核、报表定义类能力归管理端，日常业务操作、协同、查询、填报类能力归用户端。

#### 3.1.2 E1 关键业务规则

| 编号 | 规则 |
|---|---|
| BR-E1-01 | 需求必须归属一个产品与一个需求类型；父需求与子需求不能跨产品 |
| BR-E1-02 | 需求进入"评审中"须至少指定 1 名评审人；评审通过方可拉入迭代 |
| BR-E1-03 | 迭代容量以成员可用工时之和计算，拉入需求预估工时超容量时给出超载提示但不阻断 |
| BR-E1-04 | 缺陷严重级（阻塞/严重/一般/轻微）与优先级（P0–P3）独立；"阻塞"缺陷自动标记为迭代阻断项 |
| BR-E1-05 | 缺陷流转非法（如"已关闭"→"待处理"）须经"重新打开"动作，否则返回状态冲突错误 |
| BR-E1-06 | 测试执行失败可一键生成缺陷，缺陷自动回填测试用例与构建版本 |
| BR-E1-07 | 发布审批通过前不允许执行生产环境部署；回滚须记录原因与操作人 |
| BR-E1-08 | 提交关联遵循"同租户、同产品可见范围"校验，跨租户关联一律拒绝 |

#### 3.2.2 E2 关键业务规则

| 编号 | 规则 |
|---|---|
| BR-E2-01 | 指标计算统一以 UTC 时间为准，展示按租户时区转换；统计窗口默认自然日 00:00–24:00 |
| BR-E2-02 | DORA 变更前置时间 = 变更关联最近一次提交时间 → 生产部署完成时间；无生产部署不计入 |
| BR-E2-03 | 变更失败率 = 导致回滚/热修复的生产部署数 ÷ 生产部署总数；故障恢复时间取 MTTR 中位数 |
| BR-E2-04 | 缺陷逃逸率 = 生产环境发现缺陷数 ÷（测试阶段发现 + 生产发现）缺陷总数 |
| BR-E2-05 | 代码贡献度排除合并提交、二进制文件、生成代码（按路径/扩展名规则过滤） |
| BR-E2-06 | 指标快照按（租户, 产品, 团队, 指标, 周期, 粒度）唯一，重复计算幂等覆盖 |
| BR-E2-07 | 数据可见范围遵循数据权限：团队负责人见本部门及下级，个人见本人，管理员见全部 |

## 4. 非功能需求

### 4.1 性能需求

| 编号 | 需求 | 指标 |
|---|---|---|
| NFR-P-01 | 服务可用性 | ≥ 99.99%（年不可用 ≤ 52.6 分钟） |
| NFR-P-02 | 并发支撑 | 支撑 3400 人在线，核心接口峰值 ≥ 1200 QPS |
| NFR-P-03 | 核心接口响应 | P95 ≤ 300ms，P99 ≤ 800ms |
| NFR-P-04 | 看板渲染 | 单迭代 500 工作项看板首屏 ≤ 1.5s（内网） |
| NFR-P-05 | 指标聚合 | 大盘指标查询（近 90 天，10 指标）P95 ≤ 800ms；离线聚合任务单租户 ≤ 10 分钟 |
| NFR-P-06 | Webhook 高频写入 | 单租户突发 500 QPS Webhook 事件不丢、不阻塞，落库延迟 P95 ≤ 500ms |
| NFR-P-07 | 页面首屏 | 4G ≤ 2s，内网 ≤ 1s |
| NFR-P-08 | 单接口错误率 | ≤ 0.1% |

### 4.2 安全需求

| 编号 | 需求 |
|---|---|
| NFR-S-01 | 全链路 TLS 1.3；微服务间 mTLS；满足等保三级 |
| NFR-S-02 | 源代码访问、第三方集成令牌（Token/AppSecret）AES-256-GCM 加密存储，密钥 KMS 管理、≤ 90 天轮换 |
| NFR-S-03 | 集成令牌与 Webhook Secret 展示层脱敏，仅创建时明文返回一次 |
| NFR-S-04 | 生产环境部署、发布审批强制 MFA 二次确认与双人复核 |
| NFR-S-05 | 全量操作审计，审计日志哈希链 + WORM，留存 ≥ 6 个月 |
| NFR-S-06 | 代码库只读最小权限，禁止平台回写代码内容至第三方仓库（除状态回写白名单） |

### 4.3 可用性与可靠性需求

| 编号 | 需求 |
|---|---|
| NFR-A-01 | 同城双活，RPO ≤ 5min，RTO ≤ 30min |
| NFR-A-02 | Webhook 与消息处理支持重试（指数退避，最多 5 次）与死信队列 |
| NFR-A-03 | 无状态服务多副本，滚动发布不中断 |
| NFR-A-04 | 关键写操作幂等（`Idempotency-Key`），重复提交不产生脏数据 |

### 4.5 可维护性需求

| 编号 | 需求 |

| NFR-M-03 | 配置外置（Nacos），支持热更新 |
| NFR-M-04 | 开放 API 与内部接口分层，契约变更向后兼容至少 12 个月 |

| 任务 | 执行单元 | 负责人、状态、预估/实际工时、关联需求/缺陷 |
| 缺陷 | 质量单元 | 严重级、优先级、状态、环境、复现步骤 |
| 测试用例 | 测试资产 | 分组、步骤、前置条件 |
| 测试执行 | 执行记录 | 结果、执行人、关联构建 |
| 代码库 | 仓库绑定 | 类型、地址、令牌（加密）、默认分支 |

| 流水线 | 集成流水线 | 类型、定义、触发方式 |
| 构建 | 构建记录 | 编号、状态、制品、关联提交 |
| 发布 | 发布单 | 版本、环境、审批状态、部署时间 |
| 效能指标快照 | 聚合结果 | 指标码、周期、粒度、值 |
| 度量配置 | 口径配置 | 指标码、公式、权重、目标值、版本 |

### 5.2 数据量与留存

| 项目 | 估算（单租户，3400 人规模年） |
|---|---|
| 工作项（需求+任务+缺陷） | ≈ 300 万行/年 |
| 代码提交映射 | ≈ 2000 万行/年 |
| Webhook 事件 | ≈ 8000 万条/年（滚动归档 90 天热存） |
| 效能指标快照 | ≈ 500 万行/年 |
| 审计日志 | 留存 12 个月，冷热分层 |

### 5.3 数据质量要求

- 所有表强制 `tenant_id` + RLS；公共字段（审计四字段、`deleted`、`version`）齐备。
- 度量数据须记录采集批次与数据质量标记（正常/缺失/异常），派生的指标快照须可溯源至源记录。
- 逻辑删除不物理删除工作项；提交映射与事件按归档策略滚动清理。

## 6. 接口需求

### 6.1 内部接口

- 遵循基线规范 §5：HTTPS、RESTful、`/api/devops/v1` 前缀、统一响应体、标准错误码、`X-Tenant-Id`/`X-Client-Type` 请求头、`Idempotency-Key` 幂等。
- 覆盖产品、需求、迭代、任务、缺陷、测试、代码库、流水线、构建、发布、度量等资源。
- 核心接口 ≥ 40 个（详见《接口文档》FL-DEVOPS-API-001）。

### 6.2 第三方集成接口（入站 Webhook）

| 集成方 | 事件 | 端点 | 校验 |
|---|---|---|---|
| GitLab | Push/Merge Request/Tag/Pipeline | `POST /api/devops/v1/integration/gitlab/webhook` | `X-Gitlab-Token` 比对 |
| GitHub | Push/Pull Request/Release/Workflow Run | `POST /api/devops/v1/integration/github/webhook` | `X-Hub-Signature-256` HMAC-SHA256 |
| Jenkins | Build 状态回调 | `POST /api/devops/v1/integration/jenkins/webhook` | Bearer Token + HMAC 签名 |
| SonarQube | 质量门禁 Webhook | `POST /api/devops/v1/integration/sonarqube/webhook` | 共享密钥 + 签名校验 |

要求：全部入站 Webhook 必须验签、幂等（事件 ID 去重）、异步落库、限流保护、异常入死信队列。

### 6.3 出站接口（调用第三方）

| 集成方 | 用途 | 认证 |
|---|---|---|
| GitLab API v4 | 拉取分支/提交/MR/标签 | Private Token（加密存储） |
| GitHub REST API v3 | 拉取提交/PR/Release | PAT / App Token |
| Jenkins Remote API | 触发构建、查询状态 | API Token |
| SonarQube Web API | 拉取质量指标（覆盖率/复杂度/技术债） | User Token |

### 6.4 开放 API

- 前缀 `/openapi/devops/v1`，AppKey/AppSecret HMAC-SHA256 签名，OAuth2.1 授权码。
- 开放资源：需求、迭代、缺陷、发布、度量指标的受控读写。
- 开放事件：`requirement.created`、`requirement.status_changed`、`defect.created`、`release.deployed`、`metric.snapshot_ready`，经 Kafka Webhook 推送。

## 8. 验收标准

### 8.1 功能验收

| 编号 | 验收项 | 判定标准 |
|---|---|---|
| AC-01 | 需求全生命周期 | 需求从创建到发布验收全流程可在线完成，状态流转符合状态机定义 |
| AC-02 | 迭代与看板 | 迭代容量、燃尽图、看板拖拽流转正确；WIP 限制生效 |
| AC-03 | 缺陷闭环 | 缺陷提交→修复→回归→关闭闭环，非法流转被阻断 |
| AC-04 | 测试执行 | 用例执行结果记录正确，失败可生成缺陷并回填构建版本 |
| AC-05 | 代码关联 | 提交信息关键字可正确关联需求/缺陷，时间线可见 |
| AC-06 | 流水线与发布 | 流水线触发/构建状态同步正确；发布审批通过后可部署，未通过被阻断 |
| AC-07 | DORA 四项指标 | 计算口径正确，抽样核对与人工计算一致（误差 0） |
| AC-08 | 效能大盘 | 多维多指标展示正确，下钻与对比可用，导出内容与页面一致 |
| AC-09 | 双端分离 | 管理端/用户端路由、权限域、首页互不串扰；越权返回 403 |

### 8.2 非功能验收

| 编号 | 验收项 | 判定标准 |
|---|---|---|
| AC-10 | 性能 | 核心接口 P95 ≤ 300ms，压测错误率 ≤ 0.1% |
| AC-11 | Webhook 吞吐 | 单租户 500 QPS 事件零丢失，落库 P95 ≤ 500ms |
| AC-12 | 安全 | 等保三级控制矩阵逐项对照通过，集成令牌加密与脱敏验证通过 |
| AC-13 | 可用性 | 演练达成 RPO ≤ 5min、RTO ≤ 30min |
| AC-14 | 兼容性 | 主流浏览器与断点适配通过 |
