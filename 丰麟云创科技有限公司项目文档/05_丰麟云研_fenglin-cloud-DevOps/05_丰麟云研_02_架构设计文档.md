## 1. 架构概览

### 1.1 设计目标

| 目标 | 说明 |
|---|---|
| 过程在线化 | 需求→迭代→任务→缺陷→测试→代码→构建→发布全链路在线 |
| 度量实时化 | 多源数据采集与近实时聚合，支撑洞察大盘 |
| 集成标准化 | GitLab/GitHub/Jenkins/SonarQube 统一接入与事件驱动 |
| 双端分离 | 管理端/用户端工程、路由、权限域、首页分离 |
| 高可用 | 99.99% 可用，同城双活，RPO ≤ 5min / RTO ≤ 30min |
| 安全合规 | 等保三级，源代码与集成凭据强保护 |

### 1.2 架构风格

丰麟云研采用**微服务中台 + 事件驱动 + CQRS 读写分离（度量域）**的混合架构：

- 过程管理域（E1）以 OLTP 写为主，遵循统一 RESTful 契约；
- 度量域（E2）以高吞吐写入（Webhook/提交）+ 复杂聚合读为主，采用事件驱动采集 + 物化视图/快照表 + 预聚合缓存；
- 与中台能力（IAM/租户/工作流/消息/文件/审计/搜索）通过内部接口协作，不重复建设。

## 4. 关键流程时序

### 4.1 需求评审流程（BPMN 编排）

```
PM 提交需求 ──▶ [devops-service] 创建需求(status=待评审)
     │
     ├─▶ 调用 fenglin-workflow-service 启动流程 devops-requirement-review
     │
评审人处理 ──▶ 评审通过 ──▶ 需求 status=已评审（可拉入迭代）
             └▶ 评审驳回 ──▶ 需求 status=已驳回（附驳回意见，可修改再提）
     │
     └─▶ 全过程写 fenglin-audit-service；结果经 fenglin-message-service 通知
```

### 4.2 代码提交关联（Webhook 事件驱动）

```
GitLab/GitHub ──push 事件──▶ POST /integration/{vcs}/webhook
   │  网关验签/限流 → integration-worker 消费
   ├─ 幂等校验（commit_sha + repo_id 去重）
   ├─ 解析提交信息关键字（#REQ-xxx / #BUG-xxx / [req:123]）
   ├─ 写 devops_commit + devops_commit_link
   ├─ 更新工作项时间线（含提交行数、作者、分支）
   └─ 发 Kafka 事件 commit.linked → metric-worker 增量刷新贡献度
```

### 4.3 构建与发布流程

```
开发 ──触发──▶ devops-service /pipelines/{id}/trigger
   ├─ 调用 Jenkins/GitLab CI 触发构建
   ├─ 构建状态回调 ──▶ /integration/jenkins/webhook ──▶ 更新 devops_build
   └─ 构建成功后 ──▶ 创建发布单(devops_release, status=待审批)
                           │
                           ├─ 启动 devops-release-approval（BPMN，双人复核+MFA）
                           ├─ 审批通过 ──▶ 执行部署 ──▶ devops_deployment 记录
                           │                    └─▶ 发 release.deployed 事件 → DORA 计算
                           └─ 审批驳回 ──▶ 发布单关闭
```

### 4.4 度量聚合流程（离线 + 近实时）

```
XXL-Job（每日 01:00）/ Kafka 事件触发
   ├─ 采集：commit/task/defect/release/pipeline/quality(sonar)
   ├─ 清洗：去重、过滤（合并提交/二进制/生成代码）、时区归一
   ├─ 计算：贡献度、交付效率、质量、DORA
   ├─ 落库：devops_metric_snapshot / devops_dora_metric（幂等 upsert）
   └─ 发 metric.snapshot_ready → 刷新 Redis 预聚合缓存 + 触发预警判断
```

## 5. 数据架构

### 5.1 存储分工

| 存储 | 用途 |
|---|---|
| PostgreSQL `fenglin_devops` | 主数据与业务数据（≥ 22 张 `devops_*` 表），RLS 多租户隔离 |
| Redis | 看板/大盘缓存、会话、分布式锁、幂等键、限流计数 |
| Elasticsearch | 工作项全文检索、日志分析 |
| Kafka | Webhook 事件、领域事件、度量触发 |
| MinIO | 附件、测试截图、构建制品元数据引用 |
| 数据仓库/物化视图 | 度量聚合中间层（按周期物化） |

### 5.2 读写分离策略

- E1 写：主库；E1 读（列表/详情）：优先主库或只读副本（延迟容忍）。
- E2 读：只读副本 + Redis 预聚合缓存；大盘默认读快照表，避免实时全表扫描。
- 提交映射与 Webhook 事件：分区表（按 `created_at` 月分区）滚动归档。

### 5.3 缓存策略

| 键 | 内容 | TTL |
|---|---|---|
| `devops:board:{sprintId}` | 看板列与工作项 | 60s |
| `devops:metric:dashboard:{tenant}:{scope}` | 大盘指标聚合 | 300s |
| `devops:idem:{key}` | 幂等结果 | 24h |
| `devops:repo:token:{repoId}` | 解密后集成令牌（受控） | 10min |

## 6. 集成与开放

### 6.1 入站 Webhook 处理链

验签（HMAC/Token 比对）→ 事件去重（事件 ID 幂等）→ 限流（Sentinel）→ 入 Kafka → integration-worker 消费 → 业务落库 → 失败重试（指数退避 ≤ 5 次）→ 死信队列。

### 6.2 出站调用

统一经 `fenglin-openapi-service`/内部 HTTP 客户端调用，带熔断与超时（连接 1s / 读 5s），令牌从 KMS 解密后短期缓存，绝不落明文日志。

### 6.3 开放 API

前缀 `/openapi/devops/v1`；应用注册、AppKey/AppSecret HMAC-SHA256 签名、OAuth2.1、按 QPS 配额限流（超限返回 `0000006`）；开放事件经 Kafka Webhook 回调。

## 7. 双端分离架构

| 维度 | 管理端 | 用户端 |
|---|---|---|
| 前端工程 | `fenglin-hub-admin-ui`（Element Plus） | `fenglin-hub-portal-ui`（自研 Portal 组件） |
| 路由前缀 | `/admin/devops` | `/app/devops` |
| 权限域 | `platform:*`、`tenant:*` | `biz:*` |
| 令牌声明 | `client_type=ADMIN` | `client_type=PORTAL` |
| 导航骨架 | 左侧菜单 + 面包屑 | 顶部导航 + 卡片工作台 |
| 默认首页 | 租户研发概览/配置/集成/审计 | 我的工作台/待办/我的效能 |
| 审计粒度 | 配置类操作细粒度审计 | 业务操作审计 |

网关按 `client_type` 与路由前缀执行路由与鉴权策略；管理端接口不向用户端令牌开放，反之亦然。

## 8. 高可用与容灾

| 项 | 措施 |
|---|---|
| 服务可用性 | 多副本 + 无状态 + 滚动发布；跨 AZ 部署 |
| 数据库 | 一主两从，同步复制；自动故障切换；连接池隔离 |
| 缓存 | Redis 哨兵/集群，持久化 AOF |
| 消息 | Kafka 3 Broker，副本因子 3，min.insync.replicas=2 |
| 容灾 | 同城双活，RPO ≤ 5min，RTO ≤ 30min；异地冷备 |
| 降级 | 度量查询不可用时降级读上一快照；第三方不可用时熔断并缓存最近数据 |
| 限流 | 网关 + Sentinel 双层；Webhook 独立限流配额保护主链路 |

## 9. 安全架构

| 层 | 措施 |
|---|---|
| 传输 | 客户端↔网关 TLS 1.3；服务间 mTLS |
| 认证 | OAuth2.1/OIDC + JWT(RS256) + MFA（管理端与生产部署强制） |
| 授权 | RBAC + ABAC + 数据权限（行/列级），租户边界默认拒绝 |
| 凭据保护 | 第三方令牌/Webhook Secret 使用 AES-256-GCM 加密存储（KMS 管理，≤ 90 天轮换），展示脱敏 |
| 数据保护 | PII 加密 + `{field}_hash`；数据库 TDE；附件水印 |
| 审计 | 全链路审计，哈希链 + WORM，留存 ≥ 6 个月（建议 12 个月） |
| 主机/应用 | HIDS、镜像扫描、依赖 SCA、WAF、Sentinel 流控 |
| 代码安全 | 集成仅只读拉取；状态回写限白名单字段 |

## 10. 技术风险

| 编号 | 风险 | 影响 | 缓解措施 |
|---|---|---|---|
| R-01 | 第三方 API 变更（GitLab/GitHub/Jenkins/Sonar） | 集成中断 | 版本适配层 + 契约测试 + 灰度开关 |
| R-02 | Webhook 高频写入冲击主库 | 主链路抖动 | 独立限流、Kafka 削峰、分区表、异步落库 |
| R-03 | 度量聚合任务数据量大耗时 | 大盘数据延迟 | 增量计算 + 物化视图 + 只读副本 + 缓存 |
| R-04 | 看板大迭代渲染性能 | 用户体验下降 | 分页/虚拟滚动 + 服务端聚合 + 缓存 |
| R-05 | 令牌泄露风险 | 代码库安全 | KMS 加密、最小权限、脱敏、轮换、审计告警 |
| R-06 | 指标口径争议 | 决策偏差 | 口径版本管理 + 计算过程可溯源 + 评审发布 |
| R-07 | 集成令牌过期/失效 | 同步停止 | 健康检查 + 失效预警 + 自动告警 |
