## 1. 环境规划

### 1.1 环境划分

| 环境 | 用途 | 域名 | 命名空间 | 数据 |

## 2. 部署拓扑

```
                       ┌────────────┐
        Internet ──────▶│  WAF/CDN   │
                       └─────┬──────┘
                    ┌────────▼─────────┐
                    │  Nginx Ingress   │
                    └────────┬─────────┘
              ┌──────────────▼───────────────┐
              │   fenglin-gateway (x3)       │  TLS1.3 终止
              └──────────────┬───────────────┘
                             │ mTLS
   ┌───────────────┬─────────┼──────────┬────────────────┐
   ▼               ▼         ▼          ▼                ▼
[devops-service][metric-worker][integration-worker][中台服务集群]
   x4              x2               x3
   │               │                │
   └───────────────┴────────┬───────┘
                            ▼
   PostgreSQL(主备/只读) · Redis · Kafka · ES · MinIO · XXL-Job
```

- K8s 1.28+，多可用区；双机房各承载 50% 流量（同城双活）。
- 外部流量终止于网关；服务间 mTLS；数据库跨机房同步复制。
- 每日 01:00（租户时区）由 XXL-Job 触发度量离线聚合。

## 3. 依赖中间件

| 中间件 | 版本 | 用途 | 关键配置 |
|---|---|---|---|
| PostgreSQL | 15.x | 业务库 `fenglin_devops` | `max_connections=500`；RLS 启用；`pg_stat_statements` |
| Redis | 7.x | 缓存/锁/幂等/限流 | 持久化 AOF；`maxmemory-policy allkeys-lru` |
| Kafka | 3.6 | 事件总线 | 副本因子 3；`min.insync.replicas=2`；分区 ≥12 |
| Elasticsearch | 8.x | 全文检索 | IK 分词；副本 1 |
| MinIO | RELEASE.2024 | 附件/制品 | 纠删码；版本管理 |
| Nacos | 2.3.x | 注册与配置 | 集群 3 节点；配置加密 |
| XXL-Job | 2.4.x | 调度 | 执行器注册 `fenglin-devops-metric-worker` |
| SkyWalking | 9.x | 链路追踪 | OAP 集群 + ES 存储 |
| Prometheus/Grafana/Loki | 最新稳定 | 指标/日志 | 采集 worker 与 service `/actuator/prometheus` |

### 3.1 数据库初始化

1. 由 DBA 创建库 `fenglin_devops` 与专用账号（最小权限），启用 TDE 与 RLS。
2. 执行 Flyway 迁移（共 20 个脚本，`V{版本}__{描述}.sql`），不手工改库。
3. 初始化租户级默认需求状态方案、缺陷严重级字典、度量指标口径默认配置。

## 4. 部署步骤

### 4.1 前置检查

| 步骤 | 命令/检查 |
|---|---|
| 1 | `kubectl -n fenglin-devops get nodes` 节点就绪 |
| 2 | Nacos、PostgreSQL、Redis、Kafka 连通性检查 |
| 3 | 镜像已在私有仓库并完成漏洞扫描 |
| 4 | Flyway 迁移脚本评审通过，备份已完成 |

### 4.2 数据库迁移

```bash
# 以 Job 方式执行 Flyway（幂等，失败即中断）
kubectl -n fenglin-devops create job --from=cronjob/devops-flyway-migrate flyway-migrate-$(date +%s)
kubectl -n fenglin-devops logs -f job/flyway-migrate-<id>
# 校验
psql -h $PG_HOST -U devops_app -d fenglin_devops -c "select version, success from flyway_schema_history order by installed_rank desc limit 5;"
```

### 4.3 应用部署（GitOps）

```bash
# 方式一：ArgoCD 同步（推荐）
argocd app sync fenglin-devops-prod --prune
argocd app wait fenglin-devops-prod --health --timeout 600

# 方式二：Helm 手动发布
helm upgrade --install fenglin-devops ./charts/fenglin-devops \
  -n fenglin-devops --create-namespace \
  -f values-prod.yaml --atomic --timeout 10m
```

### 4.4 部署顺序与健康检查

1. 先迁移数据库 → 2. 发布 `metric-worker` / `integration-worker` → 3. 滚动发布 `devops-service`（`maxSurge=1, maxUnavailable=0`） → 4. 冒烟验证。

```bash
kubectl -n fenglin-devops rollout status deploy/fenglin-devops-service
curl -s https://devops.fenglincloud.com/actuator/health | jq .status   # 期望 UP
curl -s -H "Authorization: Bearer $TOKEN" -H "X-Client-Type: PORTAL" \
     https://devops.fenglincloud.com/api/devops/v1/products | jq .code # 期望 "0"
```

### 4.5 冒烟清单

| 序号 | 检查项 |
|---|---|
| S-01 | 登录与端别隔离（管理端/用户端令牌互斥） |
| S-02 | 产品/需求列表可读、创建需求成功 |
| S-03 | 需求评审、迭代/看板可访问 |
| S-04 | 代码库绑定与 Webhook 验签联调 |
| S-05 | 流水线触发、发布审批与部署 |
| S-06 | 大盘指标查询、贡献度/DORA 返回 |

## 6. 灰度与回滚

### 6.1 灰度策略

| 策略 | 说明 |
|---|---|
| 按比例灰度 | 新版本先承接 5% 流量，观察 30min，逐级 5%→20%→50%→100% |
| 按租户灰度 | 指定试点租户（如内部租户）先行 |
| 按端点灰度 | 先灰度读接口，再灰度写接口与 Webhook |
| 特性开关 | 新功能经 Nacos 开关控制，可即时关闭 |

### 6.2 灰度判定门禁

错误率 ≤ 0.1%、P95 ≤ 300ms、关键业务冒烟全通过、无新增致命/严重缺陷。任一门禁不达标即暂停并回滚。

### 6.3 回滚

```bash
# 应用回滚
helm rollback fenglin-devops -n fenglin-devops --timeout 10m
# 或 ArgoCD 回退到上一 Revision
argocd app rollback fenglin-devops-prod <history-id>
```

- 数据库迁移采用**向后兼容**原则（先加列/表，后删；新列可空）；如需回滚数据，执行对应 `U` 变更或备份恢复。
- 回滚须记录操作人、原因、版本号，写入审计。

## 7. 监控与告警

### 7.1 监控指标

| 维度 | 指标 | 阈值/告警 |
|---|---|---|
| 应用 | QPS、响应 P95/P99、错误率 | P95>300ms 或错误率>0.5% 告警 |
| 应用 | JVM 堆/GC、线程池、连接池 | 堆>80%、GC P99>100ms 告警 |
| 数据库 | 连接数、慢查询、复制延迟、锁等待 | 复制延迟>5s、慢查询>500ms 告警 |
| Kafka | lag、分区均衡、Broker 磁盘 | lag>1万且 5min 未消化告警 |
| Redis | 内存、命中率、连接 | 内存>80%、命中率<90% 告警 |
| 业务 | 大盘查询耗时、Webhook 落库延迟、聚合任务时长 | 超阈值告警 |
| 集成 | 第三方 API 成功率、令牌有效性 | 失败率>5% 或令牌失效告警 |
| 审计 | 审计写入成功率、WORM 写入 | 失败即告警 |

### 7.2 告警分级与通知

| 级别 | 场景 | 通知渠道 | 响应 |
|---|---|---|---|
| P0 | 服务不可用、数据错乱、越权 | 电话 + 企微/群 + 工单 | 5min 响应 |
| P1 | 核心接口劣化、Webhook 积压 | 企微/群 + 工单 | 15min |
| P2 | 非核心异常、容量预警 | 企微/群 | 1h |
| P3 | 提示级 | 邮件/日报 | 当日 |

### 7.3 关键看板

服务健康（Grafana）、接口黄金指标、Kafka lag、DB 慢查询 TopN、集成同步状态、审计写入。

## 8. 备份与恢复

### 8.1 备份策略

| 对象 | 方式 | 频率 | 保留 |
|---|---|---|---|
| PostgreSQL | 全量 + WAL 增量（PITR） | 每日全备 + 持续归档 | 全备 30 天、归档 7 天 |
| Redis | AOF + RDB | 持续/每小时 | 7 天 |
| Kafka | 副本因子 3 | 实时 | 按 Topic 保留 7 天 |
| MinIO | 版本管理 + 跨机房复制 | 实时 | 30 天 |
| 配置（Nacos） | 导出快照 | 每日 | 90 天 |
| 审计日志 | WORM 双副本 | 实时 | ≥ 6 个月（建议 12） |

### 8.2 恢复演练与目标

- RPO ≤ 5min，RTO ≤ 30min；**季度**恢复演练，记录 RTO 实测。
- 恢复步骤：选定时间点 → PITR 恢复至临时库 → 校验 `flyway_schema_history` 与关键表行数 → 切换/回灌 → 冒烟验证。

```bash
# 示例：PITR 恢复到指定时间点
pgbackrest --stanza=fenglin_devops --type=time \
  --target="2026-10-19 03:00:00+08" restore
```

## 9. 巡检与应急预案

### 9.1 日常巡检（每日）

| 项 | 检查 |
|---|---|
| 服务健康 | `/actuator/health` 全 UP |
| 容量 | CPU/内存/磁盘/连接数未超阈值 |
| 数据 | 聚合任务成功执行、快照完整 |
| 集成 | 四类 Webhook 正常、令牌有效 |
| 审计 | 审计写入正常、WORM 无失败 |
| 备份 | 备份成功、WAL 归档连续 |

### 9.2 应急处置

| 故障 | 现象 | 处置 |
|---|---|---|
| 服务不可用 | 健康检查失败/5xx 飙升 | 检查 Pod/日志 → 扩容或回滚 → 恢复后复盘 |
| 数据库主库故障 | 连接失败/复制中断 | 触发主备切换 → 校验一致性 → 恢复只读 |
| Webhook 积压 | Kafka lag 持续上涨 | 提升消费并行度 → 临时提高限流 → 定位慢处理 |
| 大盘查询慢 | P95 超阈值 | 命中缓存/降级读上一快照 → 检查慢查询与索引 |
| 集成令牌失效 | 同步停止 | 重置令牌（KMS）→ 重新绑定 → 回补数据 |
| 指标计算错误 | 指标异常 | 冻结口径版本 → 修正算法 → 重算快照（幂等覆盖） |
| 越权/安全事件 | 告警触发 | 立即封禁账号/令牌 → 取证审计 → 上报安全组 |

### 9.3 应急联系人（角色）

| 角色 | 职责 |
|---|---|
| 值班运维 | 一线响应与初步定位 |
| 研发值守 | 代码级定位与热修 |
| DBA | 数据库故障与恢复 |
| 安全组 | 安全事件处置 |
| 产品负责人 | 业务影响评估与决策 |

### 9.4 应急预案要点

- 变更与发布遵循"可观测、可回滚、可灰度"。
- 重大故障 15min 内升级，1h 内出具初步结论。
- 事后 3 个工作日内完成故障复盘与改进项闭环。
