## 1. 评估范围

### 1.1 评估对象

| 对象 | 说明 |
|---|---|
| 应用服务 | `fenglin-devops-service`（E1 研发效能、E2 研发效能度量） |
| 数据库 | PostgreSQL 15.x · `fenglin_devops`（33 张 `devops_*` 表） |
| 集成面 | GitLab/GitHub/Jenkins/SonarQube Webhook 回调与 API 拉取 |
| 凭据面 | 代码库访问令牌、CI Token、Sonar Token、Webhook Secret、审批签名密钥 |
| 双端 | 用户端 `/app/devops`、管理端 `/admin/devops` |
| 接口 | `/api/devops/v1` 下 74 个接口（含 4 个 Webhook 回调） |

### 1.2 评估依据

GB/T 22239-2019 网络安全等级保护基本要求（第三级）；基线规范 §8 控制矩阵；OWASP Top 10 (2021)；OWASP ASVS 4.0.3；ISO/IEC 27001。

### 1.3 重点评估方向

- **源代码保护**：仓库只读最小权限、禁止平台回写代码内容、访问审计；
- **凭据保护**：集成令牌（Token/AppSecret/Webhook Secret）AES-256-GCM 加密存储、脱敏展示、KMS 管理与 ≤ 90 天轮换；
- **第三方集成安全**：Webhook 验签、防重放、出站白名单；
- **越权与数据隔离**：功能权限 × 数据权限 × 租户 RLS × 端别隔离。

### 1.4 评估方法

代码审计（SAST）、依赖成分分析（SCA）、动态扫描（DAST，OWASP ZAP）、渗透测试（越权/注入/验签绕过/SSRF）、配置核查、控制矩阵逐项对标。

## 2. 等保三级控制矩阵逐项对照

| 控制类别 | 控制项 | 平台基线措施 | 丰麟云研落地 | 结论 |
|---|---|---|---|---|
| 身份鉴别 | 双因子/强口令/登录失败锁定 | MFA、口令复杂度、5 次锁定、会话超时 30min | 由中台 IAM 统一提供；生产部署与发布审批在平台基础上**强制 MFA 二次确认**；令牌 RS256（access 30min / refresh 7d 轮换） | 符合 |
| 访问控制 | 最小权限、职责分离 | RBAC+ABAC+数据权限、三员分立 | 权限码 `{域}:{模块}:{操作}`（`biz:*`/`tenant:*`/`platform:*`）；数据权限 `self/dept/dept_sub/dept_list/all`；研发管理员与发布审批人分离 | 符合 |
| 安全审计 | 全量审计、防篡改 | 全链路审计日志、哈希链、WORM、留存 ≥6 个月 | 所有写操作留审计；发布/部署/凭据/集成操作写**哈希链 + WORM**；留存 ≥ 6 个月（建议 12） | 符合 |
| 入侵防范 | 边界防护、攻击检测 | WAF、IDS/IPS、Sentinel 流控、漏洞扫描 | 网关 WAF + Sentinel 限流（按接口分级，如创建 5 QPS/租户）；Webhook 入口独立限流与签名校验 | 符合 |
| 恶意代码防范 | 主机/应用防护 | 主机 HIDS、镜像扫描、依赖 SCA | 镜像准入扫描、CI 依赖 SCA 门禁、制品签名校验 | 符合 |
| 数据完整性 | 传输/存储完整性 | TLS1.3、HMAC、数据库校验 | 全链路 TLS 1.3；Webhook HMAC-SHA256 验签；关键字段审计哈希链 | 符合 |
| 数据保密性 | 传输/存储加密 | TLS、AES-256-GCM、密钥 KMS 管理 | 集成令牌/Secret AES-256-GCM 加密 + `{field}_hash`（SHA-256+租户盐）检索；KMS 托管、≤90 天轮换 | 符合 |
| 数据备份恢复 | 本地+异地备份、演练 | 每日全备+增量、异地容灾、季度演练 | 见 FL-DEVOPS-OPS-001 §8；RPO ≤ 5min、RTO ≤ 30min；季度恢复演练 | 符合 |
| 剩余信息保护 | 数据擦除 | 存储/内存剩余信息清理、介质销毁 | 逻辑删除 + 归档销毁流程；内存中凭据即时清零；介质按流程销毁 | 符合 |
| 个人信息保护 | 最小必要、脱敏、同意 | PII 加密、脱敏、授权访问、审计 | 研发人员信息按中台 PII 规范加密；导出/展示脱敏（如手机号中间四位）；访问审计 | 符合 |
| 安全管理 | 制度、机构、人员、建设、运维 | 安全管理制度体系、三员分立、应急预案 | 沿用平台制度；三员分立；应急预案见 OPS 手册 §9 | 符合 |

### 2.1 关键补充项核查

| 项 | 要求 | 核查结果 |
|---|---|---|
| 全链路加密 | 客户端↔网关 TLS1.3，微服务间 mTLS | 已启用；证书由平台统一签发与轮换 |
| 存储加密 | PII AES-256-GCM；数据库 TDE | 已启用；集成令牌字段级加密 |
| 密钥轮换 | ≤ 90 天 | KMS 策略 90 天自动轮换，Webhook Secret 支持手工重置 |
| 审计留存 | 操作 ≥6 个月、安全日志 ≥6 个月 | 已配置；WORM 桶不可删除 |

## 3. 威胁建模（STRIDE）

| 威胁 | 场景 | 风险 | 现有控制 | 残余风险 |
|---|---|---|---|---|
| **S**poofing 身份伪造 | 伪造第三方 Webhook 触发流水线/部署 | 高 | HMAC-SHA256 验签、时间戳防重放（±5min）、`Idempotency-Key` 去重；失败返回 `5000204` | 低 |
| **T**ampering 篡改 | 篡改提交关联或指标快照 | 高 | 审计哈希链 + WORM；指标快照唯一键幂等覆盖；乐观锁 `version` | 低 |
| **R**epudiation 抵赖 | 否认执行生产部署/回滚 | 中 | 部署/回滚强制 MFA + 双人复核 + 操作人留痕 + 审计不可篡改 | 低 |
| **I**nformation Disclosure 信息泄露 | 集成令牌明文泄露、跨租户读取指标 | 高 | 令牌 AES-256-GCM 加密、创建时一次性明文返回、展示脱敏；RLS + 数据权限双层隔离 | 低 |
| **D**enial of Service 拒绝服务 | Webhook 洪泛、大盘重查询打垮库 | 中 | Sentinel 接口级限流、Webhook 独立队列缓冲、大盘结果缓存、Kafka 削峰 | 中（见 §7） |
| **E**levation of Privilege 提权 | 用户端令牌调用管理端接口 | 高 | 网关按 `client_type` 强校验端别；管理端接口拒绝 PORTAL 令牌；权限码最小化 | 低 |

### 3.1 攻击面清单

| 攻击面 | 入口 | 主要防护 |
|---|---|---|
| Webhook 回调 | 公网 POST 4 个回调地址 | 验签、限流、IP 白名单（可选）、防重放 |
| 开放 API | `/api/devops/v1` | OAuth2.1、scope 最小化、限流、审计 |
| 出站集成 | GitLab/Jenkins/Sonar API | 出站域名白名单、凭据加密、只读最小权限 |
| 管理端配置 | `/admin/devops` | MFA、端别隔离、敏感操作二次确认 |
| 报表导出 | 导出接口 | 数据权限过滤、水印、导出审计 |

## 5. 加固措施

### 5.1 源代码保护专项

| 编号 | 措施 |
|---|---|
| SEC-C-01 | 代码库绑定仅授予**只读**最小权限（`read_repository`），禁止平台回写代码内容 |
| SEC-C-02 | 平台对第三方仓库的状态回写仅限**白名单动作**（提交状态、MR 评论），不写代码/分支 |
| SEC-C-03 | 仓库访问凭据加密存储、按租户隔离、访问留审计 |
| SEC-C-04 | 提交/分支/MR 浏览受数据权限控制，跨租户一律拒绝 |
| SEC-C-05 | 本地缓存与临时文件不落盘明文代码内容，内存即时清理 |

### 5.2 第三方集成令牌与凭据安全

| 编号 | 措施 |
|---|---|
| SEC-T-01 | 集成 Token/AppSecret/Webhook Secret 采用 **AES-256-GCM** 加密落库，密钥由 KMS 托管 |
| SEC-T-02 | 新增 `{field}_hash`（SHA-256 + 租户盐）用于检索与唯一约束，禁止明文唯一索引 |
| SEC-T-03 | 凭据创建时**仅返回一次明文**，后续展示统一脱敏（如 `glpat-****3f7a`） |
| SEC-T-04 | Secret 支持一键重置，轮换周期 ≤ 90 天，轮换事件审计 |
| SEC-T-05 | 出站集成访问采用域名/端口白名单，防 SSRF；禁止访问内网地址段 |
| SEC-T-06 | Webhook 强制 HMAC-SHA256 验签 + 时间戳防重放（±5min）+ 幂等去重 |

### 5.3 通用加固

- 统一错误码与响应体，屏蔽堆栈与数据库细节（`5000007`）。
- 接口级限流（Sentinel），写接口按租户限额，Webhook 独立队列。
- 会话/令牌：RS256、短时效 access、refresh 可撤销、异常登录告警。
- 依赖 SCA 与镜像扫描纳入 CI 门禁，阻断高危依赖合入。
- 管理端敏感操作（发布、部署、凭据、权限）强制 MFA + 双人复核 + 审计。

## 6. 合规结论

| 维度 | 结论 |
|---|---|
| 等保三级 | 控制矩阵 11 类控制项逐项**符合**，关键补充项（加密/轮换/审计留存）达标 |
| OWASP Top 10 | 无高危遗留；中危已修复或已缓解 |

## 7. 残余风险

| 编号 | 残余风险 | 等级 | 缓解/监控 |
|---|---|---|---|
| RR-01 | 极端 Webhook 洪泛（> 1000 QPS 持续）可能造成队列积压 | 中 | 限流阈值告警、Kafka 扩容预案、死信队列兜底；纳入 SLO 监控 |
| RR-02 | refresh token 泄露窗口 | 低 | 撤销机制、设备绑定、异常登录告警与自动封禁 |
| RR-03 | 报表截屏外泄 | 低 | 水印、导出审计、数据权限最小化 |
| RR-04 | 间接依赖偶发新披露漏洞 | 低 | 每日 SCA 扫描与月度升级窗口 |
| RR-05 | 审计日志依赖外部 WORM 存储可用性 | 低 | WORM 双副本、写入失败告警与重试 |

> 残余风险均为可接受级别，且具备监测与处置手段；建议每季度复评一次。
