### 4.4 业务规则

| 编号 | 规则 |
|---|---|
| BR-D1-01 | 凭证借贷合计必须相等，容差为 0，否则拒绝保存 |
| BR-D1-02 | 制单人 ≠ 审核人；审核通过后不可修改，仅可冲销 |
| BR-D1-03 | 过账后凭证进入哈希链，任何修改请求返回 `4001002`（已过账不可修改） |
| BR-D1-04 | 结账前校验：期间内凭证全部过账、试算平衡、资产折旧已计提、往来核销完成 |
| BR-D1-05 | 封账（SEALED）后禁止任何记账；需反结账须有 `tenant:finance:period:reopen` 且强审计 |
| BR-D1-06 | 报销单提交时按预算 `STRICT` 强控占用，余额不足直接拒绝（`4001006`） |
| BR-D1-07 | 收付款与往来核销在同一事务，核销额不得超过未核销余额 |
| BR-D1-08 | 账龄按到期日与当前日期差自动分桶；坏账准备按政策（默认 5%/10%/30%/50%/100%） |
| BR-D1-09 | 外币业务按交易日即期汇率折算，期末按期末汇率重估并结转汇兑损益 |
| BR-D1-10 | 科目停用前须校验余额为 0 且无未过账凭证 |

### 4.5 状态机（凭证）

```
DRAFT(草稿) ──提交──▶ SUBMITTED(待审) ──审核通过──▶ AUDITED(已审) ──过账──▶ POSTED(已过账)
    ▲                    │驳回                         │冲销
    └──────修改───────────┘                            ▼
                                                  REVERSED(已冲销)
```

- 事件与动作：`submit`/`approve`/`reject`/`post`/`reverse`。
- 非法流转（如 DRAFT 直接过账）返回 `4000005`。

### 4.6 工作流（BPMN 说明）

**流程 `fin-d1-voucher-approval`（凭证审核）**

```
[开始] → [制单人提交] → [Gateway: 金额阈值?]
   ├─ 金额 ≤ 50万 → [财务主管审核]
   └─ 金额 > 50万 → [财务主管审核] → [财务经理复核]
[审核] → Gateway: 通过? ─是→ [过账任务] → [写哈希链] → [结束]
                        └否→ [驳回] → 返回制单人 → [结束]
```

- 用户任务：`voucherAuditTask`、`voucherSecondAuditTask`、`voucherPostTask`。
- 服务任务：`hashChainService`（过账写链）、`auditService`（WORM）。
- 边界事件：超时 24h 提醒（message → 待办推送）。

**流程 `fin-d1-expense-claim`（费用报销）**见 §4.7。

**流程 `fin-d1-period-close`（期末结账）**

```
[发起结账] → [校验任务: 未过账凭证?/试算平衡?/折旧计提?/往来核销?]
  → Gateway: 全部通过? ─否→ [阻断并输出未完成清单] → [结束]
                        └是→ [损益结转] → [生成结账快照+哈希链] → [期间置 CLOSED] → [结束]
```

### 4.7 工作流：费用报销（`fin-d1-expense-claim`）

```
[员工提交报销单(预算占用)] → [直属主管审批] → [Gateway: 金额>1万?]
   ├─ 是 → [部门负责人审批] → [财务审核]
   └─ 否 → [财务审核]
[财务审核] → Gateway: 通过? ─否→ [驳回] → [释放预算占用] → [结束]
                          └是→ [生成应付 fin_payable] → [出纳付款] → [生成凭证] → [预算转执行] → [结束]
```

- 幂等：`Idempotency-Key` = `claim_no`；重复提交仅生成 1 条。
- 异常边界：发票验真失败→打回；预算不足→阻断（STRICT）。

### 4.8 异常与边界

| 场景 | 处理 |
|---|---|
| 借贷不平衡 | 拒绝，提示差额（5000103 参数校验失败，错误码 `0000003`） |
| 并发过账同一凭证 | 乐观锁冲突，返回 `0000005`，提示刷新 |
| 期间已封账仍提交凭证 | 拒绝 `4001004`（期间已封账） |
| 核销超余额 | 拒绝 `4001005`（核销金额超限） |
| 预算原子占用失败 | Redis Lua + DB 双重校验，回滚 |
| 银行流水重复导入 | 按 `txn_no + account_id` 去重，幂等 |

### 4.9 验收标准

| 编号 | 验收 |
|---|---|
| AC-D1-01 | 不平衡凭证 100% 被拒；过账后修改 100% 被拒 |
| AC-D1-02 | 同 `Idempotency-Key` 重复提交仅 1 条记录 |
| AC-D1-03 | 结账 50 万凭证行 ≤5min，试算平衡差额为 0 |
| AC-D1-04 | 账龄计算与坏账准备结果与手工一致 |
| AC-D1-05 | 报表（资产负债表）左右平衡，误差为 0 |
| AC-D1-06 | 哈希链校验通过（任一节点篡改可检出） |

### 4.10 与标杆产品差异点（对照用友 YonSuite）

| 维度 | 用友 YonSuite | 丰麟云财 |
|---|---|---|
| 多租户 | 面向多企业，租户隔离以数据库/账套为主 | 共享库 + RLS 行级 + 账套双层隔离，适配 SaaS |
| 双端 | 以统一平台为主，前台能力弱 | 严格管理端/用户端分离，员工报销/工时/碳填报在用户端 |
| 凭证防篡改 | 提供审计日志 | 过账即写**哈希链 + WORM**，可验证不可篡改 |
| 业财一体 | 覆盖广 | 事件驱动 + 规则引擎可配置，与云销/云法/云才事件打通 |
| 幂等 | 部分场景 | **金额/库存/审批全量强制幂等** |
| 碳与 ESG | 非重点 | D4 双碳/ESG 与财务同源，碳资产入账 |

### 5.4 业务规则

| 编号 | 规则 |
|---|---|
| BR-D2-01 | 项目编号 = `FIN{yyyyMM}{6位}`，租户内唯一 |
| BR-D2-02 | 立项通过后方可填报工时与归集成本 |
| BR-D2-03 | 工时成本 = 工时(小时) ÷ 8 × 成本费率（元/人天），费率取填报日生效值并快照 |
| BR-D2-04 | 工时单审批通过方计入项目成本；驳回后修改重提，同一工时单不重复计成本 |
| BR-D2-05 | 成本归集支持人工/采购/外包/差旅/分摊（管理费按人天或收入比例分摊） |
| BR-D2-06 | 收入确认：完工百分比法（成本法）= 已发生成本 / 预计总成本 × 合同额，需财务确认 |
| BR-D2-07 | 项目结算生成应收并触发开票申请；结算金额与已确认收入差额入递延 |
| BR-D2-08 | 成本达预算 80%/90%/100% 分级预警（Level 1/2/3）并推送 PM 与财务 |
| BR-D2-09 | 项目关账前须成本归集完毕、结算完成、收入确认完毕 |

### 5.5 状态机（项目）

```
DRAFT ──提交──▶ APPROVING ──通过──▶ ACTIVE ──发起结算──▶ SETTLING ──结算完成──▶ CLOSED
   ▲                │驳回                 │暂停                 │
   └────修改────────┘                     ▼                    │
                                    SUSPENDED ──恢复──▶ ACTIVE  │
                                                              │
   REJECTED ◀──驳回(立项)                                     └──▶
```

### 5.6 工作流（BPMN 说明）

**流程 `fin-d2-project-approval`（立项审批）**

```
[PM提交立项] → [部门负责人审批] → [Gateway: 合同额>100万?]
   ├─ 是 → [经营会审] → [财务审批]
   └─ 否 → [财务审批]
[财务审批] → Gateway: 通过? ─是→ [项目置 ACTIVE + 生成项目编号] → [结束]
                             └否→ [驳回] → [结束]
```

**流程 `fin-d2-timesheet-approval`（工时审批）**

```
[员工提交周工时] → [PM审批] → Gateway ─通过→ [计入成本池: 生成 fin_cost_collection(LABOR)] → [结束]
                                  └驳回→ [退回修改] → [结束]
```

**流程 `fin-d2-project-settlement`（项目结算）**

```
[PM发起结算(阶段/终验)] → [PM所属部门审批] → [财务审批] → [生成应收 + 开票申请]
  → [事件 finance.project.settled] → [D1 生成凭证] → [项目置 SETTLING→CLOSED] → [结束]
```

- 服务任务：`createReceivableService`、`financeVoucherService`（借 应收账款 / 贷 主营业务收入 / 应交税费-销项税额）。
- 幂等：结算单 `settlement_no` 作幂等键，防重复生成应收。

### 5.7 异常与边界

| 场景 | 处理 |
|---|---|
| 工时超 24h/日 | 校验拒绝，提示 |
| 费率缺失 | 归集时按角色兜底费率，仍缺失则阻断并提示补录 |
| 结算金额 > 合同额-已结算 | 拒绝 `4002003` |
| 项目已关账再归集成本 | 拒绝 `4002004` |
| 收入确认后成本重大变化 | 触发重算并留痕 |

### 5.8 验收标准

| 编号 | 验收 |
|---|---|
| AC-D2-01 | 项目立项→工时→成本→结算→凭证全链路贯通 |
| AC-D2-02 | 工时成本计算与手工核算一致，误差为 0 |
| AC-D2-03 | 重复结算请求（同幂等键）仅生成 1 条应收 |
| AC-D2-04 | 成本超支预警在 80%/90%/100% 准确触发 |
| AC-D2-05 | 项目盈利（毛利/毛利率）与财务口径一致 |

### 5.9 与标杆产品差异点（对照代码时空）

| 维度 | 代码时空 | 丰麟云财 |
|---|---|---|
| 定位 | 项目交付与成本 | 与财务总账/应收应付**同源一体**，结算即凭证 |
| 成本口径 | 项目成本 | 支持多分摊模型 + 财务科目映射，可对账 |
| 双端 | 以项目人员为主 | PM/成员在用户端，财务在管理端，权限分离 |
| 收入确认 | 支持 | 完工百分比/里程碑/合同法，与收入科目联动 |
| 预警 | 基础 | 三级成本预警 + 消息推送 + 与预算联动 |

### 6.4 业务规则

| 编号 | 规则 |
|---|---|
| BR-D3-01 | 折旧方法：直线法 `月折旧 = (原值-残值)/使用月数`；双倍余额递减法 `月折旧 = 期初净值 × 2/使用月数`（最后两年改直线）；年数总和法按剩余年数加权 |
| BR-D3-02 | 当月新增资产当月不提折旧，次月起提；当月处置资产当月照提，次月停提（可配置） |
| BR-D3-03 | 净值不低于残值；提足折旧后停提 |
| BR-D3-04 | 折旧按批次号 `calc_batch_no` 幂等，同资产同期间不可重复计提（唯一约束） |
| BR-D3-05 | 处置生成凭证（借 固定资产清理/累计折旧 / 贷 固定资产；取得价款 借 银行存款 / 贷 固定资产清理；差额入 资产处置损益） |
| BR-D3-06 | 盘盈按重置成本入账；盘亏先挂"待处理财产损溢"，审批后转损益 |
| BR-D3-07 | IT 资产与 CMDB 同步以 `cmdb_ci_id` 为主键映射，冲突以 CMDB 为准并留差异日志 |
| BR-D3-08 | 借用到期未还自动提醒并升级 |

### 6.5 状态机（资产卡片）

```
IN_USE(在用) ──借用──▶ LENT(借出) ──归还──▶ IN_USE
   │  闲置                            │
   ▼                                   │
IDLE(闲置) ──领用──▶ IN_USE            │
   │                                   │
   ├──维修──▶ MAINTENANCE ──完工──▶ IN_USE
   │
   └──处置──▶ DISPOSING(处置中) ──审批──▶ DISPOSED(已处置)
```

盘点单状态：`DRAFT → IN_PROGRESS → SUBMITTING → COMPLETED`。

### 6.6 工作流（BPMN 说明）

**流程 `fin-d3-asset-disposal`（资产处置）**

```
[资产管理员发起处置] → [资产部门负责人审批] → [Gateway: 原值>50万?]
   ├─ 是 → [财务经理审批]
   └─ 否 → [财务审核]
[财务审核] → Gateway: 通过? ─是→ [处置执行(生成凭证)] → [资产置 DISPOSED] → [结束]
                             └否→ [驳回] → [结束]
```

**流程 `fin-d3-asset-stocktaking`（资产盘点）**

```
[资产管理员发起盘点(范围)] → [生成盘点任务] → [指派盘点人] 
  → [盘点人扫码逐项盘点(用户端)] → [提交盘点结果]
  → [资产管理员复核差异] → [Gateway: 有盘盈盘亏?]
       ├─ 是 → [盘盈盘亏审批] → [账务处理(生成凭证)] → [盘点报告] → [结束]
       └─ 否 → [盘点报告] → [结束]
```

- 用户任务：`stocktakingCheckTask`（盘点人）、`stocktakingReviewTask`（复核）、`surplusDeficitApprovalTask`。
- 幂等：盘点结果提交以 `stocktaking_id + asset_id` 去重。

**流程 `fin-d3-depreciation-batch`（批量折旧，定时触发 XXL-Job）**

```
[定时触发(月度 02:00)] → [扫描启用资产] → [分批计算折旧] → [生成折旧明细]
  → [汇总生成折旧凭证] → [更新累计折旧/净值] → [事件 finance.depreciation.completed] → [结束]
```

### 6.7 异常与边界

| 场景 | 处理 |
|---|---|
| 同资产同期间重复折旧 | 唯一约束拦截，返回 `4003002` |
| 折旧致净值低于残值 | 自动调整至残值 |
| 盘点资产不在范围 | 标记为"范围外"，不参与盘盈亏 |
| 处置已处置资产 | 状态校验拒绝 `4003004` |
| CMDB 不可用 | 标记 `sync_status=PENDING`，恢复后补偿同步 |

| 编号 | 验收 |
|---|---|
| AC-D3-01 | 三类折旧方法结果与手工核算一致（误差 0） |
| AC-D3-02 | 10 万资产批量折旧 ≤3min |
| AC-D3-03 | 折旧/处置/盘盈亏凭证与总账一致 |

### 7.4 业务规则

| 编号 | 规则 |

| BR-D4-02 | 核算结果必须记录 `factor_id` 与 `factor_version`，可追溯 |
| BR-D4-03 | 范围二默认采用"基于位置"法（区域电网因子），可切换"基于市场"法（绿电证书） |
| BR-D4-04 | 碳活动数据经复核（VERIFIED）后方可核算；锁定（LOCKED）后不可修改，需解锁审批 |
| BR-D4-05 | 重算生成新版本（`is_latest`），历史结果保留 |
| BR-D4-06 | 双碳目标达成进度 = (基准排放-当前排放)/(基准排放-目标排放) |
| BR-D4-07 | ESG 报告需 ESG 负责人复核后发布，发布后版本冻结 |
| BR-D4-08 | 单位换算按内置换算表（如天然气 m³→GJ→Nm³ 口径统一） |

```
DRAFT ──提交──▶ SUBMITTED ──复核通过──▶ VERIFIED ──锁定──▶ LOCKED
   ▲               │复核驳回                │解锁(审批)
   └────修改────────┘                        ▼
                                        DRAFT(重新填报)
```

### 7.6 工作流（BPMN 说明）

**流程 `fin-d4-carbon-verification`（碳数据核证 / MRV）**

```
[排放源责任人填报碳活动] → [系统校验(单位/必填/合理性)] → [ESG 专员复核]
  → Gateway: 通过? ─是→ [数据置 VERIFIED] → [碳核算] → [更新目标进度] → [结束]
                    └否→ [驳回并附原因] → [退回填报] → [结束]
```

**流程 `fin-d4-esg-report`（ESG 报告出具）**

```

  → Gateway: 通过? ─是→ [发布(PUBLISHED, 冻结版本, 导出 PDF/Excel)] → [结束]
                    └否→ [退回修改] → [结束]
```

**流程 `fin-d4-carbon-unlock`（碳数据解锁）**

```
[发起解锁申请] → [ESG 负责人审批] → Gateway ─通过→ [置 DRAFT, 记录解锁审计] → [结束]
                                          └否→ [拒绝] → [结束]
```

### 7.7 异常与边界

| 场景 | 处理 |
|---|---|
| 活动数据单位缺失/不匹配 | 阻断并提示，附换算建议 |
| 排放因子过期 | 提示选用最新版本，允许指定版本并留痕 |
| 已锁定数据被修改 | 拒绝 `4004006`，引导走解锁流程 |
| 核算重算并发 | 以 `calc_batch_no` 幂等，仅最新为 `is_latest` |
| 报告发布后修改 | 拒绝，需创建新版本 |

### 7.8 验收标准

| 编号 | 验收 |
|---|---|
| AC-D4-01 | 核算结果 = 活动数据 × 因子，误差 0，可追溯因子版本 |
| AC-D4-02 | 同批次重算幂等，仅 1 条 `is_latest` |
| AC-D4-03 | 双碳目标进度计算正确 |
| AC-D4-04 | ESG 报告按 GRI/ISSB 框架完整生成并导出 |
| AC-D4-05 | 锁定数据不可篡改，解锁留审计 |
