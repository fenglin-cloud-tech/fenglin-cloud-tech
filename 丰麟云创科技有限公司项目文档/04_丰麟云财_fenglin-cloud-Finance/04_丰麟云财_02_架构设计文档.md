## 1. 架构概览

### 1.1 定位

丰麟云财（Fenglin Cloud Finance）为丰麟云枢平台"域D：财务与经营"业务域，采用**微服务中台 + 领域内模块化**架构，服务名 `fenglin-finance-service`，命名空间 `fenglin-finance`，通过网关统一接入，与平台中台能力（IAM/租户/工作流/消息/文件/审计/报表/AI）协同。

### 1.2 架构原则

| 原则 | 说明 |
|---|---|
| 业财一体 | 业务事件驱动凭证生成（事件 + 规则引擎），保证业务与财务同源 |
| 精确可信 | 金额一律 `decimal`（numeric(20,4)）；凭证过账后不可篡改（哈希链） |
| 幂等优先 | 金额/库存/审批写操作强制 `Idempotency-Key` 幂等 |
| 双端分离 | 管理端/用户端在网关、权限、路由、首页全维度分离 |
| 多租户隔离 | 共享库共享模式 + `tenant_id` + RLS；私有化独立库 |
| 可观测 | 全链路审计、TraceId、指标告警 |
| 可扩展 | 核算规则/折旧政策/预算控制/排放因子可配置化 |

### 1.3 逻辑视图

```

│ 接入层  管理端 fenglin-finance-admin-ui(/admin/finance)                │
```

## 2. 分层与部署图

### 2.1 分层职责

| 层 | 组件 | 职责 |
|---|---|---|
| 接入层 | Admin UI / Portal UI / 开放网关 | 渲染、端别声明、请求汇聚 |
| 网关层 | `fenglin-gateway` | JWT 校验、`client_type` 路由、限流（Sentinel）、审计埋点、灰度 |
| 中台层 | 平台中台服务 | 身份、租户、流程、消息、文件、审计、报表、AI |
| 业务域层 | `fenglin-finance-service` | D1–D4 领域逻辑，模块化包内隔离 |
| 数据层 | PG/Redis/ES/Kafka/RocketMQ/MinIO | 持久化、缓存、检索、事件、对象存储 |

### 2.2 部署拓扑（SaaS 生产）

```
                    ┌──────────────┐
   Internet ──TLS──▶│  WAF + LB    │
                    └──────┬───────┘
                           ▼
              ┌────────────────────────┐
              │ fenglin-gateway ×3     │  (K8s Deployment)
              └───────────┬────────────┘
        ┌─────────────────┼─────────────────────┐
        ▼                 ▼                     ▼
 fenglin-auth    fenglin-finance-service   fenglin-report-service
 (中台 ×2)          (×6, HPA 2→12)             (×2)
        │                 │                     │
        └────────┬────────┴──────────┬──────────┘
                 ▼                   ▼
        PostgreSQL 15 (主备+只读副本)   Redis Cluster
        Kafka / RocketMQ / ES / MinIO / Nacos
```

- 同城双活：两个可用区各部署一套服务与一份数据库（流复制 + 只读副本），RPO ≤ 5min、RTO ≤ 30min。
- HPA：`fenglin-finance-service` 依据 CPU/请求队列在 2–12 副本弹性伸缩，结账窗口期预扩容。

## 4. 关键流程时序

### 4.1 凭证过账（含不可篡改审计）

```
制单人        Admin UI     finance-service   工作流        DB           审计服务
  │  录凭证      │               │             │           │              │
  ├────────────▶│──POST /vouchers(Idem-Key)──▶│           │              │
  │             │               │ 借贷平衡校验 │           │              │
  │             │               │─────────────┼─INSERT fin_voucher/entry──▶│
  │  提交        │               │             │           │              │
  ├────────────▶│──/submit─────▶│──启动审批──▶│           │              │
  │             │               │             │ 审核通过   │              │
  │             │               │◀────────────┤           │              │
  │             │               │──/post 过账─▶│           │              │
  │             │               │  生成哈希链  │──UPDATE status=POSTED──▶│
  │             │               │─────────────┼───────────┼─写审计WORM──▶│
  │◀─ 凭证已过账 │◀──────────────│             │           │              │
```

要点：制单人≠审核人；过账后不可修改；`fin_voucher_audit_log` 记录 `prev_hash` 与记录摘要形成哈希链，同步写平台审计服务 WORM 存储。

### 4.2 费用报销

```
员工(PORTAL) → 报销单填报 → 预算占用(Redis 预占+DB 台账) → 审批流(Flowable)
 → 财务终审 → 生成应付 → 付款单 → 生成凭证(DEBIT 费用 / CREDIT 银行存款)
```

### 4.3 项目结算与业财联动

```
项目经理 → 结算申请 → 审批 → 生成应收(fin_receivable) + 开票申请
 → 事件 finance.project.settled 发布(Kafka) → D1 凭证引擎(规则:借 应收账款 / 贷 主营业务收入/应交税费)
```

### 4.4 资产批量折旧

```
XXL-Job(月度 02:00) → 扫描启用资产 → 计算本月折旧(方法/残值/停提规则)
 → 写 fin_depreciation_schedule → 汇总生成折旧凭证 → 更新净值 → 事件 finance.depreciation.completed
```

### 4.5 碳核算

```
ESG 专员 → 碳活动数据填报 → 数据校验/单位换算 → 关联排放因子版本
 → 核算服务 计算 CO2e → 写 fin_carbon_emission(可追溯因子版本) → 目标对比/看板
```

## 5. 数据架构

### 5.1 数据分域

| 域 | 主要表（前缀 `fin_`） |
|---|---|
| 总账/凭证 | `fin_accounting_subject`、`fin_accounting_period`、`fin_voucher`、`fin_voucher_entry`、`fin_voucher_audit_log` |
| 往来 | `fin_receivable`、`fin_payable`、`fin_receipt`、`fin_payment`、`fin_reconciliation` |
| 费用/预算 | `fin_expense_claim`、`fin_expense_claim_item`、`fin_budget`、`fin_budget_control` |
| 项目 | `fin_project`、`fin_project_member`、`fin_project_milestone`、`fin_timesheet`、`fin_labor_rate`、`fin_cost_collection`、`fin_project_settlement` |
| 资产 | `fin_asset_category`、`fin_asset_card`、`fin_depreciation_schedule`、`fin_asset_change`、`fin_asset_stocktaking`、`fin_asset_stocktaking_item`、`fin_it_asset` |
| 碳/ESG | `fin_emission_factor`、`fin_carbon_activity`、`fin_carbon_emission`、`fin_carbon_target`、`fin_esg_indicator`、`fin_esg_report` |
| 公共 | `fin_currency`、`fin_exchange_rate`、`fin_bank_account`、`fin_bank_transaction`、`fin_invoice`、`fin_attachment`、`fin_idempotency_record` |

（完整字段字典见 FL-FIN-DB-001。）

### 5.2 数据一致性

| 场景 | 策略 |
|---|---|
| 业财联动（业务单据→凭证） | 本地消息表 + Kafka 最终一致；关键强一致用 RocketMQ 事务消息 |
| 收付款与往来核销 | 行锁 + 乐观锁（`version`）+ 幂等，事务内完成 |
| 跨域（云法合同、云才员工） | Seata AT（强一致）+ 本地消息表兜底 |
| 金额一致性 | 一律 decimal；跨表汇总以分录为准，禁止浮点 |

### 5.3 缓存策略

| 缓存对象 | Key | 失效 |
|---|---|---|
| 科目树 | `fin:subject:{tenant}` | 科目变更时失效 |
| 汇率 | `fin:rate:{tenant}:{ccy}:{date}` | 每日 |
| 预算余额 | `fin:budget:{tenant}:{budget}` | 占用/释放时更新（Lua 原子） |
| 排放因子 | `fin:ef:{code}:{version}` | 因子版本发布时失效 |

### 5.4 检索（ES）

凭证摘要、项目、资产、碳活动数据建立 ES 索引（IK 分词），用于全局检索与模糊查询；索引按租户字段过滤（`tenant_id`），禁止跨租户召回。

## 6. 集成与开放

- **内部集成**：通过 Kafka 事件订阅云销（合同/回款）、云法（合同/签章）、云才（员工/组织）、云枢（租户/权限）。
- **业财一体规则引擎**：业务事件→凭证模板（借贷科目映射、辅助核算映射）可配置；支持条件分支与多模板。
- **开放 API**：`/openapi/finance/v1/**`，AppKey/AppSecret（HMAC-SHA256），OAuth2.1 授权码；配额按应用/接口 QPS，超限返回 `0000006`。
- **事件与 Webhook**：Kafka 主题 + Webhook 回调（重试 + 签名验签 + 幂等）。

## 7. 双端分离架构

| 维度 | 管理端 | 用户端 |
|---|---|---|
| 前端工程 | `fenglin-finance-admin-ui` | `fenglin-finance-portal-ui` |
| 路由 | `/admin/finance` | `/app/finance` |
| 权限域 | `platform:*`、`tenant:*` | `biz:*` |
| 令牌声明 | `client_type=ADMIN` | `client_type=PORTAL` |
| 首页 | 财务运营概览/待办/审批/监控 | 我的工作台（待办/我的报销/我的工时/资产） |
| 组件库 | Element Plus（信息密集） | 自研 Portal 组件（任务导向） |
| 网关策略 | 路由至管理端允许接口集 | 路由至用户端允许接口集 |

实现要点：

1. 网关依据 JWT 中 `client_type` 与 `X-Client-Type` 一致性校验，不一致拒绝（403）。
2. 接口标注端别（ADMIN/PORTAL），网关按端别白名单放行，越端调用返回 `0000002`。
3. 两端共用设计令牌（Design Token），导航骨架与信息密度按 FL-HUB-STD-001 §9.2 差异化。

## 8. 高可用与容灾

| 项 | 设计 |
|---|---|
| 服务可用性 | ≥ 99.99%（年 ≤52.6min） |
| 网关/服务 | 多副本 + 无状态 + K8s 探针 + HPA |
| 数据库 | 主备流复制 + 只读副本；同城双活；RPO ≤5min、RTO ≤30min |
| 缓存 | Redis Cluster（3 主 3 从） |
| 消息 | Kafka 3 副本 + RocketMQ 主从 |
| 批处理 | 结账/折旧任务支持断点续跑、幂等重试、失败补偿 |
| 降级 | Sentinel 熔断降级，非核心（看板/检索）可降级，核心记账不可降级 |
| 备份 | 每日全备 + 增量，异地容灾，季度恢复演练 |

## 9. 安全架构

| 层面 | 措施 |
|---|---|
| 边界 | WAF、IDS/IPS、网关限流、灰度 |
| 传输 | 客户端↔网关 TLS1.3；微服务间 mTLS |
| 存储 | PII AES-256-GCM + `{field}_hash`；数据库 TDE |
| 密钥 | KMS 管理，轮换 ≤90 天 |
| 认证 | OAuth2.1/OIDC + MFA + SSO；登录失败 5 次锁定；会话超时 30min |
| 授权 | RBAC + ABAC + 数据权限（行/列）；三员分立 |
| 审计 | 全链路审计、哈希链、WORM，留存 ≥6 个月（审计日志 12 个月） |
| 防篡改 | 凭证过账哈希链；审计日志防篡改；结转/结账快照 |
| 财务专用 | 制单/审核/过账三权分离；金额幂等；结账后不可记账 |

## 10. 技术风险

| 编号 | 风险 | 影响 | 应对 |
|---|---|---|---|
| R-01 | 期末结账/折旧批处理数据量大导致超时 | 影响月结时效 | 分片并行 + 断点续跑 + 窗口期扩容 |
| R-02 | 业财事件最终一致下的凭证重复 | 财务数据错误 | 幂等键 + 本地消息表去重 + 对账补偿 |
| R-03 | 多币种汇率波动导致折算差异 | 报表偏差 | 期末汇兑损益结转 + 汇率版本留痕 |
| R-04 | 金额浮点精度风险 | 合规风险 | 强制 decimal(numeric(20,4)) + 静态扫描 + 用例覆盖 |
| R-05 | 碳因子版本变更导致可比性下降 | 结果口径不一致 | 因子版本化 + 核算留痕 + 重算可对比 |
| R-06 | 跨域强一致依赖 Seata 带来性能损耗 | 响应变慢 | 仅关键路径用 Seata，其余本地消息表 |
| R-07 | 报表聚合海量数据慢查询 | P95 超标 | 预聚合 + 物化视图 + 只读副本 + 缓存 |
| R-08 | 等保三级审计项遗漏 | 合规不达标 | 逐项对照矩阵 + 专项渗透测试 |
