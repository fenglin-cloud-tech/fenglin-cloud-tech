## 2. 部署拓扑

```
                    ┌──────────────┐
   Internet ──TLS──▶│  WAF + LB    │
                    └──────┬───────┘
                           ▼
        ┌──────────────────────────────────┐
        │ fenglin-gateway ×3 (K8s)         │
        └──────────────┬───────────────────┘
     ┌─────────────────┼───────────────────────┐
     ▼                 ▼                        ▼
fenglin-auth   fenglin-finance-service    fenglin-report-service
 (中台×2)        (×6, HPA 2→12)               (×2)
     │                 │                        │
     └────────┬────────┴───────────┬────────────┘
              ▼                    ▼
   PostgreSQL15(主备+只读)     Redis Cluster
   Kafka / RocketMQ / ES / MinIO / Nacos(×3)
```

- 同城双活：两可用区各部署一套应用与数据库副本，流量经 LB 分发。
- 无状态服务，配置外置于 Nacos/ConfigMap。

## 4. 部署步骤（容器/脚本）

### 4.1 镜像构建（GitLab CI）

```yaml
# .gitlab-ci.yml（节选）
build:
  stage: build
  script:
    - ./mvnw -pl fenglin-finance-service clean package -DskipTests
    - docker build -t registry.fenglincloud.com/finance/fenglin-finance-service:${CI_COMMIT_TAG} .
    - docker push registry.fenglincloud.com/finance/fenglin-finance-service:${CI_COMMIT_TAG}
scan:
  stage: scan
  script:
    - trivy image --exit-code 1 --severity HIGH,CRITICAL registry.fenglincloud.com/finance/fenglin-finance-service:${CI_COMMIT_TAG}
```

### 4.2 数据库迁移（Flyway）

```bash
# 迁移前必须备份
pg_dump -h pg.fenglincloud.com -U fl_finance -Fc fenglin_finance > fin_backup_$(date +%Y%m%d%H%M).dump
# 执行迁移（应用启动自动执行 migrate；亦可手动）
java -jar fenglin-finance-service.jar --spring.flyway.enabled=true --spring.flyway.locations=classpath:db/migration
# 校验
psql -h pg.fenglincloud.com -U fl_finance -d fenglin_finance -c "select version, description, success from flyway_schema_history order by installed_rank desc limit 5;"
```

> 生产禁止手工改库；迁移纳入流水线并留痕审计。

### 4.3 Kubernetes 部署（ArgoCD GitOps）

```yaml
# deployment.yaml（节选）
apiVersion: apps/v1
kind: Deployment
metadata:
  name: fenglin-finance-service
  namespace: fenglin-finance-prod
spec:
  replicas: 6
  selector: { matchLabels: { app: fenglin-finance-service } }
  template:
    metadata: { labels: { app: fenglin-finance-service } }
    spec:
      containers:
        - name: app
          image: registry.fenglincloud.com/finance/fenglin-finance-service:1.0.0
          ports: [{ containerPort: 8080 }]
          envFrom:
            - configMapRef: { name: fenglin-finance-config }
            - secretRef:    { name: fenglin-finance-secret }
          readinessProbe: { httpGet: { path: /actuator/health/readiness, port: 8080 }, initialDelaySeconds: 30, periodSeconds: 10 }
          livenessProbe:  { httpGet: { path: /actuator/health/liveness,  port: 8080 }, initialDelaySeconds: 60, periodSeconds: 20 }
          resources: { requests: { cpu: "2", memory: "4Gi" }, limits: { cpu: "8", memory: "16Gi" } }
---
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata: { name: fenglin-finance-hpa, namespace: fenglin-finance-prod }
spec:
  scaleTargetRef: { apiVersion: apps/v1, kind: Deployment, name: fenglin-finance-service }
  minReplicas: 2
  maxReplicas: 12
  metrics:
    - type: Resource
      resource: { name: cpu, target: { type: Utilization, averageUtilization: 65 } }
```

```bash
# 部署
argocd app sync fenglin-finance-prod
kubectl -n fenglin-finance-prod rollout status deploy/fenglin-finance-service
```

### 4.4 初始化

1. 创建库与角色：`fenglin_finance`、应用角色 `fl_finance`、平台角色 `fl_platform`（BYPASSRLS）。
2. 执行 Flyway 迁移（V1_0_0 → V1_0_18）。
3. 导入种子数据（币种、科目模板、排放因子）。
4. 在 Nacos 注册配置；在 IAM 注册权限码；在工作流服务部署 `fin-*` BPMN。
5. 配置 XXL-Job 任务（月度折旧、月结、碳核算）。

## 6. 灰度与回滚

### 6.1 灰度发布

1. 预发（staging）验证通过后，生产按 **10% → 30% → 100%** 流量灰度（网关按 `X-Tenant-Id` 哈希分流）。
2. 灰度期观察：核心接口 P95、错误率、结账/折旧任务成功率、审计链校验。
3. 无异常则逐步放量；异常则暂停并回滚。

### 6.2 回滚

```bash
# 应用回滚（ArgoCD 回退到上一版本）
argocd app rollback fenglin-finance-prod
# 或 K8s 回滚
kubectl -n fenglin-finance-prod rollout undo deploy/fenglin-finance-service
```

- 数据库迁移**向前兼容**：新增字段可空、不删列；回滚不回退已执行的 DDL（必要时以补偿脚本处理）。
- 回滚后校验：健康检查、核心接口冒烟、飞行窗口内批次任务状态。

## 7. 监控告警

### 7.1 指标（Prometheus + Grafana）

| 类别 | 指标 | 告警阈值 |
|---|---|---|
| 应用 | QPS、RT(P95/P99)、错误率 | P95>300ms 持续 5min；错误率>0.1% |
| JVM | 堆内存、GC、线程 | 堆>85%；FullGC 频繁 |
| 数据库 | 连接数、慢查询、锁等待 | 连接>80%；慢查>1s 增多 |
| 缓存 | 命中率、内存 | 命中率<80% |
| 队列 | Kafka 消费延迟 | 延迟>60s |
| 业务 | 结账耗时、折旧耗时、对账差额 | 结账>5min；折旧>3min；对账差额≠0 |
| 安全 | 登录失败、越权 403、审计链校验 | 失败激增；校验失败立即告警 |
| 可用性 | 健康探测成功率 | 低于 99.99% |

### 7.2 日志与链路

- 结构化 JSON 日志（Logback）→ Loki；全链路 TraceId → SkyWalking。
- 关键业务日志（凭证过账、结账、折旧、碳核算）单独索引，留存 12 个月。

## 8. 备份恢复

| 项 | 策略 |
|---|---|
| 全备 | 每日 01:00 `pg_dump` 全量 |
| 增量 | WAL 归档持续（PITR） |
| 异地 | 备份同步至异地对象存储 |
| 保留 | 全备保留 30 天，月度全备保留 12 个月 |
| 演练 | 季度恢复演练，验证 RPO ≤5min、RTO ≤30min |
| 恢复 | `pg_restore` + WAL 回放至时间点 |

```bash
# 恢复示例
pg_restore -h pg-restore -U fl_finance -d fenglin_finance -Fc fin_backup_20261019.dump
# PITR
restore_command = 'cp /wal_archive/%f %p'
recovery_target_time = '2026-10-19 08:00:00+08'
```

## 9. 巡检与应急预案

### 9.1 日常巡检（每日）

1. 服务健康与副本数、HPA 状态。
2. 核心接口 P95/错误率、告警清零情况。
3. 数据库连接、慢查询、复制延迟、只读副本状态。
4. 批处理任务（结账/折旧/碳核算）成功与耗时。
5. 磁盘/备份/证书/KMS 轮换状态。
6. 审计链校验结果。

### 9.2 应急预案

| 场景 | 处置 |
|---|---|
| 核心接口超时 | 检查 DB/缓存 → 扩容 HPA → 限流非核心（看板/检索）→ 降级 |
| 数据库主库故障 | 切换备库（Patroni/流复制）→ 应用重连 → 校验数据 |
| 结账/折旧任务失败 | 查看批次日志 → 断点续跑（幂等）→ 校验无重复 |
| 幂等键冲突异常 | 检查 `fin_idempotency_record` → 确认无重复记账 |
| 审计链校验失败 | 立即隔离 → 取证 → 定位篡改点 → 上报安全组 |
| 密钥泄漏 | KMS 立即轮换 → 失效旧密钥 → 全量审计排查 |
| 大促/月结高峰 | 预扩容 + 错峰调度 + 提前压测 |

### 9.3 变更管理

- 所有变更走工单与审批；生产禁手工改库；变更留痕审计。
- 高风险变更（DDL、批处理逻辑）须评估回滚方案并在低峰执行。
