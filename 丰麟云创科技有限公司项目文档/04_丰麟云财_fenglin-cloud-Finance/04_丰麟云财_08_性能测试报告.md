## 1. 目标与指标

### 1.1 总体目标

验证丰麟云财在**3400 人在线规模**下的性能与稳定性，重点覆盖**报表聚合、期末结账批处理、资产折旧批量计算**三大重负载场景。

### 1.2 指标基线

| 指标 | 目标值 | 说明 |
|---|---|---|
| 服务可用性 | ≥ 99.99% | 年不可用 ≤ 52.6 分钟 |
| 并发用户 | 3400 在线 | 峰值核心接口 ≥ 1200 QPS |
| 核心接口 P95 | ≤ 300ms | P99 ≤ 800ms |
| 单接口错误率 | ≤ 0.1% | 5xx + 业务失败 |
| 页面首屏 | ≤ 2s（4G）/ ≤1s（内网） | |
| 报表聚合 | 年度报表 ≤ 3s | 10 万凭证行 |
| 期末结账 | ≤ 5min | 50 万凭证行 |
| 资产折旧批量 | ≤ 3min | 10 万资产 |
| 报表导出 | ≤ 30s | 5 万行（异步） |

### 1.3 容量模型（单租户 3400 人）

| 参数 | 值 |
|---|---|
| 在线用户 | 3400 |
| 峰值日活比例 | 60% → 2040 活跃 |
| 并发比例 | 35% → 约 1200 并发 |
| 平均请求/人/分钟 | 6 次 |
| 峰值 QPS（核心） | ≥ 1200 |
| 读写比 | 8:2 |

## 5. 瓶颈分析

| 编号 | 瓶颈现象 | 根因 | 影响 |
|---|---|---|---|
| B-01 | 结账批处理早期耗时 8min+ | 逐条余额聚合、缺少批量提交 | 超时 |
| B-02 | 报表聚合初期 P95 4.1s | 全表扫描 + 实时聚合 | 超标 |
| B-03 | 折旧批处理初期 5min | 单线程计算 + 逐条写库 | 超标 |
| B-04 | 列表查询高峰期偶发 450ms | 缺失复合索引 | P95 波动 |
| B-05 | 写入高峰期锁等待 | 预算占用串行更新 | RT 上升 |
| B-06 | 报告导出阻塞应用线程 | 同步导出占用线程池 | 影响其他请求 |

## 6. 调优措施

| 编号 | 对应瓶颈 | 措施 | 效果 |
|---|---|---|---|
| O-01 | B-01 | 结账改为分批（5000 行/批）+ 批量 SQL + 并行分片 + `unedologgin` 临时表 | 8min → 2min42s |
| O-02 | B-02 | 引入物化视图 + 预聚合余额表 + 只读副本查询 + Redis 缓存 | P95 4.1s → 1.42s |
| O-03 | B-03 | 折旧计算向量化 + COPY 批量写入 + 分片并行 | 5min → 1min38s |
| O-04 | B-04 | 补充复合索引（见 DB 文档 §5），`tenant_id` 前置 | P95 稳定 ≤205ms |
| O-05 | B-05 | 预算占用改 Redis Lua 原子 + 异步落库 + 乐观锁重试 | 锁等待消除 |
| O-06 | B-06 | 导出改异步任务（XXL-Job）+ 文件服务异步下载 | 释放应用线程 |
| O-07 | 通用 | 连接池 HikariCP 调优、JVM G1、K8s HPA 2→12、结账窗口预扩容 | CPU 峰值下降 12% |

## 7. 结论与容量建议

### 7.1 结论

- 所有性能指标**达标**：核心接口 P95 ≤ 300ms、峰值 ≥1200 QPS、错误率 ≤0.1%。
- 三大重负载场景达标：报表聚合 ≤3s、期末结账 ≤5min、资产折旧批量 ≤3min。
- 长稳 72h 可用性 99.995%，满足 ≥99.99% 要求。
- 单租户 3400 人规模运行稳定，无内存泄漏与连接泄漏。

### 7.2 容量建议

| 项 | 建议 |
|---|---|
| 应用副本 | 常态 6，峰值 HPA 至 12；结账窗口 02:00–04:00 预扩至 10 |
| 数据库 | 主库 16C64G 起，只读副本 ≥2；凭证分录/折旧/碳活动按年分区 |
| 缓存 | Redis Cluster 3 主 3 从；预算余额与科目树缓存 |
| 批处理窗口 | 结账/折旧/碳核算错峰调度（XXL-Job），避免同窗竞争 |
| 扩容阈值 | 当单租户凭证行 >800 万或资产 >30 万，建议升级主库并增加分区 |
| 监控 | 对结账耗时、折旧耗时、报表 P95 设置告警阈值 |

### 7.3 后续优化方向

- 报表预聚合下沉至物化视图 + 增量刷新。
- 折旧/结账引入列存或分布式计算（超大规模租户）。
- 冷热数据分层，历史年度数据转冷存储。
