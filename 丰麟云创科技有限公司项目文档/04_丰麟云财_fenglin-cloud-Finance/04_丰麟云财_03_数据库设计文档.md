## 1. 设计原则

| 编号 | 原则 |
|---|---|
| P-01 | 多租户共享库共享模式：每张业务表含 `tenant_id`，启用 PostgreSQL RLS 行级安全 |
| P-02 | 主键统一 `bigint` 雪花 ID；对外暴露使用 `uuid` 映射（`fin_*` 表不直接暴露自增） |
| P-03 | **金额字段一律 `numeric(20,4)` 精确类型**，并显式声明币种列 `currency_code`（ISO-4217）；禁止 `float/double/money` |
| P-04 | 数量 `numeric(18,4)`；汇率 `numeric(18,8)`；比率/进度/税率 `numeric(9,6)` |
| P-05 | 全表公共字段：`id`、`tenant_id`、审计四字段（`created_by`/`created_at`/`updated_by`/`updated_at`）、`deleted`、`version` |
| P-06 | 逻辑删除 `deleted smallint`（0 正常 / 1 删除），查询默认过滤 |
| P-07 | 乐观锁 `version int`，更新语句 `WHERE id=? AND version=?` |
| P-08 | 所有 DDL/DML 通过 Flyway 脚本，命名 `V{版本}__{描述}.sql`，禁止手工改库 |
| P-09 | PII 字段 AES-256-GCM 加密 + `{field}_hash`（SHA-256+租户盐）用于检索与唯一约束 |
| P-10 | 时间统一 `timestamptz` 存 UTC；展示按租户时区转换 |

| 字段 | 类型 | 空 | 默认 | 说明 |
|---|---|---|---|---|

## 2. 逻辑模型（ER）

```
图例：  ──1:N──▶ 表示一对多 | ══1:1══ 表示一对一

[fin_ledger 账套]
   │1:N
   ├──▶ [fin_accounting_subject 科目] ──self(parent_id)──▶ 科目树
   ├──▶ [fin_accounting_period 期间]
   ├──▶ [fin_voucher 凭证] ──1:N──▶ [fin_voucher_entry 分录]
   │        │1:N                         │
   │        ├──▶ [fin_voucher_audit_log 凭证审计链(哈希链)]
   │        └──▶ [fin_period_close_snapshot 结账快照]
   ├──▶ [fin_budget 预算] ──1:N──▶ [fin_budget_control 预算控制台账]

[fin_voucher] ◀── 生成 ── [fin_receipt 收款单] / [fin_payment 付款单] / [fin_expense_claim 报销单]
[fin_receivable 应收] ──1:N──▶ [fin_arap_write_off 核销] ◀──1:N── [fin_receipt]
[fin_payable 应付]   ──1:N──▶ [fin_arap_write_off 核销] ◀──1:N── [fin_payment]
[fin_invoice 发票] ──N:1──▶ [fin_receivable]/[fin_payable]
[fin_bank_account 银行账户] ──1:N──▶ [fin_bank_transaction 流水] ──N:1──▶ [fin_reconciliation 对账]

[fin_project 项目] ──1:N──▶ [fin_project_member 成员]、[fin_project_milestone 里程碑]
        │1:N
        ├──▶ [fin_timesheet 工时] ──N:1──▶ [fin_labor_rate 费率]
        ├──▶ [fin_cost_collection 成本归集]
        └──▶ [fin_project_settlement 项目结算] ──▶ [fin_receivable]

[fin_asset_category 资产类别] ──1:N──▶ [fin_asset_card 资产卡片]
[fin_asset_card] ──1:N──▶ [fin_depreciation_schedule 折旧明细]
[fin_asset_card] ──1:N──▶ [fin_asset_change 资产变动]
[fin_asset_stocktaking 盘点单] ──1:N──▶ [fin_asset_stocktaking_item 盘点明细] ──N:1──▶ [fin_asset_card]
[fin_asset_card] ══1:1══ [fin_it_asset IT资产台账]（it_asset_flag=true）

[fin_emission_factor 排放因子] ◀──N:1── [fin_carbon_activity 碳活动]
[fin_carbon_activity] ──1:N──▶ [fin_carbon_emission 碳排放核算]
[fin_carbon_target 双碳目标] ── 汇总 ── [fin_carbon_emission]
[fin_esg_indicator ESG指标] ── 汇总 ── [fin_esg_report ESG报告]

[fin_currency 币种] ──1:N──▶ [fin_exchange_rate 汇率]
[fin_attachment 附件]（多态：biz_type+biz_id）
[fin_idempotency_record 幂等记录]（幂等键）
```

## 6. 约束与 RLS

### 6.1 约束清单

| 表 | 约束 | 说明 |
|---|---|---|
| fin_voucher | CHECK (total_debit = total_credit) | 借贷平衡 |
| fin_voucher_entry | CHECK (amount > 0) | 金额为正 |
| fin_voucher_entry | CHECK (direction IN ('DEBIT','CREDIT')) | 方向枚举 |
| fin_depreciation_schedule | UNIQUE (asset_id, period_code) | 单期单次计提 |
| fin_expense_claim | CHECK (total_amount >= 0) | 非负 |
| fin_budget | CHECK (occupied_amount + executed_amount <= budget_amount) | 预算不超（STRICT） |
| fin_carbon_emission | CHECK (emission_amount >= 0) | 非负 |
| 全局 | 外键 `REFERENCES` 均带 `tenant_id` 复合约束 | 防跨租户引用 |

### 6.2 RLS 策略（每张业务表统一启用）

```sql
-- 以 fin_voucher 为例，所有 fin_* 业务表采用同一模式
ALTER TABLE fin_voucher ENABLE ROW LEVEL SECURITY;

CREATE POLICY p_fin_voucher_tenant ON fin_voucher
  USING (
    tenant_id = current_setting('fl.tenant_id')::bigint
    AND deleted = 0
  )
  WITH CHECK (
    tenant_id = current_setting('fl.tenant_id')::bigint
  );

-- 应用连接在事务开始执行：
-- SET LOCAL fl.tenant_id = :tenantId;
-- 平台运营端跨租户查询使用专用角色 fl_platform（BYPASSRLS）并强制审计。
```

### 6.3 数据权限（行级业务）

- 数据权限（本人/本部门/本部门及下级/指定部门/全部）在应用层通过 MyBatis 拦截器注入 `dept_id IN (...)` 或 `created_by = ...` 条件，叠加在 RLS 之上。
- 字段权限（如银行账号、身份证）按角色返回脱敏或 null。

## 7. 敏感字段加密

| 表 | 明文列（不落库） | 加密列 | 哈希列 | 展示 |
|---|---|---|---|---|
| fin_bank_account | — | `account_no_enc`（AES-256-GCM） | `account_no_hash`（SHA-256+租户盐） | 尾 4 位 `**** **** 8888` |
| fin_ledger | — | `tax_no_enc` | `tax_no_hash` | 前 4 后 2 掩码 |
| fin_employee(PII，若冗余) | — | `mobile_enc`、`id_card_enc` | `mobile_hash`、`id_card_hash` | `138****8888`、`110***********1234` |

实现：

- 加密/解密通过自定义 MyBatis `TypeHandler` 透明完成，业务代码不感知。
- 唯一性与检索一律基于 `{field}_hash`，明文列不建索引。
- 密钥由 KMS 管理，轮换周期 ≤ 90 天；历史密钥保留以支持解密。
- 数据库启用 TDE 透明加密；备份文件加密存储。
