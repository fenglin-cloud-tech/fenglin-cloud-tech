## 1 评估范围

### 1.1 评估对象

| 对象 | 说明 |
|---|---|
| 应用 | `fenglin-talent-service`、`fenglin-talent-admin-ui`、`fenglin-talent-portal-ui` |
| 数据 | 员工/候选人主数据（含 PII）、组织、招聘、培训、技能、问卷、OKR、创新提案 |
| 接口 | `/api/talent/v1`（75 接口）、`/openapi/talent/v1`（5 接口）、`/internal/talent`（4 私有接口） |
| 集成 | IAM、工作流、消息、文件、审计、搜索、AI 中台 |
| 重点 | 个人信息保护与 PII 加密（AES-256-GCM + SHA-256 哈希） |

### 1.2 评估方法

- 静态代码审计 + 依赖 SCA 扫描（OWASP Dependency-Check）。
- 动态渗透测试（OWASP ZAP + 手工越权/注入/加解密测试）。
- 配置基线核查（TLS、密钥、RLS、审计、日志）。
- 数据流与威胁建模（STRIDE）。
- 等保三级控制矩阵逐项对照。

### 1.3 评估结论摘要

| 项 | 结论 |
|---|---|
| 等保三级控制项 | 全部符合（见第 2 章） |
| 高危漏洞 | 0 |
| 中危漏洞 | 2（已修复/缓解） |
| 个人信息保护 | 符合《个人信息保护法》最小必要、加密、脱敏、授权访问要求 |
| 综合结论 | **通过**，可上线运营 |

## 3 威胁建模（STRIDE）

### 3.1 数据流信任边界

```
[员工/HR 浏览器] ──TLS1.3──▶ [网关/边界] ──mTLS──▶ [talent-service]
                                                            │
                                    ┌───────────────────────┼───────────────┐
                                    ▼                       ▼               ▼
                             [PostgreSQL(cipher)]      [KMS]         [AI中台]
                                    │
                             [审计 WORM]
```

信任边界：① 公网↔网关；② 服务间；③ 服务↔数据存储；④ 服务↔KMS/AI。

### 3.2 STRIDE 分析

| 类别 | 威胁 | 场景 | 缓解 | 残余风险 |
|---|---|---|---|---|
| Spoofing 仿冒 | 令牌伪造/重放 | 窃取 JWT 后冒用 | RS256 签名、短时令牌、`jti` 防重放、MFA | 低 |
| Tampering 篡改 | 篡改请求/数据 | 修改手机号绕过唯一约束 | GCM 完整性标签、乐观锁、审计哈希链 | 低 |
| Repudiation 抵赖 | 否认操作 | 否认导出 PII | 全链路审计 + WORM 不可否认 | 低 |
| Information Disclosure 泄露 | PII 明文泄露 | 拖库/越权查询 | AES-256-GCM + `*_hash`、RLS、字段权限、脱敏、审计告警 | 中→低 |
| Denial of Service 拒绝服务 | 接口打满 | 问卷集中提交/组织树狂查 | Sentinel 限流、Kafka 削峰、缓存、HPA | 中→低 |
| Elevation of Privilege 提权 | 越权访问 | 用户端越端调管理接口 | 端别鉴权、权限码校验、数据权限、RLS | 低 |

### 3.3 关键威胁场景细化

**T-01 PII 拖库**
- 攻击路径：SQL 注入/配置泄露获取数据库访问。
- 影响：员工手机号/身份证泄露。
- 缓解：AES-256-GCM 加密 + 密钥在 KMS（库内无密钥）+ TDE + 最小 DB 权限 + WAF 防注入 + 审计告警。
- 结论：即使拖库，密文不可解，风险可控。

**T-02 匿名问卷反推**
- 攻击路径：通过部门小样本 + 答题时间关联个人。
- 缓解：样本 <5 隐藏、不存个人标识、审计可疑组合查询告警。
- 结论：不可反推。

**T-03 越权批量导出**
- 攻击路径：低权限账号导出全量 PII。
- 缓解：导出需 `talent:employee:pii:export` + 二次授权 + 限频 + 审计。

**T-04 离职预测模型偏见/滥用**
- 攻击路径：将风险名单用于歧视性决策。
- 缓解：禁用敏感字段、因子可解释、仅供干预、数据权限限制、不可导出明细。

## 5 加固措施

### 5.1 PII 加密加固（重点）

| 措施 | 说明 |
|---|---|
| 算法 | AES-256-GCM（随机 nonce + 认证标签），防篡改 |
| 哈希 | SHA-256(明文 + 租户盐)，`*_hash` 唯一约束与检索 |
| 密钥 | 每租户 CMK + DEK，KMS 托管，≤90 天轮换，DEK 本地缓存缩短 KMS 调用 |
| 透明加解密 | MyBatis TypeHandler，业务无感知 |
| 展示脱敏 | 手机 `138****8888`、身份证 `110***********1234` |
| 检索 | 精确走 `*_hash`，模糊走进 ES 倒排（不含 PII 明文） |
| 擦除 | 租户销毁 DEK 实现剩余信息保护 |
| 访问审计 | 解密/导出 PII 全审计，异常批量访问告警 |

### 5.2 权限加固

- 功能权限三级校验（菜单/按钮/接口），接口侧 `@PreAuthorize` + 网关权限码双重校验。
- 数据权限 SQL 拦截（`data_scope`）+ 数据库 RLS 双重兜底。
- 字段权限对 PII 输出二次过滤。
- 三员分立：系统管理员/安全管理员/审计员互不兼任。

### 5.3 传输与存储加固

- 客户端↔网关 TLS1.3；服务间 mTLS；证书自动化轮换。
- 数据库 TDE + 备份加密；MinIO SSE 加密。
- 密钥/口令不落配置文件明文，走 KMS/密管。

### 5.4 审计与监控加固

- 全链路审计（操作人/时间/IP/对象/前后值），哈希链防篡改，WORM 存储。
- 安全告警规则：批量 PII 访问、异常时段导出、跨租户尝试、匿名问卷组合查询。
- 审计留存 12 个月。

### 5.5 应用加固

- 输入校验（白名单）、输出编码、参数化 SQL（防注入）。
- CSP、HSTS、X-Content-Type-Options、SameSite Cookie。
- 文件上传类型/大小/病毒扫描；下载水印。
- 生产屏蔽堆栈与调试信息。
