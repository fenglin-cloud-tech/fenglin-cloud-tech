## 1.5 状态机

### 1.5.1 招聘需求状态机（`talent_recruit_requisition.req_status`）

```
DRAFT ──提交──▶ APPROVING ──通过──▶ RECRUITING ──暂停──▶ PAUSED
   ▲               │                    │  ▲              │
   │            驳回│                    │  └──恢复────────┘
   └───────────────┘                 完成│
                                        ▼
                                      DONE ──关闭──▶ CLOSED
```

| 当前状态 | 事件 | 目标状态 | 校验 |
|---|---|---|---|
| DRAFT | 提交 | APPROVING | 编制充足、必填完整 |
| APPROVING | 审批通过 | RECRUITING | 工作流回调 |
| APPROVING | 审批驳回 | DRAFT | — |
| RECRUITING | 暂停 | PAUSED | — |
| PAUSED | 恢复 | RECRUITING | — |
| RECRUITING | 招满/关闭 | DONE | 在招人数=0 或人工关闭 |
| DONE | 归档 | CLOSED | — |

### 1.5.2 员工状态机（`emp_status`）

```
PENDING ──入职──▶ PROBATION ──转正──▶ ACTIVE ──离职──▶ RESIGNED
                     │                   │
                  不通过                  │
                     ▼                   │
                  RESIGNED ◀─────────────┘
```

### 1.5.3 异动状态机（`tf_status`）

```
APPROVING ──通过──▶ EFFECTIVE
     │
  驳回/撤回──▶ CANCELED
```

## 1.6 工作流（BPMN 说明）

### 1.6.1 招聘需求审批流程（`recruitRequisitionApproval`）

BPMN 节点序列：

```
StartEvent(提交)
 → UserTask(部门负责人审批) [assignee=org.leader]
 → ExclusiveGateway(是否超编制?)
     ├─ 是 → UserTask(HRD 特批)
     └─ 否 → 直连
 → UserTask(HR 复核) [candidateGroup=HR]
 → ServiceTask(更新 req_status=RECRUITING)
 → ServiceTask(发送事件 talent.recruit.approved)
 → EndEvent
```

- 驳回路径从任一 UserTask 回退至 StartEvent 并置 `DRAFT`。
- 超时策略：48h 未审批自动催办（消息中台），7 天自动驳回。
- 幂等：工作流回调携带 `taskId`，业务侧以 `(requisitionId, taskId)` 去重。

### 1.6.2 入转调离流程（`employeeLifecycle`）

```
[入职] StartEvent(offer.accepted)
  → ServiceTask(创建 employee: PENDING)
  → UserTask(入职办理/清单勾选) → ServiceTask(PROBATION)
[转正] TimerEvent(试用期到期-7d)
  → UserTask(直属上级评估) → UserTask(HR 确认)
      ├─ 通过 → ServiceTask(ACTIVE, formal_date=today)
      ├─ 延长 → 重设 end_date（≤ +3 月）
      └─ 不通过 → 转离职流程
[异动] UserTask(现部门/目标部门/HR 会签) → ServiceTask(apply before/after snapshot)
[离职] StartEvent(离职申请)
  → UserTask(直属上级确认) → UserTask(HR 审批) → UserTask(工作交接)
  → ServiceTask(停用 IAM 账号 + 事件 talent.employee.resigned) → EndEvent
```

## 1.9 与标杆产品差异点（对比用友大易）

| 差异点 | 说明 |
|---|---|
| 全域一体化 | 大易侧重招聘 ATS；云才 C1 招聘与 C3 活水、C4 离职预测、C5 OKR 原生打通，招聘候选人命中在职员工即触发内推与回流分析 |
