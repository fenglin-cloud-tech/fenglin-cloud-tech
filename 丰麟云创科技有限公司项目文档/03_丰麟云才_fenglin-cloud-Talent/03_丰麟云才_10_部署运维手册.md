## 2 部署拓扑

```
                  Internet
                     │ TLS1.3
             ┌───────▼────────┐
             │  WAF + LB(DNS)  │
             └───────┬────────┘
                     │
        ┌────────────▼────────────┐
        │     fenglin-gateway      │  (独立命名空间, 3 副本)
        └────────────┬────────────┘
                     │
     ┌───────────────┼───────────────────┐
     ▼               ▼                   ▼
┌──────────┐  ┌──────────────┐   ┌──────────────┐
│admin-ui  │  │ portal-ui    │   │ talent-service│
│ (CDN)    │  │  (CDN)       │   │  (4-8 副本)   │
└──────────┘  └──────────────┘   └───────┬───────┘
                                          │
        ┌─────────────────────────────────┼───────────────────────┐
        ▼                ▼                ▼           ▼           ▼
   PostgreSQL        Redis            Kafka        ES          MinIO
   (主从双活)      (哨兵集群)      (3 broker)   (3 节点)   (4 节点分布式)
        │
   [XXL-Job 调度中心]  [Prometheus/Grafana/Loki/SkyWalking]
```

- 前端静态资源经 CDN 分发，回源对象存储。
- 业务服务无状态，滚动更新；Job 执行器独立部署避免影响在线服务。

## 4 部署步骤

### 4.1 前置准备

```bash
# 1. 创建命名空间
kubectl create namespace fenglin-talent

# 2. 创建镜像拉取密钥与 KMS 凭证 Secret
kubectl -n fenglin-talent create secret docker-registry fl-registry \
  --docker-server=harbor.fenglincloud.com --docker-username=... --docker-password=...

# 3. Nacos 导入配置
#    fenglin-talent-prod.yaml、application-prod.yaml
```

### 4.2 数据库迁移（Flyway）

```bash
# 迁移由应用启动时自动执行（flyway.enabled=true）
# 或独立执行：
java -jar talent-migrate.jar \
  --spring.profiles.active=prod \
  --flyway.locations=classpath:db/migration
# 脚本清单见《数据库设计文档》第 8 章
```

### 4.3 部署业务服务

```yaml
# talent-service-deploy.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: fenglin-talent-service
  namespace: fenglin-talent
spec:
  replicas: 4
  strategy:
    type: RollingUpdate
    rollingUpdate: { maxSurge: 1, maxUnavailable: 0 }
  template:
    spec:
      containers:
        - name: app
          image: harbor.fenglincloud.com/fenglin/fenglin-talent-service:1.0.0
          env:
            - name: SPRING_PROFILES_ACTIVE
              value: prod
          readinessProbe:
            httpGet: { path: /internal/talent/health, port: 8080 }
            initialDelaySeconds: 30
          resources:
            requests: { cpu: "2", memory: "4Gi" }
            limits: { cpu: "4", memory: "8Gi" }
```

```bash
kubectl apply -f talent-service-deploy.yaml
kubectl -n fenglin-talent rollout status deploy/fenglin-talent-service
```

### 4.4 部署前端与任务

```bash
# 前端构建产物上传 CDN + 对象存储
npm run build -- --mode prod && fl-cdn deploy dist/ /admin/talent/
npm run build -- --mode prod && fl-cdn deploy dist/ /app/talent/

# 任务执行器
kubectl apply -f talent-job-deploy.yaml
```

### 4.5 ArgoCD GitOps 自动同步

- 应用清单纳入 Git，ArgoCD 监听 `main` 分支自动/手动同步到 `prod`。

## 6 灰度与回滚

### 6.1 灰度策略

| 阶段 | 范围 | 观察指标 | 时长 |
|---|---|---|---|
| 金丝雀 | 1 副本 / 内部员工 | 错误率、P95 | 30min |
| 小流量 | 10% 租户 | 错误率、P95、业务指标 | 2h |
| 半量 | 50% 租户 | 同上 | 4h |
| 全量 | 100% | 同上 | — |

- 网关按 `X-Tenant-Id` 哈希路由，兼容数据库向后兼容（先加列后用、后删列）。

### 6.2 回滚

```bash
# 应用回滚
kubectl -n fenglin-talent rollout undo deploy/fenglin-talent-service

# 或 ArgoCD 回退到上一 Revision
argocd app rollback fenglin-talent

# 数据库回滚（如涉及 DDL）：执行对应 undo 脚本或前向修复脚本
# Flyway 采用前向修复（forward-only）；破坏性变更需发布前评审
```

回滚触发条件：错误率 > 0.5% 持续 5min，或 P95 > 500ms 持续 5min，或核心流程阻断。

## 7 监控告警

### 7.1 监控指标

| 层次 | 指标 |
|---|---|
| 应用 | QPS、RT(P95/P99)、错误率、JVM(GC/堆)、线程池 |
| 业务 | 问卷提交速率、离职评分批处理耗时、活水申请数、OKR 更新数 |
| 中间件 | PG 慢查询/连接数、Redis 命中率、Kafka 积压、ES 检索延迟 |
| 主机 | CPU/内存/磁盘/网络 |

### 7.2 告警规则

| 规则 | 阈值 | 级别 | 通知 |
|---|---|---|---|
| 错误率 | > 1% 持续 5min | P1 | 电话+IM |
| P95 | > 300ms 持续 5min | P2 | IM |
| 服务不可用 | 探针失败 3 次 | P1 | 电话+IM |
| DB 连接池 | > 85% | P2 | IM |
| Kafka 积压 | > 10 万 | P2 | IM |
| 离职预测失败 | 批处理失败 | P3 | IM |
| 密钥轮换到期 | ≤ 7 天 | P2 | IM |

- 工具链：Prometheus + Alertmanager + Grafana；日志 Loki；链路 SkyWalking。

## 8 备份恢复

| 对象 | 策略 | 频率 | 保留 |
|---|---|---|---|
| PostgreSQL 全备 | pg_basebackup | 每日 01:00 | 30 天 |
| PostgreSQL 增量 | WAL 归档 | 实时 | 7 天 |
| 异地容灾 | 备份复制到异地 | 每日 | 30 天 |
| Redis | RDB+AOF | 每小时 | 7 天 |
| MinIO | 跨站点复制 | 实时 | 按策略 |
| 配置(Nacos/Git) | Git 版本化 | 变更即存 | 永久 |

### 8.1 恢复流程

```bash
# 1. 停止写入（切换只读/摘流量）
# 2. 恢复基础备份
pg_restore -h pg -U postgres -d fenglin_talent base.dump
# 3. 重放 WAL 至目标时间点（PITR）
recovery_target_time = '2026-10-19 02:00:00+08'
# 4. 校验数据完整性，恢复流量
```

- 目标：RPO ≤ 5min、RTO ≤ 30min；季度演练。

## 9 巡检与应急预案

### 9.1 日常巡检（每日）

| 项 | 内容 |
|---|---|
| 服务 | 副本数、探针、错误率、P95 |
| 数据库 | 连接数、慢查询、主从延迟、磁盘 |
| 中间件 | Redis 命中、Kafka 积压、ES 健康 |
| 批处理 | 离职预测是否完成、问卷提醒是否执行 |
| 安全 | 异常审计告警、密钥轮换剩余天数 |

### 9.2 应急预案

| 场景 | 处置 |
|---|---|
| 服务不可用 | 检查探针/日志→重启副本/回滚→扩容 |
| 数据库主库故障 | Patroni 自动切主→校验从库→业务重连 |
| Redis 故障 | 哨兵切主；缓存降级直查 DB（限流） |
| Kafka 积压 | 增分区/消费者副本；问卷提交降级同步 |
| AI 服务不可用 | 匹配降级规则、预测降级统计基线 |
| ES 故障 | 检索降级 DB 模糊查询（限流） |
| PII 泄露告警 | 立即冻结相关账号、留存证据、按事件上报流程处置 |
| 灰度异常 | 触发回滚（见第 6 章） |

### 9.3 应急联系人（角色）

| 角色 | 职责 |
|---|---|
| 值班运维 | 一线响应、初步处置 |
| DBA | 数据库故障 |
| 安全负责人 | 安全事件 |
| 产品负责人 | 业务决策 |
