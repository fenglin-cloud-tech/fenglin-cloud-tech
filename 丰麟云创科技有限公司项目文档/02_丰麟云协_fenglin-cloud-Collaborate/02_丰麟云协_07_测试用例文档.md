## 1. 测试范围与策略

### 1.1 测试范围

| 层次 | 范围 | 说明 |
|---|---|---|
| 功能测试 | B1 内部协作与办公（IM/文档/日历/会议/OKR/审批/工作台）、B2 会议效率与 ONA | 覆盖 50 条 FR 的正向与异常路径 |
| 接口测试 | `/api/collab/v1` 全部核心接口 | 参数校验、鉴权、幂等、错误码、分页 |
| 权限测试 | 用户端 PORTAL / 管理端 ADMIN、RBAC + 数据权限、租户隔离 | 越权拦截（2000002）、端别路由（401/403） |
| 并发测试 | IM 高并发、文档协同冲突、会议室预定并发 | 数据一致性、幂等、乐观锁 |
| 兼容测试 | Chrome/Edge/Firefox/Safari、PWA、移动端 Web | 见 1.3 |
| 异常/边界 | 超大消息、超长文档、跨天日程、循环会议、审批驳回/加签 | 边界值与容错 |
| 非功能（引用） | 性能（FL-COLLAB-PERF-001）、安全（FL-COLLAB-SEC-001） | 本文件仅列接口层用例 |

### 1.2 测试策略

- 分层策略：单元测试（覆盖率 ≥ 70%）→ 接口/集成测试（Testcontainers：PostgreSQL 15 + Redis 7 + Kafka 3.6）→ 端到端 UI 测试（Playwright）→ 性能与安全专项。
- 数据隔离：每个用例使用独立租户前缀（`tc_`）造数，用例结束软删除，保证租户隔离约束（`phone_hash` 等）不受污染。
- 环境：测试环境 `collab.test.fenglincloud.com`，命名空间 `fenglin-collab-test`。
- 通过准则：一级/二级用例 100% 通过；三级用例 ≥ 95% 通过；无遗留 S1/S2 缺陷。

## 5. 缺陷分级

| 级别 | 名称 | 定义 | 响应时限 | 修复时限 |
|---|---|---|---|---|
| S1 | 致命 | 服务不可用、数据丢失/串租户、核心链路阻断、安全漏洞可被利用 | 立即（≤30min） | ≤8h（含热修） |
| S2 | 严重 | 主要功能不可用、并发下数据不一致、性能严重不达标（P95 > 目标 2 倍） | ≤2h | ≤24h |
| S3 | 一般 | 次要功能缺陷、边界处理不当、体验问题、非核心页面错误 | ≤1 工作日 | ≤3 工作日 |
| S4 | 轻微 | 文案/样式/提示不一致、不影响功能 | ≤2 工作日 | 下个迭代 |

缺陷状态流转：`新建 → 确认 → 修复中 → 待验证 → 关闭`（`拒绝/延期` 为分支状态）。

缺陷记录要素：编号（`BUG-COLLAB-{序号}`）、标题、级别、模块、关联用例、复现步骤、期望/实际、环境、`requestId`、日志片段、附件。
