## 1. 目标与指标

### 1.1 业务背景

丰麟云协服务于丰麟云创集团 3400 人规模的组织协作，覆盖 IM、协同文档、日历、会议与会议室、OKR、审批、工作台、ONA 八大能力。核心负载特征为：IM 消息高频写入与广播、协同文档长连接与增量合并、会议室预定短时并发争抢、工作台聚合读多写少。

### 1.2 性能指标（对齐平台基线）

| 类别 | 指标 | 目标值 | 来源 |
|---|---|---|---|
| 服务可用性 | 年度可用性 | ≥ 99.99%（年不可用 ≤ 52.6 分钟） | 平台基线 |
| 并发规模 | 同时在线用户 | 3400 人 | 平台基线 |
| 吞吐 | 核心接口峰值 QPS | ≥ 1200 QPS | 平台基线 |
| 吞吐 | IM 消息吞吐 | ≥ 20000 msg/s | 云协 SRS |
| 响应 | 核心接口 P95 | ≤ 300ms | 平台基线 |
| 响应 | 核心接口 P99 | ≤ 800ms | 平台基线 |
| 响应 | IM 消息端到端延迟 P95 | ≤ 500ms | 云协 SRS |
| 响应 | 文档协同输入延迟 P95 | ≤ 200ms | 云协 SRS |
| 稳定性 | 单接口错误率 | ≤ 0.1% | 平台基线 |
| 并发 | 单文档协同人数 | ≥ 50 人 | 云协 SRS |
| 前端 | 页面首屏（4G / 内网） | ≤ 2s / ≤ 1s | 平台基线 |
| 容灾 | RPO / RTO | ≤ 5min / ≤ 30min | 平台基线 |

### 1.3 通过准则

全部目标指标达成；长稳压测（2 小时）期间 P95 波动 ≤ 15%，无内存泄漏（堆占用净增长 ≤ 5%），错误率 ≤ 0.1%，GC 停顿 P99 ≤ 100ms。

## 3. 场景设计

### 3.1 场景总览

| 场景编号 | 场景名称 | 模型 | 目标 |
|---|---|---|---|
| S1 | 登录与工作台 | 3400 人在线，30% 并发操作 | 验证登录与工作台聚合读 |
| S2 | IM 消息收发 | 2000 用户持续发消息，目标 20000 msg/s | 验证 IM 吞吐与延迟 |
| S3 | 文档协同编辑 | 50 人/文档 × 40 文档 | 验证协同同步与合并 |
| S4 | 会议室预定并发争抢 | 500 用户争抢 20 会议室 × 8 时段 | 验证并发锁与幂等 |
| S5 | 审批流转 | 300 用户并发发起/办理 | 验证工作流引擎吞吐 |
| S6 | 消息/文档搜索 | 500 并发检索 | 验证 ES 检索 |
| S7 | 混合业务峰值 | 3400 在线，混合 S1~S6 | 验证峰值 QPS ≥ 1200 |
| S8 | 长稳定性 | S7 的 60% 负载，持续 2 小时 | 验证稳定性与资源基线 |
| S9 | 前端首屏 | 4G 网络模拟 | 验证首屏 ≤ 2s |

### 3.2 关键场景脚本设计

- **S2 阶梯加压**：1000→2000→3000→4000 并发发送用户，每级 3 分钟，逐步逼近 20000 msg/s，记录拐点。
- **S3 协同模型**：每文档 50 客户端，操作分布=插入 70% / 删除 20% / 格式 10%，平均操作间隔 2s；长连接保持 5 分钟。
- **S4 争抢模型**：使用同步栅栏（barrier）使 500 请求在同一毫秒释放，制造真实并发冲突；校验成功数（≤20×8=160）与冲突返回（2006005）。
- **S7 混合比例**：IM 45%、文档 20%、工作台 15%、日历/会议室 10%、审批 5%、搜索 5%。

## 4. 结果与图表

### 4.1 场景结果汇总

| 场景 | 并发/规模 | 吞吐 | P95 | P99 | 错误率 | 结论 |
|---|---|---|---|---|---|---|
| S1 登录与工作台 | 3400 在线 | 1,860 QPS | 212ms | 486ms | 0.02% | 达标 |
| S2 IM 消息 | 2000 发送者 | 23,400 msg/s | 268ms | 712ms | 0.03% | 达标 |
| S3 文档协同 | 40 文档 × 50 人 | 4,100 ops/s | 156ms | 402ms | 0.01% | 达标 |
| S4 会议室争抢 | 500 并发 | 500 req/s | 96ms | 238ms | 0.00%（冲突为业务拒绝） | 达标 |
| S5 审批流转 | 300 并发 | 840 QPS | 246ms | 655ms | 0.04% | 达标 |
| S6 搜索 | 500 并发 | 1,120 QPS | 288ms | 764ms | 0.05% | 达标 |
| S7 混合峰值 | 3400 在线 | 2,760 QPS | 274ms | 788ms | 0.06% | 达标 |
| S8 长稳定（2h） | 60% 负载 | 1,650 QPS | 231ms | 598ms | 0.02% | 达标 |
| S9 前端首屏 | 4G 模拟 | — | 1.62s | 2.10s | 0% | 达标（内网 0.8s） |

### 4.2 S2 IM 阶梯加压曲线（文字化）

```
吞吐(msg/s)
24000 ┤                                  ●─────●  (23400)
20000 ┤                        ●─────●
16000 ┤              ●─────●
12000 ┤     ●─────●
 8000 ┤ ●──●
      └──┬────┬────┬────┬────┬────┬──►  发送并发
       1000 1500 2000 2500 3000 3500
P95(ms) 118  156  198  232  268  341
P99(ms) 320  402  498  566  712  980 ↑
```

拐点分析：并发发送用户超过 2500 后 P99 上升加快（712ms→980ms），但 2000 用户档位（对应 23400 msg/s）稳定满足 P95/P99 目标，吞吐能力具备 17% 余量。

## 5. 瓶颈分析

| 序号 | 瓶颈现象 | 定位 | 根因 |
|---|---|---|---|
| B1 | S2 高并发时 P99 抬升（980ms@3500 并发） | Kafka 单分区消费滞后 + WebSocket 广播线程池饱和 | 消息广播串行度高，分区数不足（16 分区） |
| B2 | S7 混合场景 PostgreSQL 主库 CPU 74% | 工作台聚合 SQL（多表 JOIN + 未读计数） | 未读计数实时聚合查询频繁 |
| B3 | S6 搜索 P95 288ms | ES deep paging + IK 分词高亮开销 | 分页与高亮在大结果集上开销大 |
| B4 | S3 快照合并偶发毛刺（P99 402ms） | 大文档（>10 万字）全量快照序列化 | 快照体量大，序列化阻塞 |
| B5 | 前端首屏 P99 2.10s（4G） | 首屏 JS 包体积（1.9MB gzip 后 680KB） | 未充分路由级懒加载 |

## 6. 调优措施

| 序号 | 措施 | 对应瓶颈 | 效果 |
|---|---|---|---|
| M1 | Kafka `collab.message` 主题分区 16→48；广播线程池 32→64，改批量广播（每 50ms 合批） | B1 | P99 由 980ms 降至 712ms，吞吐提升至 23400 msg/s |
| M2 | 未读计数改 Redis 增量维护，工作台聚合走 CQRS 读模型（物化视图 + 5s 缓存） | B2 | 主库 CPU 由 74% 降至 58%，聚合 P95 212ms |
| M3 | 搜索限制 deep paging（search_after），高亮按需开启 | B3 | 搜索 P95 由 288ms 降至 196ms |
| M4 | 文档快照改增量 CRDT 差分 + 快照分片压缩（zstd）；超 5 万字启用异步快照 | B4 | 合并 P99 由 402ms 降至 210ms |
| M5 | 前端路由级懒加载 + 依赖分包 + CDN 预取；首屏关键 CSS 内联 | B5 | 首屏 P95 由 2.10s 降至 1.62s，内网 0.8s |
| M6 | 网关接入层启用 HTTP/2 + 连接复用；Sentinel 热点参数限流（会话维度） | 综合 | 峰值 QPS 提升至 2760，连接数下降 34% |
| M7 | PostgreSQL 热点表分区（message 按月）+ 索引优化（覆盖索引） | B2 | IOPS 由 42000 降至 31000 |
| M8 | JVM 参数调优：G1、`MaxGCPauseMillis=100`、堆 8G | 综合 | GC 停顿 P99 86ms |

## 7. 结论与容量建议

### 7.1 结论

| 目标指标 | 目标值 | 实测值（峰值场景 S7） | 结论 |
|---|---|---|---|
| 同时在线 | 3400 人 | 承载 3400 人（S1/S7） | 达标 |
| 核心接口峰值 QPS | ≥ 1200 | 2,760 | 达标（余量 130%） |
| P95 | ≤ 300ms | 274ms | 达标 |
| P99 | ≤ 800ms | 788ms | 达标 |
| IM 吞吐 | ≥ 20000 msg/s | 23,400 msg/s | 达标（余量 17%） |
| 消息端到端 P95 | ≤ 500ms | 268ms | 达标 |
| 文档协同输入 P95 | ≤ 200ms | 156ms | 达标 |
| 单文档协同人数 | ≥ 50 人 | 50 人稳定 | 达标 |
| 错误率 | ≤ 0.1% | 0.06% | 达标 |
| 可用性 | 99.99% | 99.995%（含故障演练） | 达标 |
| 首屏（4G/内网） | ≤ 2s / ≤ 1s | 1.62s / 0.8s | 达标 |

**综合结论：丰麟云协 V1.0.0 全部性能指标达成，具备 3400 人在线、峰值 2760 QPS、IM 23400 msg/s 的承载能力，满足上线条件。**

### 7.2 容量建议

| 项目 | 单副本承载 | 建议副本（生产） | 弹性策略 |
|---|---|---|---|
| `collab-service` | ~1000 QPS | 4（常态）/ 12（峰值） | HPA：CPU>65% 或 QPS>800/副本扩容 |
| `fenglin-gateway` | ~1200 QPS | 3 / 6 | HPA |
| WebSocket 网关 | ~3000 长连接 | 4 / 8 | 按连接数与内存扩容 |
| PostgreSQL | 主库 ≤ 3000 TPS | 1 主 2 从 | 读写分离；写瓶颈时按月分区 + 分库 |
| Redis 集群 | 6 万 OPS/节点 | 3 主 3 从 | 水平扩分片 |
| Kafka | 单 Broker ~1.5GB/s | 3 / 6 | 按分区与吞吐扩容 |

### 7.3 风险与后续优化

1. IM 广播在 3500+ 并发发送者时 P99 接近上限，建议下一版本引入"读扩散按需拉取"降低广播放大。
2. 文档超大文档（>20 万字）协同尚需专项验证，建议纳入 V1.1 性能回归。
3. 长稳测试未覆盖跨月数据增长（消息分月分区），建议季度性全量数据压测。
