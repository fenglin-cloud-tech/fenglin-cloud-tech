## 1 引言

### 1.1 目的

本文档定义**丰麟云智（Fenglin Cloud Intelligence）**的产品需求基线，是丰麟云创科技有限公司面向中大型企业客户交付"企业智能搜索与 AI 洞察平台"的需求依据。本文档用于：

1. 明确 H1（企业级知识搜索引擎）、H2（生成式 AI 助手 AI Copilot）、H3（商业智能与自动洞察）三大模块的功能与非功能需求边界；
2. 明确**独立产品模式（standalone）**与**能力嵌入模式（embedded）**双模式这一强制架构的产品级需求；
3. 作为架构设计、数据库设计、接口设计、UI/UX 设计、测试与验收的上游输入；
4. 作为与客户、平台架构组（FL-HUB-STD-001 归口）之间需求确认与变更控制的基线文件。

品牌口号：**搜得到、问得清、看得远的企业智能大脑**。

## 2 产品概述

### 2.1 产品定位

丰麟云智是丰麟云枢平台域H的核心产品，面向中大型企业（含丰麟云创自身 3400 人规模集团）提供"**搜得到、问得清、看得远**"的企业智能大脑：

1. **搜得到（H1）**：汇聚企业多源异构知识，构建统一索引与知识图谱，提供全文+向量混合、权限感知的企业级检索；
2. **问得清（H2）**：以 AI Copilot 承接自然语言问答、写作、总结、翻译与 Agent 自动化，答案可溯源、可信、合规；
3. **看得远（H3）**：以自助取数、指标体系、看板、自动洞察与归因分析，将数据转化为前瞻性经营洞察。

产品同时以**双模式**交付：作为独立 SaaS 售卖，或以智能中台形式为其余 7 款业务产品（云销/云协/云才/云财/云研/云服/云法）输出 AI、检索、BI 能力。

核心价值主张：

1. **统一知识底座**：一处索引、全域检索，打破知识孤岛；
2. **可信生成**：RAG 引用溯源 + 输出安全合规护栏；
3. **人人可用的 BI**：自然语言问数与自动洞察降低用数门槛；
4. **能力可复用**：以标准内部契约向全产品矩阵输出智能能力。

### 2.4 双模式架构概述

依据 FL-HUB-STD-001 第 13 章，本品以**同一套代码**支持两种交付模式，由部署配置 `intelligence.mode` 控制：

| 模式 | 配置值 | 对外暴露面 | 计费计量 | 门户 |
|---|---|---|---|---|
| 模式① 独立产品模式 | `standalone` | 面向前台用户的知识搜索/Copilot/BI 门户（`/app/intelligence`、`/admin/intelligence`）+ 开放 API | 按席位/调用量 | 独立门户 |
| 模式② 能力嵌入模式 | `embedded` | 仅内部能力契约（`/api/intelligence/v1/**` 内部化 + `/internal/**`） | 按能力调用计量计入宿主产品 | 无独立门户（宿主产品内嵌） |

## 3 业务需求（模块级功能需求）

> 编号规则：`{模块码}-FR-{3位序号}`。优先级：P0（必须）、P1（重要）、P2（一般）。端别：ADMIN（管理端）/PORTAL（用户端）/BOTH/SYS（系统内部）/INTERNAL（嵌入模式服务间）。

### 3.1 H1 企业级知识搜索引擎

模块定位：企业级多源知识统一索引、全文+向量混合检索、权限感知检索与知识图谱（参考标杆：滴普科技 DEEPEXI）。

| 编号 | 需求名称 | 优先级 | 需求描述 | 端别 | 关键权限码 |
|---|---|---|---|---|---|
| H1-FR-001 | 多源数据接入与连接器 | P0 | 支持知识源接入：本地文件（Word/PDF/Excel/PPT/TXT/MD）、对象存储（MinIO/S3）、企业网盘/云文档（飞书/企微/钉钉）、数据库（PostgreSQL/MySQL/Oracle）、HTTP/API、企业已有业务系统（云协文档等）；提供连接器配置、连通性测试、增量同步（全量+增量+CDC）。 | ADMIN | `tenant:ai:source:manage` |
| H1-FR-002 | 文档解析与智能分块 | P0 | 解析文档正文、标题层级、表格、图片 OCR；按语义/固定窗口/标题层级分块，支持分块大小与重叠参数；生成分块元数据（页码、章节、字符偏移）以支撑引用定位。 | SYS | `ai:document:parse` |
| H1-FR-003 | 嵌入与索引构建 | P0 | 对分块调用嵌入模型生成向量，写入向量库；同时对正文建立 ES 倒排索引（IK 分词）；索引任务支持并发度、优先级、失败重试与断点续传，状态可观测。 | SYS | `ai:index:build` |
| H1-FR-004 | 全文检索（关键词） | P0 | 基于 ES（IK 分词）的全文检索，支持布尔查询、短语、通配、字段限定、同义词、拼写纠错；返回高亮片段与命中字段。 | PORTAL | `ai:search:query` |
| H1-FR-005 | 向量语义检索 | P0 | 基于向量库的 KNN/ANN 语义检索，支持按知识库/标签/时间过滤；对 query 做改写与嵌入，返回 Top-K 相似分块及相似度。 | PORTAL | `ai:search:query` |
| H1-FR-006 | 混合检索与重排 | P0 | 全文与向量结果经 RRF/加权融合，再经交叉编码器（rerank）重排，输出统一排序；融合权重、Top-K、rerank 开关可配置。 | PORTAL | `ai:search:query` |
| H1-FR-007 | 权限感知检索（强制） | P0 | 检索结果必须按调用者数据权限（数据范围）与文档级 ACL（可见部门/角色/用户、密级）实时过滤，越权文档不计入召回与统计；支持密级（公开/内部/秘密/机密）分级。 | PORTAL/INTERNAL | `ai:search:secure` |
| H1-FR-008 | 检索结果高亮、预览与溯源 | P0 | 结果展示标题、摘要、来源、更新时间、高亮关键词；支持原文定位预览（分块→原文档页码/段落），并保留权限校验（预览同样受权限约束）。 | PORTAL | `ai:search:view` |
| H1-FR-009 | 知识图谱构建 | P1 | 从文档抽取实体（人/组织/产品/项目/术语）与关系，支持人工校准与规则模板；构建实体-关系图，支持增量更新与版本。 | ADMIN/SYS | `tenant:ai:kg:manage` |
| H1-FR-010 | 知识图谱检索与关联推荐 | P1 | 支持实体检索、关系路径查询、图谱可视化；检索结果侧栏推荐关联实体/文档，形成"以点带面"的知识发现。 | PORTAL | `ai:kg:query` |
| H1-FR-011 | 知识入库审核工作流 | P0 | 文档入库可配置审核（Flowable）：提交→审核→发布/驳回；审核通过后方可被检索；保留审核记录与版本；支持敏感文档强制审核。 | ADMIN | `tenant:ai:kb:review` |
| H1-FR-012 | 检索行为分析与热词 | P1 | 采集检索日志（query、命中、点击、无结果），生成热词、无结果词、零点击分析，支撑知识补全与搜索优化。 | ADMIN | `tenant:ai:search:analytics` |
| H1-FR-013 | 检索词建议与联想 | P2 | 输入时提供联想词、历史搜索、热门搜索、实体联想，提升检索效率。 | PORTAL | `ai:search:suggest` |

**H1 验收要点**：多源接入成功率 ≥ 99%；混合检索相关性优于单一检索（NDCG@10 提升 ≥ 8%）；越权检索 100% 被拦截；索引任务可观测、可重试。

### 3.2 H2 企业级生成式 AI 助手（AI Copilot）

模块定位：企业级生成式 AI 助手，覆盖对话、RAG 知识问答、写作/总结/翻译、Agent 编排与提示词管理（参考标杆：微软 Copilot）。

| 编号 | 需求名称 | 优先级 | 需求描述 | 端别 | 关键权限码 |
|---|---|---|---|---|---|
| H2-FR-001 | 多轮对话与上下文管理 | P0 | 提供流式（SSE）多轮对话，维护会话上下文（窗口裁剪/摘要压缩），支持新建/重命名/置顶/归档会话、@知识库、@文件、引用历史消息。 | PORTAL | `ai:chat:use` |
| H2-FR-002 | RAG 知识问答 | P0 | 基于 H1 混合检索的检索增强问答，先检索后生成；支持指定知识库范围、检索 Top-K、温度等参数；无命中时明确告知并给出建议。 | PORTAL | `ai:chat:rag` |
| H2-FR-003 | 引用溯源与可信标注 | P0 | 回答中标注引用来源（文档名+分块+定位链接），可点击跳转原文（受权限约束）；支持"仅依据知识库作答"与置信度提示。 | PORTAL | `ai:chat:cite` |
| H2-FR-004 | 写作助手 | P1 | 提供营销文案、邮件、公文、周报、OKR 等模板化写作，支持续写、改写、扩写、润色、语气调整与多版本对比。 | PORTAL | `ai:writing:use` |
| H2-FR-005 | 总结与摘要 | P1 | 对长文档/会话/会议纪要生成摘要（简明/详细/要点列表），支持分段摘要与关键结论提取。 | PORTAL | `ai:summarize:use` |

## 6 接口需求

1. 全部接口遵循 `/api/intelligence/v1` 前缀、RESTful 风格、统一响应体。
2. 统一请求头：`Authorization`、`X-Tenant-Id`、`X-Client-Type`（ADMIN/PORTAL）、`X-Request-Id`、`Idempotency-Key`（写操作）；流式接口（对话）使用 `text/event-stream`（SSE）。
3. 错误码域前缀 `80`，结构 `{域2}{模块2}{序号3}`：
   - 通用/校验：`8000001`–`8000999`
   - H1 检索：`8001xxx`；H2 Copilot：`8002xxx`；H3 BI：`8003xxx`；双模式/嵌入：`8004xxx`。
4. 分页：`page`（从 1 起）、`size`（默认 20，最大 200）。
5. **能力嵌入契约（强制）**：`embedded` 模式下内部能力接口以 `/internal/**` 提供，供其余 7 款产品以服务身份（mTLS + 服务令牌）调用，覆盖检索/RAG/写作/总结/翻译/Agent/取数/看板/洞察能力。
6. 开放 API：前缀 `/openapi/intelligence/v1`，提供知识检索、问答、洞察等开放能力与事件 Webhook。
7. 核心接口清单与逐接口定义详见 FL-AI-API-005《接口文档》（核心接口 ≥ 45 个）。

## 7 约束与假设

### 7.1 约束

1. 必须遵循 FL-HUB-STD-001 的命名体系、技术栈、接口/数据/权限/安全/UI 规范及第 13 章双模式规范；
2. 必须严格实现管理端（`/admin/intelligence`）与用户端（`/app/intelligence`）分离；
3. 必须严格实现双模式（`standalone`/`embedded`）且同一套代码；
4. 后端统一技术栈：Java 17 / Spring Boot 3.2.x / Spring Cloud 2023.0.x / MyBatis-Plus 3.5.x / PostgreSQL 15 / Redis 7 / Kafka 3.6 / Elasticsearch 8.x / Flowable 7 / XXL-Job 2.4.x；
5. 向量库选用 Milvus 2.4.x（SaaS）/ PgVector 0.7（私有化轻量），嵌入模型可插拔；
6. 前端统一 Vue 3.4 + TypeScript + Vite 5；管理端 Element Plus，用户端自研 Portal 组件；
7. 不得引入异构框架，确需引入须报平台架构组评审。

### 7.2 假设

1. 丰麟云枢中台（IAM/租户/消息/文件/审计/工作流/开放平台）可用并按契约提供能力；统一检索与 AI 能力中台（`fenglin-search-service`、`fenglin-ai-service`）与本品协同；
2. LLM 能力由外部供应商（公有云）或私有化/本地模型提供，均通过统一模型网关接入；
3. 数据源与知识源具备合法访问授权，遵守数据安全与个人信息保护法规；
4. 客户具备必要的浏览器、网络与（私有化场景）算力环境。
