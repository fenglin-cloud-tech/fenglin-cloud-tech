## 1 架构概览

### 1.1 定位与设计原则

丰麟云智是丰麟云枢域H的智能与洞察平台，采用**微服务 + 能力中台 + 双模式**架构。设计原则：

1. **能力中台化**：检索、AI、BI 三大能力以内聚服务实现，对外同时提供门户（standalone）与内部能力契约（embedded）；
2. **同一套代码双模式**：由配置 `intelligence.mode` 控制暴露面、鉴权与计费，业务代码与数据模型一致；
3. **权限贯穿**：检索、问答、问数、洞察全链路权限感知，遵循最小权限与租户边界；
4. **可插拔模型**：LLM 与嵌入模型通过模型网关抽象，供应商可替换；
5. **可观测与可降级**：模型/向量库/BI 引擎故障时按模式差异化降级。

## 2 分层与部署图

### 2.1 分层职责

| 层次 | 组件 | 职责 |
|---|---|---|
| 接入层 | 用户端 UI、管理端 UI、开放 API、宿主产品 | 交互、鉴权接入、能力调用 |
| 网关层 | `fenglin-gateway` | 统一鉴权、限流、路由、审计埋点、灰度、模式路由 |
| 应用层 | `fenglin-intelligence-service` | 检索域/Copilot 域/BI 域业务逻辑、双模式控制 |
| 中台复用 | 云枢中台服务 | IAM/租户/权限/消息/文件/审计/工作流/开放平台 |
| 数据层 | PG/Redis/ES/Milvus/Kafka/MinIO/CH | 结构化、缓存、倒排、向量、事件、对象、OLAP |
| AI 基础设施 | 模型网关后端 | LLM/Embedding/Rerank/OCR 推理能力 |

### 2.2 双模式部署视图（强制）

**模式① standalone 独立产品模式部署视图：**

```
                 Internet
                    │  HTTPS(TLS1.3)
        ┌───────────▼────────────┐
        │  CDN/WAF → fenglin-gateway│  暴露: /api/intelligence/v1/**、/app/**、/admin/**、/openapi/**
        └───────────┬────────────┘
                    │
     ┌──────────────┼───────────────────────────────┐
     ▼              ▼                               ▼
 用户端UI       管理端UI                    fenglin-intelligence-service
 /app/intelligence /admin/intelligence        (H1/H2/H3 全能力 + 独立计费/席位)
     │              │                               │
     └──────────────┴───────────────┬───────────────┘
                                     ▼
        PG(fenglin_intelligence) · Redis · ES · Milvus · Kafka · MinIO · ClickHouse
                                     │
                                     ▼
                     LLM/Embedding/Rerank（公有云或私有化）
```

**模式② embedded 能力嵌入模式部署视图：**

```
   云销 云协 云才 云财 云研 云服 云法（7 款宿主产品，各自门户）
        │  mTLS + 服务令牌（X-Caller-Product / X-Tenant-Id / X-On-Behalf-Of）
        ▼
   ┌────────────────────────────────────────────────────────────┐
   │ fenglin-gateway（内网）                                      │
   │   仅放行 /api/intelligence/v1/internal/** 与 /internal/**    │
   │   门户路由 /app/**、/admin/** 一律 404/403                    │
   └───────────────┬────────────────────────────────────────────┘
                   ▼
        fenglin-intelligence-service（intelligence.mode=embedded）
        能力授权(CapabilityGrant) → 检索/RAG/写作/总结/翻译/Agent/取数/看板/洞察
        计量(UsageMetering) → 计入宿主产品账单
                   │
                   ▼
        PG · Redis · ES · Milvus · Kafka · ClickHouse（可共享或多租户隔离）
```

**双模式部署差异对照：**

| 维度 | standalone | embedded |
|---|---|---|
| `intelligence.mode` | `standalone` | `embedded` |
| 暴露面 | 门户 + 全量 API + 开放 API | 仅 `/internal/**` + 内部化 `/api/intelligence/v1/**` |
| 门户路由 | 启用 `/app`、`/admin/intelligence` | 关闭（网关拦截） |
| 鉴权主体 | 终端用户（JWT）+ 应用 | 宿主服务身份（mTLS + 服务令牌 + 用户代理头） |
| 计费 | 席位/调用量独立计费 | 按能力调用计量计入宿主 |
| 数据库 | 独立库（SaaS 共享库共享模式 / 私有化独立库） | 可共享库 + `tenant_id`/`host_product` 隔离 |
| 知识库范围 | 独立租户知识库 | 可复用宿主知识库或独立知识库 |

### 2.3 服务内部模块划分

`fenglin-intelligence-service` 内部按限界上下文划分为：`search`（H1 检索域）、`copilot`（H2）、`bi`（H3）、`mode`（双模式与授权计量）、`common`（共享）。

## 4 关键流程时序

### 4.1 知识入库索引管线（ETL→分块→嵌入→索引）

```
管理端/连接器      intelligence-service      解析器     Embedding   向量库/ES   审核引擎
   │  提交文档          │                        │          │           │          │
   ├──────────────────►│ 1.创建 Document(待审核) │          │           │          │
   │                   ├──────────────────────────────────────────────────────────►│ 2.入库审核(Flowable)
   │                   │◄──────────────────────────────────────────────────────────┤ 3.审核通过
   │                   ├──►│ 4.解析(正文/表格/OCR)│          │           │          │
   │                   │◄──┤ 5.结构化文本         │          │           │          │
   │                   ├──►│ 6.智能分块(chunk)    │          │           │          │
   │                   │◄──┤ 7.分块列表           │          │           │          │
   │                   ├──────────────────────────────►│ 8.批量嵌入(向量)          │
   │                   │◄──────────────────────────────┤ 9.向量              │          │
   │                   ├──────────────────────────────────────────►│ 10.写向量集合      │
   │                   ├──────────────────────────────────────────►│ 11.写 ES 倒排索引  │
   │                   ├──────────────────────────────────────────►│ 12.KG 实体抽取(异步)
   │◄──────────────────┤ 13.索引完成(可检索)  │          │           │          │
```

**要点**：索引任务支持并发度、优先级、失败重试与断点续传；`ai_index_task` 记录状态机（PENDING→PARSING→CHUNKING→EMBEDDING→INDEXING→SUCCEEDED/FAILED）。

### 4.2 RAG 问答时序（权限感知）

```
用户端      gateway    intelligence-service  权限引擎   混合检索(ES+向量)  LLM网关   护栏
  │ 提问(PORTAL) │            │                  │             │            │       │
  ├────────────►│ 鉴权/端别   │                  │             │            │       │
  │             ├───────────►│ 1.输入护栏(注入/敏感词)──────────────────────────────►│
  │             │            │◄─2.放行/拦截 ────────────────────────────────────────┤
  │             │            ├────────────────►│ 3.计算数据权限范围(行列/ACL/密级)  │
  │             │            │◄───4.权限过滤器(Filter DSL)────────────────────────│
  │             │            ├────────────────────────────►│ 5.全文+向量召回
  │             │            │◄────────────────────────────┤ 6.RRF融合+Rerank Top-K
  │             │            ├─────────────────────────────────────────►│ 7.组装Prompt(含引用)
  │             │◄───────────┤ 8.流式生成(SSE)─────────────────────────┤ 8'.输出护栏/脱敏
  │◄──token 流──┤            │ 9.标注引用+落库(Message/SearchLog)        │
```

**要点**：权限过滤在**召回阶段**（ES filter + 向量库 filter）与**重排后复核**双重执行，确保越权文档既不计入召回也不可被预览。

### 4.3 BI 自动洞察与归因时序

```
调度(XXL-Job)  intelligence-service   语义层/数据集   OLAP(ClickHouse)   LLM   交付渠道
   │ 触发洞察任务   │                        │               │            │       │
   ├──────────────►│ 1.读取 InsightTask 配置 │               │            │       │
   │               ├───────────────────────►│ 2.解析指标/维度│            │       │
   │               ├───────────────────────────────────────►│ 3.聚合查询(权限过滤)
   │               │◄───────────────────────────────────────┤ 4.结果集
   │               ├─► 5.异动检测(同环比/突变/异常点)       │            │       │
   │               ├─► 6.归因分析(维度下钻+贡献度)          │            │       │
   │               ├─────────────────────────────────────────────────────►│ 7.生成洞察结论
   │               ├─────────────────────────────────────────────────────┤ 8.结论+建议
   │               ├─► 9.落库(InsightResult/AttributionAnalysis)
   │               ├──────────────────────────────────────────────────────────────►│ 10.订阅推送
```

### 4.4 Agent 执行时序

用户发起 → 编排引擎加载 Agent 定义（节点图）→ 顺序/分支执行（LLM 节点/检索节点/工具调用节点/条件节点/人工确认节点）→ 每步记录 `ai_agent_execution` → 支持中断/暂停/续跑 → 完成回传结果。工具调用通过服务令牌访问 `/internal/**` 或开放 API。

## 5 数据架构

### 5.1 存储分工

| 存储 | 承载数据 | 说明 |
|---|---|---|
| PostgreSQL `fenglin_intelligence` | 所有 `ai_*` 业务表 | 结构化主数据、事务、RLS |
| Elasticsearch | 文档分块倒排索引 | 全文检索（IK 分词），与 PG 通过 `ai_document_chunk.id` 对齐 |
| Milvus / PgVector | 分块向量 | 集合按租户/知识库/模型维度管理 |
| Redis | 会话上下文、检索/嵌入缓存、限流令牌 | TTL 管理 |
| Kafka | 索引事件、洞察事件、审计事件 | 事件总线 |
| MinIO/S3 | 原始文档与附件 | 对象存储，预览水印 |
| ClickHouse/Doris | BI 抽取数据集、聚合结果 | OLAP 加速大屏 |

### 5.2 关键设计

1. **索引一致性**：文档分块写入 PG 为权威源，ES/向量库为派生索引；通过 Kafka 事件驱动与补偿任务保证最终一致；分块 ID 全局唯一以保证引用回溯。
2. **多租户**：所有表含 `tenant_id` + RLS；向量集合与 ES 索引可按租户物理隔离（高合规）或逻辑过滤（默认）。
3. **权限过滤器（Filter DSL）**：由权限引擎根据用户数据范围与文档 ACL/密级生成统一过滤表达式，注入 ES/向量库/OLAP 查询。
4. **向量维度和模型绑定**：`ai_vector_index_meta` 记录集合名、维度、嵌入模型与版本，模型升级走双写迁移。
5. **BI 语义层**：`ai_metric_definition` + `ai_dataset` 构成语义层，看板、NL2SQL、洞察共用同一口径，避免"同指标不同数"。

### 6.2 能力嵌入集成（embedded，强制）

| 能力 | 内部接口 | 说明 |
|---|---|---|
| 知识检索 | `POST /internal/v1/search/query` | 传入 query、知识范围、调用者上下文 |
| RAG 问答 | `POST /internal/v1/copilot/rag` | 返回答案 + 引用 |
| 写作/总结/翻译 | `POST /internal/v1/copilot/text` | 指定能力类型 |
| Agent 执行 | `POST /internal/v1/agent/{code}/run` | 触发宿主注册的 Agent |

### 6.3 开放 API 与事件

- 开放前缀 `/openapi/intelligence/v1`，能力：知识检索、RAG 问答、洞察查询。
- 事件订阅（Kafka→Webhook）：`ai.document.indexed`、`ai.insight.generated`、`ai.agent.executed`、`ai.usage.threshold_reached`。

## 7 双端分离架构

- 前端工程：用户端 `fenglin-hub-portal-ui`（`/app/intelligence`）、管理端 `fenglin-hub-admin-ui`（`/admin/intelligence`）；
- 令牌 `client_type`（ADMIN/PORTAL）由网关校验，路由与鉴权策略据此分流；
- 后端接口约定：`/api/intelligence/v1/admin/**` 仅 ADMIN；其余业务路径仅 PORTAL；`/internal/**` 仅服务间；
- 两端共用设计令牌，导航骨架与信息密度差异化（见 FL-AI-UIUX-006）。

| 服务可用性 | ≥ 99.99%；多副本无状态部署，K8s 滚动更新与健康探针 |
| 网关 | 多实例 + 负载均衡；Sentinel 限流熔断 |
| 数据库 | PG 主备流复制 + Patroni 自动切换；只读副本分担查询 |
| ES/向量库 | 集群多副本分片；向量集合副本 ≥ 1 |
| 缓存 | Redis Sentinel/Cluster 高可用 |
| 消息 | Kafka 多副本（replication ≥ 3） |
| 存储 | MinIO 纠删码/多节点 |
| 容灾 | 同城双活，RPO ≤ 5min、RTO ≤ 30min；异地冷备 |
| 降级 | LLM 不可用→仅检索/模板回复；向量库不可用→仅全文检索；BI OLAP 不可用→直连/缓存结果；embedded 模式降级返回标准响应不阻塞宿主 |

## 9 安全架构

| 层面 | 措施 |
|---|---|
| 认证 | OAuth2.1/OIDC + JWT(RS256) + MFA；服务间 mTLS + 服务令牌 |
| 授权 | RBAC + ABAC + 数据权限；检索/问数权限感知；能力授权开关 |
| 传输 | TLS1.3（外网）；mTLS（内网服务间） |
| 存储 | 数据源凭据/模型 Key AES-256-GCM；PII 加密；DB TDE；KMS 轮换 ≤ 90 天 |
| LLM 安全 | 提示注入检测、越权指令拦截、输入输出内容安全过滤、脱敏、内容标识 |
| 审计 | 全链路审计（检索/问答/洞察/授权/计量），哈希链 + WORM，留存 ≥ 6 个月 |
| 数据合规 | 数据出境评估、供应商合规准入、敏感数据不投喂、私有化/本地模型可选 |
| 隔离 | 租户隔离（RLS + 集合/索引隔离）、双模式暴露面隔离 |

> 逐项等保三级对照与威胁建模见 FL-AI-SEC-009《安全评估报告》。

## 10 技术风险

| 编号 | 风险 | 影响 | 等级 | 应对 |
|---|---|---|---|---|
| R1 | LLM 供应商不稳定/限流 | 问答不可用 | 高 | 多供应商路由、降级、缓存、私有化模型 |
| R2 | 向量库大租户规模增长 | 检索延迟上升 | 中 | 分片/分区、HNSW/IVF 调参、冷热分层 |
| R3 | 混合检索相关性不足 | 用户信任下降 | 中 | Rerank、权重调优、相关性评测闭环 |
| R4 | 索引一致性问题 | 检索缺漏 | 中 | 事件驱动 + 补偿任务 + 对账 |
| R5 | 提示注入/越权 | 数据泄漏 | 高 | 输入输出护栏、权限双重过滤、审计 |
| R6 | 模型数据出境合规 | 合规风险 | 高 | 出境评估、私有化模型、数据脱敏 |
| R7 | BI 大屏高并发聚合 | 响应超时 | 中 | ClickHouse 预聚合、抽取模式、缓存 |
| R8 | 双模式配置漂移 | 行为不一致 | 中 | 配置集中声明与启动校验 |
| R9 | 计量口径不一致 | 计费争议 | 中 | 统一计量模型 + 对账 + 幂等 |
| R10 | 长上下文成本/延迟 | 成本上升 | 中 | 上下文压缩、摘要、模型分级路由 |
