## 4 结果与图表

### 4.1 S1 混合检索（阶梯压测）

| 并发(QPS) | P50(ms) | P95(ms) | P99(ms) | 错误率 | ES CPU | Milvus CPU |
|---|---|---|---|---|---|---|
| 50 | 62 | 138 | 240 | 0.00% | 22% | 28% |
| 100 | 71 | 165 | 298 | 0.00% | 35% | 41% |
| 200 | 88 | 212 | 402 | 0.01% | 58% | 66% |
| 300 | 106 | 268 | 512 | 0.03% | 74% | 81% |
| 400 | 138 | 342 | 736 | 0.12% | 88% | 92% |

**结论**：300 QPS 以内 P95 ≤ 300ms 达标；400 QPS 时 P95 超阈、错误率 0.12%，为容量拐点。

### 4.2 S3 Copilot 并发（200 会话）

| 指标 | 结果 | 目标 | 结论 |
|---|---|---|---|
| TTFT P50 | 0.62s | ≤2s | 达标 |
| TTFT P95 | 1.42s | ≤2s | 达标 |
| TTFT P99 | 1.98s | ≤2s | 临界达标 |
| 输出速率均值 | 31 token/s | ≥25 | 达标 |
| 流式中断率 | 0.4% | ≤1% | 达标 |
| 5xx | 0 | 0 | 达标 |

### 4.3 S5 索引构建吞吐

| 阶段 | 单节点吞吐 | 说明 |
|---|---|---|
| 解析 | 9.2 万 token/min | Tika+PaddleOCR，含表格/图片 |
| 分块 | 30 万 token/min | 语义分块 |
| 嵌入 | 58 万 token/min | 批大小 64，GPU 加速 |

| **端到端** | **52.6 万 token/min/节点** | 10 节点约 526 万 token/min |

**结论**：端到端 ≥ 50 万 token/min/节点 达标；500 万文档（约 400 亿 token）全量约 12.7 小时（10 节点）。

## 5 瓶颈分析

| 编号 | 瓶颈 | 证据 | 结论 |
|---|---|---|---|
| B1 | 向量检索在高并发下 CPU 饱和 | S1 400 QPS 时 Milvus CPU 92% | 主瓶颈，需分片/副本与 ef 调参 |
| B2 | Rerank 增加检索延迟约 60–90ms | 关闭重排 P95 降 78ms | 折中：Top-K 预剪枝后重排 |
| B3 | 权限过滤在高过滤比下额外开销 | S2 P95 +35ms | 过滤下推至 ES/Milvus 原生 filter |
| B4 | 大屏直连 PG 慢 | S6 直连 P95 2.35s | 强制抽取模式 + CH 预聚合 |
| B5 | 长上下文 RAG 拖高 TTFT | S3 P99 1.98s | 上下文压缩 + 摘要 + 模型分级 |
| B6 | 索引嵌入阶段波动 | GPU 队列等待 | 批调优 + 多实例 + 限流 |
| B7 | 大租户影响小租户 | 最大租户占 40% 数据 | 租户级集合/资源隔离 |

## 6 调优措施

| 编号 | 措施 | 效果 |
|---|---|---|
| O1 | Milvus 分片提升至 8、副本 2，HNSW `ef=128`（检索时） | 向量检索 P95 降 18%，CPU 降 15% |
| O2 | 检索链路引入本地缓存（热点 query，TTL 60s） | 热点检索 P95 降 35%，QPS 提升 22% |
| O3 | 权限过滤下推 ES `filter`/Milvus `expr`，避免后置过滤 | 高过滤比 P95 降 22ms |
| O4 | Rerank 前置 Top-50 → 重排 Top-10，模型批推理 | 重排耗时降 40% |
| O5 | BI 默认抽取模式，ClickHouse 预聚合物化视图 | 大屏 P95 由 2.35s → 1.12s |
| O6 | 上下文压缩（摘要+去重）+ 模型分级路由 | TTFT P99 1.98s → 1.61s |
| O7 | 嵌入批大小 64、异步流水线、GPU 复用 | 索引吞吐 +21% |
| O8 | 网关+Sentinel 限流与排队，保护后端 | 拐点后错误率可控（≤0.12%） |
| O9 | JVM/G1 调参、连接池调优（HikariCP 50） | GC 停顿 < 30ms |
| O10 | SSE 连接复用与背压 | 并发会话稳定 ≥ 200 |

## 7 结论与容量建议

### 7.1 结论

1. 混合检索在 **300 QPS 内 P95 ≤ 300ms**，满足目标；400 QPS 为单集群拐点，需扩容。
2. Copilot **TTFT P95 ≤ 2s**、并发 200 会话达标（P99 临界，经调优后 1.61s）。
3. **索引构建 ≥ 50 万 token/min/节点** 达标，全量可控在 13 小时内。
4. **BI 大屏 P95 ≤ 1.5s**（抽取模式）达标；直连模式不满足大屏要求，须默认抽取。
5. 混合负载峰值 **1286 QPS**、错误率 0.06%，8h 稳定性良好，月可用性 99.995% ≥ 99.99%。

### 7.2 容量建议（生产）

| 项 | 建议 |
|---|---|
| 应用副本 | H1 检索 ≥ 4 副本（HPA 基于 QPS/CPU）；H2 ≥ 3；H3 ≥ 3 |
| ES | ≥ 6 数据节点 + 2 专用 master；分片按租户/时间滚动 |
| Milvus | ≥ 4 查询节点 + 2 索引节点；大租户独立集合 |
| ClickHouse | ≥ 4 节点分片+副本；大屏数据集预聚合 |
| LLM | 多供应商路由 + 本地 vLLM 兜底；TTFT 监控告警 |
| 扩容阈值 | 检索 QPS > 300 或 P95 > 260ms 触发扩容 |
| 监控告警 | P95/错误率/TTFT/索引积压/CH 慢查询 全量接入 |
| 容量余量 | 设计余量 ≥ 30%，重大活动前预扩容 |
