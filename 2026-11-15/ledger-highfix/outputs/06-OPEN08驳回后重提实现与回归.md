## 二、接口行为

| 场景 | 结果 |
| --- | --- |
| 本人 + `REJECTED` | 200，`review_status=PENDING`、`status=DISABLED`，驳回意见与时间保留，进入审核队列 |
| 非本人（同租户其它用户） | 403（归属校验先于状态校验） |
| 非 `REJECTED`（PENDING / APPROVED） | 409 `FL-COMMON-0409`，message 带当前状态 |
| 并发/重复提交 | 条件更新只有一次生效，其余 409 |
| 审计 | `OPENAPI_APP_RESUBMITTED`（dev 环境 AuditSink 为 Slf4j，不入 `hub_audit_log`；集成测试断言事件已发出） |

## 四、台账与待重录

- OPEN-08 计入「已修复」；复算脚本输出：明细 137 行、去重 137、开放 69（0/37/32）、已修复 64、待验证 1；脚本按状态字面量统计 `已关闭=2`，`COL-13` 状态写作「已关闭（误判）」故未入桶，人工口径按台账既有约定计 3 条关闭，合计 69+64+3+1=137。
- 新增第十三节「待重录清单」：7 个租户名 + 2 个 OKR 周期名，均为造数编码丢失、库内只剩 `0x3F`/乱码占位，**原值不可恢复，需业务方重新录入**，明确不属于待修项，不回填、不删除。

## 五、回滚方式与影响面

- 回滚：删除新增端点/服务方法/Mapper 方法、门户按钮与 `resubmitApp` 即可；无迁移、无数据变更，历史 `review_comment` / `reviewed_at` 不受影响。
- 影响面：仅开发者门户应用审核链路；管理端 1002 审核逻辑未变（仍只接受 PENDING），同名重建规则未变。
- 已知遗留（不在本次范围）：管理端「应用审核」表单用手输 `app_id`，`el-input-number` 对 19 位雪花 ID 会丢精度（实测输入被写为 `...186000`），审核需改走接口/列表入口；建议后续单独修。
