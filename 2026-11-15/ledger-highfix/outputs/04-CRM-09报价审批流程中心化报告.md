# 高优批次 5：CRM-09 报价审批改走流程中心（方案 A）

> 日期：2026-11-15
> 范围：报价审批统一由流程中心任务办理，报价状态由流程 `PROCESS_COMPLETED` 回调驱动；存量挂起实例收口。
> 规程：造数全部走真实接口（创建/提交/审核均 HTTP），存量实例用官方任务接口补办结；真实浏览器回归；截图逐张校验；台账脚本复算；提交不推送。

## 一、变更

| 层 | 变更 |
| --- | --- |
| 迁移 | 新增 `V1_0_66__seed_crm_quotation_callback.sql`：为租户 9001 的 `crm_quotation_approval` 写入 `hub_wf_callback`（`events=PROCESS_COMPLETED`，回调 `http://localhost:18095/api/crm/v1/internal/quotations/approval/callback`）。 |
| 工作流 | 回调 payload 增加 `operator_id`（实例 `updated_by`），请求头增加 `X-Callback-Token`（`fenglin.workflow.callback-token`，默认 `fenglin-dev-callback`）；新增 `GET /api/hub/v1/workflow/instances/by-no/{instanceNo}/pending-tasks`，按实例号返回待办任务，供管理端业务页定位任务。 |
| CRM | 新增 `POST /api/crm/v1/internal/quotations/approval/callback`：校验 `X-Callback-Token`（缺失/错误 403，`FL-COMMON-0403`），按 `business_key=CRM_QUOTATION:<id>` 解析报价并复用状态机；`handleApproval` 对「目标状态与当前状态一致」的重复回调幂等返回。 |
| 列表 | `QuotationListItemView` 增加 `approve_instance_id`，Mapper 同步查询，便于前端按实例号定位流程任务。 |
| 前端 | admin-ui 报价页「批准/驳回」改为：按 `approve_instance_id` 调 `pendingByInstance` 取待办 → 弹窗填写意见 → `POST /workflow/tasks/{id}:handle` → 回调回写后刷新；移除 `crmApi.quotations.approve`（直调内部审批）调用与方法。页面提示改为「审批统一在流程中心任务办理，历史直调记录不可再审批」。 |

### 1.1 存量实例处置：补办结（不是终止）

- 现状：`QUO202611000009` 报价已 `APPROVED`（`approve_instance_id=WF2121809307581792258`），但实例 `RUNNING`、任务 `salesManagerApprove` `PENDING`。全库 `crm_quotation_approval` 存量仅此 1 条（其余 37 条 RUNNING 属其它流程）。
- 选择**补办结**：用管理端任务接口办结该任务（意见「历史直调审批已通过，补办流程节点（QUO202611000009）」），实例 `COMPLETED`、任务 `DONE`；回调以 `APPROVED` 幂等命中，不二次改写报价。
- 不选终止的依据：① 业务结果（批准）已成事实，补办结让实例终态与报价一致，审计链完整；② 终止接口仅允许发起人调用，而发起人（员工）不具备工作流权限，放开权限的影响面更大；③ 终止仅产生 `PROCESS_TERMINATED`，不会给业务端留任何闭环记录。

## 三、回滚与影响面

- **回滚**：`DELETE FROM fenglin_hub.hub_wf_callback WHERE process_key='crm_quotation_approval' AND tenant_id=9001;` 并回退 CRM/工作流/前端提交；已办结实例与报价状态不回滚（业务结果已发生）。
- **影响面**：
  - 报价审批入口从 CRM 内部接口切换为流程中心任务；前端直调方法已移除。
  - 工作流回调新增 `X-Callback-Token`，需与 CRM 配置一致（`fenglin.workflow.callback-token` / `fenglin.crm.workflow-callback-token`），默认值仅供开发环境，生产必须通过环境变量覆盖。
  - 其它流程若后续接入业务回调，可复用 `hub_wf_callback` + 令牌约定。
  - `GET /instances/by-no/{no}/pending-tasks` 使用 `biz:workflow:task:view` 权限，仅管理端业务页使用。

## 四、遗留说明

- 回调配置以迁移播种到租户 9001（演示租户）；生产多租户需按租户写入同 `process_key` 配置，或后续补管理端回调配置 API。
- 回调为同步 HTTP（3s 超时、最多 3 次重试），失败落 `hub_wf_callback_log` 供排查；未引入 MQ。
