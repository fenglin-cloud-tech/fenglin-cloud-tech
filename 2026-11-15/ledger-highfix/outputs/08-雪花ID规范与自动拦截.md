# 雪花 ID "一律字符串" 规范落地与自动拦截（2026-11-15）

> 前置：`07-雪花ID输入精度普查与修复.md`（全仓 32 处 ID 输入改 `IdInput`）。
> 本批：规范成文 + 类型收口 + 静态检查接 CI + 复核截断 ID 后果 + 剩余开放项汇总。

## 一、规范文档

- 位置：《丰麟云枢 · 平台总体规范与统一标准》新增 **5.6 雪花 ID 前端表示（强制）**，并追加 5.6.1 自动检查；修订记录升 V1.1。
- 强制条款：
  1. 雪花 ID 前端一律 `string`：请求、响应、表单、URL 查询参数、路由参数全程不转 `number`；
  2. 禁止 `Number()` / `parseInt()` / `parseFloat()` / `+id` / `~~id` / 一元 `+`；
  3. 禁止绑定 `el-input-number` / `type="number"`，统一 `IdInput`；
  4. `JSON.parse` 后 ID 视为不可信，必须经 `SnowflakeId` / `CrmId` / `FinanceId` 类型别名声明为 `string`；
  5. ID 仅透传、同型比较、展示；缩短展示用字符串截取；
  6. 金额、数量不受此约束（后端 `BigDecimal`，禁止整型分契约）。
- 文档含三种已发生形态的反例（强转、JSON 回读、数字控件）、正例，以及 17:24 真实截断案例。

结果：`admin-ui`、`portal-ui`、`developer-portal` 三端 `vue-tsc --noEmit` **全部通过**；现在把 number 赋给任一 ID 字段会直接编译失败。

### 2.2 静态扫描脚本

- 路径：`frontend/scripts/check-id-precision.mjs`（纯 Node，无依赖）。
- 规则：
  - `ID_INPUT_NUMBER`：`el-input-number` 或 `type="number"` 且 `v-model` 为 ID 字段；
  - `ID_NUMBER_CAST`：ID 被 `Number()` / `parseInt()` / `parseFloat()` / `~~` / 一元 `+` 包裹。
- 输出 `文件:行号 [规则] 代码行`，任一命中退出码 1。
- 基线：`node scripts/check-id-precision.mjs --baseline <json>`；新增命中失败，**基线中已消失的条目同样失败**，强制清理，不允许永久白名单。
- npm 入口：`frontend/package.json` → `lint:id-precision`。
- CI：`.github/workflows/ci.yml` 新增 `frontend-id-precision` job（push/PR 均执行 `node frontend/scripts/check-id-precision.mjs frontend`）。
