## 二、两个 500

### 2.1 绩效「提交审批」500
- 真因（非“重试成功”）：`hub_wf_definition` 已有 performanceApproval v1(PUBLISHED)，但 Flowable `act_re_procdef` 无该 key（历史部署失败）。启动时 404 `0004001 流程定义不存在` → HttpWorkflowClient 自动部署 → Flowable 从 v1 计数，平台唯一索引 `uk_hub_wf_definition(tenant_id, process_key, def_version)` 与已存在的 v1(SUSPENDED) 冲突 `duplicate key` → 部署失败 → 原 404 被包装为 500。招聘审批能起，是因为其定义已存在且版本一致，与通用链路无关。
- 修复：部署版本取 `max(Flowable 版本, 平台 maxVersion + 1)`，保证版本单调（WorkflowDefinitionService/WorkflowDefinitionMapper）。
- 修复后同用户同请求：`POST /api/talent/v1/performance/evaluations/2121839685956784129/submit` → 200，`eval_status=APPROVING`，`process_instance_id=WF2121857449299677185`；`hub_wf_definition` 现为 v1 SUSPENDED + v2 PUBLISHED。

### 2.2 `POST /flow/demands` 500
- 真因：请求体非法 JSON（PowerShell 直传导致引号被剥离），后端无 `HttpMessageNotReadableException` 映射，落到 500。
- 修复：`ApiExceptionHandler` 新增 400 映射“请求体格式错误，请检查 JSON 字段与类型”。
- 修复后对照（同用户 admin、同 URL）：
  - 非法 JSON → 400 `FL-COMMON-0400 请求体格式错误…`
  - 合法蛇形体 → 200，`demand_no=TD202611344578`（随后 `/publish` 200 → PUBLIC）

## 三、调动单绕过审批（优先项）

- 后端守卫：`createEffectiveTransfer` 仅允许 `APPROVED` 才生效，否则 `STATE_CONFLICT`（HTTP 409，语义化的 4xx，非 400/403 但同样拒绝且说明原因）。
- 实测（API + 页面双份，同数据）：
  1. 创建 → 200 `APPROVING`（id 2121859535588519937 / API 侧 2121857831824486401）
  2. APPROVING 点「生效」→ 409 `异动单尚未审批通过，不能生效（当前状态：APPROVING）`，员工组织仍为「总部」
  3. 审批通过 → `APPROVED`，员工组织仍为「总部」（不再自动生效）
  4. 再点「生效」→ 200 `EFFECTIVE`，员工组织变为「测试部门-1115」，`version` 1→2
- 同类扫描（全后端）：仅 `POST /talent/v1/transfers/{id}/effective` 是“审批后独立生效”的端点到；`/resignations/{id}/approve`、finance `/settlements/{id}/approve` 均有 `APPROVING` 守卫，通过即终态，无绕过路径。
